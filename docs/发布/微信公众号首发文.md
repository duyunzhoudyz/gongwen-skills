每年 11 月、12 月，是写材料最密集的两个月。年终总结、次年要点、述职述廉、考核迎检，一份接一份。这两年，越来越多的人把 AI 拉进来帮忙，翻车的也越来越多。

## 一、AI 写材料，常见的几种翻车

**编事实。** 让 AI 配几个本地案例，结果张冠李戴、查无此企业，这类事已经被公开通报过。更常见的编造不起眼。你只给了几条工作记录，它顺手补上一段你没做过的事，或者加一句“成效显著”。

**替人表态。** 述职述廉报告里，AI 会直接写上“没有违规收受礼品礼金”。这种话只能由本人确认后写。

**一股 AI 腔。** 段首“值得注意的是”，通篇“赋能”“闭环”，破折号一个接一个。读的人未必说得出哪里不对，但都觉得不像人写的。

**态度含糊。** 请示里没有倾向性意见，部署工作用商量口气，结尾再附一句免责声明。

**格式不对。** 粘贴进 Word 满屏星号和井号，序号、日期、发文字号的写法不合国标，还得自己重新排。

**泄密。** 这是最严重的一种。国家安全部通报过涉密人员使用 AI 工具导致泄密的事。中央网信办和国家发展改革委 2025 年 10 月发布的《政务领域人工智能大模型部署应用指引》也要求，防止国家秘密、工作秘密和敏感信息输入非涉密大模型。

## 二、我做了什么

gongwen-skills 是一套开源的公文写作 Skills 集合，MIT 许可，免费使用。10 月 31 日发布的 v1.0.0 有 22 个 skill，其中 17 个核心 skill 覆盖从接任务、起草、改稿、核稿到排版的全过程；5 个行业包，分别面向乡镇街道和社区、公立医院、高校、中小学、国有企业。

它装在 Claude Code、Codex、Cursor、Qwen Code、Kimi Code CLI 等 Agent 工具里用；也有提示词版，可以复制到 DeepSeek、豆包、Kimi 等网页大模型，或者单位内网部署的模型里用。

所有 skill 都遵守六条红线。

1. **保密先于生成。**发现密级标识、“内部资料”字样，或者身份证号、病案号这类个人信息，先停下来提醒。
2. **事实只来自用户。**缺的标【待补】，存疑的标【待核实】。
3. **正文干净，提示外置。**正文里不写免责声明，需要核实的事项放到正文后的“起草说明”。
4. **默认做减法。**开门见山，遵守减负规定的篇幅要求，不照抄上级文件。
5. **规则可溯源、可机检。**格式、标点、数字规则都标注条款号，能写成脚本检查的，就不靠模型自觉。
6. **辅助不代笔。**对照检查、述职这类需要本人经历的材料，没有本人事例就只给提纲。

拿一份年终总结来说，总入口先确认需求和单位类型；综合文稿 skill 把你的工作记录拆成素材台账，每条标明来源；标题 skill 给出三套小标题方案；成稿后清理 AI 腔和防御性写法；核稿 skill 按政治、政策、权限、法规、文风、文字、格式、程序八关过一遍；最后排成国标 Word。

不同单位写法不同。医院材料要讲清 DRG、CMI 等指标的口径，高校要分清学校发文还是部门发文，国企的重大事项要先过党委前置研究。项目内置 7 类单位画像和 5 种角色模式。新人用教学模式，会讲清楚为什么这样写；审稿的领导用审稿模式，只看问题清单。

## 三、效果怎么样

v1.0 的评测正在进行，结论出来后单独发一篇。这里先留个位置【待补：v1.0 评测结论】。

先看 v0.1 的数据。10 月中旬，我对当时的 7 个 skill 做了一次对比评测。104 条用例、621 项检查，材料全部虚构；同一个模型分两组跑，一组读 skill，一组不读；评分时打乱顺序，评分员不知道哪份来自哪组。

| 口径 | 装 skill | 不装 skill |
|---|---|---|
| 全部检查通过率（621 项） | 94.8% | 59.7% |
| 通用检查通过率（422 项） | 95.0% | 74.6% |
| 防编造用例（34 条）中出现编造的次数 | 0 | 15 |
| 带“内部资料”等标识的用例（7 条）停下提醒 | 7 条 | 2 条 |

“通用检查”是熟悉公文写作的人不看本项目规则也能做到的检查，比全部检查更能说明问题。需要说明的是，每条用例只跑了一次，评分员和被评模型是同一个模型，结果有一定偶然性。装了 skill 也有吃亏的时候，比如一条写函的用例，事实齐全，第一轮却没出稿。这些问题都已列入 v1.0 的修改范围。完整方法和局限见仓库的 `evals/results/` 目录。

再看两个示例。

**一篇 AI 起草的通知，体检前后。** 这是一份模拟 AI 起草的区教育局冬季校园安全检查通知，里面有段首评论语、新八股词、Markdown 符号、“仅供参考”式的免责声明、不规范的发文字号，还有一句对家长“一律移交公安机关予以拘留”。依次经过去防御性、去 AI 味、核稿三个 skill 后，机检的必改问题从 5 处降到 0，建议改问题从 31 处降到 0，篇幅从 1092 字压到 807 字，所有数值没有变。拘留那一句，核稿时确认区教育局没有处罚权，予以删除，是否补写替代要求留给用户决定。

**一份医院科室年终总结。** 输入是科秘书口语化的工作记录和一张缺了几项的指标表。成稿里 9 处缺项全部标了【待补】，存疑的 2 处标了【待核实】，患者姓名改成了“张某”。素材只够写约 1400 字，用户要的是 2000 字，起草说明写明了补齐哪几项可以写足，没有拿背景铺垫和表态凑字数。

## 四、怎么安装

**Claude Code** 用户在对话框里依次输入下面两行。

```
/plugin marketplace add duyunzhoudyz/gongwen-skills
/plugin install gongwen@gongwen-skills
```

行业包按需加装，例如医院用 `/plugin install gongwen-hospital@gongwen-skills`。

**Codex、Cursor、Qwen Code、Kimi Code CLI 等工具**，下载仓库后运行一键安装脚本，脚本会探测本机装了哪些工具。也可以用 `npx skills add duyunzhoudyz/gongwen-skills`。

**网页大模型或内网模型**，打开仓库的 `dist/prompts/` 目录，复制对应的提示词文件，粘贴到对话开头，再说需求。第一次用建议从总入口 `gongwen.md` 开始。

排版功能需要电脑上有 Python 和 python-docx；没有的话，会改为给出 WPS、Word 的手动设置清单。详细步骤见仓库 README。

## 五、保密提示（请一定读完）

> 1. 涉密信息严禁输入任何联网 AI 工具。带密级标识，或标注“内部资料”“工作秘密”的材料，不要粘贴到任何公网大模型。
> 2. 处理内部材料，请使用单位内网部署的模型。本项目的提示词版和离线包可以在内网模型上使用。
> 3. 个人信息先脱敏再输入，包括身份证号、手机号、病案号、学号，以及患者、学生的真实姓名。
> 4. 本项目的脚本只在本机运行，不联网，不收集数据。你用的 AI 工具怎么处理数据，以该工具的用户协议为准。

工具能做的是搭结构、守规矩、查错漏、出格式。文稿的事实、判断和最终表述，由写的人负责；正式发文前，请按本单位程序审核签发。
