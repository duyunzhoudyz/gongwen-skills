## 二、入群须知（群规）

### 第一条　保密

1. 不发涉密材料，不发标注“内部资料”“工作秘密”“注意保密”的材料。
2. 不发内部文件的截图、照片、拍屏，不转发工作群的聊天记录。
3. 不发真实的个人信息，包括身份证号、手机号、病案号、学号、住址，以及患者、学生、群众的真实姓名。
4. 需要举例时，单位写“某市某局”“某医院”，人名写“张某”，数字自己编一组。
5. 误发了，请立即撤回。管理员发现后会删除消息，并私信提醒。

### 第二条　讨论范围

1. 欢迎讨论：公文规范、文种选择、写作方法、各行业的写法差异、gongwen-skills 的安装和使用、AI 工具的使用经验。
2. 与写作无关的时政话题不在群里讨论。涉及政治性提法的，只讨论“以哪份原文为准”，不评论内容本身。

### 第三条　不允许的内容

1. 广告、代充、卖号、引流链接、二维码。
2. 有偿写稿的需求、接单信息，包括私下拉人接单。
3. 宣传“降 AI 率”“让稿子查不出是 AI 写的”之类的服务。
4. 未经本人同意转发群成员的发言和信息。

### 第四条　提问方式

提问时写清：

- 单位类型：如区直机关、乡镇、公立医院、高校、中小学、国企；
- 文书类型：如年终总结、请示、会议纪要；
- 使用的工具：如 Claude Code、Qwen Code、网页版 DeepSeek；
- 卡在哪一步：报错信息、输出不对的地方（用虚构内容复现）。

### 第五条　违规处理

1. 一般违规：管理员提醒并删除，再次违规移出群聊。
2. 发内部材料、真实个人信息，或发布写稿接单信息的：删除消息并直接移出。

## 三、常见问题

**1. 这个项目是什么？收费吗？**

gongwen-skills 是给机关、事业单位、国企文字工作者用的公文写作 Skills 集合，v1.0.0 有 22 个 skill。项目按 MIT 许可开源，免费使用。

**2. 没有 Claude，能用吗？**

能。Skill 版支持 Claude Code、Codex、Cursor、Gemini CLI、GitHub Copilot、Qwen Code、Kimi Code CLI 等工具，Trae、CodeBuddy 的安装目录来自社区资料，装的时候会提示。没有这些工具的，可以用提示词版：打开仓库 `dist/prompts/`，复制文件内容粘贴到 DeepSeek、豆包、Kimi 等网页大模型，或者单位内网部署的模型。

**3. 单位的材料能直接贴进去吗？**

涉密材料和标注“内部资料”“工作秘密”的材料，不能输入任何联网 AI 工具。处理内部材料请用单位内网部署的模型，提示词版和离线包可以在内网使用。个人信息先脱敏再输入。skill 发现密级标识或敏感信息时会先停下来提醒，但这只是最后一道提醒，判断责任在使用者。

**4. 它会不会编数据？**

规则要求只用你给的材料，缺的标【待补】，存疑的标【待核实】。v0.1 评测中，34 条故意少给材料的用例，装了 skill 后出现编造 0 次，不装的有 15 次。模型输出有随机性，定稿前请逐条核对数字、人名、文号。

**5. 能帮我降 AI 率，让稿子查不出是 AI 写的吗？**

不做这件事，也不承诺这种效果。去 AI 味改的是文风质量，比如段首评论语、新八股词、破折号过多，目的是让稿子更好读。

**6. 我在医院（高校、中小学、国企、乡镇社区），有专门的吗？**

有 5 个行业包：gongwen-hospital、gongwen-university、gongwen-k12、gongwen-soe、gongwen-grassroots，各自带本行业的专用文书模板、红线和核稿清单。本行业的通用文书，比如总结、通知、讲话，仍由核心 skill 处理。没装行业包时，核心 skill 按单位画像处理。

**7. 排出来的 Word 字体不对，或者电脑上没有 Python，怎么办？**

项目不随附字体，方正小标宋简体、仿宋_GB2312 等请用单位授权的或自行合法获取。没有 Python 时，排版 skill 会给出 WPS、Word 的手动设置清单。不同电脑上显示可能有细微差别，正式印发前请打印核对。

**8. 对照检查材料、述职报告能直接写出来吗？**

这类材料要写本人真实的经历。你提供了本人事例，可以整理成文；没有事例时，只给提纲和填写指引。廉洁自律之类的表态，要本人确认后才写进正文。

**9. 提法会不会过时？**

项目不内置“最新提法库”。政治性提法、上级精神只对照你提供的原文。核稿时会把疑似过时的提法和机构旧称标出来，请你对照原文确认，不会自行替换。

**10. 发现规则错了，或者想贡献本行业的经验，怎么做？**

规则纠错请在 GitHub 提 issue，附上依据的文件名称和条款号。行业经验欢迎发到 GitHub Discussions，或者在群里先讨论。提交的示例和评测材料请全部虚构，不要提交真实的内部文件，哪怕已经公开。
