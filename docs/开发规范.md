## 2. 命名与 frontmatter

- 目录名与 `name` 完全一致，统一 `gongwen-` 前缀（总入口为 `gongwen`），只用小写字母、数字、连字符，≤64 字符，不含 claude、anthropic。
- frontmatter 只用三个字段：`name`、`description`、`license`（值为 `MIT`）。
- `description` **必须写在一行内**（工具链按单行解析），中文，≤300 字（硬上限 1024 字符），由三部分组成：
  1. 做什么（第一句话说清）；
  2. 何时使用：列出用户可能的说法，正式说法与口语说法都要有（如"年终总结""弄个汇报材料"）；
  3. 边界：哪些情况不归本 skill，转给哪个 skill。

写作要求：
- 指令写给模型看：明确、可执行，多用"先……再……"的步骤，少用抽象原则。
- 用中文写作，行业通用英文术语（Agent、Prompt、Token、docx、JSON）保留英文。
- 本项目自身的文字也要过得了自家的"去 AI 味"标准：少用破折号，不用"值得注意的是""不是……而是……"这类句式，不堆砌形容词。
- 路径一律写相对 skill 根目录的路径，如 `references/_shared/guardrails.md`。

## 4. 共享资料机制

单个 skill 不能可靠引用自身目录以外的文件，因此共享资料以 `shared/` 为唯一源，由 `tools/sync_shared.py` 按各 skill 的 `manifest.json` 复制进去，CI 校验二者逐字节一致。**修改共享资料只改 `shared/`，再运行同步脚本。**

`manifest.json` 格式：

```json
{
  "name": "gongwen-review",
  "version": "0.1.0",
  "status": "beta",
  "shared": [
    {"src": "guardrails.md"},
    {"src": "style/output-format.md"},
    {"src": "scripts/gongwen_lint.py", "dest": "scripts/gongwen_lint.py"},
    {"src": "scripts/lint_rules.json", "dest": "scripts/lint_rules.json"},
    {"src": "scripts/style_patterns.json", "dest": "scripts/style_patterns.json"}
  ],
  "prompt_bundle": [
    "references/_shared/guardrails.md",
    "references/_shared/style/output-format.md",
    "references/checklist.md"
  ]
}
```

- `src`：相对 `shared/` 的路径。`dest`：相对 skill 根目录的路径，省略时为 `references/_shared/<src>`。
- `status`：`stable`、`beta`、`draft` 三选一。v0.1 统一为 `beta`。
- `prompt_bundle`：导出提示词版时，按顺序拼接在 SKILL.md 正文之后的资料（相对 skill 根目录），只放网页大模型真正需要的内容，控制总长度。
- 所有 skill 至少同步 `guardrails.md`、`style/output-format.md`、`style/ai-tone.md`、`style/defensive.md`。后两份是"写作时就要避开"的精简规则（各不超过 120 行）；详细的改写指南分别放在 gongwen-humanize 和 gongwen-direct 自己的 `references/` 中。

## 5. 输出约定

详见 `shared/style/output-format.md`，要点如下：

- 正文是纯文本公文体，不用 Markdown；层次序数 一、→（一）→ 1. →（1）。
- 正文中唯一允许的提示性内容是两种标记：`【待补：说明】`、`【待核实：说明】`（全角方括号、全角冒号）。
- 正文之后单独一行写 `【起草说明】`，之后是说明内容。脚本以这一行为界，之前是正文，之后忽略。
- Agent 工具环境下，交付文件放在 `公文/<YYYYMMDD>-<简短标题>/`，文件名清单见 `shared/style/output-format.md` 第三部分；同名文件已存在时加 `-v2`、`-v3`，不覆盖。
- 网页环境跨 skill 时使用交接卡，格式见 `shared/style/output-format.md` 第四部分。

## 7. 脚本约定

- Python 3.9 及以上，只依赖标准库；处理 Word 用 `python-docx`，处理 Excel 用 `openpyxl`，二者缺失时给出安装提示并退出，不崩溃。
- 不访问网络，不收集任何数据。
- 所有文件读写显式使用 UTF-8；Windows 控制台输出前调用 `sys.stdout.reconfigure(encoding="utf-8")`（加 try 保护）。
- 路径用 `pathlib`；从脚本自身位置定位数据文件：`Path(__file__).resolve().parent`。
- 命令行参数用 `argparse`，`--help` 为中文。
- 代码注释用中文，标识符用英文。
- 每个脚本都要有降级说明：SKILL.md 中写明"无法运行脚本时，按某清单人工检查"。

## 8. 机检接口（gongwen_lint.py）

所有 skill 调用机检都走同一个命令行接口，其他 skill 只依赖这个接口，不依赖内部实现：

```text
python scripts/gongwen_lint.py <文件> [--doc-type 文书类型] [--checks 类别,类别] [--json] [--strict]
```

- 输入：`.txt`、`.md`、`.docx`。遇到 `【起草说明】` 行即停止读取。
- `--checks`：`all`（默认）或逗号分隔的类别：`residue`（残留）、`punct`（标点）、`number`（数字）、`format`（格式要素）、`structure`（结构）、`style`（AI 味）、`defensive`（防御性）、`privacy`（隐私与保密）、`marker`（待补标记）、`length`（篇幅）、`legal`（面向群众或下级的强制措施、处罚表述）、`jianfu`（减负规定相关要求）。
- `--json` 输出格式：

```json
{
  "file": "正文.txt",
  "doc_type": "通知",
  "char_count": 2310,
  "summary": {"P0": 1, "P1": 3, "P2": 2, "markers": {"待补": 0, "待核实": 0}},
  "issues": [
    {
      "id": "NUM-003",
      "level": "P0",
      "category": "数字",
      "line": 12,
      "excerpt": "X发〔2026〕第5号",
      "message": "发文字号不加\"第\"字",
      "suggestion": "X发〔2026〕5号",
      "basis": "GB/T 9704-2012 7.2.5"
    }
  ]
}
```

- issue 还可以带以下可选字段，调用方不得依赖其必然存在：`gate`（八关名称）、`check`（检查类别英文名）、`context`（命中处前后文）、`rule_id`。
- `summary` 另含 `markers` 字段：`{"待补": N, "待核实": M}`。【待补】【待核实】标记是起草阶段的正当产物，机检每处报 P2，并在 `markers` 中单独计数，提醒定稿前补齐；不计入 P0、P1。

- 级别：`P0` 必须改（错误、违规、泄密风险）；`P1` 建议改（明显不规范、文风问题）；`P2` 提示（需人工判断）。
- 退出码：默认 0；`--strict` 时存在 P0 返回 1；输入错误返回 2。

`style_patterns.json` 格式（由文风词表维护，机检引擎读取）：

```json
{
  "version": "0.1.0",
  "patterns": [
    {
      "id": "AI-001",
      "group": "style",
      "category": "段首评论语",
      "pattern": "(^|[。！？\\n])\\s*值得(注意|一提)的是",
      "level": "P1",
      "message": "段首评论语，属于典型 AI 句式",
      "suggestion": "删除评论语，直接陈述事实",
      "density_per_1000": null,
      "exempt_doc_types": [],
      "source": "lieflat-less-ai-tone (MIT)"
    }
  ],
  "whitelist": [
    {"id": "WL-001", "pattern": "[一二三四五六七八九十]是", "note": "\"一是……二是……\"为公文正当列举方式"}
  ]
}
```

- `group`：`style`（AI 味）或 `defensive`（防御性）。
- `pattern`：Python `re` 语法；引擎对每段文本匹配。
- `density_per_1000`：非空时，只有每千字命中次数超过该值才报告（用于破折号、冒号这类"多了才是问题"的特征）。
- `whitelist`：命中区间与白名单重叠时不报告。

`lint_rules.json` 中正则类规则使用同样的字段（`id`、`category`、`pattern`、`level`、`message`、`suggestion`、`basis`、`doc_types`、`exempt_doc_types`）；无法用正则表达的检查（层次序号连续性、数字概括与条数一致、篇幅上限）在引擎中以函数实现，规则 ID 同样登记在 `lint_rules.json` 的 `procedural` 列表中。

### 8.1 事实一致性检查（fact_diff.py）

改稿类 skill（humanize、direct，以及 review 的"直接改"模式）改完后，用它确认没有改动事实：

```text
python scripts/fact_diff.py <原稿> <改稿> [--json] [--strict]
```

- 比对两稿中的数字（含百分数、金额、日期）、`【待补】`/`【待核实】` 标记、书名号和引号内的内容、发文字号。
- 输出"原稿有而改稿没有""改稿新增"两张清单；`--strict` 时任一清单非空返回 1。
- 只比对 `【起草说明】` 之前的正文。

### 8.2 核稿意见 JSON（review → format）

gongwen-review 除了输出 `核稿意见.md`，还输出 `核稿意见.json`，供 gongwen-format 写成 Word 批注：

```json
{
  "source_file": "正文.txt",
  "issues": [
    {
      "level": "P1",
      "gate": "文字关",
      "category": "标点",
      "excerpt": "原文中能唯一定位的一段文字",
      "message": "问题说明",
      "suggestion": "修改建议",
      "basis": "GB/T 15834-2011 4.5.3.5"
    }
  ]
}
```

- `excerpt` 必须是原文中的连续片段（逐字一致），尽量能唯一定位；format 按它查找批注位置，找不到时把该条列入未定位清单。
- `gate` 取值：政治关、政策关、权限关、法规关、文风关、文字关、格式关、程序关。

### 8.3 文本重合检测（overlap_check.py）

用于 implement 检测照抄上位文件，以及 party 检测材料雷同：

```text
python scripts/overlap_check.py <稿件> <参照文件> [<参照文件>...] [--min-len 15] [--json] [--strict]
```

- 只比对稿件中 `【起草说明】` 之前的正文；参照文件全文参与比对。支持 .txt、.md、.docx（docx 需要 python-docx）。
- 比对前去掉空白和标点差异，找出长度不少于 `--min-len` 个汉字的连续重合片段。
- 输出每个参照文件的重合率（重合字数除以稿件正文字数），以及重合片段清单：稿件位置、参照位置、片段文字。
- `--strict` 时，任一参照的重合率超过 30% 返回 1；输入错误返回 2。只用标准库。

### 8.4 表格转 Excel（md2xlsx.py）

用于 implement 的任务分解表、rectify 的整改台账、minutes 的督办清单：

```text
python scripts/md2xlsx.py <输入.md> <输出.xlsx> [--title 表题] [--all-tables]
```

- 默认转换文件中的第一张 Markdown 表格；`--all-tables` 时每张表各占一个工作表。
- 公文表格样式：表题居中加粗，表头加粗并加底色，全部加边框，自动列宽并自动换行，冻结首行，字体为宋体。
- 输出文件已存在时加后缀 `-v2`、`-v3`，不覆盖。需要 openpyxl，未安装时给出提示并返回 2。

## 9. 评测格式

`evals/evals.json`（兼容 skill-creator）：

```json
{
  "skill_name": "gongwen-report",
  "evals": [
    {
      "id": 1,
      "prompt": "用户原话，口语化、贴近真实工作场景",
      "expected_output": "期望结果简述",
      "files": ["evals/files/某科室2026年工作记录.txt"],
      "expectations": [
        "正文不含 Markdown 符号",
        "素材中没有的数字一律标【待补】，未编造任何数据"
      ],
      "unit_type": "公立医院",
      "role_mode": "高效模式",
      "tags": ["年终总结", "防编造"]
    }
  ]
}
```

要求：每个 skill ≥10 条；覆盖 ≥4 种单位类型、≥3 种角色模式；至少 2 条"防编造"用例（故意少给数据）；至少 1 条"保密"用例（材料含敏感信息）。所有材料一律虚构，单位用"某市某局""某医院"等，不出现真实单位名称。

`evals/trigger.json`：20 条，10 条应触发、10 条不应触发。不应触发的用例优先选与相邻 skill 容易混淆的说法：

```json
[
  {"query": "帮我把这篇年终总结的 AI 味去掉", "should_trigger": false},
  {"query": "下周要交科室年终总结，素材我发你", "should_trigger": true}
```
