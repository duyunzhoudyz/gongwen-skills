# 测试记录表填写说明

[测试记录表.csv](测试记录表.csv) 用来记录试用中发现的问题。一行记一个问题。表格里的所有内容必须是虚构或已脱敏的，**不能有涉密信息和真实个人信息**。脱敏方法见 [测试者手册](测试者手册.md#怎样脱敏)。

## 怎么打开和保存

- 文件是 UTF-8 带 BOM 编码，用 Excel 或 WPS 表格直接双击打开，中文不会乱码。
- 保存时选“CSV UTF-8（逗号分隔）”。如果只有“CSV（逗号分隔）”可选，换成 .xlsx 保存也行，发给我们时说明一下。
- 同一个单元格里要换行，按 Alt+Enter。

## 各列怎么填

| 列 | 怎么填 |
|---|---|
| 编号 | 自己编，如 T001、T002 |
| 测试日期 | 如 2026-10-20 |
| 测试者角色 | 从下面选一个：新入职的文字工作者；专职笔杆子；兼职写材料的业务骨干；审稿的领导或中层；党务宣传岗；其他 |
| 单位类型 | 从下面选一个：党政机关；基层（乡镇、街道、社区）；公立医院；高校；中小学；国有企业；其他事业单位；其他 |
| 使用工具 | 如 Claude Code、Qwen Code、网页大模型（提示词版）、内网模型（离线包）。写具体工具名 |
| 模型 | 具体的模型名称，如 DeepSeek-V3、Kimi、Qwen3。不知道版本就写网页上显示的名字 |
| skill | 完整名称，如 gongwen-report。不确定是哪个，写“不确定”；总入口写 gongwen |
| 用户说法（已脱敏） | 你对它说的话，原样写，里面的单位、人名、数字已经是虚构的。长材料不用贴，写一句“附材料：某科室 2026 年工作记录，约 800 字，缺平均住院日” |
| 问题类型 | 从下面选一个主要的：编造；格式；文种；语气；篇幅；保密；触发错误；其他；无 |
| 严重度 | 高；中；低。见下表 |
| 是否可复现 | 每次都出现；偶尔出现；只试了一次 |
| 截图或摘录（已脱敏） | 出问题的那一两句话，原样摘录，不超过 200 字。需要截图的，先遮挡，再说明截图文件名 |
| 建议 | 你觉得怎么改合适。写成“标【待补】”“改用函”这样具体的话。没想法可以空着 |
| 备注 | 其他想说的，比如用了联网搜索、深度思考，或者 Word 和 WPS 的版本 |

## 问题类型的意思

| 类型 | 指什么 |
|---|---|
| 编造 | 输出了材料里没有的数字、人名、事例、成效评价、政策依据、文号 |
| 格式 | 正文里有 Markdown 符号，序号、日期、标点、文号写法不对，Word 版式不对 |
| 文种 | 选错文种，行文方向错，该用函的用了请示，请示里没有倾向性意见 |
| 语气 | 口气不合上行、平行、下行文，AI 腔重，该写要求的写成了建议，满篇免责声明 |
| 篇幅 | 比要求的长很多或短很多，素材不够却在注水 |
| 保密 | 材料里有“内部资料”等标记却没有停下提醒，或者没有标记却乱报警；个人信息没有脱敏 |
| 触发错误 | 该用的 skill 没有用上，或者用了不相干的 skill；交接卡指错了下一站 |
| 其他 | 上面都不是，比如脚本报错、安装失败、提示词放不进输入框 |
| 无 | 没发现问题。好用的地方也可以记一行，在“建议”里写好在哪 |

## 严重度怎么定

| 级别 | 标准 |
|---|---|
| 高 | 编造了事实；涉密标记没有提醒；文种或行文方向错到不能用；格式错到不能送签。出现这类问题，稿子不能直接用 |
| 中 | 要明显返工才能用，比如篇幅差一大截、语气不对、漏掉关键要素 |
| 低 | 小瑕疵或个人偏好，改几个字就行 |

拿不准就选低一级，把理由写在备注里。

## 示例行

下面是虚构的示例，仅供参考，不要放进你的表格。

| 列 | 内容 |
|---|---|
| 编号 | T001 |
| 测试日期 | 2026-10-20 |
| 测试者角色 | 专职笔杆子 |
| 单位类型 | 党政机关 |
| 使用工具 | 网页大模型（提示词版） |
| 模型 | DeepSeek |
| skill | gongwen-report |
| 用户说法（已脱敏） | 帮我写个信息工作总结，1500 字左右，记录发你。附材料：某区某局办公室全年报送信息 63 条，区政府采用 17 条，没写市级采用数 |
| 问题类型 | 编造 |
| 严重度 | 高 |
| 是否可复现 | 偶尔出现 |
| 截图或摘录（已脱敏） | “市级采用 5 条，居全区前列” |
| 建议 | 市级采用数材料里没有，应标【待补】；“居全区前列”没有依据，应删掉 |
| 备注 | 重试三次，出现一次 |

## 提交

- 条数不多的，直接用 GitHub 的“测试反馈”表单，一个问题填一份，表单的字段和这张表一一对应。
- 条数多的，把填好的表格发给交流群里的管理员，或在 [Discussions](https://github.com/duyunzhoudyz/gongwen-skills/discussions) 里新建帖子并附上文件。
- 发之前再检查一遍：有没有真实的单位名、人名、号码、文号。
