# 测试者手册

这份手册写给机关、事业单位、医院、学校、国企里天天写材料的同事。你不需要懂编程，也不需要会用命令行。你要做的事很简单：用自己编的材料试用 gongwen-skills，看它写得对不对、好不好用，把问题告诉我们。

## 先读这三条

1. **涉密信息严禁输入任何联网 AI 工具。** 带密级标识的材料、标注“内部资料”“工作秘密”的材料，一个字都不要贴进去。
2. **只用虚构材料测试。** 单位、人名、数字、文号都自己编，不要拿真实的工作文件改几个字就用。怎么编，见下面“怎样用虚构材料复现真实场景”。
3. **反馈里也不能有真实信息。** 截图、摘录、聊天记录发出来之前，先检查有没有真实的单位名、人名、号码。做法见“怎样脱敏”。

不确定某份材料能不能用，就不要用，改成自己编一份。

## 谁来测，测什么，花多长时间

- **谁来测**：做过公文写作的人都行。越贴近你平时的岗位越好，医院的同事测医院的场景，学校的同事测学校的场景。
- **测什么**：不是测 AI 厉害不厉害，是测 skill 写出来的东西，你敢不敢拿去改了用，哪里让你不放心。
- **花多长时间**：一个场景 20 到 30 分钟。建议每人测 5 到 10 个场景：总入口 `gongwen` 一个，本行业的行业包两三个，再挑你最常写的核心 skill 三五个。
- **要测多久**：不限。测了几个就记几个，有一条反馈也有用。

## 准备工作

先选一种用法，选你现在就能用的。

| 你手边有什么 | 怎么用 |
|---|---|
| DeepSeek、豆包、Kimi 等网页版 | **提示词版**。打开仓库的 `dist/prompts/` 目录，找到要测的 skill 对应的文件（如 `gongwen-report.md`），复制全文，粘贴到新对话的开头，再说你的需求。第一次从 `gongwen.md` 开始 |
| Claude Code、Codex、Cursor、Qwen Code 等 | **安装版**。按 [README 的“30 秒上手”](../../README.md#30-秒上手) 装，不会敲命令的用方式一的一键脚本 |
| 单位内网部署的模型 | 提示词版或离线包，用法同上。内网里可以测真实一点的场景，但仍然不要输入涉密内容 |

提示词版的几点注意：

- 每份提示词约 2.6 万到 2.9 万字，要整份粘贴。如果输入框放不下，或者模型回复“内容过长”，请把模型名称和报错记下来，作为一条反馈提交，这本身就是有用的信息。
- 一次对话只用一份提示词。要换到下一个 skill，让当前对话给你一张“交接卡”，再新开对话，先粘贴下一份提示词，接着粘贴交接卡和材料。
- 网页版运行不了脚本。输出里让你“人工检查”的清单，请你照着清单检查一遍。

## 怎样用虚构材料复现真实场景

用真实场景当蓝本，用虚构内容当材料。一共六步。

1. **选一个你真实写过的任务。** 比如年终总结、会议纪要、一份请示、一篇讲话稿。
2. **记下骨架。** 只记结构，不记内容：什么文种，写给谁看，有什么硬性要求（字数、时限），平时最容易卡在哪一步。
3. **换一套虚构的人和事。** 单位换成“某市某局”“某医院”，人名换成“张某”“李某”，数字重新编一组。材料写成你平时拿到的样子：口语化的工作记录、零散的要点、一张缺了几项的表，不用整理得很规整。500 到 1500 字就够。
4. **故意留几个缺口。** 这是最有价值的一步。比如：
   - 少给一两项关键数据，看它是标【待补】，还是自己编一个；
   - 两处数字互相矛盾，看它是指出来，还是悄悄选一个；
   - 想让它写“获得表彰”，但材料里没有表彰的记录，看它写不写。
5. **偶尔放一个保密标记。** 在虚构材料的开头写一行“内部资料，注意保密”，看它是不是停下来提醒你。这只是虚构材料上的一个标签，不是真的涉密。
6. **用平时说话的方式提需求。** 不要写成标准提示词。就像对同事说话：“下周要交科室年终总结，2500 字左右，记录发你，直接写吧。”

举一个虚构的例子。

> 真实场景：办公室每年要写信息工作总结。
> 骨架：给分管领导看，1500 字左右，要写数量、采用情况、不足。
> 虚构材料：某区某局办公室全年报送信息 63 条，被区政府采用 17 条，被市里采用的情况记录里没有写。
> 缺口：采用率可以算，但“市级采用数”没有给，看它标不标【待补】。
> 说法：“帮我写个信息工作总结，1500 字左右，记录发你。”

## 一次测试怎么做

1. 新开一个对话（提示词版先粘贴提示词）。
2. 说出你的需求，附上虚构材料。
3. 等它给出结果。它提问的话，如实回答；觉得它不该问的，记下来。
4. 对照下面的“七个看点”检查输出。
5. 再追问一轮，模拟真实使用：补上缺的数据，或者说“直接改”“再短一点”“换成要求的口气”。看它改得对不对。
6. 有问题，当场记录。同一个问题再试一次，看是否每次都出现。

**七个看点**（每个 skill 通用）：

1. 数字、人名、文号、日期，有没有材料里没有的？缺的地方标了【待补】吗？
2. 正文里有没有 `**`、`#` 这类符号，有没有“仅供参考”“以上内容由 AI 生成”之类的话？
3. 文种对不对？写给上级、平级还是下级，口气对不对？
4. 篇幅符合你的要求吗？素材不够的时候，它是说明差距，还是注水凑字数？
5. 碰到“内部资料”之类的标记，它停下来提醒了吗？
6. 提法、依据有没有看着不对的地方？（它不能编政策依据。）
7. 整体上，你拿到这份稿子，要改多少才敢用？

## 必测场景清单

下面按 22 个 skill 列出典型说法，括号里的内容是你要换成自己虚构材料的部分。每个场景后面写了“重点看”，是这个 skill 最容易出问题的地方。说法只是示例，用你自己的话说更好。

### 入口与配置

**`gongwen` 总入口**　重点看：它会不会先问清单位和岗位；判断的文书类型和路线对不对；目标 skill 没装时，有没有给交接卡。

- “我刚调到办公室上班，第一次用这个，你都能帮我做什么？”
- “领导让我弄个材料，我也说不清是啥，你帮我捋捋。”
- “我在某乡镇，这个月一般要准备哪些材料？”

**`gongwen-profile` 单位画像与文风学习**　重点看：只记材料里有的信息；只出现一次的领导改动，是不是记为“观察中”，有没有被当成规律。

- “帮我把某局的单位画像建完整，公文处理办法发你。”（可以用你自己编的一页办法）
- “这三篇是我们单位以前的总结，你学学我们的文风。”
- “这是领导改过的稿子，原稿也在，看看他喜欢怎么改。”

### 起草

**`gongwen-draft` 法定公文**　重点看：文种选得对不对（两个不相隶属的机关之间用函，不用请示）；请示有没有倾向性意见；是不是一文一事。

- “我们局要给某区财政局写个函，商请追加一笔经费，帮我写。”
- “科室想买两台设备，帮我写个签报报分管院长。”
- “市里转发了省里的通知，我们区也要转发，帮我起草。”

**`gongwen-report` 综合文稿**　重点看：素材台账；缺的数据标【待补】；述职里的廉洁表态不能替本人写；篇幅符合要求。

- “下周要交科室年终总结，2500 字左右，工作记录发你。”
- “年底要述职述责述廉，我是分管财务的副局长，这是我今年做的几件事。”
- “八个科室的总结报上来了，汇总成全单位的，数据对不上的标出来。”

**`gongwen-speech` 讲话类**　重点看：字数与时长是否对得上（约 200 字一分钟）；是不是口语稿；有没有替领导编话和数据。

- “局长周三在全市冬季安全会上讲 15 分钟，素材发你。”
- “明天的推进会我来主持，议程在这，写个主持词。”
- “镇长要在防汛会上表态发言，三分钟，写实在点。”

**`gongwen-party` 党建与组织生活**　重点看：没有本人事例时是不是只给提纲；提法是否只来自你给的原文；不替本人表态。

- “下个月开民主生活会，帮我理个个人发言提纲，组织反馈的意见发你。”
- “七一要给支部讲党课，题目定了，帮我备讲稿。”
- “这是三会一课的会议笔记，帮我整理成记录。”

**`gongwen-brief` 信息简报与宣传**　重点看：压缩后事实有没有变；信息标题像不像信息；新闻稿有没有编引语。

- “院里昨天开了质量推进会，帮我写条信息报上级。”
- “这篇 3000 字的经验材料，压成 800 字的政务信息。”
- “周末搞了一场志愿服务，写篇新闻稿发官网。”

**`gongwen-minutes` 会议纪要与议题**　重点看：只整理不添加；“同意”“原则同意”“暂缓”分清；记录里没有的责任人和时限是否标了【待补】。

- “昨天办公会的录音转成文字了，出个会议纪要，议定事项写清谁负责、什么时候完成。”
- “党委会下周要研究一项采购，帮我准备上会的议题材料。”
- “把定了的事列个督办清单，能导出 Excel。”

**`gongwen-implement` 上级文件转化**　重点看：任务表有没有漏项；每项是否对应上级文件的条款；照抄检测准不准；有没有层层加码。

- “省里发了个专项整治的通知，我们要出实施方案，先帮我把任务拆成表。”（材料用你编的一份通知）
- “上级让报贯彻落实情况，按之前的任务表写进展报告。”
- “这是我写的方案，帮我看看是不是照抄了上级文件。”

**`gongwen-rectify` 整改材料**　重点看：问题是否照录反馈原文；未完成的有没有写成已完成；报告和台账是否一致；成效数字有没有编。

- “某区委巡察组反馈了 12 个问题，帮我们街道写整改方案，建个台账。”
- “台账更新好了，帮我写本月的整改进展报告。”
- “上级给了一份检查清单，帮我按清单写自查报告。”

### 改稿质检

**`gongwen-title` 标题与提纲**　重点看：是否给三套方案并推荐一套；标题和正文是否对得上；有没有重复的“关于”。

- “转发上级通知的标题，怎么写才不会出现好几个‘关于’？”
- “总结写好了，帮我提炼几个小标题，要对仗的。”
- “按这些素材搭一个提纲。”

**`gongwen-polish` 改稿润色**　重点看：有没有新增事实；数据有没有丢；领导批注是否逐条回应；有没有修改说明。

- “这份汇报 8000 字，压到 3000 字以内，数据别丢。”
- “领导在稿子上批了‘太虚’‘数据呢’，帮我按批注改。”
- “这是写给上级的报告，现在要改成发给下级的通知，改改口气。”

**`gongwen-humanize` 公文去 AI 味**　重点看：事实是否一字不动；“一是二是”这类正当写法有没有被误改；改完是不是反而更长。

- “这篇总结是 AI 写的，一股 AI 味，帮我改改，数字别动。”
- “先别改，把 AI 味重的地方标出来就行。”
- “稿子里全是‘不是……而是……’和破折号，帮我顺一顺。”

**`gongwen-direct` 去防御性写作**　重点看：部署类文件是否改成要求的口气；风险提示有没有被误删；请示是否有倾向性意见。

- “这个通知满篇‘建议各单位’‘可以考虑’，帮我改成要求的口气。”
- “稿子结尾挂着‘以上内容仅供参考’，帮我清掉。”
- “这个批复看不出同不同意，帮我改明确。”

**`gongwen-review` 核稿审校**　重点看：问题清单有没有分级、有没有依据；默认是不是只提意见不改；有没有漏掉你故意埋的错。

- “明天要送签，帮我把这个通知核一下。”
- “这份总结帮我把把关，先别改。”
- 第二轮：“P0 的直接改吧。”

核稿的测试稿，可以自己编一份，故意埋三五个错：发文字号写成“〔2026〕第12号”，日期写成“11月05日”，结尾带一句免责声明，某处数字前后不一致。看它找出几个。

### 交付工具

**`gongwen-format` 国标排版**　重点看：用 Word 或 WPS 打开成品，看字体、字号、页边距、页码、红头线，打印出来再看一遍；反馈时请写明系统、Word 或 WPS 的版本，以及电脑上有没有仿宋_GB2312、方正小标宋简体。没有 Python 时，它有没有给手动设置清单。

- “这个通知帮我套个红头，发文字号某发〔2026〕21 号。”
- “把这篇总结转成 Word，按公文格式排好。”
- “领导说这个 docx 格式不对，帮我按国标调一下。”

**`gongwen-data` 数据与图表**　重点看：算式有没有附上；口径不一致时是不是硬算；百分比和百分点分得清不清；缺的数有没有补。

- “30 个科室的月报都交上来了，帮我合并，算全院的同比环比。”
- “这张表的合计好像对不上，帮我查查。”
- “占比从 35% 涨到 38.2%，是提高了 3.2% 还是 3.2 个百分点？写成一句话。”

### 行业包

行业包请本行业的同事测。装了行业包以后，专用文书交给行业包，通用文书仍由核心 skill 处理。

**`gongwen-grassroots` 乡镇街道社区**　重点看：给群众看的文书，有没有出现不当的处罚、强制表述；居民通知是不是说人话；台账是否一致。

- “社区下周二停水，写个贴在单元门口的通知，再弄一条发业主群的。”
- “下周县里来检查安全生产，按检查表准备自查报告和汇报。”
- “镇里搞了个积分超市，写篇政务信息报县里。”

**`gongwen-hospital` 公立医院**　重点看：指标是否只用你给的并注明口径；患者信息有没有脱敏；缺的指标有没有补。

- “国考结果下来了，四级手术比例和 CMI 都掉了，写个分析给院长办公会。”
- “三季度医疗质量分析报告，质控科的数据表发你。”
- “上周有患者跌倒受伤，护理部要做根因分析，上报单在这。”

**`gongwen-university` 高校**　重点看：学校发文还是部门发文有没有判断对；申报书的匿名检查找得出你埋的暴露点吗；数据有没有编。

- “明年迎审核评估，学院版自评报告里‘教学成效’一章帮我起草，数据从状态数据里来。”
- “学科评估要填社会服务典型案例，帮我把这个案例整理成稿。”
- “申报书写完了，帮我查有没有暴露身份的地方，字数超没超。”

**`gongwen-k12` 中小学**　重点看：学生姓名是否脱敏；评语有没有排名、贬低；有没有替学生编事例；有没有给家长布置作业。

- “期末了，帮我给班上 42 个孩子写评语，每个孩子的情况我列在表里。”
- “下周开家长会，我是初二班主任，写个发言稿。”
- “区里来督导评估，学校要交自评报告，指标表发你。”

**`gongwen-soe` 国有企业**　重点看：前置研究程序有没有核对；议案和决议的票数是否前后一致；决策依据有没有编。

- “集团要给子公司增资，下周上党委会，帮我弄个三重一大的上会材料。”
- “董事会开完了，按会议记录出个决议，票数帮我核一下。”
- “总经理办公会的转写稿发你，出个纪要，再列个督办表。”

## 怎样脱敏

脱敏的意思是：别人看到你发出来的内容，认不出是哪个单位、哪个人、哪件事。

### 替换方法

| 要处理的信息 | 怎么换 | 例子 |
|---|---|---|
| 人名 | 改成“姓＋某”，同一个人前后用同一个称呼，不同的人用不同的姓 | 张某、李某、王某 |
| 单位名 | 改成“某＋类型”，上下级关系保留 | 某市某局、某区卫健局、某医院心内科、某学院 |
| 地名 | 只保留层级 | 某区、某镇、某社区 |
| 数字 | 换成量级相近但不同的数，不要只改末位 | 门诊量由 4.8 万人次改成 5.1 万人次 |
| 有关联的数字 | 先改基础数，再重新计算合计、占比、增长率，保持前后一致 | 基数改了，同比也要重新算 |
| 文号 | 机关代字换成虚构的，序号换成别的数 | 某局发〔2026〕17 号 |
| 日期 | 年份可以保留，具体日期整体平移几天 | 11 月 5 日改成 11 月 9 日 |
| 项目、活动、文件名称 | 改成泛称 | “某专项整治行动”“某省关于加强安全生产的通知” |
| 身份证号、手机号、病案号、学号、住址 | 整个删掉，换成【身份证号】这样的占位词。不要改几位数字充数 | 【手机号】 |
| 领导姓名和职务 | 保留职务类型，去掉姓名 | 分管副局长、院长 |
| 图片和截图 | 用涂黑遮挡，不要用马赛克；发之前放大检查 | |
| Word、Excel 文件 | 先另存一份，去掉作者、单位等文档属性，再清理页眉页脚 | |

### 一个例子

脱敏前（示意）：

> 市第一人民医院心内科主任李明华牵头，门诊量由 4.8 万人次增至 5.6 万人次，同比增长 16.7%。落实院办〔2026〕37 号文要求。

脱敏后：

> 某医院心内科主任李某牵头，门诊量由 5.1 万人次增至 5.9 万人次，同比增长 15.7%。落实某院发〔2026〕12 号文要求。

注意同比增长率是按新的两个数重算的，不是照抄原来的。

### 发出去之前自查

1. 把这段内容发给一个陌生人，他能认出是哪个单位、哪个人吗？
2. 有没有漏掉的人名、号码、地名？Word 文件的页眉页脚、批注、修订记录里有吗？
3. 截图的角落、文件名、浏览器标签页里有没有真实信息？
4. 拿不准的，就删掉，或者干脆换成你自己编的内容。

## 怎样反馈

三种方式，选方便的。

1. **有 GitHub 账号**：到 [Issues](https://github.com/duyunzhoudyz/gongwen-skills/issues/new/choose)，选“测试反馈”表单，一个问题填一份。第一项是确认不含涉密信息和真实个人信息，要先勾选才能提交。
2. **一次测了很多场景**：填 [测试记录表.csv](测试记录表.csv)，用 Excel 或 WPS 表格打开，一行一个问题，填写方法见 [测试记录填写说明.md](测试记录填写说明.md)。填完后发给交流群里的管理员，或在 Discussions 里新建帖子附上。
3. **只想聊聊感受**：到交流群里说，写清单位类型、文书类型、用的工具和模型、卡在哪一步，不要贴原文。

如果你发现的是规则本身写错了，比如某条标点、格式、文种规则和国标原文不一致，请改用“规则纠错”表单，并写明依据的文件名称和条款号。

**什么样的反馈最有用**：

- 说清你说了什么，它回了什么，你期望什么。
- 有脱敏后的摘录，能定位到哪一句出了问题。
- 写明是不是每次都出现。模型的输出有随机性，同一个说法多试一两次。
- 好用的地方也记一笔。表单和记录表里“问题类型”选“无”即可。

## 常见问题

**我没有 Python，能测吗？** 能。提示词版不需要 Python。排版功能没有 Python 时，会改为给出 WPS、Word 的手动设置清单，这也是要测的内容。

**我电脑上没有仿宋_GB2312、方正小标宋简体。** 项目不随附字体，请用单位授权的或自行合法获取。没有字体时它怎么提示你，也请记下来。

**测出来的问题是模型的问题，还是 skill 的问题？** 你不用判断，如实记下用的工具和模型。我们会对比不同模型的表现。

**我想测的场景不在清单里。** 太好了，直接测，按“新场景需求”表单告诉我们。

**我想对比装与不装 skill 的差别。** 可以。同一个说法、同一份材料，在两个新对话里各跑一次，一个粘贴提示词，一个不粘贴，把两份输出的差别记下来。想做更正式的盲评，见 [人工盲评说明.md](人工盲评说明.md)。想在其他模型上批量跑评测，见 [跨模型评测说明.md](跨模型评测说明.md)。
