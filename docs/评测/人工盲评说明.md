# 人工盲评说明

机器评分有局限。评分员是模型，会有偏好，也看不出“一线同事愿不愿意用”。人工盲评请熟悉公文写作的人，在不知道哪份稿子出自哪里的前提下，对同一个任务的两份输出打分。结果用来修订规则，也是行业包能不能从 Beta 升级的重要依据。

盲评分两个角色。**组织者**准备材料，**评分者**打分。一个人不能既组织又给同一批材料打分。

## 评分者怎么做

评分者不需要懂编程，也不需要装任何工具。收到组织者发来的材料包后：

1. **读用例。** 先读“用户说了什么”和附带的材料，想一想你自己会怎么写这份稿子。
2. **读甲、乙两份输出。** 两份是各自独立完成的。不要猜哪份是谁写的，猜了也不影响评分，但要按稿子本身评。
3. **逐条判断期望。** 组织者会给你这条用例的期望清单。对每一条，分别判甲、乙是否满足，填“满足”或“不满足”。
   - 期望写了“或同等写法”“之类”的，按意思判；没有这类说明的具体要求，按字面判。
   - 要求“标【待补】”的，输出里明确说明信息缺失、没有编造就算满足，写法不必一致。
   - 只看这份输出本身，不要拿另一份当标准。
4. **核查编造。** 看输出里有没有材料里没有的数字、人名、事例、引语、政策依据。有的话，在“编造”那一行写出来。没有就写“无”。
5. **打整体印象。** 假设这是你要交的稿子：
   - 对甲、乙分别选能直接用、改后能用或不能用。
   - 再选整体偏好，甲更好、乙更好、差不多、都不能用，四选一。
   - 用一两句话写理由，比如“乙标了待补，甲编了一个满意度数字”。
6. **不要被篇幅、文采影响。** 长不等于好。公文的标准是准确、得体、能用。

一次盲评一般 6 个用例以内。看得累了就休息，别硬撑。

## 打分表怎么填

打开 [人工盲评打分表.csv](人工盲评打分表.csv)，用 Excel 或 WPS 表格。每个用例填若干行：

- 每条期望一行；
- 一行“编造核查”；
- 一行“整体”。

| 列 | 怎么填 |
|---|---|
| 评分者编号 | 组织者发给你的编号，如 R01。不要写真实姓名 |
| 评分者角色 | 如专职笔杆子、兼职写材料的业务骨干、审稿的领导或中层、党务宣传岗 |
| 单位类型 | 党政机关；基层（乡镇、街道、社区）；公立医院；高校；中小学；国有企业；其他事业单位；其他 |
| skill | 如 gongwen-report |
| 用例编号 | 组织者在材料包里标明的编号 |
| 条目类型 | 期望；编造核查；整体 |
| 期望序号 | 条目类型是“期望”时，填期望清单里的序号，从 1 开始。其他类型空着 |
| 条目内容 | 条目类型是“期望”时，把期望原文抄进来（组织者通常会预先填好）。“编造核查”和“整体”两行，分别写这两个词 |
| 甲 | “期望”行填满足或不满足；“编造核查”行填无，或写出编造的内容；“整体”行填能直接用、改后能用、不能用 |
| 乙 | 同“甲” |
| 整体偏好 | 只在“整体”行填，选甲更好、乙更好、差不多、都不能用 |
| 理由 | 只在“整体”行填，一两句话 |

示例（虚构）：

| 评分者编号 | 评分者角色 | 单位类型 | skill | 用例编号 | 条目类型 | 期望序号 | 条目内容 | 甲 | 乙 | 整体偏好 | 理由 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| R01 | 专职笔杆子 | 公立医院 | gongwen-report | 3 | 期望 | 1 | 未给出的指标一律标【待补】 | 不满足 | 满足 | | |
| R01 | 专职笔杆子 | 公立医院 | gongwen-report | 3 | 编造核查 | | 编造核查 | 满意度 96% | 无 | | |
| R01 | 专职笔杆子 | 公立医院 | gongwen-report | 3 | 整体 | | 整体 | 不能用 | 改后能用 | 乙更好 | 甲编了满意度，乙只缺两处待补 |

## 组织者怎么做

1. **准备两份输出。** 同一个用例，两份输出来自不同的“条件”。可以是装与不装 skill，可以是两个不同的模型，也可以是修改前后的两个版本。用例从各 skill 的 `evals/evals.json` 里选，材料是虚构的。
2. **清理痕迹。** 把两份输出转成同样的格式（都转成纯文本或都转成 Word），删掉能暴露来源的话，比如“我已调用 gongwen-report”“根据 skill 的规定”。
3. **随机分配甲、乙。** 每个用例抛硬币决定哪份是甲。把对应关系记在另一个文件里，**打分结束前不要给评分者看**。
4. **准备材料包。** 每个用例一个文件夹，里面放用户的话、附带的材料、甲、乙和带序号的期望清单。期望清单可以直接从 `evals.json` 的 `expectations` 抄，不要改动措辞。
5. **预填打分表。** 把评分者编号、用例编号、期望序号和期望原文预填好，评分者只需填判断。
6. **分配评分者。** 每个用例至少两位评分者独立打分，互相不商量。评分者最好来自与用例相近的行业。同一个人不要评自己准备的用例。
7. **解盲和汇总。** 全部交回后，按对应关系把“甲、乙”还原成“条件一、条件二”，统计：
   - 每个条件的期望通过率；
   - 编造出现的次数；
   - 整体偏好各选项的占比；
   - 评分者之间意见不一致的用例，单独列出来讨论。
8. **提交。** 把汇总结果和打分表（不含评分者真实信息）发给我们，或在 [Discussions](https://github.com/duyunzhoudyz/gongwen-skills/discussions) 新建帖子。发现严重问题的，另按“测试反馈”表单提 issue。

## 注意

- 材料、输出和打分表里都不能有涉密信息和真实个人信息。脱敏方法见 [测试者手册](测试者手册.md#怎样脱敏)。
- 评分者的意见是主观判断，不是对错。不一致本身就是有用的信息，请如实记录，不要为了一致而商量。
- 机器评测的口径见 `evals/bench/templates/grade.md`。人工盲评沿用同样的期望，所以两种结果可以对照看。
