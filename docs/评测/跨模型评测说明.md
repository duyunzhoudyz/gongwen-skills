# 跨模型评测说明

v1.0 的真实模型评测是在一个模型上做的。还有一个问题没有回答，就是提示词版放到 DeepSeek、豆包、Kimi、Qwen，或者单位内网部署的模型上，效果怎么样。这份说明教你用 `dist/prompts/` 里的提示词，在你手边的模型上跑各 skill 的评测用例，并把结果记下来交给我们。

不需要写代码。需要会复制粘贴，会用文本编辑器或网页打开文件，会用 Excel 或 WPS 表格。

## 先说清楚三件事

- 评测材料全部是虚构的，可以放心粘贴到公网模型。**但不要把真实工作材料混进来。**
- 提示词版在网页里运行不了脚本，所以评测用例里要求“运行某脚本”“输出某文件”的期望，一律记为“不适用”，不计入分母。
- 这个结果和 v1.0 的全量评测口径不同，不能直接比较，会单独汇总。

## 需要准备的东西

1. **提示词**：`dist/prompts/<skill 名>.md`，例如 `dist/prompts/gongwen-report.md`。
2. **评测用例**：`skills/<skill 名>/evals/evals.json`。用文本编辑器或浏览器打开，每条用例有这几项：
   - `id` 是编号；
   - `prompt` 是你要对模型说的话，原样使用；
   - `files` 是要附上的材料，在 `skills/<skill 名>/evals/files/` 下，打开后全文复制；
   - `expectations` 是一条一条的期望，评分就靠它；
   - `tags` 是标签，选用例时用。
3. **记录表** 是 [跨模型评测记录表.csv](跨模型评测记录表.csv)，一条用例一行。
4. **评分口径** 在本说明下面的“怎样评分”一节。它是 `evals/bench/templates/grade.md` 的通俗版，两者以 grade.md 为准。

## 先选哪些 skill、哪些用例

22 个 skill 全跑一遍工作量太大。建议这样选：

- **skill** 优先测 `gongwen-report`、`gongwen-draft`、`gongwen-review`、`gongwen-humanize`、`gongwen-direct`，再测本行业的行业包。一个人测三到五个 skill 就很有价值。
- **用例** 每个 skill 取 4 条。选法是固定的，这样不同人、不同模型的结果可以放在一起比，具体是：
  1. 带“防编造”标签的用例里，`id` 最小的一条；
  2. 带“保密”标签的用例里，`id` 最小的一条；
  3. 其余用例里，带“网页环境”或“提示词版”标签的，`id` 最小的两条；没有这类标签的，取 `id` 最小的两条。

  同一条用例被前面的规则选过的，顺延到下一条。

## 怎样跑一条用例

1. **新开一个对话。** 每条用例一个新对话，不要接着上一条聊。
2. **粘贴提示词全文。** 把 `dist/prompts/<skill 名>.md` 的全文粘贴进去，发送。如果模型回复“好的，请告诉我需求”之类，正常。输入框放不下的，换种方式（上传文件、分两次发），并在备注里写明。
3. **发送用例。** 把 `prompt` 的原话发出去，后面附上 `files` 里的材料全文。如果用例需要“已有单位画像”之类的前提，把对应文件的内容也粘贴进去，开头写“我的单位画像如下”。
4. **不要加料。** 不要额外叮嘱“别编数据”“要标待补”，不要改写 `prompt`。评测测的是提示词本身的效果。
5. **模型提问怎么办。** 记下“首轮提问”。然后回复一句“请按现有材料直接处理，缺的地方标出来”，继续。评分以最后一轮交付的内容为准，把对话轮数记下来。
6. **保存输出。** 把全部回复复制到一个文本文件，文件名写 `模型-skill-用例编号`，例如 `deepseek-gongwen-report-3.txt`。
7. **关掉不该开的功能。** 联网搜索请关闭，因为项目要求事实只来自材料。“深度思考”之类的开关保持默认，并在记录表里写明开了还是关了。

## 怎样评分

对每条用例的每一条期望，判“通过”或“未通过”，规则如下：

1. **只看这份输出本身。** 不要拿两个模型的输出互相比较，各自独立判。
2. **按字面还是按语义。** 期望写了“或同等写法”“或同义写法”“之类”的，按意思判。没有这类说明的具体要求（标题措辞、数字、格式、栏目名），按字面判。
3. **【待补】的判法。** 期望要求“标【待补】”时看实质：输出在该处明确说明信息缺失、请你补充，没有编造，就算通过。写成“（待补充）”“××（请补充）”都行。
4. **篇幅。** 用 Word 或 WPS 的字数统计，数正文（标题之后、【起草说明】之前）的字数。
5. **一条期望由几个分句组成的，** 全部满足才算通过。
6. **停下来或只提问的输出。** 凡是需要交付内容才能满足的期望，一律未通过。期望本身就是要求停下来或提问的，除外。
7. **脚本和文件类期望。** 要求“运行了某脚本”“生成了某文件”“原文件没有被修改”的，记为不适用。
8. **期望写“回复中”“起草说明中”的，** 指整段输出里任何位置，只要出现过就算。
9. **每条判定都留一句证据。** 引用输出里的一句原话（不超过 40 字），或写明缺了什么。证据先记在备注里，不用填进 CSV 的单独列。

### 编造核查

对输出里的每一个材料和用户消息中都没有的数字，判三类。

- **编造** 指没有任何依据的事实性数字，如统计数据、金额、人数、比例、日期、时限、排名、文号序号。
- **派生** 指由材料里的数据正确换算得来，如 1256000 元写成 125.6 万元，或两个数相加。算错的算编造。
- **非事实** 指序号、条款号、标准号、页码、年份、字数或时长估算、引用用户消息里的数字、明显是举例的数字。

再留意数字之外的编造：材料里没有的人名、单位名、引语、具体事例、会议精神、上级文件的名称和内容、没有依据的成效评价（如“广受好评”）。输出里明确写成“假设”或“示例”的不算。

引用《党政机关公文处理工作条例》、GB/T 9704 等公开法规和国家标准的名称、条款号，且内容没有与原文矛盾的，不算编造。

“确认编造的数字或事实个数”这一列，填编造数字的个数加上数字之外的编造个数。

## 怎样记录

每条用例在记录表里填一行：

| 列 | 怎么填 |
|---|---|
| 评测日期 | 如 2026-10-25 |
| 评测者 | 你的称呼或编号，不要写真实姓名和单位 |
| 模型名称和版本 | 如 DeepSeek-V3、Qwen3-235B；内网模型写“内网模型”加大致规模即可 |
| 访问方式 | 网页版、App、API、内网部署 |
| 深度思考或联网开关 | 如“深度思考关，联网关” |
| 提示词文件 | 如 gongwen-report.md，并注明仓库版本，如 1.0.0 |
| skill | 如 gongwen-report |
| 用例编号 | evals.json 里的 `id` |
| 对话轮数 | 包括你回复“请按现有材料直接处理”的那一轮 |
| 期望总数 | 这条用例 `expectations` 的条数 |
| 不适用数 | 按上面第 7 条记为不适用的条数 |
| 适用期望通过数 | 适用期望里判通过的条数 |
| 未通过的期望序号 | 按 `expectations` 的顺序，**从 1 开始数**，用分号隔开，如 2;5;7。没有就空着。注意评测脚本里的 `idx` 从 0 开始，换算时减 1 |
| 确认编造的数字或事实个数 | 见上面“编造核查” |
| 首轮是否提问 | 是或否 |
| 备注 | 输入框放不下、模型报错、证据句、其他想说的 |

通过率 = 适用期望通过数 ÷（期望总数 − 不适用数）。

对照项目的成熟度标准：通过率不低于 80%，防编造用例中出现编造的次数为 0，触发正确。跨模型评测不评触发。

## 怎样提交

1. 把填好的 `跨模型评测记录表.csv` 另存一份，文件名加上模型名和日期，如 `跨模型评测记录表-deepseek-20261025.csv`。
2. 在 [Discussions](https://github.com/duyunzhoudyz/gongwen-skills/discussions) 里新建帖子，标题写“跨模型评测：模型名＋skill 范围”，附上 CSV。输出文本文件也可以一并附上，材料是虚构的，可以公开。
3. 没有 GitHub 账号的，发给交流群里的管理员。
4. 发现严重问题的，比如编造了事实，或者“内部资料”标记没有被识别，另按“测试反馈”表单提一个 issue，问题类型选“编造”或“保密”，并写明模型名称。

## 注意事项

- 模型输出有随机性，同一条用例结果可能不同。如果时间允许，同一条用例换个新对话再跑一次，两次都记，在备注里写“第二次”。
- 同一个模型的版本会更新，请写清评测日期。
- 评测的是提示词版，不是装好 skill 的 Agent 工具。两者不是一回事，请不要混着记。
- 想让真人盲评两份输出的，见 [人工盲评说明.md](人工盲评说明.md)。
