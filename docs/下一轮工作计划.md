### 5.1 gongwen-profile　单位画像与文风学习

- **定位**：建立和维护 `.gongwen/` 下的四个文件：单位画像.md、领导偏好卡.md、禁用词.md、文风参数.md。总入口只做"3 问简版建档"，完整建档和学习交给本 skill。
- **功能**：
  1. **完整建档**：
     - 分轮问卷，每轮不超过 3 问；或者从用户提供的本单位公文处理办法、历史文件中提取字段，填入 profile-template.md 的完整版。
     - 更新画像时只改相关条目，先征得同意。
  2. **文风学习**：
     - 读 3–10 篇本单位历史稿（txt/docx，已脱敏），用 `style_profile.py` 计算客观参数：平均句长、段长、各级标题数量与句式、"一是……"使用率、顿号/破折号/冒号密度、高频四字格和套语、篇幅分布。
     - 模型再补充定性观察，写入 文风参数.md。
     - 只记参数和表述习惯，不保存原文段落。
  3. **花脸稿学习**：
     - 输入原稿和领导改稿两份文件，或一份带修订痕迹的 docx。
     - 用 `draft_diff.py` 按句对齐，抽取删除、新增、替换。
     - 归纳成偏好条目（如"删形容词""数据前置""不用'着力'"），每条附例证和出现次数，追加到 领导偏好卡.md，注明来源日期。与已有条目冲突时询问用户。
  4. **禁用词管理**：增删禁用和慎用表述。
  5. **画像体检**：字段是否完整；与单位类型默认值有何差异；提示可能过期的信息。
- **红线**：
  - 历史稿先脱敏；
  - 画像不存个人姓名、电话，只存角色；
  - 偏好卡只记写作偏好，不记对领导个人的评价。
- **脚本**：`scripts/style_profile.py`、`scripts/draft_diff.py`（支持读取 docx 修订痕迹 w:ins/w:del），测试放在 `tests/profile/`。
- **评测重点**：从制度文件提取画像；文风学习；花脸稿（两份稿件、修订痕迹 docx）；历史稿含人名电话；偏好冲突；更新时不覆盖原有内容；网页版输出画像文本。

### 5.2 gongwen-draft　法定公文

- **定位**：15 种法定文种加签报的起草与改写，承接 v0.1 总入口的过渡起草能力并深化。
- **覆盖**：
  - 通知：会议通知、转发通知、印发通知、部署性通知；
  - 通报：表彰、批评、情况通报；
  - 请示：一文一事，必须有倾向性意见；
  - 报告：就一件事的情况报告、答复上级询问；
  - 批复：明确表态；
  - 函：商洽、询问、请求批准、答复；
  - 意见、决定、通告、公告，以及签报。
- **分级**：
  - P0：通知、请示、报告、函、通报、批复、意见、签报；
  - P1：决定、通告、公告；
  - P2：决议、命令、公报、议案（只给结构说明）。
- **流程**：
  1. 文种决策（决策表 + 易混辨析）；
  2. 行文规则检查（《条例》第十三至十七条）；
  3. 按文种结构起草；
  4. 自检（机检中的请示、报告结构检查已有）。
- **不负责**：纪要交 minutes；年度或专项的全面工作报告交 report；需要拆解任务的贯彻落实方案交 implement；整改报告交 rectify；讲话交 speech。
- **references**：
  - `doc-types/` 下每个文种一份：结构、惯用语、正误对照、单位差异；
  - 行文规则检查表；
  - 单位发文体系差异：签报、校级与部门两级发文、党政两套代字。
- **评测重点**：函与请示；报告夹带请示；多头主送；越级行文；转发标题叠用；会议通知要素；表彰通报；批复态度不明；签报（医院、国企）；高校两级发文（装有行业包时由行业包承接，见第七节）；面向群众的通告中的法律表述。

### 5.3 gongwen-speech　讲话类

- **覆盖**：
  - 领导讲话：动员部署、推进会、总结表彰、座谈会、年度工作会、开学或毕业典礼；
  - 主持词；
  - 致辞：欢迎、开幕、闭幕；
  - 表态发言、交流发言。
- **输入**：场合、讲话人身份、时长（默认按约 200 字/分钟换算，画像中可以调整）、听众、会议议程（前后有谁讲话、主报告内容，避免重复）、领导偏好卡。
- **流程**：任务卡 → 结构与要点 → 成稿 → 时长校核 → 自检。
  - 结构可选：肯定成绩、分析形势、部署任务；"讲三点意见"式；致辞式。
  - 成稿要求口语化：短句、称谓、过渡语、前后呼应。
- **要求**：
  - 区分"念的稿"和"讲的稿"；
  - 主持词与各讲话环节衔接；
  - 表态发言的承诺要具体，不超出权限；
  - 不编金句，不编引文；领导人讲话只引用用户提供的原文；
  - 主要负责同志讲话不超过 1 小时（减负规定第 6 条）。
- **不负责**：大会工作报告（如职代会、教代会工作报告）交 report；党课交 party。
- **评测重点**：动员会讲话（时长换算）；开学典礼（面向学生）；主持词衔接；表态发言不空泛；缺引文原文时标【待核实】；领导偏好卡生效。

### 5.4 gongwen-party　党建与组织生活材料

- **覆盖**：
  - 民主生活会、组织生活会对照检查材料（个人、班子）；
  - 党建工作报告、书记抓基层党建述职；
  - 党课讲稿、主题党日方案、谈心谈话提纲；
  - 学习研讨发言提纲与心得体会；
  - 党支部工作计划和总结；
  - "三会一课"记录整理（只整理，不编造）。
- **最严格的红线**：
  - 对照检查、心得体会、研讨发言必须基于本人的真实事例和认识。缺少时只出提纲和填写指引，不生成完整正文。
  - 提法必须对照用户提供的会议通知、学习材料原文。不内置"最新提法库"，不自行更新提法；缺原文的标【待核实】。
  - 查摆问题要具体，整改措施要可检验（有时限、有标准）。用户提供征求意见清单时，要逐条回应。
  - 雷同提醒：用户提供往年或他人的材料时，用 `overlap_check.py` 检测重合段落。
  - 所有党建材料一律叠加严谨模式。
- **定位**：做结构与素材的组织助手，对外不宣传"代写"。
- **不负责**：非党课的讲话交 speech；国企"党建与经营融合"经验材料交 soe 行业包。
- **评测重点**：没有个人事例时只出提纲；有事例时出完整对照检查；缺提法原文；雷同检测；班子材料与个人材料的区别；党课讲稿的引文处理；谈心谈话只给提纲、不代写记录。

### 5.5 gongwen-polish　改稿润色

- **功能**：
  1. **压缩**：按目标字数或减负规定的上限压缩。删除顺序：铺垫 → 复述 → 空泛表态 → 重复举例；事实和措施保留。
  2. **扩写**：只展开用户提供的事实，不凑字数。
  3. **调语气**：上行、平行、下行之间互转（措辞对照表）。
  4. **转译**：把业务语言改成公文语言。
  5. **口语化或书面化**。
  6. **按领导批注改稿**：逐条落实，输出"批注落实对照表"；建议用 profile 更新领导偏好卡。
  7. **多稿合并**：取长补短，冲突处列出，由用户决定。
- **规则**：不新增事实，用 fact_diff 校验；输出修改说明，教学模式下逐处解释原因。
- **不负责**：AI 腔交 humanize；防御性表述交 direct；全面核稿交 review；需要重写结构的交回原起草 skill；标题交 title。
- **评测重点**：8000 字压到 3000 字；上行文改为下行文；大白话改成公文；落实"太虚""数据呢"等批注；两稿合并；扩写时不编数据。

### 5.6 gongwen-implement　上级文件转化

- **流程**：
  1. 上级来文 → 提取要点（任务、时限、责任要求、报送要求）；
  2. 生成任务分解表：任务 / 牵头单位 / 配合单位 / 时限 / 成果形式 / 对应上级条款；
  3. 起草本单位实施方案或贯彻落实方案；
  4. 后续起草贯彻落实情况报告，按任务表逐项报进展；
  5. 学习贯彻材料，即会议传达要点。
- **关键要求**：
  - **逐条对应**：任务表与上级文件逐条对应，不漏项（对标对表）。
  - **照抄检测**：用 `overlap_check.py` 比对上级文件，重合超过阈值的段落提示改写为本地措施（减负规定不得照搬照抄）。
  - **本地措施只来自用户**，缺少的标【待补】。
  - **时限**：本单位时限早于上级时限。
  - **不层层加码**：不擅自提高标准，不要求基层重复报送。
- **脚本**：
  - `shared/scripts/overlap_check.py`：由本 skill 负责实现，接口见开发规范 8.3；
  - `shared/scripts/md2xlsx.py`：由 rectify 负责实现，本 skill 用它把任务分解表转成 Excel。
- **不负责**：只转发、不拆解任务的交 draft；不以上级文件为依据、自主制定的方案交 report。
- **评测重点**：省级专项行动通知转为区级实施方案；漏项检测；照抄检测；时限倒排；落实情况报告与任务表一致；加码风险提示。

### 5.7 gongwen-rectify　整改材料

- **覆盖**：巡视巡察、审计、督查、考核反馈问题的整改方案、整改台账、整改进展报告（月报或阶段报告）、整改情况报告，以及按检查清单逐项开展的自查报告。
- **整改方案**：按问题、任务、责任"三清单"编写。每条包含：问题表现（保持反馈原文，不弱化）、原因、措施、责任领导、责任部门、时限、成效标准。
- **状态口径**：已完成、立行立改、持续推进、长期坚持，每种状态的认定标准写入 references。
- **红线**：
  - 报告中的整改状态必须与台账一致，用 `rectify_check.py` 对账；
  - 未完成的不得写成已完成；
  - 不编造整改成效数字。
- **脚本**：
  - `shared/scripts/md2xlsx.py`：由本 skill 负责，接口见开发规范 8.4；
  - `scripts/rectify_check.py`：读取台账（md 或 xlsx）和报告，逐条比对编号与状态，报出不一致。
- **评测重点**：巡察反馈 12 个问题；审计整改；台账与报告状态不一致；缺措施时标【待补】；纠正弱化问题表述的写法；医院、高校、国企的差异。

### 5.8 gongwen-minutes　会议纪要与议题材料

- **覆盖**：
  - **会议记录整理**：记全过程，按发言顺序。
  - **会议纪要**：只记议定事项。分清"会议指出、会议强调、会议要求、会议议定"的用法；参会人员的写法。发文时用 format 的纪要版式。
  - **上会议题材料**：议题名称、汇报单位、背景、两个以上方案的比较、需要决策的事项、前置程序说明、附件。
  - **督办清单**：议定事项、责任单位、时限，用 md2xlsx 转成 Excel。
- **规则**：
  - 只整理，不添加；发言归属准确；口语转书面时不改原意；
  - "原则同意""同意""暂缓"要区分；
  - "三重一大"事项须集体决策，国企、医院、高校按党委前置程序办理；
  - 不处理音频，转写文字由用户提供。
- **不负责**：会议通知交 draft；会上讲话交 speech。
- **评测重点**：从转写文字出纪要；纪要与记录的区分；议定事项的责任和时限；议题材料的方案比较；督办清单；跳过前置程序的风险提示。

### 5.9 gongwen-brief　信息简报与宣传

- **覆盖**：
  - 政务信息：动态类、经验类、问题建议类；
  - 工作简报，按期号格式；
  - 新闻稿：倒金字塔结构，要素齐全；
  - 单位官方公众号推文：不写成自媒体腔；
  - 从长材料中提炼经验做法信息。
- **要求**：
  - 标题点睛：可用主副标题，可以用数字概括，但数目必须与实际条数一致；
  - 开头即结论，数据要实；
  - 篇幅：信息一般 500–800 字，以画像为准；
  - 选题角度提示：新、特、实；
  - 群众和领导的原话只能来自用户提供的材料；
  - 对外发布的材料叠加严谨模式，并提醒图片授权和敏感信息。
- **不负责**：长篇经验材料交 report。
- **评测重点**：活动转政务信息；3000 字压成 800 字信息；新闻稿要素；公众号推文语体；缺引语不编造。

### 5.10 gongwen-data　数据整理与图表

- **功能**：
  1. **报表体检**：空值、合并单元格、合计行校验、单位不一致、口径或时段不一致。
  2. **多表合并**：汇总下级报表。
  3. **指标计算**：同比、环比、增减量、增速、百分点、占比、拉动、完成率、平均值。
  4. **数据转文字**：生成可直接写进公文的句子，遵守数据表述规范。
  5. **公文图表**：用 openpyxl 生成 Excel 原生图表；装有 matplotlib 时可另出 PNG。以黑白灰为主色，标注单位和数据来源。
- **脚本**：
  - `scripts/data_tool.py`：子命令 inspect、merge、calc、phrase，支持 csv 和 xlsx，输出 JSON；
  - `scripts/chart_tool.py`；
  - 测试放在 `tests/data/`。
- **共享资料**：`shared/rules/data-expression.md`，由本 skill 负责。内容包括：同比、环比、百分点、增速、倍数、约数、占比、"翻一番"、负增长的表述；小数位和千分位；单位换算；与 GB/T 15835 的衔接；常见错误的正误对照。
- **红线**：
  - 数据不出本机，不调用任何外部服务；
  - 输出计算公式，便于复核；
  - 不补造缺失数据；
  - 口径冲突不悄悄合并。
- **评测重点**：30 个科室的月报合并；同比与环比；百分点与百分比的区分；合计校验失败；口径冲突；生成数据段落；生成图表。

### 5.11–5.15　行业包（共同规格）

**结构**：每个行业包是一个独立 skill，名为 `gongwen-<包名>`，自带行业路由。

**SKILL.md 包括**：
- 适用范围：本行业专用文书清单，以及哪些情况转交核心 skill；
- 开工检查：读取单位画像，套用行业画像；
- 专用文书路由表：每类文书对应本包模板，并说明借用哪个核心 skill 的流程；
- 行业红线；
- 行业核稿附加检查；
- 角色适配。

**references 包括**：
- `profile-detail.md`：行业画像详版；
- `templates/`：每类专用文书一份，写明用途、结构、写法、数据项、常见毛病、正误对照；
- `glossary.md`：术语表；
- `redlines.md`：红线；
- `calendar.md`：行业写作日历；
- `review-addon.md`：行业核稿附加清单。

**与核心 skill 的分工**：
- 本行业的通用文书（总结、通知、讲话）由核心 skill 处理，并读取单位画像；
- 本行业的专用文书（如等级评审自评报告）由行业包处理；
- 行业包在 Agent 环境下复用核心 skill 的流程（素材台账、机检、排版）；在网页提示词版中，把精简后的核心流程写进自己的提示词。

**准确性**：行业制度、指标、术语必须上网核实，写明出处和年份。核实不了的不写，或改为"以当年文件为准"。

**评测**：至少 12 条用例；trigger 用例的反例取同行业的通用文书（应交核心 skill）。
