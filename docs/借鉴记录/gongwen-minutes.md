## 三、自研内容

以下设计在调研的项目中没有找到对应实现，为本模块自研：

1. 议定事项梳理表的固定七列和"已明确、待补、待核实"三种状态，"定了没有"的判定规则，主持人口语与结论类型对照表（`references/decisions.md`）。
2. 督办清单的抽取规则、五种办理状态的认定和"不升级"原则（`references/supervision-list.md`）。
3. 议题材料只有一个方案时的处理、按七类单位的前置程序核对表和程序风险提示写法（`references/agenda-material.md`）。
4. `scripts/minutes_check.py`：议定事项识别（同一段中同意与暂缓、不同意、另行研究分开判定，暂缓事项下的准备任务单列）、责任单位和时限检查、督办清单逐条对账与草表生成（按子句把责任单位与时限配对，牵头与配合对调、时限挂到同一条中其他单位的任务上都报不一致；任职、审议通过、维持现状等无需落实的结论不报缺项）；测试采用 gongwen-kit 的"必错标本、必过标本"方法（该方法已在 `docs/借鉴记录/gongwen-review.md` 登记）。
5. 用 `fact_diff.py --ledger` 以原始记录作台账，核对纪要中的数字、日期是否都来自记录。

## 四、有意没有采用的内容

1. zhaohui-yang 规格中"信息允许时完整展开结构，不要压缩成简要摘要"和"认为、决定段落先概括三到五句再分点、每点五到七句"的篇幅要求：与本项目"默认做减法"冲突，且容易诱导模型补写记录中没有的内容，不采用。
2. zhaohui-yang 规格中版记默认保留"主送、抄送、审核"字段：属于该项目自定的模板，GB/T 9704-2012 10.3 没有此要求，本模块只按用户给的发送范围写。
3. gongyu0918 的会议抄告单（`meeting-copy-slip.md`）：属于部分地方的专门文种，使用面窄，本模块不单列，用户需要时按纪要的议定事项改写。
4. 检索到的面向英文场景的会议记录 skill（只按"决议、行动项、负责人、截止日期"组织）：没有区分同意、原则同意、暂缓，也没有前置程序，不适合公文语境，未采用。
