# 公文去 AI 味（gongwen-humanize）

AI 起草的公文常带一套固定腔调：段首先下评论，爱用“不是……而是……”翻案，破折号和冒号制造停顿，“赋能”“闭环”扎堆，成效只有“显著提升”没有数据。本 skill 逐类找出这些写法并改掉，同时保留公文的正当写法和全部事实，输出改后正文和按类别统计的修改说明。定位是文风改进：不判断稿件是不是 AI 写的，也不承诺任何 AI 检测结果。

## 适用范围

- 适用：
  - AI 起草或 AI 润色过、读着“一股 AI 味”的公文和材料；
  - 句式、词汇、标点、结构四个层面的 AI 腔（分类见 `references/_shared/style/ai-tone.md` 第一部分）；
  - 三种模式：全文改写（默认）、只标注不改、轻度改写。
- 不适用（转交）：
  - 对冲语气（可能、在一定程度上）、平衡腔、“建议”“可以考虑”式部署、模糊主体、请示批复态度不明：转 gongwen-direct。正文里的免责声明（如“以上内容仅供参考”）、AI 自述和对话引导语例外，按红线三直接删除，在修改说明中注明；
  - 格式、标点和数字用法错误（GB/T 15834、GB/T 15835）、提法核查、全面核稿：转 gongwen-review；
  - 压缩、扩写、调语气：转 gongwen-polish；起草新稿、补写内容：转对应起草 skill（gongwen-report、gongwen-draft、gongwen-speech、gongwen-brief 等）；
  - 重拟标题和小标题转 gongwen-title；排版成 docx 转 gongwen-format。
- 转交方式：能调用其他 skill 的环境直接调用；目标 skill 未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交：给交接卡、“新开对话粘贴 `dist/prompts/<skill>.md` 继续”的说明和安装命令。
- 行业包起草的专用文书（如医院等级评审自评报告），去 AI 味同样归本 skill；要补写、重写内容的交对应行业包，未安装行业包的交对应起草 skill。
- 一稿同时有 AI 腔和防御腔：本 skill 只改 AI 腔，免责声明以外的防御性表述原样保留，列入起草说明的“转交事项”，建议接着用 gongwen-direct。

### 用户要求“降 AI 率”“躲过 AI 检测”时

先说明，再照常处理。参考说法：“这个 skill 做的是文风改进，去掉 AI 腔，让材料读起来像熟手写的公文。各类 AI 检测工具的算法不公开、结果也不稳定，这里不对任何检测结果作承诺。下面按文风改进来改。”

然后按正常流程改写，并遵守：
1. 不用对抗检测的手法：故意写错别字、乱换同义词、打乱语序、插入无关内容。
2. 不估算、不报告“AI 率”。
3. 稿件是述职报告、对照检查材料、心得体会等需要本人真实经历的材料时，提醒用户：具体事例必须由本人补写（`references/_shared/guardrails.md` 第六条），改稿中缺事例的地方标【待补：本人具体事例】。

## 开工检查

1. 保密（红线一，`references/_shared/guardrails.md` 第一条）：
   - 首次收到稿件时，在回复开头附第一条第1款的保密提示，同一会话只说一次。
   - 稿件有密级标识（“秘密★”等），或标注“内部资料”“工作秘密”“不得外传”“内部使用”：立即停止，不改写、不复述原文，按第一条第2款告知用户。正文中正常出现“保密工作”之类的词语不算。
   - 稿件有身份证号、手机号、病案号、住院号、学号、银行卡号、家庭住址、患者或学生真实姓名：提醒用户脱敏；改稿中改用“张某”“138****0000”之类的替代写法。这是本 skill 唯一允许改动的事实，逐条写进起草说明“保密提示”。
2. 单位画像：先读工作目录的 `.gongwen/单位画像.md`，没有再找用户目录 `~/.gongwen/单位画像.md`；同目录有 `禁用词.md`、`文风参数.md` 的一并读取。没有画像时不追问，按 `references/_shared/profiles/roles.md` 第九节“无画像降级”从稿件判断单位类型和角色模式，判断不出的按党政机关、教学模式处理，写进“所作假设”。
3. 文书类型：从标题、文种、落款判断，使用统一词表名称（讲话稿、信息、总结、汇报材料、实施方案、通知、请示……），判断不出用“其他”。文书类型决定白名单和阈值，见 `references/doc-type-notes.md`。
4. 模式：

   | 模式 | 识别信号 | 做法 |
   |---|---|---|
   | 全文改写（默认） | “去 AI 味”“改自然点”“改得像人写的” | 处理全部类别 |
   | 只标注不改 | “先别改”“标出来就行”“看看哪里有 AI 味”；审稿模式默认 | 只出问题清单 |
   | 轻度改写 | “稍微改改”“别大动”“轻度处理一下” | 只处理 P1 和残留 |

5. 留底：Agent 环境下，用户贴的是文字时，先把原文原样存为 `公文/<YYYYMMDD>-<简短标题>/原稿.txt`，供复检比对；用户给的是文件时，直接以该文件为原稿，不改动它，输出仍写入 `公文/<YYYYMMDD>-<简短标题>/`。
6. 提问：稿件本身已经提供文种和内容，一般不提问，首轮直接交付。确需确认的（如分不清是讲话稿还是汇报材料），先按最可能的类型改，写进所作假设，问题放在回复末尾，最多 3 个，不阻塞改稿（`references/_shared/profiles/roles.md` 第十节）；用户说“直接改”时不问。
7. 交接卡：用户贴了交接卡的（网页或 Agent 环境），按卡上的单位画像、当前模式、任务和已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 工作流程

### 第一步　冻结事实

动笔前通读全文，列一份事实清单（供自己对照，不必输出）：
1. 数字、日期（“周五”“月底”等相对时间照原话，不推算成具体日期）、金额、百分数、发文字号、书名号和引号内的内容；
2. 人名、职务、单位名、责任分工、完成时限；
3. 义务强度词（必须、应当、要、可以、原则上、力争），条件和适用范围；
4. 政治性提法、上级文件原文、领导讲话原话；
5. 【待补】【待核实】标记。

改写全程对照这份清单，清单上的内容不改。

### 第二步　诊断

1. 有 Python 时运行：
   `python scripts/gongwen_lint.py <原稿> --doc-type <文书类型> --checks style,residue --json`
   有 `.gongwen/禁用词.md` 的，加 `--banned .gongwen/禁用词.md`。读取 issues 中的 id、level、line、excerpt。规则号 AI-xxx 对应 ai-tone.md 各类标题后括号中的编号，RES 开头的残留规则按 `references/rewrite-guide.md`（十四）处理。脚本报错或没有输出时，转人工诊断。
2. 没有 Python 或机检未执行时，按 `references/_shared/style/ai-tone.md` 第一部分的十三类和 `references/rewrite-guide.md` 补充的（十四）至（十六）类，逐段人工排查。
3. 每个命中项先查白名单（ai-tone.md 第二部分）和 `references/doc-type-notes.md`，属于正当写法的划掉。四字格、“一是……二是……”“坚持……坚持……”一律不动。
4. 密度类问题以人工判断为准。500 字以下的短稿，出现一次的“助力”或破折号不必改，不机械照搬机检结果。
5. 风险提示中的“可能”、问题查摆中的“一定程度上存在”不算问题；各类对冲表述不归本 skill，记入转交事项（免责声明、AI 自述例外，见“适用范围”）。

诊断结果按“类别、位置（第几部分第几段）、原文片段、级别”记录。出现一次就要改的类别记 P1（如段首评论语、翻案句、互联网黑话、元话术、残留），过密才改或需要判断的记 P2（如新八股词密度、套话堆砌、概括代替数据、相邻句雷同）。机检给出的级别优先。

### 第三步　分类改写

按 `references/rewrite-guide.md` 第二部分的顺序（删、拆并、换、标点、通读）逐类改写：

1. 只改命中的句子，其余逐字保留。
2. 不动：第一步清单上的全部内容；白名单写法；层次序号；行业术语（见 `references/unit-notes.md`）。
3. 缺数据不编，不添原稿没有的做法：概括代替数据又找不到数据的，总结、汇报、述职的成效部分改成“原稿已有的做法＋【待补：数据】”，原稿没有做法的只留【待补：具体做法和数据】；其他文种删去空泛评价，信息稿评价句前面没有已落实的事实、数据时一律删（前文是【待补】占位不算支撑），拿不准的非信息稿保留原句。改后的做法、功能、范围、成效都要能在原稿找到出处，比喻和口号不能推出新动作（“管家”不等于“全天候受理诉求”）。用户要求“加点数据和例子”时，说明数据和事例要由用户提供，正文只标【待补】。
4. 只做减法：改后篇幅不超过原稿，不为衔接补写铺垫、背景和意义（红线四）。用户另给了字数目标的（【待补】不计入字数），改后不在目标 ±10% 内时，在回复第一段说明差距，压缩或扩写建议接着用 gongwen-polish，本 skill 不注水、不删事实。
5. 提法、引语中带 AI 腔的，不改，记入起草说明“保留未改”。用户材料中加引号的做法名称、本单位提法同样原样保留，不当作强调引号去掉；确需改写的，原句不动，改法写进“附：提法核对清单”请用户确认（`references/_shared/guardrails.md` 第二条第8款）。
6. 改后读起来不比原句好的，恢复原句。

轻度改写只处理 P1 和残留。只标注不改跳过本步，直接输出问题清单。

### 第四步　复检

1. 再跑一次机检（命令同第二步，文件换成改稿），确认 P1 已清零，或每条都有保留理由。
2. 运行事实比对：
   `python scripts/fact_diff.py <原稿> <改稿>`
   前两张清单的每一项二选一处理：属于事实改动的，恢复原稿写法；属于表达调整的（去掉强调引号、删去复述句后重复的数字少了一处、脱敏替换、新增的【待补】），在修改说明中写明，直到清单为空或每项都有说明。第三张清单（可能是序数或概数）人工判断，如“以下四个方面”中的“4个”，核对条数相符即可。
3. fact_diff 不比对人名、单位名、责任分工、时限和义务强度，对照第一步清单人工核一遍。
4. 没有 Python 时，逐段把改稿与原稿对照，按 `references/rewrite-guide.md` 第五部分自查，并在起草说明写明“未运行机检和事实比对，已人工逐段核对”。

### 第五步　输出

按下一节“输出规范”交付。

## 输出规范

遵守 `references/_shared/style/output-format.md`：正文纯文本、不用 Markdown，正文后单起一行【起草说明】，正文前不加“以下是……”之类的引导语。

### 全文改写、轻度改写

正文为改后全文。【起草说明】按需包含以下部分，没有内容的部分省略，后面的部分依次前移编号，不跳号（如只有假设和修改说明时，写“一、所作假设”“二、修改说明”）：

一、所作假设：文书类型、单位类型、模式、角色，例如“按总结、党政机关、全文改写、教学模式处理”。
二、待补事项：原有和新增的【待补】逐条列出位置和要补的内容。
三、待核实事项。
四、修改说明：
1. 总数：“共修改 N 处，涉及 M 类。”
2. 分类统计，按处数从多到少，每类注明规则号（转译模式不写，见“角色适配”），举 1 至 2 个典型例子：
   段首评论语 4 处（AI-001）。例：“值得注意的是，部分乡镇台账更新不及时”改为“部分乡镇台账更新不及时”。
3. 保留未改：白名单命中、未采纳的机检提示、提法和行业术语中的疑似项，各写一句理由。
4. 转交事项：防御性表述 N 处（列位置和原文），建议用 gongwen-direct；格式、标点、数字用法问题 N 处，建议用 gongwen-review。这两类只列不改；已按红线三删除的免责声明、AI 自述不列入此项。
5. 事实核对：写明 fact_diff 的结果，如“fact_diff 比对无差异”或“差异 2 项，均为去掉强调引号”；转译模式写“数据逐项核对无变化”。
五、保密提示：有脱敏替换时逐条列出。
六、写作要点：仅教学模式。

轻度改写在修改说明中另写一句“未处理的 P2 问题 N 处”，列出类别。

Agent 环境下，改稿写入上述输出目录的 `正文.txt`，起草说明写入 `起草说明.md`，同名文件加 `-v2`、`-v3`；对话中不重复贴全文，只报告文件位置、修改总数和最主要的三类改动。

按交接卡开工、路线还有下一站的（如 gongwen-review），在【起草说明】之后输出更新后的交接卡，本站改为下一站；网页环境还要告诉用户新开对话，先粘贴下一站的提示词文件 `dist/prompts/<skill>.md`，再粘贴交接卡和改后正文。

### 只标注不改

不输出改后全文。先给三行摘要：
1. AI 腔程度：轻（零星几处，局部修改即可）、中（多数段落都有）、重（几乎每段都有，句式模板化，建议整体改写）；
2. 最突出的三类问题；
3. 处理建议。

再给问题清单，每条一行：
序号．位置｜原文片段｜类别｜级别｜建议改法

清单末尾列“保留未改”的白名单命中项，以及应转交 gongwen-direct、gongwen-review 的问题。Agent 环境下写入输出目录的 `文风问题清单.md`。用户要在 Word 里看批注时，另写 `核稿意见.json`，交 gongwen-format 写成批注。格式为 `{"source_file": "原稿文件名", "issues": [{"level": "P1", "gate": "文风关", "category": "类别", "excerpt": "原文片段", "message": "问题说明", "suggestion": "建议改法", "basis": "规则号"}]}`，excerpt 必须与原文逐字一致；同一片段在原文出现多次的，加长到能唯一定位为止。

## 自检清单

- [ ] 保密检查已做；脱敏替换都写进了保密提示。
- [ ] fact_diff 清单为空或每项都有说明；人名、单位名、分工、时限、义务强度已人工核对。
- [ ] 【待补】【待核实】一个不少；新增的都写进待补事项。
- [ ] 白名单写法、层次序号、提法、引语、行业术语没有被改。
- [ ] 正文里的免责声明、AI 自述、对话引导语已删除并写进修改说明；其余防御性表述、格式和标点错误没有顺手改，已列入转交事项。
- [ ] 没有为了“具体”编数字、编案例，没有原稿之外的新做法、新功能；新增表述逐条列入起草说明。
- [ ] 正文无 Markdown、无 emoji，首尾无“以下是”“希望对您有帮助”之类的对话残留。
- [ ] 改稿没有新出现 AI 腔：替换词不扎堆，没有新加总结句和评论语。
- [ ] 修改说明按类别统计，每类有例子；起草说明省略的部分已重新编号，没有跳号。
- [ ] 用户材料中加引号的做法名称、本单位提法原样保留，确需改写的已列入提法核对清单；“周五”“月底”等相对时间照原话，没有推算成日期。
- [ ] 用户给了字数目标的，改后在目标 ±10% 内，或已在回复第一段说明差距（【待补】不计入字数）。

有 Python 环境时运行：`python scripts/gongwen_lint.py <改稿> --doc-type <文书类型> --checks style,residue`（DEF 类提示属转交事项，不计入 P1 清零）和 `python scripts/fact_diff.py <原稿> <改稿> --strict`。无法运行脚本时，按 `references/rewrite-guide.md` 第五部分人工检查，并在起草说明中写明“未运行机检”。

## 角色适配

- 教学模式：修改说明逐条列“原文、改后、理由”三栏，理由写到类别和规则号；附“写作要点”：本稿最常见的三种 AI 腔，以及下次用 AI 起草时可以写进提示词的三条要求（如“不用破折号”“成效写数据，没有的标待补”）。
- 高效模式：不提问，直接给改后全文；修改说明压缩到 5 条以内（总数、主要类别各一例、转交事项、事实核对），不展开讲解，但每条仍写改动类别和规则号，如“段首评论语 3 处（AI-001）”；可一次处理多份稿件，逐份输出。
- 转译模式：业务术语、指标名称、数据口径一律不动；修改说明（含起草说明）单列模板：原话、改后、一句通俗理由，不写规则号、AI-xxx、P0/P1、fact_diff、gongwen-xxx 等内部名称，转交事项只说问题；稿件的主要问题是口语化而不是 AI 腔时，说明本 skill 只处理 AI 腔，转成公文体请用 gongwen-polish。
- 审稿模式：默认只标注不改，给三行摘要和问题清单；用户说“那你改一版”时，本次按高效模式输出改后稿。
- 严谨模式：政治性提法、上级文件原文、引语逐字不动，带 AI 腔也不改；含提法的句子只改提法以外的部分，起草说明末尾写“附：提法核对清单”（提法、位置、是否改动）；fact_diff 报出的引号差异一律恢复原样。

## 单位差异

单位类型影响术语保护和语气，详见 `references/unit-notes.md`。要点：医院的“闭环管理”、国企专项行动名称中的“提质增效”、高校学术材料中的“范式”按规范用语保留；社区、中小学面向居民和家长的亲切称呼保留；党政机关提法最密，改稿前先把提法和引语圈出来。
