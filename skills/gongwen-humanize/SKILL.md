# 公文去 AI 味（gongwen-humanize）

AI 起草的公文常带固定腔调：宏大开头、空泛总括、段尾拔高、翻案句、破折号、“赋能”“闭环”扎堆，成效只有“显著提升”没有数据。本 skill 先冻结全部事实，再把命中的句子改到位（不是换几个词），保留正当写法。定位是文风改进：不判断稿件是否 AI 所写，不承诺检测结果。

## 适用范围

- 适用：
  - AI 起草或润色过、读着“一股 AI 味”的公文和材料；
  - 句式、词汇、标点、结构四个层面的 AI 腔（分类见 `references/_shared/style/ai-tone.md` 第一部分），三种模式：全文改写（默认）、只标注不改、轻度改写。
- 不适用（转交）：
  - 对冲语气（可能）、平衡腔、“建议”“可以考虑”式部署、模糊主体、请示批复态度不明：转 gongwen-direct。正文里的免责声明（如“以上内容仅供参考”）、AI 自述和对话引导语例外，按红线三直接删除，在修改说明中注明；
  - 格式、标点和数字用法错误（GB/T 15834、GB/T 15835）、提法核查、全面核稿：转 gongwen-review；
  - 压缩、扩写、调语气：转 gongwen-polish；起草新稿、补写内容：转对应起草 skill（gongwen-report、gongwen-draft、gongwen-speech、gongwen-brief 等）；
  - 重拟标题和小标题转 gongwen-title；排版成 docx 转 gongwen-format。
- 转交方式：能调用其他 skill 的直接调用；否则按 `references/_shared/style/output-format.md` 第四部分给交接卡和安装命令。行业包专用文书同样归本 skill。
- 一稿同时有 AI 腔和防御腔：限定语（一定程度上、在某种意义上、相对而言、一定的等）按“改写强度”第 7 款处理；免责声明和限定语以外的防御性表述原样保留，列入“转交”，建议接着用 gongwen-direct。

### 用户要求“降 AI 率”“躲过 AI 检测”时

先说明“这里做文风改进，检测结果不稳定，不作承诺”，再照常处理，并遵守：
1. 不用对抗检测的手法（错别字、乱换同义词、打乱语序、插入无关内容）。
2. 不估算、不报告“AI 率”。
3. 述职报告、对照检查材料、心得体会等需要本人经历的，在说明中提醒事例由本人补写（guardrails 第六条），正文不插占位。

## 开工检查

1. 保密（红线一，`references/_shared/guardrails.md` 第一条）：
   - 保密提示按第一条第1款办理，只放在起草说明末尾，不进正文文件。
   - 稿件有密级标识（“秘密★”等），或标注“内部资料”“工作秘密”“不得外传”“内部使用”：立即停止，不改写、不复述原文，按第一条第2款告知用户。正文中的“保密工作”之类词语不算。
   - 稿件有身份证号、手机号、病案号、住院号、学号、银行卡号、家庭住址、患者或学生真实姓名：提醒脱敏，改稿用“张某”“138****0000”替代。这是唯一允许改动的事实，逐条写进保密提示。
2. 单位画像：先读 `.gongwen/单位画像.md`，没有再找 `~/.gongwen/单位画像.md`；同目录有 `禁用词.md`、`文风参数.md` 的一并读取。没有画像时不追问，按 `references/_shared/profiles/roles.md` 第九节“无画像降级”判断，判断不出的按党政机关、教学模式，写进假设。
3. 文书类型：从标题、文种、落款判断，使用统一词表名称（讲话稿、信息、总结、汇报材料、实施方案、通知、请示……），判断不出用“其他”。文书类型决定白名单和阈值，见 `references/doc-type-notes.md`。
4. 模式：

   | 模式 | 识别信号 | 做法 |
   |---|---|---|
   | 全文改写（默认） | “去 AI 味”“改自然点”“事实不动”“数字别动”“结构别动” | 处理全部类别，命中句改到位，强度见“改写强度” |
   | 只标注不改 | “先别改”“标出来就行”“看看哪里有 AI 味”；审稿模式默认 | 只出问题清单 |
   | 轻度改写 | 用户明说“稍微改改”“别大动”“轻度处理一下” | 只处理 P1 和残留；“事实不动”“结构别动”不等于轻度 |

5. 留底：Agent 环境下，用户贴的文字原样存为 `公文/<YYYYMMDD>-<简短标题>/原稿.txt`；给的是文件的以它为原稿，输出仍写入该目录。
6. 提问：一般不提问，首轮直接交付。确需确认的先按最可能的类型改，问题放在回复末尾，最多 3 个（`references/_shared/profiles/roles.md` 第十节）；用户说“直接改”不问。
7. 交接卡：用户贴了交接卡的，按卡上的单位画像、模式、任务和已确认事项开工，已有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 工作流程

### 第一步　冻结事实

动笔前通读全文，列一份事实清单（供自己对照，不必输出）：
1. 数字、日期（“周五”“月底”等相对时间照原话，不推算成具体日期）、金额、百分数、发文字号、书名号和引号内的内容；
2. 人名、职务、单位名、责任分工、完成时限；层次序号、标题层级与数量、段落数量与顺序（用户说“结构别动”时全部冻结，标题措辞仍可改）；
3. 义务强度词（必须、应当、要、可以、原则上、力争），条件和适用范围；
4. 政治性提法、上级文件原文、领导讲话原话、文件名称；
5. 【待补】【待核实】标记。

改写全程对照这份清单，清单上的内容不改；清单之外的表达（句序、搭配、连接、取舍）可以重写。

### 第二步　诊断

1. 有 Python 时运行：
   `python scripts/gongwen_lint.py <原稿> --doc-type <文书类型> --checks style,residue --json`
   有 `.gongwen/禁用词.md` 的，加 `--banned .gongwen/禁用词.md`。规则号 AI-xxx 对应 ai-tone.md 各类标题后的编号，RES 开头的残留规则按 rewrite-guide（十四）处理。无输出转人工诊断。
2. 没有 Python 或机检未执行时，按 `references/_shared/style/ai-tone.md` 第一部分的十三类和 `references/rewrite-guide.md` 补充的（十四）至（十九）类，逐段人工排查。
3. 每个命中项先查白名单（ai-tone.md 第二部分）和 `references/doc-type-notes.md`，属于正当写法的划掉。单个四字格、条目各有实质内容的“一是……二是……”不动；口号式小标题按“改写强度”第 3 款改；空壳条目、排比、四字格堆叠按（十七）至（十九）处理。
4. 密度类问题以人工判断为准；500 字以下短稿，一次“助力”不必改。
5. 风险提示中的“可能”、问题查摆中的“不同程度存在”不算问题。

诊断结果按“类别、位置（第几部分第几段）、原文片段、级别”记录。出现一次就要改的类别记 P1（如段首评论语、翻案句、互联网黑话、元话术、残留），过密才改或需要判断的记 P2（如新八股词密度、套话堆砌、概括代替数据、相邻句雷同）。机检给出的级别优先。

### 第三步　分类改写

按 `references/rewrite-guide.md` 第二部分的顺序逐类改写：

1. 命中的句子整句改到位，不是只换词；没命中的逐字保留。强度见“改写强度”。
2. 不动：第一步清单上的内容；白名单写法；层次序号；行业术语（见 `references/unit-notes.md`）。
3. 改写优先于删除：空泛总括句、段尾拔高句优先改写成原稿已有事实的概括或平实表述，纯口号、与上下文完全重复的才删；具体措施、要求、安排（哪怕笼统，如“加大监督检查力度”）不删，只改平实；整段删除限于全段无事实、无措施。信息稿评价句前没有已落实事实、数据的删；部署性目标表述、上级原文除外。
4. 缺数据不编，不添原稿没有的做法，不在正文插【待补】【待核实】：成效句找不到数据的，改成原稿已有做法的平实表述，没有做法可写的删或改成平实的工作性表述；需补的事例、数据写在说明里作建议。改后的做法、功能、范围、成效须能在原稿找到出处，比喻和口号不能推出新动作。用户要求“加点数据和例子”时，说明要由用户提供，正文不加。
5. 篇幅：改后一般为原稿的 85%～100%（用户要求压缩的除外），不补写铺垫、背景和意义（红线四）；低于 85% 时复检有无删事实或措施。用户给了字数目标的，改后不在 ±10% 内时在回复第一段说明差距，压缩扩写用 gongwen-polish，本 skill 不注水、不删事实。
6. 提法、引语中带 AI 腔的不改，记入“保留未改”。用户加引号的做法名称、本单位提法同样原样保留，不当作强调引号去掉；确需改写的原句不动，改法写进“附：提法核对清单”请用户确认（guardrails 第二条第8款）。
7. 改后不比原句更实、信息少于原句的，恢复原句。
8. 交付稿标题去掉“（初稿）”“（征求意见稿）”等草稿标记，用户要求保留的除外。用户要求“改到能用/能报审/能上会”的，按综合改稿力度：85% 下限不适用，空话段落可压缩；原稿内部矛盾按 gongwen-polish 办法处理，正文取最合理的一致写法，说明中请用户确认。

轻度改写只处理 P1 和残留。只标注不改跳过本步，直接输出问题清单。

### 改写强度（全文改写）

1. 事实冻结、表达放开：可以重组、合并、拆分句子，把后文的数据、做法提到句首顶替总括句。
2. 必处理五类：宏大开头（直接写本单位的事实）；空泛总括句和段尾拔高句（见上第 3 款）；抽象名词堆叠（改成“谁做了什么”）；空壳排比和机械总分（压缩合并）；“切实”“扎实”“有力”“有效”一段超过两个的只留一个。
3. 标题也要改：主标题、小标题中的口号、套话、四字格堆砌（如“质效显著提升”“织密网络”）按“写实”改成说明做了什么、涉及什么的平实标题，层级、数量、顺序不变，不添原稿没有的内容。
4. 体裁不变：保持公文书面语，不改成网文腔；讲话稿保留口语和号召，并按第 8 款改写。不新增套话（如“拉开帷幕”“扬帆起航”“交出满意答卷”）。
5. 用户说“结构别动”：标题层级、序号、段落数量与顺序不变，条目不增不减，段内、句内和标题措辞照常改写。
6. 力度参照：几乎每段都有宏大开头、总括或拔高的稿子，改动比例一般在 20% 以上；不足 10% 而仍有明显套话的，视为没改到位，回头重过。误正例见 `references/rewrite-guide.md` 第六部分。
7. 对冲、防御性限定语（一定程度上、在某种意义上、相对而言、一定的等）在不改变事实的前提下删去或改成确定表述；涉及事实判断强弱的（如“基本完成”）和与“可能”连用的整句不改。
8. 讲话稿按讲话语体改写，不只修剪：长句拆短，书面连接词换口头衔接，开头致意简化，事实和层次不变，不加个人经历和段子。

### 第四步　复检

1. 再跑一次机检（命令同第二步，文件换成改稿），确认 P1 已清零，或每条都有保留理由，新增的 style 类命中项一律改掉；再按 `references/rewrite-guide.md` 第五部分第 5 款逐段扫残留模式，并逐句扫口号短语（如“送政策、送服务、解难题”“说到心坎上”），改写成做了什么、对谁、结果如何的写实表述。
2. 运行 `python scripts/change_guard.py <原稿> <改稿> --json`，用户要求结构不动的加 `--keep-structure`。CHG-001（P0 事实变化）逐条处理：事实改动的恢复原稿写法；表达调整的（去掉强调引号、删句后重复数字少了一处、脱敏替换）在说明中写明；CHG-004（结构变化）在结构不动时必须恢复；CHG-003（无规则依据的改动）按需列入说明。
3. change_guard 不比对责任分工、时限、义务强度，人名、单位名和序号结构也可能漏，对照第一步清单逐项人工核一遍。
4. 没有 Python 时，按 `references/rewrite-guide.md` 第五部分逐段对照原稿自查，注明“未运行机检和事实比对，已人工逐段核对”。

## 输出规范

遵守 `references/_shared/style/output-format.md`：正文纯文本、不用 Markdown，正文后单起一行【起草说明】，正文前不加引导语。

### 全文改写、轻度改写

回复开头直接给改后全文，不加引导语，不写过程说明；篇幅差距说明（一句）除外。交付的全文（对话中的和写出的文件）只含正文，不带【起草说明】。全文之后单起一行【起草说明】，不超过 5 行，每行一句，用普通话说清改了什么、为什么，不写规则号、类别名、工具名。按需取用，没有的省略：
1. 改了什么：共几处，举一两例（原文→改后），写明所作假设（文书类型、模式）；轻度改写另写未处理的问题数；
2. 保留了什么及理由：白名单写法、提法、行业术语；
3. 需要用户补的事例、数据（作为建议，正文不插占位）和原有的【待补】【待核实】；
4. 建议转交的问题：防御性表述、格式和数字问题，写明位置和原文，只列不改；已删除的免责声明、AI 自述在第 1 行注明；
5. 事实核对结果，一句话。

有脱敏替换的，另一行写明替换了哪些，计入 5 行。教学模式见“角色适配”，不受 5 行限制。

Agent 环境下，先在对话开头贴出改后全文，同时把同一份正文写入输出目录的 `正文.txt`（同名加 `-v2`、`-v3`）；起草说明只在对话里。

按交接卡开工、路线还有下一站的，在【起草说明】之后输出更新后的交接卡，本站改为下一站；网页环境还要告诉用户新开对话，先粘贴 `dist/prompts/<下一站>.md`，再粘贴交接卡和改后正文。

### 只标注不改

不输出改后全文。先给三行摘要：
1. AI 腔程度：轻（零星几处，局部修改即可）、中（多数段落都有）、重（几乎每段都有，句式模板化，建议整体改写）；
2. 最突出的三类问题；
3. 处理建议。

再给问题清单，每条一行：序号．位置｜原文片段｜类别｜级别｜建议改法。清单末尾列“保留未改”的白名单命中项，以及应转交 gongwen-direct、gongwen-review 的问题。Agent 环境下写入输出目录的 `文风问题清单.md`。用户要在 Word 里看批注时，另写 `核稿意见.json`，交 gongwen-format 写成批注。格式为 `{"source_file": "原稿文件名", "issues": [{"level": "P1", "gate": "文风关", "category": "类别", "excerpt": "原文片段", "message": "问题说明", "suggestion": "建议改法", "basis": "规则号"}]}`，excerpt 与原文逐字一致，重复出现的加长到能唯一定位。

## 自检清单

- [ ] 保密检查已做；脱敏替换已写进保密提示。
- [ ] 冻结事实逐项核对一字不差，CHG-001 为空或每项有说明；原有【待补】【待核实】一个不少，没有新插占位。
- [ ] 白名单写法、层次序号、提法、引语、行业术语没有被改；免责声明、AI 自述、对话引导语已删除并注明，限定语已按第 7 款处理，其余防御性表述、格式和标点错误已列入转交、没有顺手改。
- [ ] 没有编数字、编案例，没有原稿之外的新做法、新功能；措施句没被当空话删掉，篇幅在原稿 85%～100%（要求“能报审”的除外），标题已改写、草稿标记已去。
- [ ] 正文无 Markdown、emoji，首尾无对话残留。
- [ ] 改稿没有新出现 AI 腔（替换词不扎堆，无新加总结句），宏大开头、总括句、段尾拔高、名词堆叠、空壳排比、口号短语没有残留，力度达标。
- [ ] 回复开头就是改后全文，全文和文件里没有【起草说明】；起草说明不超过 5 行（教学模式除外），每行一句，不含规则号、类别名、工具名。

有 Python 时运行 `python scripts/gongwen_lint.py <改稿> --doc-type <文书类型> --checks style,residue`（DEF 类转交）和 `python scripts/change_guard.py <原稿> <改稿> --strict`；否则按第四步第 4 款。

## 角色适配

- 教学模式：修改说明逐条列“原文、改后、理由”三栏，理由写到类别和规则号；附“写作要点”：本稿最常见的三种 AI 腔，以及下次起草可写进提示词的三条要求（如“不用破折号”）。
- 高效模式：不提问，直接给改后全文；说明照上文 5 行写；多份稿件逐份给。
- 转译模式：业务术语、指标名称、数据口径一律不动；说明按“原话、改后、一句通俗理由”列，不写规则号、AI-xxx、P0/P1、change_guard、CHG-、gongwen-xxx 等内部名称；主要问题是口语化而非 AI 腔的，说明本 skill 只处理 AI 腔，转公文体请用 gongwen-polish。
- 审稿模式：默认只标注不改；用户说“那你改一版”时，本次按高效模式输出改后稿。
- 严谨模式：政治性提法、上级文件原文、引语逐字不动，带 AI 腔也不改；含提法的句子只改提法以外的部分，说明末尾附“提法核对清单”（提法、位置、是否改动）；fact_diff 报出的引号差异恢复原样。
