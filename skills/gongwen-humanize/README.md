# 公文去 AI 味（gongwen-humanize）

用 AI 起草的材料，常被领导一眼看出来：“值得注意的是”开头，“不是……而是……”翻案，破折号一个接一个，“赋能”“闭环”扎堆，成效只有“显著提升”没有数字。这个 skill 把这些写法逐类找出来改掉，同时保住公文该有的写法和稿子里的每一个事实。

## 能做什么

- 改到位而不是换几个词：事实冻结、表达放开，宏大开头、空泛总括句、段尾拔高、抽象名词堆叠、空壳排比和口号式标题改写成平实表述（改写优先于删除，措施句不删，篇幅保持原稿 85%～100%）；“结构别动”时保持标题、序号、段落数量与顺序。
- 改写 AI 腔：段首评论语、翻案句、破折号和提示性冒号、空话引出列表、译文腔、拟人化比喻、空泛概括、新八股词、套话堆砌、宏大开头、元话术和总结口号、相邻句雷同、Markdown 和对话残留。
- 对冲限定语（一定程度上、在某种意义上等）在不改事实的前提下删去，“基本完成”这类事实判断强弱词不改；口号短语改成写实表述。
- 保留公文正当写法：单个四字格、条目各有实质内容的“一是……二是……”、“坚持……坚持……”排比小标题、“现将……通知如下”、层次序号、政治性提法。
- 按文书类型调整：讲话稿按讲话语体改写（长句拆短、口头衔接、致意简化），可以设问；实施方案的顿号和冒号不按密度改；总结的成效部分对“空泛概括”最严。
- 按单位类型调整：医院的“闭环管理”、国企的专项行动名称、学校给家长信里的亲切称呼，都不当作 AI 腔改掉。
- 事实一字不动：数字、日期、人名、单位名、文号、【待补】标记保持原样，有 Python 时用 `scripts/change_guard.py` 逐项比对改稿前后。
- 三种模式：全文改写（默认）、只标注不改、轻度改写。

## 怎么说

- “这篇总结是 DeepSeek 写的，一股 AI 味，帮我改改，数字别动。”
- “领导说这稿子太像机器写的，帮我顺一顺。”
- “先别改，帮我标出来哪些地方 AI 味重。”
- “稍微去一下 AI 痕迹就行，结构别动。”
- “讲话稿是 AI 生成的，改得像人说话，但别改成公文腔。”

## 输入和输出

- 输入：一篇稿件，可以直接粘贴文字，也可以给 .txt、.md、.docx 文件。
- 输出（全文改写、轻度改写）：改后正文（纯文本，可直接粘贴进 Word，文件里只有正文），对话里正文之后另附不超过 5 行的【起草说明】，用普通话说清改了什么、为什么、保留了什么、哪些要你补充或转交。
- 输出（只标注不改）：AI 腔程度摘要和问题清单（位置、原文、类别、级别、建议改法），不动原文。需要 Word 批注时，可生成 `核稿意见.json` 交 gongwen-format 处理。
- 在 Claude Code、Codex 等能写文件的工具里，结果存放在 `公文/<日期>-<标题>/` 目录下，原稿另存为 `原稿.txt` 供比对。

## 注意事项

1. 这是文风改进工具，不判断稿件是否由 AI 生成，也不承诺任何 AI 检测结果。用户要求“降 AI 率”时，会先说明这一点，再按文风改进处理。
2. 不编数据。成效写得空、又没有数据的地方，会改成原稿已有的做法或删去，不在正文插【待补】，需要你补的事例和数据写在说明里。
3. 不管防御腔和格式错误。“可能”“建议考虑”等对冲表述请用 gongwen-direct；标点、数字用法、格式和提法核查请用 gongwen-review；压缩、扩写、调语气请用 gongwen-polish。改稿时会把这些问题列出来，但不动它们。正文里“以上内容仅供参考”之类的免责声明和 AI 对话残留例外，会直接删掉，并在修改说明里写明。
4. 需要其他 skill 接着处理时，能调用的环境直接调用；对方 skill 没装或在网页版的，会给交接卡、“新开对话粘贴 `dist/prompts/<skill>.md` 继续”的说明和安装命令。从总入口拿到交接卡的，贴上卡片和稿子即可，卡上写过的不会再问。
5. 保密优先。涉密材料请勿输入联网 AI；稿件有密级标识或“内部资料”等标注时会停止处理，稿件有个人敏感信息、“内部”“不公开”字样等敏感信号时才在起草说明末尾提示一句。稿件中的患者、学生姓名和证件号会提醒你脱敏，改稿中用“张某”之类代替。
6. 述职报告、对照检查等需要本人真实经历的材料，具体事例必须由本人补写。

## 成熟度

- 版本 1.0.0，Stable。
- 改写流程、白名单、文书类型和单位类型的调整规则已完成，评测用例 25 条（含网页版交接卡、讲话稿口语化、对冲语处理用例）。
- v1.0 真实模型评测（Sonnet 5.5）：装 skill 的 A 组期望通过率 98.1%（101/103），编造 0 次；不装的 B 组约 61%（63/103）。触发评测正例 10/10、反例 10/10，详见 `evals/results/v1.0-benchmark.md`。不装时常见的问题是改动应保留的原文、补编原文没有的措施。
- `scripts/fact_diff.py` 已可用：比对数字（含百分数、金额）、日期、【待补】【待核实】标记、书名号和引号内容、发文字号，层次序号不算事实。人名、单位名、责任分工、时限和义务强度需要人工核对。
- 机检引擎 `scripts/gongwen_lint.py` 是各 skill 共用的脚本；机检结果与白名单、文书类型规则冲突时，以人工判断为准。
- 网页版（DeepSeek、豆包、Kimi 等）使用 `dist/prompts/gongwen-humanize.md`，无法运行脚本，按文中清单人工检查。
