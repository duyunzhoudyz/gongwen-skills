# 标题与提纲（gongwen-title）

本 skill 解决“起标题难”：发文标题要素不全、“关于”用错、转发标题层层叠用；材料小标题大而无当、与正文脱节、数字概括对不上条数。它只出标题、小标题和提纲要点，不写正文段落。

## 适用范围

- 适用：
  - 公文标题：拟定和纠错，包括三要素、“关于”、转发叠用、回行、标点。
  - 材料标题：总结、汇报材料、经验材料、调研报告、述职报告、讲话稿、信息的单标题和主副标题。
  - 小标题提炼：根据正文或素材给出 3 套方案，推荐其中一套。
  - 提纲搭建：从素材搭出标题层级和每节要点。
  - 一致性检查：逐节检查标题与正文是否对得上。
- 不适用（转交）：
  - 整篇起草、把提纲扩成稿子：总结、计划、汇报、述职、调研、经验材料、实施方案交 gongwen-report；通知、请示、报告、函、纪要等法定公文和讲话稿交 gongwen。
  - 全文核稿（标点、数字、提法、保密扫描）交 gongwen-review，本 skill 只查标题。
  - 正文的 AI 腔交 gongwen-humanize；免责、对冲、态度不明交 gongwen-direct；排成 docx 交 gongwen-format。
  - 说不清要写什么（“帮我弄个材料”）先交总入口 gongwen。

## 开工检查

1. 保密：按 `references/_shared/guardrails.md` 第一条执行。第一次请用户提供材料时，或用户第一条消息就附了材料时，在本次回复开头附一句保密提示，同一会话只提示一次。材料带有密级标识（“秘密★”“机密★”“绝密★”，或版头标注的密级和保密期限），或标注了“内部资料”“工作秘密”“不得外传”“内部使用”等字样时立即停止，不提炼、不改写，告知改用内网模型或删去涉密内容后再继续；正文中正常出现“保密工作”“涉密人员管理”之类的词语不算，照常处理。出现患者或学生姓名、病案号、学号、身份证号、手机号时提醒脱敏；标题和提纲一律写“张某”“某科室”，不把个人信息带进标题。
2. 单位画像：工作目录存在 `.gongwen/单位画像.md` 时先读取（没有再找 `~/.gongwen/单位画像.md`），再读 `.gongwen/领导偏好卡.md`（“结构习惯”一栏常写小标题偏好）和 `.gongwen/禁用词.md`。都不存在时按 `references/_shared/profiles/roles.md` 第九节“无画像降级”处理；只改一个标题的小任务不为画像追问，直接按默认值处理。
3. 角色模式：按 `references/_shared/profiles/roles.md` 第一节确定，本 skill 的差异见“角色适配”。
4. 已有成果：同一任务目录下已有 `素材台账.md`（gongwen-report 生成）的，提纲要点以台账为准，素材编号沿用台账编号；已有 `提纲.md` 的，在它的结构上拟标题，不另起一份提纲，拟出的方案写入 `标题方案.md`。网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务和已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。
5. 提问：一次最多问 3 个，只问影响标题的事项，如文种、发文机关、材料用途。用户说“直接给”时不再问，采用默认值并写进起草说明。

## 工作流程

### 第一步　判断任务类型

按用户给的东西和说法归类，可以组合，如“搭提纲并给小标题”：

| 用户给的 | 用户常说 | 任务 |
|---|---|---|
| 一个发文标题，或文件事由 | 标题对不对、转发怎么写、太长怎么回行 | 任务一 公文标题 |
| 材料类型和主旨 | 起个标题、要主副标题 | 任务二 材料标题 |
| 写好的正文，或成段的素材 | 提炼小标题、改得对仗些、三个坚持那种 | 任务三 小标题提炼 |
| 零散素材、工作记录、数据表 | 搭提纲、出个框架 | 任务四 提纲搭建 |
| 带标题的正文 | 标题和内容对不上、小标题大而无当 | 任务五 一致性检查 |

用户要求“顺便把正文写了”时，完成标题和提纲后说明正文交 gongwen-report 或 gongwen 起草，可把提纲直接交给它。本 skill 不写正文段落。

### 第二步　按任务执行

#### 任务一　公文标题

1. 拆三要素：发文机关名称、事由、文种（《党政机关公文处理工作条例》第九条（七）；GB/T 9704-2012 7.3.1）。
   - 发文机关用全称或规范化简称；联合行文列各机关名称。本单位惯例省略发文机关的，按惯例处理，在起草说明里写明。
   - 事由一般以“关于”开头，写清做什么事，不写“关于有关事项的通知”这种空事由。
   - 文种必须是法定文种或本单位制度规定的文种（如签报）。拿不准时按 `references/_shared/rules/doc-types.md` 第六部分决策表判断。
2. 查“关于”：一个标题只用一个“关于”；“关于”后不再叠加介词（“关于对”“关于就”）；事由里不再重复发文机关；公告、命令、会议纪要等无事由的标题可以不用“关于”。
3. 对照下表纠错，改后的标题必须仍然准确反映用户给的事由，不添加用户没说的内容：

| 错误 | 误 | 正 |
|---|---|---|
| 缺文种 | 某县卫生健康局关于开展医疗机构消防检查 | 某县卫生健康局关于开展医疗机构消防检查的通知 |
| 文种叠用 | 关于增设发热门诊的请示报告 | 关于增设发热门诊的请示 |
| 事由与文种重复 | 关于申请拨付校舍维修经费的请示 | 关于拨付校舍维修经费的请示 |
| 介词叠用 | 关于对2026年度先进集体进行表彰的决定 | 关于表彰2026年度先进集体的决定 |
| 文种错用（向不相隶属的县交通运输局行文） | 某镇人民政府关于申请某村道路修缮资金的请示 | 某镇人民政府关于商请支持某村道路修缮资金的函 |
| 末尾加标点 | 关于开展安全生产检查的通知。 | 关于开展安全生产检查的通知 |

4. 转发、批转、印发类（实务做法，见 `references/_shared/rules/doc-types.md` 2.8）：
   - 全标题只留一个“关于”：去掉被转发文件标题里的“关于”。
   - 不出现“的通知的通知”：去掉被转发文件文种前的“的”。
   - 层层转发时，只写最初发文机关和原事由，省略中间转发层次；中间层次提出的补充要求在正文交代。
   - 被转发的公文标题不加书名号；印发规章、制度、方案时，名称加书名号。
   - 批转用于下级机关的公文，转发用于上级机关和不相隶属机关的公文。
   - 例：区教育局转发市教育局已转发的省教育厅通知。误：某区教育局关于转发某市教育局关于转发某省教育厅关于做好2026年秋季学期学校安全工作的通知的通知的通知；正：某区教育局关于转发某省教育厅做好2026年秋季学期学校安全工作通知的通知。
   - 被转发文件的准确标题必须来自用户提供的文件，没有时写【待补：原文件标题】。
5. 标点（GB/T 15834-2011，`references/_shared/rules/gbt15834.md`）：
   - 末尾不加标点（B.4）；不用问号、叹号、冒号、破折号。
   - 法规、规章、制度、方案名称加书名号，括注属于名称的放在书名号内：关于印发《某市公务接待管理办法（试行）》的通知（A.13.4）。会议、活动名称不加书名号（A.13.1）。
   - 并列事项可用顿号（元旦、春节期间）；特定称谓确需标示时用引号，能不用就不用（实务）。
   - 年份范围用一字线：2026—2028年（4.13.3.2）；年份不简写为两位（GB/T 15835-2011 5.1.4）。
   - 正文中引用含书名号的标题时，内层改单书名号：《关于印发〈某某办法〉的通知》（4.15.3.5）。
6. 回行（GB/T 9704-2012 7.3.1）：2 号字每行约 20 字（按每行 28 个 3 号字推算），超长时先压缩事由中的重复词和可省修饰语，再回行。
   - 词意完整：在词语之间断行，机关名称、专有名词、数字和年份不拆开；“的”和文种留在同一行。
   - 排列对称、长短适宜：排成梯形（上短下长或上长下短）或菱形（三行时中间一行最长）；避免两头长中间短，避免末行只剩“的通知”几个字。
   - 回行示例见 `references/title-patterns.md` 1.4。

#### 任务二　材料标题

1. 定类型和用途：上报、存档用单标题；交流发言、刊发、汇报会多用主副标题。各类材料的标题格式见 `references/_shared/rules/doc-types.md` 第四部分。
2. 单标题：单位、时间、事项、材料类型，如“某医院急诊科2026年工作总结”“关于某县农村供水保障工作情况的汇报”。
3. 主副标题：
   - 主标题提炼主旨，即做法、成效或特色，一般 8～20 字；两个对仗短语之间空一字，不加逗号（均为实务做法，本单位另有习惯的从其习惯）。
   - 副标题另起一行，前加破折号，交代单位、时间、事项和材料类型：“——某街道2026年老旧小区改造工作经验”。这是 GB/T 15834-2011 4.10.3.9 规定的正当用法，不算 AI 腔。
   - 主副标题不重复同一信息；副标题不用冒号、括号代替破折号。
4. 主标题中的数字、排名、“首创”“率先”必须来自用户材料。材料里没有的不写，改用做法或特色立题；用户坚持要数据亮点时，写成“门诊预约率提升至【待补：数据】”一类，并在起草说明列为待补。
5. 默认给 3 个备选并标出推荐。各类样式和正误示例见 `references/title-patterns.md` 第二部分。

#### 任务三　小标题提炼

1. 读正文，逐节写一句“本节讲了什么”，只用正文里的事实，再列出每节 2～3 个关键词。正文有几块内容就出几条标题，不合并、不凑数。总结类材料的固定一级标题（主要工作和成效、存在的问题、下一步打算一类）保持规范名称，不出多套方案；多套方案只针对“主要工作”等部分下的二级标题。“存在的问题”“打算”下有二级标题的，只给一套，并逐条检查与正文是否一致（判断方法同任务五）。
2. 出 3 套方案，从以下五种样式中选，每套内同级标题用同一种句法结构：
   - 对仗式：同级各条结构相同、字数相同，读来整齐。每条内部前后两半可以对仗，如“优化预检分诊，缩短候诊时间”，但不强制。
   - 递进式：各条有先后、因果或由浅入深的关系，顺序不能互换，如“摸清底数”“补齐短板”“建立长效机制”。正文本是平行关系的，按“基础、重点、保障”等逻辑重排，并在“适用：”行写明正文段落需要调整的顺序。
   - 数字概括式：一个总括数字统领各条，各条含同一个关键字且位置一致（多在开头），如总括“三个突出”，下设“突出……”三条。总括可写在方案名、主标题或开头段中。
   - 动宾式：动词加对象，平实清楚，如“规范预检分诊流程”。
   - 主题词式：按板块列名词短语，如“急诊救治”“质量安全”。

   默认出对仗式、递进式、数字概括式。以下两种情况，用动宾式或主题词式替换其中一套，通常替换数字概括式：
   - 书面上报、数据多的业务报告，以及计划、实施方案（这类材料的小标题惯用动宾式，如"加强组织领导""明确责任分工"）；
   - 转译模式。

   领导偏好卡指定的样式不在默认三套中的，同样替换其中一套。任何情况下都只出 3 套。
3. 每套后写一行“适用：”，一句话说明适合的场合；全部方案后写“推荐：”和一句理由。推荐只能在已给出的三套中选。推荐依据：领导偏好卡有小标题偏好的按偏好；口头汇报、交流发言、经验材料选对仗式或数字概括式；正文有明显先后、因果关系的选递进式；书面上报、数据多的业务报告，计划、实施方案，以及转译模式，选替换进来的动宾式或主题词式。
4. 数字概括式方案后写一行“条数核对：”，写明总括数字、下级标题条数、正文分项数，三者必须相等。
5. 提炼规则，逐条对照，不符合的重拟：
   - 同级结构一致、字数相近：对仗式同级各条字数相同（每条内部前后两半是否对仗不作要求）；其他样式同级相差一般不超过 2 字（本项目约定）。
   - 忠于正文：标题关键词在本节正文能找到对应事实；标题范围与本节内容一样大。正文没有成效数据的，标题不用“显著提升”“全面完成”。
   - 不拔高：一次活动不写成“体系”“机制”，试点不写成“全覆盖”。
   - 不生造词：只用规范词语，以及用户材料、上级文件原文里已有的提法；不自造缩略语和“××化”组合。误：“推进‘三化’融合”（正文没有这个说法）。
   - 数字概括与实际条数一致：共用关键字每条都有，位置一致。
   - 避开 AI 腔和新八股：对照 `references/_shared/style/ai-tone.md` 第一部分第（三）（六）（八）（九）类，标题不用“赋能”“闭环”“拉满”，不连用“走深走实”“见行见效”，不用拟人比喻和提示性冒号。排比式小标题属于白名单第 3 条，照常使用。
   - 上下级标题不重复同一个短语；序号依次用“一、”“（一）”“1.”“（1）”，标题独占一行时末尾不加标点（GB/T 15834-2011 B.3、B.4）。
6. 方案只到标题层级。用户要求把选定标题替换进原文时，只替换标题行，正文段落一字不动。细则和正误示例见 `references/heading-rules.md`。

#### 任务四　提纲搭建

1. 定材料类型、用途、读者和篇幅。篇幅用户没说的，按 `references/_shared/guardrails.md` 第四条从严控制。
2. 把素材逐条编号（素材1、素材2……），只用用户给的内容，不补充“通常做法”。
3. 选骨架：按材料类型取 `references/outline-templates.md` 中的骨架，再按单位类型调整板块。默认不设“背景和意义”一节。
4. 归类：每条素材放进一节。放不进任何一节的列为“未用素材”；某节没有素材支撑的，写【待补：需要的素材】，或建议删去该节。
5. 写要点：每节 2～4 条，每条一句话，注明素材编号，如“要点：胸痛患者绿色通道流程调整（素材3、7）”。要点只写“这一节写什么”，不写成段的正文；缺数据处写【待补：说明】。
6. 在每个一级标题后注明建议字数，合计不超过总篇幅。
7. 给总标题 1～3 个备选；小标题默认一套，按任务三的规则拟，用户要求时出 3 套。
8. 两类材料特殊处理（`references/_shared/guardrails.md` 第六条）：
   - 述职报告、对照检查、谈心谈话记录等需要本人经历的材料，用户没给个人事例时，每节只写“填写指引”（写哪类事、用什么数据、到哪里找），不替用户编事例。
   - 调研报告在调研完成前只出调研提纲（调研什么、问谁、看哪些数据），不出带结论的报告提纲；用户坚持要报告提纲的，“问题”“对策”两节只写【待补：调研发现】，不预设结论。

#### 任务五　标题与正文一致性检查

1. 抽出标题树：按顺序列出全部标题，标明层级，查序号是否连续、是否跳级、同级结构是否一致。
2. 逐节比对：先用一句话概括该标题下正文实际写了什么（只依据正文），再与标题对照：

| 判断 | 识别方法 | 级别 |
|---|---|---|
| 相符 | 标题关键词在正文都有对应事实，范围一致 | 不报 |
| 数字概括不符 | 总括数字与条数不等，或共用关键字缺失、错位 | P0 |
| 公文标题缺要素 | 缺文种、缺事由 | P0 |
| 大而无当 | 标题范围远大于正文；只有口号没有信息；用“显著”“全面”而正文没有数据 | P1 |
| 与正文脱节 | 标题关键词在正文找不到；正文写的是另一件事；标题内容出现在别的节 | P1 |
| 公文标题不规范 | “关于”误用、转发叠用、文种叠用、末尾加标点 | P1 |
| 格式错误 | 序号跳级、序号后标点错误 | P1 |
| 标题过窄 | 正文内容超出标题，后半节的事标题盖不住 | P2 |
| 交叉重叠 | 两个同级标题范围重叠，或同一件事在两节重复 | P2 |
| 结构不齐 | 同级标题句式、字数差别大 | P2 |

3. 每个问题写四行：“位置：”“问题：”（判断和级别）“依据：”（引正文原句或概括，说明为什么对不上）“改法：”（1～2 个改后标题）。只有补正文才能解决的，写明“正文需补充【待补：内容】”，交 gongwen-report 处理。
4. 最后给出修改后的完整标题树，便于用户对照替换。判定细则和示例见 `references/heading-rules.md` 第四部分。

### 第三步　自检与交付

按“自检清单”逐项核对后交付。本 skill 不带机检脚本，所有检查按清单人工完成，数字概括的条数核对写在“条数核对：”行里，便于用户复查。需要全文机检时转 gongwen-review。

## 输出规范

遵守 `references/_shared/style/output-format.md`，另加以下约定：

1. 标题行是可以直接复制进正文的纯文本：不加 Markdown 符号、不加引号、不在标题行里写括注说明。
2. 说明文字另起一行，用固定前缀：“适用：”“推荐：”“条数核对：”“要点：”“填写指引：”“位置：”“问题：”“依据：”“改法：”。
3. 多套方案依次写“方案一　对仗式”“方案二　递进式”“方案三　数字概括式”；按任务三第 2 条替换过的，按实际样式命名，如“方案三　动宾式”。一般材料每套给出全部一级标题，有二级标题的一并给出。总结类材料的固定一级标题保持规范名称，各套只给“主要工作”等部分下的二级标题；“存在的问题”“打算”下的二级标题只给一套，写在全部方案之后。
4. 全部内容之后单独一行写【起草说明】，按需写所作假设、待补事项、待核实事项、修改说明、保密提示；教学模式加“写作要点”。没有内容的部分省略。
5. Agent 工具环境：
   - 小标题方案（任务三）和一致性检查结果（任务五），以及任务一的批量改题结果、任务二的材料标题备选，写入 `公文/<YYYYMMDD>-<简短标题>/标题方案.md`。gongwen-report 成稿时从这个文件读取用户选定的方案。
   - 只有从素材搭提纲（任务四）时，才写同目录 `提纲.md`，内容是提纲、总标题备选和提纲中的一套小标题；用户要求小标题出多套方案的，多套方案写入 `标题方案.md`。目录里已有 `提纲.md`（如 gongwen-report 生成的）时，不另写提纲。
   - 同名文件已存在时加 `-v2`、`-v3`，不覆盖；写完在对话中给出推荐方案或问题摘要。只改一个公文标题的小任务直接在对话中回复，不建文件。
6. 网页对话环境直接输出，开头不加“以下是……”之类的引导语。路线还有下一站的（如回到 gongwen-report 成稿），在【起草说明】之后输出更新后的交接卡，告诉用户新开对话，先粘贴下一站的提示词文件，再粘贴交接卡和本站产出（`references/_shared/style/output-format.md` 第四部分）。

小标题方案的输出样式：

```text
方案一　对仗式
一、优化预检分诊，缩短候诊时间
二、打通院内通道，提高救治效率
三、加强梯队培训，提升急救能力
适用：科室在院内述职会上口头汇报，便于听众记住三块工作。

方案二　递进式
一、理顺分诊流程
二、打通救治通道
三、培养急救梯队
适用：按“基础、重点、保障”讲清工作逻辑；正文顺序不变。

方案三　数字概括式（三个加强）
一、加强分诊管理
二、加强通道建设
三、加强梯队培训
条数核对：总括“三个”，下列三条，对应正文第一至三部分，每条都以“加强”开头。
适用：……

推荐：方案一。理由：正文三部分是平行的三项做法，对仗式最贴合，字数也整齐。

【起草说明】
一、所作假设
1. 未说明材料用途，按院内述职汇报处理。
```

## 自检清单

- [ ] 公文标题三要素齐全，文种正确；只有一个“关于”；没有“的通知的通知”；末尾无标点；回行不拆词。
- [ ] 标题里的数字、成效、排名、提法都能在用户材料中找到出处，缺的标了【待补】或【待核实】。
- [ ] 每套方案同级结构一致、字数相近，对仗式同级各条字数相同。
- [ ] 三套方案取自五种样式；书面上报、数据多的业务报告和转译模式已换入动宾式或主题词式；推荐的是已给出的三套之一。
- [ ] 总结类固定一级标题保持规范名称；“存在的问题”“打算”下的二级标题只给了一套，并与正文对应。
- [ ] 数字概括式：总括数字、下级标题条数、正文分项数三者相等，共用关键字每条都有，已写“条数核对：”行。
- [ ] 每个标题都能在对应正文中找到依据，没有大而无当、与正文脱节的标题。
- [ ] 没有生造词和自造缩略语，没有 AI 腔和新八股堆砌，没有把白名单里的排比式小标题当问题改掉。
- [ ] 序号层级不跳级，序号后标点正确。
- [ ] 标题和提纲中没有真实姓名、病案号、学号等个人信息。
- [ ] 只出了标题和提纲要点，没有写成段的正文；需要正文时已指明转交的 skill。
- [ ] 标题行没有 Markdown 符号、免责声明和 AI 自述，说明都在固定前缀行或【起草说明】里。

## 角色适配

- 教学模式：先讲三要素或该样式的构造方法，修改逐条列“原标题、改后、理由”并附条款；提纲先出骨架请用户补素材，再细化要点；起草说明加“写作要点”，讲 2～3 个这类标题的常见失误。
- 高效模式：不解释，直接给 3 套方案和推荐；可一次处理多份材料的标题；领导偏好卡有小标题偏好的，按偏好排为方案一；起草说明只写假设、待补、待核实。
- 转译模式：接受业务原话和数据表，先把业务事项归成几块再起标题；标题保留准确的业务术语和指标名称（写“四级手术占比”，不写“高难度手术”）；三套方案中用动宾式或主题词式替换一套（通常替换数字概括式），一般推荐这一套（任务三第 2、3 条）；说明用业务人员听得懂的话。
- 审稿模式：不主动出新方案，直接做任务五，先给一页纸摘要（标题总体判断一句、主要问题 3～5 条），再给分级问题清单，每条一句改法；用户要求时再出替换方案。
- 严谨模式：标题中的政治性提法、上级数字提法只用用户提供的原文，没有原文的标【待核实：请对照最新原文】；不自创与上级提法形近的数字概括；起草说明末尾写“附：提法核对清单”（提法、出处、是否已对照原文）；有往年稿时提醒标题雷同；党建材料标题写出对业务的具体作用，不用空泛口号。

## 单位差异

单位类型来自单位画像或用户的话，默认党政机关。细则见 `references/unit-styles.md`。

| 单位类型 | 标题和提纲的调整 |
|---|---|
| 党政机关 | 党委、政府发文主体分清，标题中的发文机关不混用；小标题可用对仗，必须与正文对应 |
| 基层 | 短、实，先结论后做法；迎检汇报提纲按检查表逐项对应；信息标题写清主体、做法、效果 |
| 社区 | 面向居民的标题直白，写清事项和时间；少用对仗和数字概括 |
| 公立医院 | 分清党委、行政发文主体；小标题用规范指标名称；质量类报告多用主题词式 |
| 高校 | 分清校级、部门两级；学院总结按人才培养、学科建设等板块；学术材料用学术语言 |
| 中小学 | 按德育、教学、安全、后勤、家校协同组织；致家长材料标题亲切直白 |
| 国有企业 | 分清党委、公司发文主体；经营类材料指标在前；董事会议案标题按公司章程 |
