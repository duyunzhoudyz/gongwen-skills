# 督办清单

督办清单把纪要中的议定事项逐条列成表，供跟踪落实。只从纪要取内容，不新增事项、不改责任和时限。

## 一、列

| 序号 | 议定事项 | 纪要位置 | 责任单位 | 配合单位 | 完成时限 | 办理状态 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | 档案数字化外包，人事档案由档案室自行扫描 | 一、（一） | 档案室 | 信息中心 | 6月底前 | 待办理 |  |
| 2 | 摸清现有公务用车车况 | 三、（一） | 办公室 | | 【待补：完成时限】 | 待办理 | 暂缓事项下的准备任务 |

## 二、从纪要抽取

1. 一条议定事项含几项任务的，拆成几行，纪要位置相同；每行的责任单位、配合单位和时限跟着各自的任务走，不把两项任务的时限并进一行。
2. 进清单的：同意、原则同意、决定、明确了责任单位的“提交下次会议研究”，以及会议要求中写明单位和时限的任务（纪要位置写“会议要求第×条”）。
3. 暂缓、另行研究事项下有明确责任单位的准备任务（测算、补充材料、补充考察），单列一行，议定事项栏写纪要原话中的任务，如“摸清现有公务用车车况”，暂缓的事项本身不列。
4. 不进清单的：暂缓、不同意、另行研究且没有责任单位的、只是听取汇报的、未形成结论的。任职、审议通过等无需落实的结论，确需跟踪的才列，责任单位和时限不加【待补】。
5. 议定事项栏用纪要原句压缩，不加纪要没有的要求。责任单位、配合单位、时限逐字照纪要，牵头和配合不对调；纪要没写的，清单该格标【待补】。

## 三、办理状态

| 状态 | 认定 |
|---|---|
| 待办理 | 新建清单时的默认状态 |
| 推进中 | 用户提供了已开展的进展 |
| 已办结 | 用户提供了办结依据，如文件印发、系统上线、验收通过 |
| 申请延期 | 责任单位已提出延期，尚未批准 |
| 已延期 | 用户说明延期已批准，备注写新时限和批准依据 |

更新清单时只改用户提供了进展的行，其他行保持原状态；没报进展的不推定为没有开展。没有办结依据的不写已办结；“基本完成”“差不多了”写推进中，备注照录原话。超过时限仍未办结的，备注写“已超期”，不替责任单位解释原因。

## 四、转成 Excel 与对账

1. 有 Python 和 openpyxl 时运行 `python scripts/md2xlsx.py 督办清单.md 督办清单.xlsx --title "××会议议定事项督办清单"`。输出文件已存在时脚本自动加 -v2，不覆盖。未生成 xlsx 或报错的，交付 Markdown 表格，告诉用户复制到 Excel 中整理。
2. 对账：`python scripts/minutes_check.py 正文.txt --list 督办清单.md`，逐条核对清单与纪要的事项、责任单位、配合单位和时限；牵头与配合对调、时限挂到同一条中其他单位的任务上，都按不一致报出。不能运行时人工逐行比对，在起草说明写“未运行对账脚本，已人工核对”。
