# 会议纪要与议题材料（gongwen-minutes）

> 版本 1.0.0　成熟度：Beta（测试版）

帮办公室、院办、校办、董办的文字工作者处理会议前后的文字活，会前写上会议题材料，会后整理会议记录、起草纪要、列督办清单。它先把你给的转写稿或笔记拆成一张议定事项梳理表，每条结论都对上会上的原话，再成稿。会上没定的事不写成议定事项，没说的责任单位和时限不替你补。

## 能做什么

| 功能 | 说明 |
|---|---|
| 会议记录 | 按议程和发言顺序记全过程；发言人对不上的保留原标签并标出来，不同意见、表决结果照实记录 |
| 会议纪要 | 只记议定事项；分清“同意”“原则同意”“暂缓”“另行研究”；每条写明责任单位和时限，缺的标【待补】；党委会和行政会议分开 |
| 上会议题材料 | 议题名称、汇报单位、背景依据、方案比较、需决策事项、前置程序说明、附件；方案、数据和推荐意见只写你给的材料；核对“三重一大”、合法性审查等前置程序，有风险的写进起草说明 |
| 督办清单 | 从纪要逐条抽出事项、责任单位、时限，可转成 Excel；更新进展时只改有依据的行，没办完的不写成“已办结” |

## 可以这样说

1. “昨天院长办公会的录音我转成文字了，帮我出个纪要，再把定了的事列个督办清单。”
2. “局务会的转写稿整理成会议记录存档，谁说的要对得上。”
3. “下周校长办公会要研究学生公寓物业外包，属于三重一大，帮我把议题材料弄一下。”
4. “我刚到校办，第一次写纪要，会议指出、会议强调老分不清，你带着我弄。”
5. “这是上个月的督办清单，各科室报了进展，帮我更新一下。”

## 输入

- 必需：会议的文字材料。转写稿、手记、记录本内容、议程都可以，不用先整理。写议题材料时，给承办部门的情况说明、方案和测算、前置程序办到了哪一步。
- 最好说明：纪要是要印发执行还是存档；党委会还是行政会议；发给谁。没说的按默认处理，并在起草说明里写明。
- 可选：单位画像 `.gongwen/单位画像.md`、本单位议事规则、“三重一大”前置事项清单。
- 不支持：音频、视频。请先用单位允许的工具转成文字；涉密或敏感会议的录音不要用联网转写工具。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纪要正文（纯文本，可直接交给 gongwen-format 排成纪要格式） |
| `正文-会议记录.txt`、`正文-议题材料.txt` | 会议记录或议题材料 |
| `起草说明.md` | 所作假设、待补事项、待核实事项、未形成结论的事项、程序风险提示、保密提示 |
| `议定事项梳理表.md` | 每条结论的原话、位置、结论类型、责任单位、时限 |
| `督办清单.md`、`督办清单.xlsx` | 督办清单 |
| `原始记录.txt` | 你粘贴的记录，身份证号、手机号、病案号和群众姓名已换成代称，供对账用 |

在网页大模型里使用提示词版时，依次输出正文、起草说明，梳理表和督办清单附在起草说明末尾。

## 注意事项

1. **保密**：请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。带“内部资料”“工作秘密”等标识的记录会停止处理；患者、学生、群众的姓名和号码会改成代称；人事酝酿、未公开经营数据会先提醒你确认。
2. **只整理，不添加**：纪要里的每条结论都来自会上的原话。个人建议、没形成结论的讨论列在起草说明里，由你决定怎么处理。缺的标【待补】，存疑的标【待核实】。
3. **不补写、不倒签**：没有原始记录的会议，不能凭空补一份纪要或记录，也不能倒签日期；可以给你框架和需补充的内容清单。
4. **判断由你和汇报单位作**：议题材料的推荐方案、风险和合规意见只写汇报单位、审查部门给的，材料里没有的标【待补】，不替你选方案。发现前置程序没走完、“三重一大”准备事后补程序的，会在起草说明里写明依据和建议，是否上会由你和领导决定。
5. **正文不放表格**：纪要、议题材料的正文是纯文本，方案比较、前置程序用分项文字写；对照表放在起草说明的附表里。
6. **机检**：有 Python 时会运行 `scripts/minutes_check.py` 检查每条议定事项有没有责任单位和时限、督办清单与纪要是否一致（牵头和配合对调、时限挂错任务也会报出），`scripts/fact_diff.py` 核对纪要中的数字是否都来自记录，`scripts/gongwen_lint.py` 查标点格式；没有 Python 时按自检清单人工检查，并在起草说明中注明。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 会议通知；根据会议决定写请示、函、通知 | gongwen-draft |
| 会上的讲话稿、主持词 | gongwen-speech |
| 把会议写成新闻稿、政务信息 | gongwen-brief |
| “三会一课”记录，民主生活会、组织生活会的会议记录和材料 | gongwen-party |
| 把上级文件拆成任务分解表 | gongwen-implement |
| 整改台账 | gongwen-rectify |
| 纪要成稿后核标点、格式、提法 | gongwen-review |
| 排成纪要格式的 Word | gongwen-format |
| 医院党委会、院长办公会议题（装有行业包时） | gongwen-hospital |
| 国企“三重一大”议题、董事会议案、总经理办公会纪要（装有行业包时） | gongwen-soe |
| 中小学教研活动记录、安全教育记录（装有行业包时） | gongwen-k12 |

没有装行业包的，以上几类也由本 skill 处理。

能调用其他 skill 的环境直接调用；目标 skill 未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交：给交接卡、“新开对话粘贴 dist/prompts/<skill>.md 继续”的说明和安装命令。

一份办公会纪要的完整链路：gongwen-minutes 出纪要和督办清单 → gongwen-review 核稿 → gongwen-format 排成纪要格式。

## 成熟度

Beta。记录、纪要、议题材料、督办清单四项流程已可用；评测用例见 `evals/`。已知局限：
- 议定事项识别脚本按常见写法（“会议议定：”“会议同意……”“议定事项”标题）识别，写法特殊的纪要可能漏识别，结论仍以模型逐条对照记录为准；
- 各单位议事规则和前置事项清单差别大，前置程序核对以你提供的本单位制度为准；
- 董事会议案、决议按公司章程办理，本 skill 只整理内容，格式以章程为准。
