# 基层行业包（gongwen-grassroots）

> 版本 1.0.0　成熟度：Beta（测试版）

给乡镇（街道）、村（社区）工作人员用的行业包。它专写基层特有的文书：报给上级的政务信息，迎检时的汇报和自查，贴在单元门口的通知和倡议书，暴雨来临前发给各村的紧急通知，以及台账、走访提纲、为民办实事清单、村（居）务公开。

基层材料最容易出事的两个地方，它都会盯住：面向群众的文书里写了没有依据的罚款、断水断电、取消低保；报上去的数据和"已完成"在台账里找不到依据。你没给的事实一律标【待补】，存疑的标【待核实】，不替你编。

## 能做什么

| 文书 | 说明 |
|---|---|
| 政务信息 | 乡镇（街道）、村（社区）报上级的动态类、经验类、问题建议类信息。从你的台账里挑"新、特、实"的选题，按上级信息部门的采用导向写，给标题备选 |
| 迎检汇报与自查 | 按检查清单逐项写自查报告，出现场汇报稿和佐证材料目录；"已完成"必须有凭证，缺的材料如实写"缺"；素材撑不满汇报时长的不凑字，列出要补的素材 |
| 居民通知、告知书、倡议书、温馨提示 | 大白话，要素齐全，日期和星期逐个核对；同时出张贴版和群消息版；删掉越权的处罚和强制表述 |
| 防汛防火等应急通知 | 发给各村（社区）的工作部署型，发给居民的避险提示型；预警信息照原文转，不改级别 |
| 工作台账 | 设计表头、把记录整理成台账、台账体检、出脱敏的迎检展示版 |
| 网格走访记录提纲 | 走访提纲和空白记录表；把口述整理成规范记录 |
| 为民办实事清单 | 年初清单、年中年底完成情况报告、面向居民的公开版 |
| 村（居）务公开 | 事务、财务、名单公示的公开栏文本；核对公开期限（村（居）务公开不少于十五日，低保初审公示七日）和财务合计 |
| "一表通"和准入清单相关报告 | 清单执行情况、报表清理情况、清单外事项反映 |

## 可以这样说

1. "镇里搞了个积分超市，效果还行，帮我写篇信息报县里，争取被采用。"
2. "下周县安委办来检查安全生产，这是检查通知和我们的台账，帮我弄自查报告和十分钟的汇报。"
3. "社区下周二停水检修，帮我写个贴在单元门口的通知，再弄一条发业主群的。"
4. "楼道堆物太多了，想发个通知，不清理的罚款200，这么写行吗？"（会告诉你社区没有处罚权，并改成提醒和帮忙清理的写法）
5. "县气象台刚发了暴雨橙色预警，赶紧给各村发个防汛紧急通知。"

## 输入

- 必需：你手头的事实。台账、工作记录、检查通知、预警原文、财务明细、口头描述都可以，不用先整理。
- 最好说明：谁发（镇、街道、村还是社区）、发给谁、怎么发（张贴、群发、报送）。没说的按默认处理，并在起草说明里写明。
- 可选：单位画像 `.gongwen/单位画像.md`。没有画像也能用，最多问 3 个问题。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文，可直接用或交给 gongwen-format 排版 |
| `正文-群消息.txt` | 群消息版（居民文书、应急通知需要群发时） |
| `起草说明.md` | 所作假设、待补、待核实、删改了哪些越权表述、保密提示 |
| `素材台账.md` | 每个数据的来源（信息、迎检、实事报告） |
| `财务公开表.md` | 村（居）务公开的财务明细，张贴时作为附表打印 |
| 台账、清单、目录的 `.md` 表格 | 可转 Excel |

在网页大模型里使用提示词版时，依次输出正文和起草说明，群消息版、素材台账、财务公开表附在起草说明末尾。

## 注意事项

1. **保密**：请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。居民姓名、身份证号、电话、住址、病情会被提醒脱敏，稿中改用"张某""138****0000"。
2. **不越权**：居（村）委会没有行政执法权。面向群众的文书不写罚款、拘留、断水断电、取消低保、曝光；乡镇（街道）确有法定职权的，要你提供法律依据才写。
3. **不编造、不补记**：数据、完成情况、本地做法、下一步安排只用你提供的，没有的标【待补】；不补台账、不倒签、不代签，不编走访记录。检查要看的材料缺了，会帮你列出缺失清单，由你决定怎么说明。迎检汇报按时长换算的字数是上限，素材不够时不凑字。
4. **预警照原文**：防汛防火通知里的预警信息只照你给的原文转，不估算雨量、不改级别。
5. **法规版本**：修改后的《村民委员会组织法》、修订后的《城市居民委员会组织法》和《森林草原防灭火条例》都从 2026 年 1 月 1 日起施行，条号与旧版不同；本包按新版本写，引用前仍请对照当年文件。
6. **机检**：有 Python 时会运行 `scripts/gongwen_lint.py`（格式、法律表述、个人信息）和 `scripts/notice_check.py`（通知要素、日期星期、通俗程度、倡议书语气、公示期限、低保公示期、预警来源、已废止法规，以及村（社区）通知里常见的"取消分红资格""签责任书""不得进山"）。没有 Python 时按人工清单自检，并在起草说明注明。
7. **事实和判断由你负责**：它负责搭结构、守规矩、查错漏，发不发、怎么定调由你决定。

## 与其他 skill 的分工

本包只写基层专用文书。乡镇（街道）、村（社区）的通用文书交核心 skill，并读取同一份单位画像：

| 需求 | 用哪个 |
|---|---|
| 年度总结、计划、一般汇报材料、述职 | gongwen-report |
| 请示、函、会议通知、转发通知、通告 | gongwen-draft |
| 讲话、主持词 | gongwen-speech |
| 党建材料、组织生活会 | gongwen-party |
| 会议记录、纪要 | gongwen-minutes |
| 巡视巡察、审计、督查和检查反馈问题的整改（迎检前的自查在本包） | gongwen-rectify |
| 落实上级文件的实施方案 | gongwen-implement |
| 新闻稿、公众号推文；县（区）直部门报本部门工作的政务信息 | gongwen-brief |
| 报表合并、计算、图表 | gongwen-data |
| 核稿、排版 | gongwen-review、gongwen-format |

## 成熟度

Beta。9 类专用文书的模板、行业红线、核稿附加清单和 `notice_check.py` 已可用，评测用例见 `evals/`。行业包统一标 Beta，等基层测试者反馈后再升级。已知局限：

- 各地的信息考核办法、准入清单、防火期和汛期不同，本包不内置地方标准，需要你提供本地文件；
- `notice_check.py` 用规则判断要素和语气，标题不规范时类型可能推断错，可以用 `--kind` 指定（群消息版用 `--kind 群消息`）；强制表述只认常见写法，检索词清单仍要人工过一遍；
- 公示期限各地算法不一（首日计不计入），期限恰好卡在十五日、七日时脚本只作提示，以本地惯例为准；
- 表格转 Excel 需要 openpyxl，未安装时请把表格复制到 Excel。
