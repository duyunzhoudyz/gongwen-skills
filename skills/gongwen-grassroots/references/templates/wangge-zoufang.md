# 网格走访记录提纲

> 适用：网格员、包村（包片）干部、社区工作者入户走访前的提纲和记录表，以及把口述、手记整理成规范的走访记录。
> 不适用：编写没有发生过的走访记录；替居民填写意见或签名。
> 何时读：用户要走访提纲、记录表，或给了走访口述、手记要整理时。

## 一、本包对走访做什么

| 用户要的 | 做法 |
|---|---|
| 走访提纲 | 按第三部分出提纲；专项走访按第七部分增减 |
| 空白记录表 | 按第五部分出表，供打印或录入 |
| “我说说情况，你帮我整理成记录” | 按第六部分整理，只记用户说的 |
| “帮我写十份走访记录，检查要看” | 不写。走访记录必须来自真实走访。改为提供提纲和记录表，告诉用户走访后把情况发来再整理（`references/redlines.md` 第三条） |

## 二、走访前要明确的事

1. 走访目的：常规走访、独居老人关爱、汛前隐患排查、矛盾纠纷排查、人口信息变动核对、政策宣传。目的不同，提纲不同。
2. 走访对象清单：户别代号、楼栋或村民小组、上次走访遗留问题，来自用户。
3. 要告知的政策：只用用户提供的政策文件，没有的不在提纲里写政策内容。
4. 能当场办的事和要转办的事：哪些网格员能当场解决，哪些要报社区或镇（街道）。

## 三、提纲的通用结构

每部分给两三个问法，问法开放、不预设结论。

1. 开场：介绍自己和来意，出示工作证，说明记录用途，征得同意。
   - “您好，我是本网格的网格员，今天来了解一下家里最近有没有需要帮忙的事，大概十分钟。”
2. 核对变化：只核对与上次相比有没有变化，已经登记过的不再重复问。
   - “家里住的人和上次比有变化吗？”
3. 生活和需求：按走访目的展开。
   - “最近生活上有没有不方便的地方？”
4. 安全观察：边看边记，不翻动居民物品。燃气软管、电线、楼道堆物、电动自行车充电。
5. 诉求和矛盾：
   - “和邻居、物业之间有没有需要社区帮忙协调的事？”
6. 政策告知：只告知用户提供的政策，讲清找谁办。
7. 结束：留联系方式，说明诉求多久内回复（时限来自用户），约下次走访时间。

误（预设结论）：“您对社区今年的工作很满意吧？”“您觉得报表太多主要是哪些部门造成的？”
正（开放式）：“社区今年的哪些工作您觉得对您有帮助？哪些还需要改进？”

## 四、记录怎么写

1. 记事实，不记评价。
   - 误：该户思想觉悟低，不配合工作。
   - 正：户主表示白天上班，希望改在晚上7点以后登记。
2. 居民的诉求记原话，加引号。
3. 现场处理写清做了什么；转办写清转给谁、什么时候转的。
4. 承诺只在职权范围内，写清时限；超出职权的写“已记录，报社区研究”。
5. 个人信息只记完成工作所必需的。病情、宗教信仰、收入明细等敏感信息，与本次走访目的无关的不记（《个人信息保护法》第六条、第二十八条）。
6. 居民签字栏由居民本人签，不代签。

## 六、口述和手记的整理

1. 一次走访整理成一份记录，时间、地点、对象只用用户说的；没说的留空，标“待补”。
2. 用户说的情况如果是转述（“听邻居说……”），记录中写明是转述。
3. 口语改书面时不改原意，不加用户没说的处理结果。
4. 多户走访的，每户一份，或整理成走访台账（见 `taizhang.md`）。
5. 整理后提醒用户核对，确认无误后再入档。

## 七、专项走访提纲示例

（一）独居老人关爱
1. 最近身体怎么样？有没有按时吃药、复诊？（只问是否需要帮助，不追问病名）
2. 子女多久来看一次？有没有紧急联系人？紧急联系人电话是否有变化？
3. 买菜、做饭、就医有没有困难？需不需要助餐、上门服务？（服务项目来自用户）
4. 家里燃气、电器用起来有没有问题？

（二）汛前隐患排查
1. 房屋有没有漏雨、开裂、墙体倾斜？
2. 房前屋后有没有容易被冲走的物品、堵塞的排水沟？
3. 遇到强降雨，家里有没有人行动不便、需要提前转移？
4. 知不知道附近的安置点在哪里？（安置点来自用户）

（三）电动自行车充电安全
1. 电动自行车平时停在哪里、在哪里充电？
2. 有没有把电池拿回家充、在楼道充？
3. 小区充电桩够不够用、离家远不远？

## 八、常见毛病

1. 提纲预设结论，变成诱导式提问。
2. 记录写评价、贴标签。
3. 收集与走访目的无关的个人信息。
4. 一页记录几户，个人信息互相可见。
5. 代签名、事后补记录、按要求凑次数。
