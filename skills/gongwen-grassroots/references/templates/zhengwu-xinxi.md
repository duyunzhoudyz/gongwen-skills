# 基层政务信息（以采用为导向）

> 适用：乡镇（街道）、村（社区）向上级党委政府信息部门报送的政务信息，包括动态类、经验类、问题建议类，以及约稿和问题类专报。
> 不适用：县（区）直部门报本部门工作的政务信息，以及紧急信息、新闻稿、官方公众号推文、按期号编排的工作简报，交 gongwen-brief；长篇经验交流材料交 gongwen-report。
> 何时读：判定为政务信息后，选题前读第一至三部分，写作时读第四至七部分。

## 一、信息部门要什么

不少地方的信息部门按采用情况给报送单位计分。以某县政府办公室 2024 年三季度政务信息采用情况通报为例（出处记录在本项目仓库的借鉴记录中）：

1. 按采用刊物层级计分，层级越高分值越高，专期采用高于条目采用；
2. 被县级以上领导批示的另行加分；
3. 重要数据与事实有明显出入的扣分，明显重复、抄袭的扣分；
4. 同一信息被多级刊物采用，只记一次最高分；
5. 乡镇（街道）按月报送问题类专报课题，未按时报送扣分；通报还专门批评了反映成效、创新举措的动态信息质量不高。

各地计分办法不同，具体分值以本地信息工作考核办法为准，本包不写任何分值。

对写作的含义：
1. 上级信息部门要的是能用来掌握情况、辅助决策的信息：新做法、实效果、真问题。
2. 数据经得起核。数据失实是扣分项，也是减负规定和纪律的红线。
3. 问题建议类信息分量重，但问题必须是用户掌握的真实情况。
4. 同一件事不改头换面一稿多投，不拆成几篇凑数量。

《整治形式主义为基层减负若干规定》第8条规定不得将刊物和媒体刊发文章信息等作为督查检查考核内容。本包只借“采用导向”提高信息质量，不为凑积分编数据、拔高成效。

## 二、选题：从台账里找

从用户提供的近期工作台账、记录或数据表中找选题；用户只给了一两项事实的，照常首轮成稿，缺的标【待补】，起草说明待补一行说明补什么。选题来源：

| 来源 | 看什么 | 适合的类型 |
|---|---|---|
| 上级当前部署 | 本地落实中有没有具体、可复制的做法 | 经验类、动态类 |
| 基层首创 | 本地第一次做、别处少见的做法（来自用户描述） | 经验类 |
| 群众急难愁盼 | 一件具体民生问题怎么解决的，前后数据对比 | 动态类、经验类 |
| 苗头性问题 | 台账里反复出现、本级解决不了的问题 | 问题建议类 |
| 数据变化 | 某项数据明显上升或下降，原因清楚 | 动态类、问题建议类 |
| 季节性工作 | 防汛、防火、秋收、迎检中有特点的做法 | 动态类 |

选题三问，三问都答不上的，起草说明提醒用户采用可能性低，报不报由用户决定：
1. 新：上级信息部门以前没有采用过类似内容吗？本地是第一次做吗？
2. 特：和其他乡镇（街道）的做法有什么不同？
3. 实：有没有数据或具体事例？数据来自哪本台账？

高效模式另给 2 到 3 个选题备选，每个附一句“新在哪里、用哪些素材”；首轮按最有把握的一个成稿，用户改选的再写。

## 三、不报什么

1. 只是开了会、发了文、领导去了，没有实质做法和结果的。
2. 拍照、上传、点赞、转发数量之类的留痕数据（减负规定第8条、第14条）。
3. 还在计划中的写成已完成，试点写成全面推开。
4. 与上级已采用信息雷同、只换了地名的。
5. 涉及国家秘密、工作秘密，或未公开的人事、案件信息。
6. 含群众个人信息、未经同意的照片。

## 四、三类信息的结构

篇幅为工具约定，以本地信息部门要求和单位画像为准。用户没说类型时先数素材条数选类：素材只够动态类的，按动态类成稿，起草说明说明素材撑不起经验类并附不超过 3 条补料建议；用户要求经验类或升格的，保留经验类板块，缺的写【待补】，不注水。

### （一）动态类（300～600 字）

1. 标题：主体加动作加结果。
2. 导语一句：什么时间、谁、做了什么、结果如何。
3. 正文：做法两三点，每点带一个数据或事例，做法和数据都来自用户材料。
4. 不写下一步打算（用户要求且提供了安排的除外）。

### （二）经验类（600～1200 字）

1. 标题：可用主副标题，主标题概括做法和成效，副标题写主体和事项。
2. 导语：一两句写成效数据和做法概括。
3. 做法分 2 到 4 条，用“一是……二是……”或小标题；每条是“具体做法加数据或事例”。做法只写用户描述过的本地做法，不把上级部署当本地经验，凑不够 2 条的照实写 1 条，或标【待补：本地做法】。
4. 成效写在导语或末段，只用台账里的数据。
5. 不写背景意义，不写“在上级的正确领导下”。

### （三）问题建议类（800～1500 字）

1. 标题：直接点出问题，如“部分村级防汛物资储备不足需引起重视”。
2. 导语：问题是什么、涉及范围（几个村、多少户，来自台账）。
3. 表现：两三条，每条有数据或事例。
4. 原因：用户说明了的写，没有说明的不写原因，只写现象和数据，不替用户推断。
5. 建议：分“本级正在做的”和“需要上级支持的”，两部分都只用用户材料，没有的标【待补：本级已采取的措施】【待补：需要上级支持的事项】，不自拟措施。
   - 误：（用户只说了物资不足）我镇已建立物资动态补充机制，下一步将实现储备全覆盖。
   - 正：本级正在做的：【待补：本级已采取的措施】。需要上级支持的：【待补：需要上级支持的事项】。
6. 严谨处理：不点名具体个人，不写未经核实的传言；涉及上级部门的写“有关方面”或按用户原话。

## 五、标题

1. 写清主体和做法，成效判断要与正文数据相符。
2. 数字概括要与条数一致：“三招”下面就是三条。
3. 不用没有依据的评价：“走在全市前列”“成效显著”“全国首创”。确有依据的，依据来自用户并写进起草说明。
4. 主副标题之间用破折号或换行，副标题写主体和事项。
5. 高效模式给 3 个备选：平实式、主副标题式、问题导向式（问题建议类）。

误：某镇多措并举推动人居环境整治工作取得显著成效
正：某镇用“红黑榜”带动村民清理房前屋后，3个月清运垃圾1260吨
（“1260吨”来自台账；台账没有的，标题改用做法概括，不写吨数。）

## 六、数据写法

1. 每个数据写清统计期间和口径：“1至9月”“全镇15个村”。
2. 比较写清基准：“比去年同期”“比整治前”。
3. 增长率用百分比，比率的变化用百分点，按 `references/_shared/rules/data-expression.md` 和 `references/_shared/rules/gbt15835.md`。
4. 数据都要能在素材台账找到；算出来的算式写进台账，正文只写结果。
5. 原话是约数的（“一千多吨”），照写约数，起草说明“待核实”一行请用户核实准确数，不改成确数。

## 七、报送规范

1. 一事一报，一篇信息一个主题。
2. 时效、字数、报送渠道、报送单格式以本地信息部门要求为准。
3. 报送前经本单位领导审核（起草说明提醒）。
4. 附照片的，或对外发布、报上级党组织的，起草说明须提醒确认照片授权、群众原话同意使用，个人信息已脱敏。
5. 约稿按约稿要求的角度和篇幅写；素材不足的照实说明，不编。
6. 对外公开发布（政府网站、公众号）的，叠加严谨模式，提法核对后再发。

## 八、常见毛病与正误对照

| 毛病 | 误 | 正 |
|---|---|---|
| 开头铺垫 | 近年来，某镇深入贯彻落实上级决策部署，高度重视基层治理工作…… | 9月以来，某镇在15个村推行“有事好商量”议事会，已调处邻里纠纷38件。 |
| 概括代替数据 | 群众满意度大幅提升 | 回访的86户中，82户表示满意（来自回访台账）；台账没有的删去该句 |
| 会议流水账 | 镇党委召开专题会议，传达学习……，会议要求…… | 删去会议过程，只写会后做了什么、结果如何 |
| 拔高状态 | 全面建成村级议事会制度 | 15个村中已有11个建立议事会，其余4个计划年底前建立 |
| 问题空泛 | 部分群众参与积极性还不够高 | 9月召开的3场议事会，平均到会村民代表14人，不到应到人数的一半（来自会议签到台账） |

## 九、交付物

1. `正文.txt`：信息正文（标题加正文）。
2. `素材台账.md`：每个数据和事例的来源。
3. 起草说明只在对话中给出（不超过 5 行），选题理由并入假设；标题备选另起“附：标题备选”。
4. 用户要报多篇的，每篇一个文件：`正文-信息1.txt`、`正文-信息2.txt`。
