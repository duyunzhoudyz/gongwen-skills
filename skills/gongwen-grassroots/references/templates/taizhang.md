# 各类工作台账

> 适用：乡镇（街道）、村（社区）的工作台账：设计表头、把原始记录整理成台账、台账体检、出迎检展示版。
> 不适用：多张报表合并、同比环比等指标计算、生成图表，交 gongwen-data；整改台账交 gongwen-rectify；会议记录交 gongwen-minutes。
> 何时读：用户要建台账、整理记录或检查台账时。

## 一、本包对台账做什么

| 用户要的 | 做法 |
|---|---|
| “帮我设计一个××台账” | 按第二、三部分给表头和填写说明，字段从少 |
| “把这些记录整理成台账” | 按第四部分逐条登记，只整理用户给的记录 |
| “帮我看看台账有什么问题” | 按第五部分体检，出问题清单 |
| “迎检要用，帮我弄个能给检查组看的” | 出展示版，按第六部分脱敏 |
| “把台账补齐”“把漏记的补上” | 只能补用户确有原始记录的内容；没有原始记录的不补，见第七部分 |

台账是迎检和整改的事实依据。台账里写什么，汇报和自查报告就只能写什么。

## 二、常用台账的字段

字段只收完成工作所必需的。下表“不收”一栏是常见的过度收集。

| 台账 | 必要字段 | 不收或少收 |
|---|---|---|
| 入户走访台账 | 序号、走访日期、网格（楼栋）、户别代号、走访人、了解到的情况、诉求、处理情况、办结日期 | 身份证号、收入明细、宗教信仰（与事项无关的） |
| 矛盾纠纷排查调处台账 | 序号、受理日期、纠纷类型、当事方（张某与李某）、简要情况、调处措施、结果、回访日期 | 当事人详细住址、电话写入展示版 |
| 安全隐患排查整改台账 | 序号、排查日期、场所或部位、隐患描述、整改措施、责任人（职务）、整改时限、状态、销号日期 | 无关的经营者个人信息 |
| 特殊人群关爱台账（独居老人、困境儿童、残疾人） | 序号、户别代号、关爱类型、联系频次、最近一次联系日期、主要需求、帮扶措施 | 病名、残疾等级等，确有必要时只放工作版 |
| 为民办实事台账 | 见 `minsheng-shishi.md` | |
| 志愿服务台账 | 序号、日期、活动名称、地点、参与人数、服务时长、组织方 | 志愿者身份证号（另有平台登记的不重复收） |
| 会议活动台账 | 序号、日期、会议或活动名称、参加范围、主要内容、形成的决定 | 签到照片、学习笔记（不作为成效依据） |

## 三、设计原则

1. 最小必要：收集个人信息限于实现目的的最小范围，不得过度收集（《个人信息保护法》第六条）。医疗健康、行踪轨迹、不满十四周岁未成年人的信息属于敏感个人信息（同法第二十八条），确需记录的只放工作版，专人保管。
2. 一次采集、多方使用：同一类数据已在上级系统或“一表通”平台采集的，台账写“见某系统”，不再重复手工建账（国务院办公厅《基层报表数据“只报一次”工作指引》；减负规定第12条）。
3. 状态字段口径统一：已完成、正在办理、未启动、长期坚持，四种之外不新造。
4. 日期写实际发生日期，登记日期和办结日期分列。
5. 每行一事：一次走访一行，一起纠纷一行，不把几件事挤在一格。
6. 留“来源”列：写原始记录名称或页码，迎检时能对上。

## 四、从原始记录整理台账

1. 逐条读用户给的记录（工作日志、手写记录拍照转写、聊天记录摘录），一件事登记一行。
2. 原文没写的字段留空，表内写“待补”，起草说明汇总缺哪些字段、涉及几行。
3. 零值、无此事项、待核实分开写：本月没有发生的写“0”或“无”，记录不清的写“待核实”，不混用。
4. 原文是约数或口语的（“去了好几次”），照录原话并标“待核实”，不改成确数。
5. 日期只写原文有的；只写了“上周”“前几天”的，日期栏写“待核实”，来源栏照录原话（如“原话：上周”），不推算到具体日期。
6. 原文出现姓名、电话、住址的，工作版按用户要求保留或改代号，展示版一律脱敏。

## 五、台账体检

逐项检查，问题列入清单（列为：序号｜行号｜问题｜建议）：

| 检查项 | 怎么查 | 级别 |
|---|---|---|
| 必填项为空 | 逐列看 | P1 |
| 日期顺序 | 办结日期早于登记日期；回访日期早于调处日期 | P0 |
| 未来日期 | 记录日期晚于今天，有倒签或预填嫌疑 | P0，请用户核实 |
| 重复记录 | 同一日期、同一对象、同一事项出现两次 | P1 |
| 状态无凭证 | 写“已完成”但没有销号日期或凭证 | P1 |
| 汇总与明细不符 | 汇总行数字与明细加总不一致 | P0 |
| 个人信息 | 展示版出现身份证号、手机号、门牌、病情 | P0 |
| 口径 | 同一列混用“人”和“人次”、“户”和“人” | P1 |

数字核对要动手算，不凭感觉。体检只指出问题，不替用户改数据。

## 六、工作版和展示版

| 项目 | 工作版 | 展示版（迎检、上报） |
|---|---|---|
| 用途 | 内部办事 | 给检查组和上级看 |
| 个人信息 | 必要的保留，专人保管 | 姓名改“张某”，电话改“138****0000”，住址只到楼栋或村民小组 |
| 敏感信息 | 确需的保留 | 删去，或改为“已建档”之类的概括 |
| 文件名 | `台账-工作版.md` | `台账-展示版.md` |

## 七、红线

1. 不补记、不倒签：没有原始记录的走访、会议、活动，不生成台账行。
2. 不代签名、不代填群众意见和满意度。
3. 不把该做而没做的事写成已做。
4. 用户说“检查要看，先补上再说”的，说明这属于弄虚作假，可能被追责；改为帮其整理已有记录，并列出缺失清单，由用户决定如何向检查组说明。

## 八、正误对照

误（消防巡查要求每半月一次，用户只给了上半年 8 次巡查记录，要求“补齐”）：生成 12 行巡查记录，多出的 4 行日期和内容自拟。
正：按 8 次实际记录登记 8 行；起草说明写“按每半月一次的要求，上半年有 4 个半月没有巡查记录，已列出缺失时段，未补记”。

误：刘桂珍，女，86岁，身份证号××，住11号楼1单元302，患冠心病，电话138××××1111。（展示版）
正：刘某，11号楼，独居，每周电话联系一次，最近一次联系日期9月18日。（展示版）

## 九、交付物

1. `台账-工作版.md`、`台账-展示版.md`：Markdown 表格，有 Python 和 openpyxl 时可运行 `python scripts/md2xlsx.py 台账-展示版.md 台账-展示版.xlsx --title 台账名称` 转为 Excel（没有 openpyxl 或脚本报错时，提示用户把表格复制到 Excel）。
2. 起草说明只在对话中给出（不超过 5 行），体检问题清单附其后。
