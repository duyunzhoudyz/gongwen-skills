# 公立医院行业包（gongwen-hospital）

> 版本 1.0.0　成熟度：Beta（测试版）

给医院职能部门和临床科室主任用的专用文书助手。它先把你给的数据和记录整理成一份指标台账，再按模板搭结构、分段成稿。指标名称和口径跟国家文件一致，数值只用你给的，必须由你提供的缺了标【待补】；患者和不良事件当事医务人员的信息会脱敏。

## 能做什么

| 文书 | 说明 |
|---|---|
| 等级评审自评报告 | 按《三级医院评审标准（2025年版）》和本省细则，写前置要求自查、监测指标自评、数据质量核查和整改 |
| 绩效考核（绩效监测）自评分析 | 数据上报前的自评材料，或收到反馈后的结果分析：短板指标、失分原因、改进措施表 |
| 医疗质量分析报告 | 月度、季度、年度质量分析，先给结论，问题、原因、措施一一对应 |
| 不良事件根因分析（RCA） | 时间线、直接原因、促成因素、根本原因，改进措施标强弱；不写处分，不归咎个人 |
| PDCA 案例 | 质量改进项目的成果材料，前后同口径对比，目标达成率写算式 |
| 科室主任述职 | 分清科室成绩和本人作用，DRG、CMI 写明口径；现场述职的口头稿按时长（约 200 字/分钟）一并给出 |
| 党委会议、院长办公会议议题 | 方案比较、前置程序核对、可以直接表决的决定事项 |
| 医德医风和行风建设材料 | 九项准则落实情况自查、行风建设情况报告、医德考评方案和结果报告 |
| 院感与安全检查整改 | 整改方案、整改台账（可转 Excel）、整改情况报告，状态与台账一致，没有佐证的不算完成 |

也可以审这 8 类文书的成稿，比如“帮我看看质控科交上来的国考分析初稿”，它给一页纸摘要和行业问题清单，不重写全文；八关全面核稿用 gongwen-review。

## 可以这样说

1. “二季度质量分析报告月底要上质管会，数据表我贴给你，帮我写一下。”
2. “病区有个病人夜里自己把胃管拔了，护理部让我们做 RCA，上报单和谈话记录都在这。”
3. “国考结果下来了，四级手术和 CMI 都掉了，院长让写个分析，看看问题在哪。”
4. “我是呼吸科主任，明年1月要述职，科室数据有了，帮我搭个架子。”
5. “区卫健委安全检查提了6个问题，帮我出整改台账和整改报告。”

## 输入

- 必需：你手头的材料。数据表、上报单、访谈记录、检查反馈原文、科室报上来的情况都可以，不用先整理。
- 最好说明：写给谁（卫健委、质管会、院长办公会议、党委会议、考核组）、统计周期、依据版本（本省评审细则、当年绩效手册、本院议事规则）。没说的按默认处理，并在起草说明里写明。
- 交付节奏：第一轮就给提纲和正文，缺本省细则、缺数据的按默认结构成稿并标【待补】，要问的问题（最多 3 个）放在回复最后，不用等你确认再写。只有四种情况先给框架：述职、个人医德自评缺本人事例；只有题目、没有任何事实和数据；你明确要先看提纲；材料涉密（不处理）。指定了字数或时长而材料撑不起的，用工作性表述补足常规板块、不新增事实，起草说明说明哪几部分是常规表述。
- 可选：单位画像 `.gongwen/单位画像.md`、本院公文处理办法、往年同类材料。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文，可直接粘进 Word 或交给 gongwen-format 排版 |
| `起草说明.md` | 所作假设、待补事项、待核实事项、保密提示 |
| `素材台账.md` | 指标台账：每个数的统计周期、口径、来源系统和状态 |
| `提纲.md` | 提纲 |
| `整改台账.md`、`整改台账.xlsx` | 整改类材料的台账，有 Python 时自动转 Excel |

在网页大模型里使用提示词版时，依次输出正文、起草说明，台账放在起草说明末尾。

## 注意事项

1. **保密**：首次会在起草说明末尾提醒：涉密材料请勿输入联网 AI。标有“内部资料”“不得外传”的纪检通报、医疗纠纷材料会暂停处理。患者姓名、病案号、住院号、床号，以及当事医务人员的姓名、工号，请先删去；没删的会在稿中改成“患者张某”“当班护士甲”。
2. **不编数据**：指标值、排名、等级、标准值只用你提供的。系统生成的指标（国家监测指标、CMI、DRG 组数、满意度）不会替你计算。卫健绩效评价口径和医保结算口径分开写。已做的措施只用你给的；拟采取的措施按常规写，时限等你定的标待补，更多改进思路放在起草说明里供你取舍。
3. **有些结论必须由你确认**：评审“前置要求”是否发生、述职中本人做了什么、RCA 的事件经过，你没提供的，它只给框架和填写指引，不会替你写。
4. **不做的事**：不为提高指标建议调整病案首页编码；不在 RCA 报告中写处分；不写保证疗效、“国内领先”之类没有依据的话。
5. **机检**：有 Python 环境时，会运行通用机检 `scripts/gongwen_lint.py` 和行业机检 `scripts/hospital_check.py`（查疗效表述、党政联席会议决策、CMI 和百分点写法、不规范的指标名称、已废止的依据、RCA 归咎个人等）；没有 Python 时按人工清单检查，并在起草说明中注明。
6. **依据会更新**：评审标准、绩效手册、纠风工作要点每年或每几年调整。本包的依据核验于 2026 年 10 月，写材料时以你提供的当年文件为准。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 医院或科室年终总结、计划、汇报材料，院领导述职，职代会工作报告 | gongwen-report |
| 通知、请示、函、签报，就一件事的报告；本包材料需另附的请示或报送函 | gongwen-draft |
| 院长讲话、护士节和医师节讲话 | gongwen-speech |
| 党委会议、院长办公会议纪要 | gongwen-minutes |
| 党建工作报告、党课、对照检查材料、思想汇报 | gongwen-party |
| 依据上级文件制定本院实施方案 | gongwen-implement |
| 巡察、审计、医保飞检反馈问题的整改 | gongwen-rectify |
| 新闻稿、公众号推文 | gongwen-brief |
| 科室月报合并、指标计算、图表 | gongwen-data |
| 成稿全面核稿 / 排成国标 Word | gongwen-review / gongwen-format |

整改情况报告、九项准则自查报告这类“报告”由本包直接成文，不用再转 gongwen-draft。

能调用其他 skill 的工具里会直接调用；对应的核心 skill 没装或在网页版时，会给你交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令（见 `references/_shared/style/output-format.md` 第四部分）。

一份季度质量分析的完整链路：gongwen-data 合并科室数据 → gongwen-hospital 建台账、成稿 → gongwen-review 核稿 → gongwen-format 出 docx。

## 成熟度

Beta。8 类专用文书的模板、指标台账、行业机检和评测用例已完成（见 `evals/`）。v1.0 真实模型评测（Sonnet 5.5，16 条用例）中，A 组（装 skill）期望通过率 100.0%（135/135），编造 0 次，触发评测正例 10/10、反例 10/10，详见 `evals/results/v1.0-benchmark.md`。按决策 D7，行业包统一标 Beta，要等医院一线测试者反馈和人工盲评后再升级，条件见 `CONTRIBUTING.md` 的“成熟度从 Beta 升到 Stable”。已知局限：
- 各省评审实施细则、当年绩效手册的逐项公式、各院议事规则差异大，本包不内置，需要你提供原文；
- 行业机检只覆盖能写成规则的问题，数据是否属实、程序是否履行仍需人工核对；
- 中医医院的评审和绩效监测只给了依据名称，中医特色指标未单独适配。
