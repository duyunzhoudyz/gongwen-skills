# 不良事件根因分析（RCA）与 PDCA 案例

> 依据：《医疗质量管理办法》（国家卫生计生委令第10号）第三十四条（不良事件报告制度）、第四十七条（质量管理工具）；《患者安全专项行动方案（2023—2025年）》（国卫办医政发〔2023〕13号）第十条、第十二条（非惩罚性报告和患者安全文化）及附件2（不良事件分级分类标准）。改进措施分强弱的思路参考患者安全领域的 RCA² 方法（美国国家患者安全基金会，2015年），只用其思路。核验日期 2026-10-16。

## 一、用途与边界

1. RCA 报告：对已发生的不良事件（尤其是警告事件、有后果事件）追查系统原因，提出改进措施，报医疗质量与安全管理委员会或职能部门。
2. PDCA 案例：把一个质量改进项目整理成成果材料，用于评审佐证、院内交流、品管圈或质量改进竞赛。
3. 边界：
   - RCA 不是事故责任认定，也不是医疗纠纷处理意见。责任认定、处理处罚、与患方沟通的材料另按本院程序，不在本包写；
   - 向卫生健康行政部门报告事件经过和处置情况的那份报告，交 gongwen-draft；
   - 院内通报（表扬或批评）交 gongwen-draft。

## 二、RCA 报告结构

```text
关于某科室住院患者××事件的根本原因分析报告

一、事件概述
（发生时间、科室、事件类别、分级、患者结局；患者和当事人脱敏）

二、分析团队与方法
（团队成员写岗位：护理部、医务部、科室护士长、质控科等；方法：时间线、鱼骨图、5个为什么）

三、事件经过
（时间线：时间｜环节｜实际发生｜应当如何｜偏差）

四、原因分析
（一）直接原因
（二）促成因素（按人员、任务与流程、设备与信息系统、环境、沟通与交接、组织与管理分类）
（三）根本原因（系统层面，一般一到三条）

五、改进措施
（措施｜针对的根本原因｜强度类别｜牵头部门｜完成时限｜效果评价指标）

六、效果追踪计划
（看哪个指标、多长时间、谁负责）

附：时间线表、鱼骨图文字版
```

事件分级按国卫办医政发〔2023〕13号附件2（`references/glossary.md` 第四部分）；本院另有分级办法的按本院办法，起草说明写明用了哪一套。

## 三、RCA 写法要点

1. 事件经过只来自记录：不良事件上报单、护理记录和病历摘要、当事人访谈记录、监控或系统日志。记录没写到的时间点和动作，写【待补：××时的情况】，不按“一般流程”补全。
2. 时间线逐行写“实际发生”和“应当如何”，偏差在两者对比中自然显出，不加评价词。
3. 当事人一律用岗位代称：当班护士甲、值班医师乙、护工丙。不写姓名、工号、年龄、工作年限以外的个人信息；工作年限、资质与原因有关时才写。
4. 原因分三层：
   - 直接原因：事件发生前最后一个偏差，如“躁动患者的约束松脱后未被及时发现”；
   - 促成因素：让偏差更容易发生的条件，按六类归类，每条有记录依据；
   - 根本原因：消除后同类事件可以避免或明显减少的系统原因，如“夜间约束评估频次与在班人力不匹配”“护理系统没有约束评估到时提醒”。
5. 追问“为什么”，追到能采取系统措施为止。“未执行制度”“违反操作规程”通常是直接原因，要接着问为什么没执行：流程是否可行、人手是否够、系统有没有提醒或拦截、交接是否传递了风险（机检 HOS-019）。
6. 个人表现写成可观察的行为，不写品质评价：“护理记录中2时无约束评估记录”，不写“责任心不强”（机检 HOS-018）。
7. 改进措施标强度（工具约定，参考 RCA² 方法的思路）：
   - 强：改环境、设备或流程本身，让错误难以发生，如改造病房设施、系统强制拦截、统一设备型号或操作流程、简化流程；
   - 中：降低对记忆和注意力的依赖，或减轻工作负荷，如增加人手、调整排班、信息系统到时提醒、核查表、统一的交接工具；
   - 弱：靠人自觉，如双人核对、警示标识、修订制度、发通知、培训、警示教育。
   增加人手、调整排班一律算中，不算强。
   措施内容、牵头部门、时限只来自材料（SKILL.md 第四步第6条）：
   - 材料中的措施逐条照写并标强度；只有培训、发文等弱措施的，照写，起草说明提示“措施强度偏弱”；
   - 材料没有措施的，正文写【待补：针对根本原因X的改进措施、牵头部门和完成时限】；
   - 起草者想到的思路写进起草说明末尾“附：可供参考的改进思路”，按强、中、弱列出，每条根本原因至少一条强或中，由科室和职能部门取舍。
8. 正文措施写到牵头部门、完成时限、效果评价指标（如“下一季度本病区非计划拔管例次”“每百出院人次报告不良事件例数”）。材料没有的标【待补】。
9. 报告不写处分、扣绩效、通报批评（机检 HOS-020）。用户材料里有处理意见的，在起草说明中提示“处理意见另按程序办理，未写入本报告”。
10. 不用事后评价的口气：“显而易见”“本应很容易发现”一类的话删去。

## 四、PDCA 案例结构

```text
运用PDCA降低神经内科住院患者院内压力性损伤发生率

一、选题背景
（为什么选这个题：基线数据、与目标或标准的差距、相关的国家改进目标或评审条款）

二、计划（P）
（一）现状调查（基线期、基线值、问题构成）
（二）目标设定（目标值及依据）
（三）原因分析与要因确认
（四）对策拟定（对策、负责人、时间）

三、执行（D）
（对策实施情况：做了什么、何时、覆盖多少）

四、检查（C）
（改善前后对比：同口径、同时长；目标达成率、进步率）

五、处理（A）
（标准化：修订的制度和流程；遗留问题；下一轮计划）
```

## 五、PDCA 写法要点

1. 基线期和改善期用同一口径、同样长度，写明时段，如“基线期2026年1—3月”“改善期2026年5—7月”。
2. 目标值写依据（国家改进目标、评审标准、本院目标、文献数据，均由用户提供），没有依据的标【待补：目标值依据】。
3. 要因确认写依据（查检表、现场调查数据）；只有讨论意见、没有数据的，写“经小组讨论确定”，不写成“经调查确认”。
4. 效果计算写算式：目标达成率、进步率按 `references/data-rules.md` 第三部分；竞赛另有算法的按竞赛规则。
5. 不把同期其他因素带来的变化全部算作项目成效。用户材料提到同期有其他干预（如新入职护士、病区搬迁）的，在“检查”部分写明。
6. 改善期短（如不足3个月）的，不写“形成长效机制”，写“已修订××流程，持续监测”。
7. 成员写岗位或姓名按用户要求；用于院外交流时，确认成员同意署名。

## 六、数据项清单

| 文书 | 数据 | 一般来源 |
|---|---|---|
| RCA | 事件时间、地点、类别、分级、患者结局 | 不良事件上报单、病历摘要 |
| RCA | 时间线上的每个动作和时间点 | 护理记录、医嘱和给药记录、交接班记录 |
| RCA | 在班人力、患者数、重点观察患者数 | 排班表、护理部人力统计 |
| RCA | 系统提醒、拦截、操作日志 | 信息中心导出的系统日志 |
| RCA | 设备、设施、环境情况 | 设备科记录、现场查看记录或照片 |
| RCA | 当事人和相关人员的陈述 | 访谈记录（岗位代称） |
| RCA | 科室或职能部门已提出的改进措施 | 科室整改意见、护理部或医务部意见 |
| PDCA | 基线期和改善期的指标值、分子分母、时段 | 质控科、护理部、院感科的监测数据 |
| PDCA | 要因确认依据 | 查检表、现场调查记录 |
| PDCA | 对策实施记录 | 培训签到、流程修订文件、系统上线记录 |
| PDCA | 同期其他干预 | 人事、排班、病区调整记录 |

## 七、常见毛病与正误对照

例句中的科室、事件、数值、时间均为示意，起草时只用用户材料中的记录；记录没有的标【待补】。

1. 归咎个人。
   - 误：根本原因是当班护士责任心不强，未及时发现患者自行拔管。
   - 正：护理记录中2时无约束评估记录。当晚病区在班护士3名、患者40名，同时段有3名患者需要输液观察（排班表、护理记录）。根本原因：夜间约束评估频次的要求没有与在班人力匹配，护理系统也没有到时提醒。
2. 起草者自拟措施写进正文。（示意材料中的措施只有“组织全科学习管路固定流程”）
   - 误：正文写“留置胃管的躁动患者统一使用带防拔装置的约束手套，由护理部牵头，9月底前完成”。（措施、牵头部门、时限都是自拟的）
   - 正：正文写“全科培训管路固定流程（弱）；【待补：针对‘夜间约束评估频次与在班人力不匹配’的改进措施、牵头部门和完成时限】”。起草说明“附：可供参考的改进思路”写：留置胃管的躁动患者统一使用带防拔装置的约束手套（强）；护理系统对这类患者每2小时弹出约束评估提醒（中）；夜间高峰时段增加1名辅助护士（中）。
3. 时间线补全。
   - 误：2时，护士按规定完成约束评估。（记录中没有这一条）
   - 正：2时【待补：护理记录中无约束评估记录，请核实】。
4. PDCA 前后不同口径。
   - 误：改善前院内压力性损伤发生率为0.36%（全院口径），改善后为0.18%（神经内科口径）。
   - 正：神经内科住院患者院内压力性损伤发生率由基线期的0.36%降至改善期的0.18%，口径均为神经内科出院患者。

## 八、只出框架的情形

1. RCA 没有任何事件记录（上报单、病历摘要、访谈记录都没有），用户也说不出经过的（首轮交付情形②）：说明原因，交付 RCA 报告框架和资料收集清单（需要的记录、向谁要、访谈提纲），不写事件经过和原因。教学模式的写作要点写在回复末尾，含直接原因与根本原因的区别、非惩罚性原则、措施强中弱定义（第三部分第7条）。
2. 只有上报单、没有访谈记录的：事件概述和时间线中有记录的部分成稿，原因分析写成“待访谈后确认”的问题清单。
3. PDCA 没有基线数据或改善后数据的：选题、原因分析、对策、执行等有事实的部分成稿，成效部分写【待补：改善前后同口径数据】，不写成效；连项目做了什么都没有的，只出结构和数据收集表。

## 九、自检要点

- [ ] 事件经过每一条都有记录来源，没有按流程补全。
- [ ] 患者、当事人都已脱敏，当事人用岗位代称。
- [ ] 根本原因在系统层面，个人表现写成行为偏差。
- [ ] 正文措施只来自材料并标了强度，缺的标【待补】；起草说明的改进思路每条根本原因至少一条强或中。
- [ ] 报告中没有处分、扣绩效等处理内容。
- [ ] PDCA 前后同口径同时长，成效有算式。
- [ ] 有 Python 时运行 `python scripts/hospital_check.py 正文.txt --type RCA`（PDCA 用 `--type PDCA`）。
