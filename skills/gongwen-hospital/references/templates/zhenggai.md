## 二、整改方案结构

```text
某医院关于市卫生健康委医院感染管理专项检查反馈问题的整改方案

一、整改目标和组织
（目标、牵头院领导和部门，两三句）

二、问题和整改措施
（一）问题1：（反馈原文）
原因：
措施：
责任科室：　　责任人（岗位）：
完成时限：　　完成标准：
（二）问题2：……

三、督促检查
（谁检查、何时复查、怎样销号，一段）

附件：整改台账
```

问题多的（如超过 10 条），正文按类别归并写措施，逐条内容放整改台账。

## 三、整改台账

列为：序号｜问题（反馈原文）｜类别｜原因｜整改措施｜责任科室｜责任人（岗位）｜完成时限｜完成标准｜整改状态｜进展｜佐证材料

整改状态沿用 gongwen-rectify 的口径（其 `references/status.md`，下表为摘要）。状态只凭用户提供的进展和佐证认定，报告中的状态、数量、完成率一律从台账来。

| 状态 | 认定标准 | 计入完成数 |
|---|---|---|
| 已完成 | 措施全部落实，达到完成标准，有佐证材料；要求验收或销号的已通过 | 是 |
| 立行立改 | 检查期间，或收到反馈后、整改方案印发前已整改完毕，有佐证材料（如现场照片、更正后的记录） | 是，单列“其中立行立改 n 个” |
| 持续推进 | 措施已启动，没有全部落实或没有达到完成标准；写已做了什么、还差什么、预计何时完成 | 否 |
| 长期坚持 | 阶段性目标已达成、长效机制已建立，问题性质需要长期抓；有明确完成标准的具体问题不能记长期坚持 | 否，单列 |
| 未启动（临时） | 措施一项都没开始；写明原因和计划启动时间 | 否 |

判定顺序：措施一项没开始的记未启动 → 检查期间或方案印发前已改完、有佐证的记立行立改 → 措施全落实、达标、有佐证的记已完成 → 需要长期抓且阶段目标已达成的记长期坚持 → 其余记持续推进。

1. 整改方案阶段还没有进展的，各条默认记“未启动”；同时出方案和情况报告的，按用户给的进展逐条认定。
2. 开会、发文、部署、采购下单、安排培训，只算措施启动。计划在以后做的（如“下月安排培训”）、还在研究的，记未启动。
3. 没有佐证不算完成，与 gongwen-rectify 相同，不设例外：
   - 用户说清了具体整改动作、佐证还没附上的（如“当场上锁，已补登记”），记持续推进，进展栏写“已当场整改，佐证材料【待补：现场照片、补登记记录】”，起草说明列为“报送前须补齐的佐证”，并提示佐证补齐后可改记立行立改（或已完成）；
   - 用户只说“已整改完成”“已当场整改”，说不出做了什么的，同样记持续推进，进展栏写“已完成，佐证材料【待补：材料名称】”，并加【待核实：具体整改措施】。
4. “基本完成”“大部分完成”不是状态，按持续推进处理。
5. 完成数＝已完成＋立行立改；完成率＝完成数÷问题总数×100%，保留一位小数。长期坚持、未启动不计入完成数。

有 Python 时，用 `python scripts/md2xlsx.py 整改台账.md 整改台账.xlsx --title 整改台账` 转成 Excel；输出文件已存在时脚本自动加 -v2，不覆盖。

## 四、整改情况报告结构

```text
某医院关于医院感染管理专项检查反馈问题整改情况的报告

一、整改工作总体情况
（统计句：反馈问题n个，已完成整改n个（其中立行立改n个），持续推进n个，需长期坚持n个，尚未启动n个，整改完成率X%；各项之和等于问题总数）

二、问题整改情况
（逐条：问题原文、采取的措施、整改结果、佐证；状态与台账一致）

三、尚未完成的问题和下一步安排

附件：整改台账
```

整改情况报告是上行的“报告”文种，由本包直接成文；需要另附请示（如申请整改经费）或报送函的，那份请示或函交 gongwen-draft。

## 五、写法要点

例句中的科室、设备、日期均为示意，起草时只用用户材料中的事实。

1. 问题保持反馈原文，不弱化、不合并成更轻的说法。
   - 误：个别科室生物安全管理有待加强。（反馈原文为“检验科、病理科生物安全柜超过一年未检测”）
   - 正：检验科、病理科生物安全柜超过一年未检测（反馈原文）。
2. 原因只用材料：科室说明、检查记录、监测数据。材料没有的写【待补：原因分析】，不编“思想认识不到位”。
3. 措施写成能检查的动作，并写完成标准。措施内容、责任科室、时限只来自材料（科室说明、整改进展），缺的标【待补】；起草者想到的做法写进起草说明“附：可供参考的改进思路”。
   - 误：加强生物安全管理，提高安全意识。
   - 正：设备科委托有资质的机构检测检验科、病理科的生物安全柜，【待补：完成时限】；以取得检测合格报告为完成标准。（示意材料为“设备科已联系检测机构”；材料没有时限，标【待补】，不替医院定日期）
   - 材料只写“正在整改”的：措施写【待补：具体整改措施和责任科室】，不自拟。
4. 培训、开会、发文件本身不算整改完成，只能作为措施之一；状态为“已完成”的必须写结果和佐证。
5. 报告中的状态与台账逐条一致；用户材料只说“已部署”“已开会”的，状态写“持续推进”，不写“已完成”；佐证的处理见第三部分第3条。
6. 院感指标（如手卫生依从率、医院感染发病率）的定义和计算以国家院感质控指标文件为准；用户给的数没有分子分母的照用。
7. 涉及患者的院感病例描述脱敏；医院感染暴发等敏感事项写进对外材料前提示须经院感科和院办审核（`references/redlines.md` 第十条）。
8. 时限照材料写：材料给了具体日期的写具体日期；只给“月底前”等期限的保留原话，“下周三”等相对日期按今天推算；材料写的是触发条件的照写，如“新病区改造完工后一周内”。

## 六、数据项清单

| 数据 | 一般来源 |
|---|---|
| 反馈问题原文、检查日期、检查单位 | 检查反馈通知、反馈意见书 |
| 原因说明 | 被检查科室的书面说明、院感科或质控科分析 |
| 整改措施、责任科室、完成时限 | 院感科、质控科汇总的整改进展，院内整改部署文件 |
| 进展和佐证（照片、登记本、检测报告、培训签到和考核记录、采购和配送单） | 责任科室；院感科、设备科、人事科 |
| 院感监测数据（手卫生依从率、医院感染发病率） | 院感监测系统、院感科 |

## 七、常见毛病与正误对照

1. 弱化问题（见第五部分第1条）。
2. 状态升级。
   - 误：问题3：已整改完成。（材料只写“已召开专题会议部署”）
   - 正：问题3：持续推进。已于9月28日召开专题会议部署，【待补：具体措施的落实进度】，预计【待补：完成时间】完成。
3. 一个措施对多个不相干的问题，或问题与措施错位。
4. 报告与台账的条数、状态不一致。

## 八、只出框架的情形

用户没有提供反馈问题（原文和转述都没有）的：交付整改方案结构和空白台账，请用户补问题原文，不按“常见问题”预填。

## 九、自检要点

- [ ] 每个问题与反馈原文一致，没有弱化或合并。
- [ ] 每个问题都有原因、措施、责任科室、时限、完成标准。
- [ ] 状态只用四种口径加临时的“未启动”；“已完成”“立行立改”都有佐证；佐证没到位的记持续推进，佐证栏标【待补】并列入起草说明。
- [ ] 统计句各项之和等于问题总数，完成数只含已完成和立行立改。
- [ ] 报告与台账条数、状态逐条一致。
- [ ] 有 Python 时运行 `python scripts/hospital_check.py 正文.txt --type 整改`，台账用 `python scripts/md2xlsx.py` 转 Excel。
