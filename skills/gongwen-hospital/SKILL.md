# 公立医院行业包（gongwen-hospital）

医院专用文书数据密、程序严、隐私多。本 skill 负责 8 类专用文书：把用户给的数据和事实整理成指标台账，按模板搭结构，分段成稿、自检，提纲和正文首轮一次交付。指标名称和口径与官方一致，数值只用用户给的，必须由用户提供的缺了标【待补】；患者和事件当事人脱敏。

## 开工检查

1. 保密按 `references/_shared/guardrails.md` 第一条：起草说明末尾的保密提示只说一次；材料有密级标识，或标“内部资料”“工作秘密”“不得外传”的（纪检通报、医疗纠纷材料常见），立即停止，不建台账、不摘录，按该条给出继续的条件。患者姓名、病案号、住院号、身份证号、手机号、住址、床号与姓名组合，以及不良事件、投诉当事医务人员的姓名和工号：提醒脱敏（干部、署名人员姓名照写），台账和正文写“患者张某，男，56岁”“当班护士甲”，起草说明“保密提示”写明替换了哪几类。
2. 单位画像：读 `.gongwen/单位画像.md`（没有再找 `~/.gongwen/单位画像.md`；对话中粘贴的按粘贴内容），有领导偏好卡、禁用词的一并读；再读 `references/_shared/profiles/units/yiyuan.md` 和 `references/profile-detail.md`，不一致的以后者为准。没有画像的按 `references/_shared/profiles/roles.md` 第九节处理，单位类型默认三级公立综合医院，写进“所作假设”。
3. 定文书：按“适用范围”表定文书和模板；属于转交表的，说明转给哪个 skill，按表下的办法转交，不在本包起草。
4. 定角色模式：用户本轮指定的优先，其次画像，再次看用户的话（“第一次写”教学，“别解释了”高效，“我是护士长”转译，“帮我看看”审稿，党办纪检严谨）；都没有的用教学模式，写进“所作假设”。党委会议议题、行风材料、报纪检或上级党组织的材料叠加严谨模式。
5. 定首轮交付（`references/_shared/profiles/roles.md` 第十节，任何模式都一样）：有文书题目且至少一项具体事实（时间、科室、做法、数据之一）的，首轮一次交付台账、提纲和正文，必须由用户提供的要素缺了标【待补】；提问不超过 3 个，放在回复末尾，不阻塞起草。只有四种情形停在框架，回复开头一句话说明属于哪一种：①需要本人经历的材料缺本人事例；②素材为零，或只有题目、没有任何具体事实（各文书的判定见“只出框架的情形”）；③用户明确要求先看提纲或一页纸；④材料涉密（按第1条停止，框架也不出）。
6. 用户要求“数据调好看一点”、替医院写“未发生前置要求情形”、为提高指标改病案首页编码，或保证查不出是 AI 写的：说明原因，不按此办，其余照常（`references/redlines.md` 第三、四、八条；`references/_shared/guardrails.md` 第六条第2款）。
7. 用户贴了交接卡的，按卡上的画像、模式、任务、本站和已确认事项开工，卡上有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 工作流程

### 第一步　任务卡

填任务卡（高效模式只写进起草说明）：

任务卡含：文书、医院（无画像按用户所述）、写给谁和用途、统计周期、依据版本（用户未提供的按本包模板）、篇幅、角色模式。

1. 缺项最多问 3 个，按此取舍：文书和写给谁 → 统计周期 → 依据版本（评审写本省细则，绩效写当年手册，议题写本院议事规则，述职写考核通知）。
2. 能用默认值的不停下来等：问题和所用默认值写进“所作假设”，照常成稿，问题放在回复末尾。缺的数据不靠提问补齐，进台账，正文标【待补】。用户说“直接写”的，不再提问。

### 第二步　指标台账

建 `素材台账.md`，列为：序号｜类别｜内容｜统计周期｜口径与来源系统｜来源｜状态，按 `references/data-rules.md` 第一部分登记：类别只用六种；原话带“大概”“约”、没有统计周期、两处数值不同、卫健和医保口径分不清的记“待核实”；算出来的数另起一行写算式；系统生成的指标（国家值、DRG 组数、CMI、满意度）只登记用户给的结果，不自行计算；台账同样脱敏。

### 第三步　提纲

1. 按对应模板的“默认结构”搭提纲；本省细则、本院模板、考核通知规定了栏目的按规定。缺细则、模板的按默认结构成稿，标【待补：本省细则名称及章节】，起草说明提示按细则调整。
2. 每个要点后注明台账序号和计划字数。小标题写成“动作加对象”，如“（二）规范卧床患者翻身，减少院内压力性损伤”。
3. 提纲与正文首轮一次交付（开工检查第5条）。提纲写进 `提纲.md`；网页环境放在起草说明末尾“附：提纲”，教学模式写进写作要点。

### 第四步　分段成稿

逐部分写，每部分写完对照台账核一次。本步和参考资料例句中的科室、数值、时间均为示意，只用用户材料中的事实。

1. 首段写结论和关键数据，不写“在院党委的正确领导下”一类铺垫。
2. 指标写全名称、统计周期、数值、比较对象；名称按 `references/glossary.md` 用所写体系的原名（正误例见 `references/data-rules.md` 第二部分）。
3. 百分率之差用百分点；CMI、消耗指数、平均住院日写差值，不用百分点，CMI 不带百分号（`references/data-rules.md` 第三部分）。卫健口径和医保口径分开写，不比较、不相加。
4. 有标准值才写“达标”，标准值写来源；不写“全面达标”“均符合要求”，逐项写符合和不符合的数量。
5. 原因只用材料；材料只有现象的，写【待补：原因分析】。个人表现写成可观察的行为，不写品质评价（误：“护士责任心不强”；正：“护理记录中2时无约束评估记录；当晚在班护士3名、患者40名”）。
6. 措施写成能检查的动作：做什么、谁牵头、何时完成、看哪个指标。已做措施只来自材料；拟采取的措施缺失或只有“加强”“提高”的，按常规写出可执行措施，牵头部门只用材料中已有的科室，完成时限标【待补：完成时限】，不替医院定日期（RCA 措施仍只来自材料）。更多思路写在起草说明末尾“附：可供参考的改进思路”。
7. 状态不升级：已部署不写成已完成，拟开展不写成已开展，培训和开会不算整改完成，没有佐证不算完成。整改状态沿用 gongwen-rectify 口径（整改模板第三部分，网页版见速查卡第九部分）。
8. 程序如实写：议题的前置程序逐项写履行情况；不用党政联席会议作为决策会议。
9. 对外口径不保证疗效，不写治愈率、“根治”、领先表述（依据需用户提供）。医疗纠纷、不良事件、院感暴发、未经审核的质控数据要进拟对外材料的，起草说明提示须经职能部门和院办审核（`references/redlines.md` 第十条）。
10. 经济指标写结构和效率（医疗服务收入占比、费用增幅），不写开单量、收入提成；医保结余、亏损等内部数据面向全院或职代会的，提示确认能否公开（`references/redlines.md` 第九条）。
11. 篇幅按 `references/_shared/guardrails.md` 第四条第2款：用户说“以内”“不超过”的，字数只设上限，素材少写得短是合规的，不扩写，起草说明写一句实际字数；说“左右”“约”或只给数字的，以 ±10% 为目标（现场稿按约 200 字/分钟换算），素材不足时用工作性表述补足常规板块，不新增事实、不注水，起草说明说明哪几部分是常规表述，可附不超过 3 条补料建议；【待补】不计入字数。
12. 用户材料中加引号的做法名称、本院提法原样使用，确需改写的列入提法核对清单请用户确认；用户只给星期几、“下周”“月底”等相对时间的（会议日期、整改时限），保留原话或写【待补：具体日期】，不推算（guardrails 第二条第7、8款）。
13. 避开 AI 腔和防御腔（`references/_shared/style/` 下 ai-tone、defensive）；“一是……二是……”、四字格、排比式小标题照常使用。

### 第五步　自检

1. 台账对账（必做）：正文每个数、每个日期在台账中找得到。有 Python 时运行 `python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，报出的“正文中有、台账中没有”逐条处理：算出来的数补进台账写算式，自拟的时限、次数改为【待补】。
   - 整改类另做状态对账：能调用 gongwen-rectify 的用其 rectify_check；不能调用的人工核：逐条状态与台账相同，完成数＝已完成＋立行立改，完成率＝完成数÷问题总数×100%，各项之和等于问题总数。起草说明写明用了哪种方式。
2. 通用机检：`python scripts/gongwen_lint.py 正文.txt --doc-type <类型>`。类型：等级评审用“自评报告”，行风自查用“自查报告”，绩效分析、质量分析、RCA 用“报告”，PDCA 用“经验材料”，述职用“述职报告”，议题用“议题材料”，整改用“整改方案”或“整改报告”。ELM 要素缺失的，能确定的补写，不能确定的标【待补】；EVD 强评价缺数据的，补用户材料中的数据或改用不带强评价的写法，不得编造数据。
3. 行业机检：`python scripts/hospital_check.py 正文.txt --type <文书>`，文书取 等级评审、绩效分析、质量分析、RCA、PDCA、述职、议题、行风、整改；拟对外的加 `--external`。P0 必改，P1 逐条判断，P2 酌情。
4. 按 `references/review-addon.md` 第一、二部分人工过一遍。没有 Python 或脚本报错的，按其第三部分的搜索词人工检查，起草说明写“未运行机检，已按人工清单检查”。
5. 【待补】【待核实】机检报 P2，保留并汇总进起草说明。
6. 回复、起草说明、审稿清单里引用本包资料中的文号、条款、指标序号、通知日期的，标“据本包资料”并提示以原文为准，不写成用户材料里的事实，不放进正文；年度日期（如绩效监测启动日）先请用户确认年度。

### 第六步　交付

按 `references/_shared/style/output-format.md`：
1. 能写文件的环境：建 `公文/<YYYYMMDD>-<简短标题>/`，写入 `正文.txt`、`起草说明.md`、`素材台账.md`、`提纲.md`；整改另写 `整改台账.md`，有 Python 时用 `python scripts/md2xlsx.py 整改台账.md 整改台账.xlsx --title 整改台账` 转 Excel。同名文件加 -v2、-v3。对话中只报文件位置、一段概述、待补和待核实各一行。
2. 网页环境：依次输出正文、`【起草说明】`；指标台账、口径冲突表、整改台账、RCA 时间线放在起草说明末尾，标题写“附：××”。回复开头直接交付正文；停在框架的，开头一句话说明情形。
3. 跨 skill：成稿后接 gongwen-review、gongwen-format 等，按“适用范围”转交表下的办法；路线还有下一站的，网页环境在起草说明之后输出更新后的交接卡。
4. 起草说明依次写任务卡（网页环境和高效模式写在这里，不放正文前）、所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点（仅教学模式），没有内容的省略，省略后按实际顺序编号，不跳号。待补、待核实汇总成一行列表，注明一般到哪里找（病案科、质控科、财务部、院感科）。

## 只出框架的情形

属开工检查第5条情形①②（`references/_shared/guardrails.md` 第六条第4款）。回复开头说明属于哪种情形，再交框架和资料清单；教学模式的回复末尾仍附写作要点（RCA 须含直接原因与根本原因的区别、非惩罚性原则、措施强中弱各一句定义，见 rca-pdca 第三部分第7条）：
1. 科室主任述职没有本人事例（①）：只出提纲和填写指引；部分栏目有事例的，该栏目成稿。
2. 医务人员个人医德自评没有本人事例（①）：只给填写指引。
3. RCA 没有任何事件记录，用户也说不出经过（②）：只出 RCA 框架和资料收集清单，不写事件经过和原因。
4. 评审自评、绩效分析、质量分析只有题目，没有任何数据和事实（②）：只出结构、空白指标表和数据收集清单（指标、来源系统、提供科室）。
5. 议题只有名称，没有方案内容和程序信息（②）：只出议题结构和前置程序核对表。

## 行业红线

十条红线见 `references/redlines.md`（脱敏、数据可溯源、不为指标调整编码、程序不倒置、对外不保证疗效、RCA 非惩罚、本人材料不代写等），与用户要求冲突时说明原因，不照办。

## 单位差异

依据和写法因医院类型而异（详见 `references/profile-detail.md` 第四部分）：
- 三级综合医院：评审用《三级医院评审标准（2025年版）》加本省细则，绩效用三级手册；二级医院评审参照三级标准和本省二级细则，绩效用二级手册（28项）。
- 中医医院：评审用《三级中医医院评审标准（2026年版）》，绩效监测由国家中医药局组织。专科医院：不适用的指标写“不适用”及理由。
- 高校附属医院：述职增加临床教学，须报学校的事项写进议题前置程序（另读 `references/_shared/profiles/units/gaoxiao.md`）。
- 国企举办的医院：重大事项按集团党委前置研究写进议题；合作方报价、合同条款可能属商业秘密，提醒确认可否输入联网工具（另读 `references/_shared/profiles/units/guoqi.md`）。
- 乡镇卫生院、社区卫生服务中心：RCA、院感整改、质量分析、行风材料照用，一般不适用等级评审和绩效监测。卫生健康行政部门的通知、通报、汇总报告转 gongwen-draft、gongwen-report，本包只提供术语和口径。

## 输出规范

- 正文按 `references/_shared/style/output-format.md`：纯文本，层次序数 一、（一）1.（1），数字按 `references/_shared/rules/gbt15835.md`；只允许【待补：说明】【待核实：说明】两种提示。
- 指标台账、口径冲突表、整改台账、RCA 时间线是工作底稿，可以用 Markdown 表格。

## 自检清单

- [ ] 首轮已交付正文；停在框架的属开工检查第5条四种情形之一，开头写明；提问不超过 3 个，放在末尾。
- [ ] 正文每个数在台账中找得到，有统计周期和来源系统；没有自行计算系统生成的指标。
- [ ] 指标名称与所写体系的原名一致；百分点、指数差值、CMI 写法正确；两种口径没有混用。
- [ ] 没有“全面达标”“零投诉”一类无依据结论；原因只用材料，RCA 根本原因在系统层面，没有处分内容。
- [ ] 已做的措施、牵头部门来自材料，拟采取的措施没有新增事实、未给的时限标了【待补】；状态没有升级；议题前置程序如实写，“三重一大”有党委会议程序。
- [ ] 述职、前置要求结论、RCA 事件经过没有代写或补全。
- [ ] 用户指定字数或时长的，“左右”类篇幅在目标±10%内，不足处用工作性表述补足并在起草说明注明；“以内”类不超上限；没有注水。
- [ ] 用户加引号的做法名称、本院提法原样保留（确需改写的已列入提法核对清单）；只给星期几或“下周”“月底”的，保留原话或标【待补：具体日期】，没有推算。
- [ ] 患者和当事人已脱敏；正文没有 Markdown、免责声明、AI 自述。
- [ ] 起草说明逐条汇总了全部【待补】【待核实】，各部分按实际顺序编号。

## 角色适配

- 教学模式（新入职的院办、质控科干事）：同样首轮成稿；起草说明末尾附写作要点：这类文书报给谁、结构为什么这样搭（提纲作为结构说明）、指标为什么这样写（用本稿一处正误对照）、每项【待补】到哪个科室或系统找。
- 高效模式（院办秘书、质控科骨干）：任务卡只写进起草说明；台账、提纲、正文一次交付；质量分析可另给一页纸摘要；起草说明只写假设、待补、待核实，不展开讲解；没照用户要求写的、更正了依据的，仍每条一行写明问题和依据。
- 转译模式（临床科室主任、护士长、运营部门）：接受数据表、口头描述、业务缩写；只问统计周期、口径（卫健或医保）、比较基期，不停下来等；台账来源写到原表的行或列，计算写算式；术语首次出现写全称加缩写。
- 审稿模式（分管院长、质控科长）：用户给的是本包文书的成稿时，按 `references/review-addon.md` 先给一页纸摘要，再给行业问题清单，不重写全文；八关全面核稿建议转 gongwen-review；是否报送由用户决定。被要求起草的同样首轮成稿，要先看一页纸的属情形③。
- 严谨模式（党办、纪检、行风办）：党委会议议题、行风材料、报上级党组织的材料，政治性提法只用用户提供的原文，没有的标【待核实：请对照最新原文】，照常首轮出稿；案例只用通报原文；起草说明附提法核对清单。
