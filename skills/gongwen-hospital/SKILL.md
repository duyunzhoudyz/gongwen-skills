# 公立医院行业包（gongwen-hospital）

医院的专用文书数据密、程序严、隐私多：自评报告要经得起数据核查，RCA 要找系统原因，议题要走完前置程序，患者和当事医务人员的信息不能出现在稿子里。本 skill 负责 8 类专用文书：先把用户给的数据和事实整理成指标台账，按模板搭结构，再分段成稿、自检。指标名称和口径与官方一致，数值只用用户给的，缺的标【待补】。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户给材料时，或用户第一条消息就附了材料时，在本次回复开头附一句："请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。"同一会话只说一次。
   - 读材料前先扫：有密级标识，或标"内部资料""工作秘密""不得外传"等字样的（纪检通报、医疗纠纷材料常见），立即停止，不建台账、不摘录内容，请用户改用内网模型；用户删去相关内容，或说明标识系误加、材料已公开的，再继续。
   - 患者姓名、病案号、住院号、身份证号、手机号、住址、床号与姓名组合，以及不良事件、投诉、考评材料中的医务人员姓名和工号：提醒用户脱敏；台账和正文一律写"患者张某，男，56岁""当班护士甲"；起草说明"保密提示"写明替换了哪几类信息。
2. 单位画像：读 `.gongwen/单位画像.md`（没有再找 `~/.gongwen/单位画像.md`；用户粘贴在对话里的按粘贴内容），有领导偏好卡、禁用词的一并读取；再读 `references/_shared/profiles/units/yiyuan.md` 和 `references/profile-detail.md`，两者不一致的以后者为准。已知 yiyuan.md 仍写《三级医院评审标准（2022年版）》，该版已废止，一律按 2025 年版写；绩效监测的启动时间以国家年度通知为准。没有画像时按 `references/_shared/profiles/roles.md` 第九节处理，单位类型默认三级公立综合医院，写进"所作假设"。
3. 定文书：按"适用范围"表确定文书和模板。属于转交表的，说明转给哪个 skill；网页环境输出交接卡（见第六步第3条），不在本包起草。
4. 定角色模式：用户本轮指定的优先，其次是画像，再次看用户的话（"第一次写"教学，"别解释了"高效，"我是护士长"转译，"帮我看看"审稿，党办纪检严谨）；都没有的用教学模式，写进"所作假设"。党委会议议题、行风材料、报纪检或上级党组织的材料叠加严谨模式。
5. 查"只出框架的情形"，命中的先用一句话说明原因再交框架，不拒绝整个任务。
6. 用户要求"数据调好看一点"、替医院写"未发生前置要求情形"、为提高指标改病案首页编码，或要求保证查不出是 AI 写的：说明原因，不按此办，其余工作照常（数据、编码、前置要求见 `references/redlines.md` 第三、四、八条；规避 AI 检测见 `references/_shared/guardrails.md` 第六条第2款）。
7. 网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务、本站、已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 工作流程

### 第一步　任务卡

填任务卡给用户看（高效模式只写进起草说明）：

```text
任务卡
文书：2026年第二季度医疗质量分析报告
医院：三级公立综合医院（无画像，按用户所述）
写给谁、用途：医疗质量与安全管理委员会季度会议，书面报告
统计周期：2026年4—6月，同比
依据版本：本院质量分析报告格式（用户未提供，按本包模板）
篇幅：3000～5000字
角色模式：转译模式
```

1. 缺项最多问 3 个，按此顺序取舍：文书和写给谁 → 统计周期 → 依据版本（评审写本省细则，绩效写当年手册，议题写本院议事规则，述职写考核通知）。
2. 能用默认值的不停下来等回答（先交提纲的情形见第三步第3条）：把问题和所用默认值写进起草说明"所作假设"，照常成稿。只有判断不了写哪类文书、写给谁时，才以提问结束本轮。
3. 缺的数据不靠提问补齐，进台账，正文标【待补】。用户说"直接写"的，不再提问。

### 第二步　指标台账

把材料拆成一条一条，建 `素材台账.md`，列为：序号｜类别｜内容｜统计周期｜口径与来源系统｜来源｜状态（示例和细则见 `references/data-rules.md` 第一部分）。

1. 类别只用六种：指标、工作事项、案例、问题、下步打算、程序。
2. 原话带"大概""约"的，没有统计周期的，两处数值不同的，卫健口径和医保口径分不清的，记"待核实"。
3. 算出来的数另起一行，写算式和"由第几条计算"。国家监测指标的国家值、DRG 组数、CMI、满意度等系统生成的指标，只登记用户给的结果，不自行计算。
4. 台账同样脱敏。用户一条数据都没给的，按"只出框架的情形"处理。

### 第三步　提纲

1. 按对应模板的"默认结构"搭提纲；本省细则、本院模板、考核通知规定了栏目的，按规定。
2. 每个要点后注明台账序号和计划字数。小标题写成"动作加对象"，如"（二）规范卧床患者翻身，减少院内压力性损伤"。
3. 提纲何时确认（与 `references/_shared/profiles/roles.md` 一致）：
   - 先交任务卡和提纲，以提问结束本轮，确认后成稿：教学模式；审稿模式下被要求起草；连文书类型、写给谁都定不下来的。用户说"直接写""直接出稿"的，直接成稿。
   - 提纲与正文一次交付：高效、转译、严谨模式。缺本省细则、本院模板的，按模板默认结构成稿，标【待补：本省细则名称及章节】，起草说明提示按细则调整；缺数据的标【待补】，不因此停下。提纲写进 `提纲.md`，网页环境放在起草说明末尾"附：提纲"。

### 第四步　分段成稿

逐部分写，每写完一部分对照台账核一次。本步和参考资料例句中的科室、数值、时间均为示意，起草时只用用户材料中的事实。

1. 开门见山：首段写结论和关键数据，不写"在院党委的正确领导下"一类铺垫。
2. 指标写全名称、统计周期、数值、比较对象；名称按 `references/glossary.md` 用所写体系的原名（正误例见 `references/data-rules.md` 第二部分）。
3. 百分率之差用百分点；CMI、消耗指数、平均住院日写差值，不用百分点，CMI 不带百分号（`references/data-rules.md` 第三部分）。卫健口径和医保口径分开写，不比较、不相加。
4. 有标准值才写"达标"，标准值写来源；不写"全面达标""均符合要求"，逐项写符合和不符合的数量。
5. 原因只用材料；材料只有现象的，写【待补：原因分析】。个人表现写成可观察的行为，不写品质评价。
   - 误：当班护士责任心不强，导致患者自行拔除胃管。
   - 正：护理记录中2时无约束评估记录；当晚病区在班护士3名、患者40名（排班表）。
6. 措施写成能检查的动作：做什么、谁牵头、何时完成、看哪个指标。措施内容、牵头部门、时限只来自材料，缺的标【待补：牵头部门和完成时限】，不替医院定日期；材料只有"加强""提高"的，标【待补：具体措施】。本包自己想到的改进思路不进正文，写在起草说明末尾"附：可供参考的改进思路"，由用户取舍。
7. 状态不升级：已部署不写成已完成，拟开展不写成已开展，培训和开会不算整改完成，没有佐证不算完成。整改状态沿用 gongwen-rectify 口径（整改模板第三部分，网页版见速查卡第九部分）。
8. 程序如实写：议题的前置程序逐项写履行情况；不用党政联席会议作为决策会议。
9. 对外口径不保证疗效，不写治愈率、"根治"、领先表述（依据需用户提供）。医疗纠纷、不良事件、院感暴发、未经审核的质控数据要写进拟对外的材料的，起草说明提示须经职能部门和院办审核（`references/redlines.md` 第十条）。
10. 经济指标写结构和效率（医疗服务收入占比、费用增幅），不写开单量、收入提成；医保结余、亏损等内部数据面向全院或职代会的，提示用户确认能否公开（`references/redlines.md` 第九条）。
11. 避开 AI 腔和防御腔（`references/_shared/style/ai-tone.md`、`references/_shared/style/defensive.md`）；"一是……二是……"、四字格、排比式小标题照常使用。

### 第五步　自检

1. 台账对账（必做）：正文每个数、每个日期在台账中找得到。有 Python 时运行 `python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，输出的"正文中有、台账中没有"逐条处理：算出来的数补进台账并写算式；自拟的时限、次数改为【待补】。
   - 整改类另做状态对账：能调用 gongwen-rectify 的环境，用 gongwen-rectify 自带的对账脚本 rectify_check 核对报告与整改台账的状态、完成数、完成率。不能调用的人工核：报告逐条状态与台账相同；完成数＝已完成＋立行立改，完成率＝完成数÷问题总数×100%；统计句各项之和等于问题总数。起草说明写明用了哪种方式。
2. 通用机检：`python scripts/gongwen_lint.py 正文.txt --doc-type <类型>`。类型对照：等级评审自评、行风自查用"自查报告"，绩效分析、质量分析、RCA 用"报告"，PDCA 用"经验材料"，述职用"述职报告"，议题用"议题材料"，整改用"整改方案"或"整改报告"。扩充类型引擎只提示不报错。
3. 行业机检：`python scripts/hospital_check.py 正文.txt --type <文书>`，文书取 等级评审、绩效分析、质量分析、RCA、PDCA、述职、议题、行风、整改；材料要对外的加 `--external`。P0 必改，P1 逐条判断，P2 酌情处理。
4. 按 `references/review-addon.md` 第一、二部分人工过一遍。没有 Python 或脚本报错的，按该文件第三部分的搜索词人工检查，在起草说明写"未运行机检，已按人工清单检查"。
5. 【待补】【待核实】是正当产物，机检报 P2，保留并逐条汇总进起草说明。

### 第六步　交付

按 `references/_shared/style/output-format.md`：
1. 能写文件的环境：在当前工作目录建 `公文/<YYYYMMDD>-<简短标题>/`，写入 `正文.txt`、`起草说明.md`、`素材台账.md`、`提纲.md`；整改另写 `整改台账.md`，有 Python 时用 `python scripts/md2xlsx.py 整改台账.md 整改台账.xlsx --title 整改台账` 转 Excel。同名文件已存在时加 -v2、-v3，不覆盖。对话中只报文件位置、一段话概述、待补和待核实各几条。
2. 网页环境：依次输出正文、`【起草说明】`、说明内容；指标台账、口径冲突表、整改台账、RCA 时间线放在起草说明末尾，标题写"附：××"。正文前不加引导语。
3. 跨 skill：能调用其他 skill 的环境直接调用（如成稿后接 gongwen-review、gongwen-format）。网页环境在起草说明之后输出交接卡，告诉用户新开对话，先粘贴下一站的提示词文件（`dist/prompts/<skill 名>.md`），再粘贴交接卡和本站产出。交接卡只写任务信息，不抄患者和当事人信息。
4. 起草说明依次写所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点（仅教学模式）。待补、待核实逐条写明正文位置和一般到哪里找（病案科、质控科、财务部、院感科）。

## 只出框架的情形

依据 `references/_shared/guardrails.md` 第二条和第六条第4款。先说明原因，再交付框架和资料清单：
1. 科室主任述职没有本人事例：只出提纲和填写指引；部分栏目有事例的，该栏目成稿。
2. RCA 没有事件记录（上报单、病历摘要、访谈记录都没有）：只出 RCA 框架和资料收集清单，不写事件经过和原因。
3. 评审自评、绩效分析、质量分析没有任何数据：只出结构、空白指标表和数据收集清单（指标、来源系统、提供科室）。
4. 议题没有方案内容和程序信息：只出议题结构和前置程序核对表。
5. 医务人员个人的医德自评、思想汇报：只给填写指引。

## 行业红线

十条红线见 `references/redlines.md`，与用户要求冲突时说明原因，不照办。落实位置：
- 患者和当事人脱敏：开工检查第1条，第二步第4条，机检 privacy 类。
- 数据可溯源、不调和差异：第二步，第五步对账。不为指标调整编码：开工检查第6条。
- 程序不倒置："三重一大"上党委会议，第四步第8条，HOS-004、005。
- 对外不保证疗效：第四步第9条，HOS-001～003。RCA 非惩罚：第四步第5条，HOS-018～020。
- 本人材料、前置要求结论不代写："只出框架的情形"。廉洁表述：第四步第10条。敏感事项不对外：开工检查第1条，第四步第9条。

## 单位差异

医院类型不同，依据和写法不同（详见 `references/profile-detail.md` 第四部分）：

| 类型 | 调整 |
|---|---|
| 三级综合医院 | 评审用《三级医院评审标准（2025年版）》加本省细则；绩效用三级手册 |
| 二级医院 | 评审参照三级标准和本省二级细则；绩效用二级手册（28项） |
| 中医医院 | 评审用《三级中医医院评审标准（2026年版）》；绩效监测由国家中医药局组织 |
| 专科医院 | 不适用的指标写"不适用"及理由 |
| 高校附属医院 | 述职增加临床教学；须报学校的事项写进议题前置程序（另读 `references/_shared/profiles/units/gaoxiao.md`） |
| 国企举办的医院 | 重大事项按集团党委前置研究写进议题；合作方报价、合同条款提醒属商业秘密，确认可否输入联网工具（另读 `references/_shared/profiles/units/guoqi.md`） |
| 乡镇卫生院、社区卫生服务中心 | RCA、院感整改、质量分析、行风材料照用；一般不适用等级评审和绩效监测 |
| 卫生健康行政部门 | 写通知、通报、汇总报告的转 gongwen-draft、gongwen-report，本包只提供术语和口径 |

## 输出规范

- 正文按 `references/_shared/style/output-format.md`：纯文本，不用 Markdown，层次序数 一、（一）1.（1）；数字按 `references/_shared/rules/gbt15835.md`。
- 正文中只允许【待补：说明】和【待核实：说明】两种提示。
- 指标台账、口径冲突表、整改台账、RCA 时间线是工作底稿，可以用 Markdown 表格。

## 自检清单

- [ ] 正文每个数在台账中找得到，有统计周期和来源系统；没有自行计算系统生成的指标。
- [ ] 指标名称与所写体系的原名一致；百分点、指数差值、CMI 写法正确；两种口径没有混用。
- [ ] 没有"全面达标""零投诉"一类无依据结论；有标准值才写达标。
- [ ] 原因只用材料；RCA 根本原因在系统层面，没有处分内容。
- [ ] 措施、牵头部门、时限只来自材料，缺的标【待补】，自拟思路只在起草说明；状态没有升级。
- [ ] 议题前置程序如实写，涉及"三重一大"的有党委会议程序。
- [ ] 述职、前置要求结论、RCA 事件经过没有代写或补全。
- [ ] 患者和当事人已脱敏；正文没有 Markdown、免责声明、AI 自述。
- [ ] 起草说明逐条汇总了全部【待补】【待核实】。

有 Python 环境时运行：`python scripts/gongwen_lint.py 正文.txt --doc-type <类型>` 和 `python scripts/hospital_check.py 正文.txt --type <文书>`（取值见第五步）；无法运行时按第五步第4条人工检查。

## 角色适配

- 教学模式（新入职的院办、质控科干事）：先给任务卡和提纲，以提问结束本轮，确认后成稿；用户说"直接写""直接出稿"的直接成稿。起草说明末尾附写作要点：这类文书报给谁、结构为什么这样搭、指标为什么这样写（用本稿一处正误对照）、每项【待补】到哪个科室或系统找。
- 高效模式（院办秘书、质控科骨干）：任务卡只写进起草说明；台账、提纲、正文一次交付；质量分析可同时给正文和一页纸摘要；起草说明只写假设、待补、待核实。
- 转译模式（临床科室主任、护士长、运营部门）：接受数据表、口头描述、业务缩写；只问统计周期、口径（卫健或医保）、比较基期，问题写进"所作假设"，不停下来等；台账来源写到原表的行或列，计算写算式；术语首次出现写全称加缩写。
- 审稿模式（分管院长、质控科长）：用户给的是本包文书的成稿时，按 `references/review-addon.md` 先给一页纸摘要，再给行业问题清单，不重写全文；八关全面核稿建议转 gongwen-review；是否报送由用户决定。
- 严谨模式（党办、纪检、行风办）：党委会议议题、行风材料、报上级党组织的材料，政治性表述只用用户提供的原文，没有的标【待核实：请对照最新原文】；案例只用通报原文；起草说明附提法核对清单。
