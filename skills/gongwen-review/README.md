# 核稿审校（gongwen-review）

送签前帮你过一遍稿子。按“八关”（政治、政策、权限、法规、文风、文字、格式、程序）逐项检查，给出一份分级问题清单，P0 必须改，P1 建议改，P2 请你判断。每条都写明在哪、原文是什么、哪里不对、依据哪条规定、怎么改。

默认只提意见，不替你重写。你说“直接改”，它才按 P0、P1 改一版，并核对改动前后的数字、日期、文号等事实没有变。

## 能做什么

- 机检：发文字号、标题、主送、层次序号、标点、数字、日期、附件说明、版记，以及 Markdown 和 AI 话术残留、待补标记、篇幅，一次查完。规则依据 GB/T 9704、GB/T 15834、GB/T 15835 和《党政机关公文处理工作条例》，每条都标了条款号。
- 文种和行文规则：报告里夹带“妥否，请批示”、请示多头主送或主送领导个人、请示结尾写“特此报告”、先办后请。
- 保密和隐私：发现密级标识、“内部资料”字样会先停下来提醒你；身份证号、手机号、病案号、学号、住址等个人信息列为必改项，意见里一律脱敏。
- 提法风险：标出疑似过时或不规范的提法，请你对照原文确认，不擅自替换。
- 面向群众的文书：查有没有“罚款”“拘留”“断水断电”“取消低保”这类强制措施，提示核对法律依据和发文权限。
- 减负要求：首段铺垫背景意义、层层要报落实情况、一票否决、拍照留痕、纸质电子重复报送、按月排名、千分制。
- 单位专项：医院查患者隐私和指标口径，学校查学生隐私和“双减”，国企查前置研究和职代会程序，社区查强制性表述。
- 本单位禁用词：工作目录有 `.gongwen/禁用词.md`（可用 gongwen-profile 建立）时逐条比对，“禁用”的列为 P1 建议改，“慎用”的列为 P2 由你决定，依据写“本单位禁用词表”。没有这份表就跳过。

## 你可以这样说

1. “帮我把这个通知核一下，明天要送签。”
2. “下面科室报上来的总结，你帮我看看有什么问题，我只要清单。”
3. “这个请示有没有毛病？格式标点也帮我查查。”
4. “这篇讲话稿提法多，你从严把一下关。”
5. “按你的意见直接改一版吧，事实别动。”

## 与其他 skill 的分工

- 补写内容、重写结构的，交原起草 skill（gongwen-report、gongwen-draft、gongwen-speech 等）；压缩、扩写、调语气的，交 gongwen-polish。
- 通篇去 AI 腔交 gongwen-humanize；去免责和对冲交 gongwen-direct；排版、写成 Word 批注交 gongwen-format。
- 信息、新闻稿能不能报、能不能被采用，交 gongwen-brief 评估。
- 装有行业包时，行业专用文书只查行业问题的（如医院评审自评的指标口径）交对应行业包；八关全面核稿仍由本 skill 做。没装行业包的，按单位画像核稿。
- 能调用其他 skill 的环境直接调用；目标 skill 没装或在网页版里，会按 `references/_shared/style/output-format.md` 第四部分给你交接卡、“新开对话粘贴 `dist/prompts/<skill>.md` 继续”的说明和安装命令。

## 输入和输出

- 输入：稿件文字，或 .txt、.md、.docx 文件。有上级文件、会议精神原文的一并给出，政策和提法才能对照着查。稿件里单独一行的“【起草说明】”之后的内容不审。贴了总入口给的交接卡的，按卡上的模式和已确认事项开工，核完后给出下一站的交接卡。
- 输出：
  - `核稿意见.md`：总体评价（不超过 3 行）和分级问题清单表格。审稿模式另附一页纸摘要。
  - `核稿意见.json`：同样的问题清单，交给 gongwen-format 可以写成 Word 批注。
  - “直接改”时另有 `正文-核改.txt`：修改后全文和修改说明。数字、日期等的取值不动，汉字日期改阿拉伯数字这类写法规范照改，并在修改说明里写明。
- 在 Claude Code、Codex 等能写文件的工具里，文件放在 `公文/<日期>-<标题>/` 下；在网页对话里，直接在回复中给出。

## 注意事项

- 请勿输入涉密信息和内部敏感信息。材料涉密的，请使用单位内网部署的模型。
- 机检只覆盖能写成规则的项目；提法、口径、程序这些需要判断的地方由模型审读，最终以你的判断为准，是否签发由你决定。
- 提法只标记、不替换；上级文件没给的，政策关只列待确认事项，不会凭印象下结论。
- 医院、学校、国企的公文格式以本单位公文处理办法为准；在单位画像里写明后，核稿会按画像执行。
- 机检脚本需要 Python 3.9 及以上，读 .docx 需要 `pip install python-docx`。没有 Python 时，会按人工清单逐项检查。
- 已知局限：单段文字超过约 10 万字时机检耗时明显增加，真实公文不会出现。
- 行业附加检查：稿件是行业专用文书且装有对应行业包的，核稿时一并执行行业包的附加检查项，合并成一份清单；没装行业包的，只做八关，并提示可安装的行业包。
