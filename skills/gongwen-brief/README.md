# 信息简报与宣传（gongwen-brief）

> 版本 1.0.0　成熟度：Stable（稳定版）

帮信息员、宣传干事和兼职写稿人写政务信息、工作简报、新闻稿和单位官方公众号推文。它先把你给的材料拆成一份素材台账，挑一个“新、特、实”的角度，标题写出主体、做法和效果，开头第一句就是结论。数据和原话只用你给的，不编；对外发布的稿子会逐项核对图片授权和敏感信息。

## 能做什么

| 功能 | 说明 |
|---|---|
| 政务信息 | 动态类、经验类、问题建议类，以及突发事件的紧急信息（首报、续报） |
| 工作简报 | 按期号编排报头、各篇信息和报尾（报送范围），支持综合简报、专题简报、会议简报 |
| 新闻稿 | 会议新闻、活动新闻、工作成效报道，按倒金字塔写，六要素齐全 |
| 发布词 | 新闻发布会上宣读的发布词，按发布时长（约 200 字/分钟）定篇幅；答记者问口径只整理你提供的，不代拟 |
| 公众号推文 | 活动报道、服务告知、工作成效、人物，语言通俗，不写成自媒体腔 |
| 长材料提炼 | 把 3000 字的经验材料、总结压成 500～800 字的信息，数字一个不改 |
| 一稿多版 | 同一件事同时出报上级的信息、官网新闻稿、公众号推文，数据各版一致 |
| 评估稿件 | 看一篇信息能不能报：标题、导语、数据、篇幅、对外风险，给出分级问题和关键句改法 |

## 可以这样说

1. “昨天局里开了个现场推进会，这是我记的东西，帮我写条信息报区委办。”
2. “这篇经验材料3000多字，帮我压成800字的信息报市里。”
3. “医院周末搞了义诊，写篇新闻稿发官网。”（会提醒照片授权，不写疗效保证）
4. “社区助餐点开张了，发个公众号告诉老人怎么去吃饭。”
5. “下面报上来一篇信息，你帮我看看能不能被市里采用，别改全文。”

## 输入

- 必需：你手头的材料。活动记录、工作群里的流水账、统计表、经验材料、采访记录都可以，不用先整理。
- 最好说明：报给谁或发在哪里（上级信息部门、官网、公众号）、字数要求、事情发生的时间。没说的按默认处理，并在起草说明里写明。
- 有的话一并给：上级的约稿通知、往期简报（照它的报头和报送范围写）、采访记录（引语只用这里的原话）、照片的授权情况。
- 提供往期简报作格式参考时，先删去“内部资料”等标注和各篇正文，只保留报头、报尾样式；也可以直接描述报头格式。带“内部资料”标注发来的，它会停止处理。
- 可选：单位画像 `.gongwen/单位画像.md`。没有画像也能用。
- 材料里有具体事实的，第一轮就出稿；要问的最多 3 个，放在回复末尾，不耽误出稿。只有材料涉密、一条事实都没有，或你要求先看角度时，才先不写正文。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文，可直接粘进 Word、后台编辑器，或交给 gongwen-format 排版；多版输出时为 `正文-信息.txt`、`正文-新闻稿.txt`、`正文-推文.txt` |
| `素材台账.md` | 每条事实、数据、原话的内容、来源和状态 |

起草说明只在对话中给出（不超过 5 行；对外稿后附对外发布核对清单和图片清单），不写入文件。在网页大模型里使用提示词版时，依次输出正文、起草说明和素材台账。

## 注意事项

1. **保密**：涉密材料请勿输入联网 AI。材料带密级标识或“内部资料”等标注时会停止处理；出现患者、学生、居民的姓名和证件号时会提醒你脱敏。
2. **不编引语、不编数据**：群众和领导的原话只能来自你提供的材料。你要“加几句群众的话”而材料里没有，它不会替你编，只在起草说明里告诉你怎么采集。
3. **标题数字要对得上**：标题写“三项措施”，正文就得有三项；领导想要“五个一”而做法只有三条，它会说明原因，不会凑数。
4. **对外稿多一道核对**：新闻稿和推文会检查无依据的“全国领先”“首创”、医院的疗效保证、学校的升学率宣传、国企未公开的经营数据，以及照片是否取得本人或监护人同意。稿子交给你后，仍须按本单位规定审核后发布。
5. **做减法**：信息默认 500～800 字，不写背景铺垫，不凑字。你指定了字数而素材撑不起的，会用工作性表述补足常规部分，不新增事实，缺了稿子就不成立的缺项才标【待补】，一般不超过 3 处。
6. **提法和日期照原样**：材料里加引号的做法名称、本单位提法原样使用；你说“周五”等相对日期的，已知当天日期时推算为具体日期，“月底”等期限原样保留。
7. **机检**：有 Python 环境时会运行 `scripts/brief_check.py`（篇幅、标题数字和空词、引语和说话人溯源、导语、宣传用语、简报要素；医院稿加 `--unit 公立医院`，“根治欠薪”一类工作提法只作提示，“胃癌根治术”一类手术名称不报）和 `scripts/gongwen_lint.py`（标点、数字、隐私、AI 腔）；没有运行时按人工清单自检，并在起草说明中注明。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 1500 字以上的经验材料和书面经验交流材料、工作总结、汇报材料、宣传活动方案 | gongwen-report |
| 只缩短篇幅、文体不变 | gongwen-polish |
| 通知、通报，突发事件的正式情况报告 | gongwen-draft |
| 会议纪要、会议记录 | gongwen-minutes |
| 领导讲话稿、致辞、主持词，会上口头交流发言 | gongwen-speech |
| 乡镇（街道）、村（社区）报上级党委、政府信息部门的政务信息（装有行业包 gongwen-grassroots 时；没装的由本 skill 照写）。这类单位的紧急信息、简报、新闻稿、推文，以及县（区）直部门本部门的信息，仍由本 skill 写 | gongwen-grassroots |
| 只要标题方案 | gongwen-title |
| 已有稿子 AI 味重 | gongwen-humanize |
| 逐字核稿（标点、格式、提法） | gongwen-review |
| 排成 Word | gongwen-format |
| 不确定该写什么 | gongwen |

能调用其他 skill 的环境直接调用；目标 skill 未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交，同时给交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令。gongwen-grassroots 没装时不转交，由本 skill 照写。

一条信息的常见链路：gongwen-brief 建台账、成稿 → gongwen-review 核稿 → 报送。需要 Word 版简报的，成稿后交 gongwen-format 用简报版式排版（报头、多篇稿件、报尾，字段见该 skill 的 `references/meta-fields.md`）。

## 成熟度

Stable。v1.0 真实模型评测（Sonnet 5.5，16 条用例）中，A 组（装 skill）期望通过率 100.0%（128/128），编造 0 次，触发评测正例 10/10、反例 10/10，详见 `evals/results/v1.0-benchmark.md`。信息、简报、新闻稿和发布词、推文的结构、素材台账、对外核对和多版输出流程已可用；评测用例见 `evals/`。已知局限：
- 引语溯源按“去掉标点后逐字包含”比对，材料中原话写法有出入（如错字、口语省略）的，会报找不到，需要人工判断；说话人按引语在材料中出现位置前后的文字核对，采访记录里说话人写在开头、离原话较远的，会提示人工核对；
- 标题数字与条数的比对按“一、”“（一）”“一是”“1.”识别分项，做法写成自然段而没有序号时只给提示；
- gongwen-format 的简报版式是机关常见做法的默认样式（简报无国家标准格式），与本单位往期简报不一致的，核对后在 Word 中微调；
- 疗效保证按同一段落有没有医疗词语判断语境，医院稿件请加 `--unit 公立医院`；非医疗语境的“根治”“立竿见影”只作提示，需要人工确认是不是工作提法原文。
