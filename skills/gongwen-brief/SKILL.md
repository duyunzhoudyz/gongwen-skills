# 信息简报与宣传（gongwen-brief）

帮信息员、宣传干事和兼职写稿人写政务信息、简报、新闻稿、发布词和官方公众号推文。先建素材台账，按“新、特、实”选一个角度，标题点睛、开头即结论；数据和原话只用用户给的，缺的标【待补】，不编数据、不编引语；对外稿逐项核对授权和敏感信息。是否报送、发布由用户所在单位决定。

## 适用范围

- 适用：
  - 政务信息：动态类、经验类、问题建议类，突发事件的紧急信息（首报、续报）；
  - 工作简报、专题简报、会议简报，按期号格式编排；
  - 新闻稿：会议新闻、活动新闻、领导活动稿、工作成效报道；新闻发布会上发言人宣读的发布词和答问口径整理；
  - 单位官方公众号推文：活动报道、服务告知、工作成效、人物；
  - 从经验材料、总结、调研报告等长材料中提炼 500～800 字的经验做法信息；
  - 同一份素材出信息、新闻稿、推文几个版本；评估一篇信息、新闻稿能不能报、能不能被采用。
- 不适用（转交）：

| 用户要的 | 转给 |
|---|---|
| 1500 字以上的经验材料和书面经验交流材料，工作总结、汇报材料，宣传活动方案 | gongwen-report |
| 只缩短篇幅、文体不变（如把报告从 8000 字压到 3000 字） | gongwen-polish |
| 通知、通报，就一件事向上级报告的报告（含突发事件情况报告） | gongwen-draft |
| 会议纪要、会议记录 | gongwen-minutes |
| 领导讲话稿、致辞、主持词，会上口头交流发言 | gongwen-speech |
| 装有行业包 gongwen-grassroots 时：乡镇（街道）、村（社区）报上级党委、政府信息部门的政务信息。没装的由本 skill 照写；这类单位的紧急信息、简报、新闻稿、推文，以及县（区）直部门本部门的信息，仍由本 skill 写（`references/units.md` 第三部分） | gongwen-grassroots |
| 只要标题方案，不动正文 | gongwen-title |
| 已有稿子只改 AI 腔 | gongwen-humanize |
| 逐字核稿：标点、格式、提法按八关审 | gongwen-review |
| 排成 Word | gongwen-format |
| 报表合并、算同比环比 | gongwen-data |
| 说不清要写什么 | gongwen |

能调用其他 skill 的环境直接调用；目标 skill 未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交，同时给交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令。gongwen-grassroots 没装时不转交，本 skill 照写。用户同意的，可以先在本站建好素材台账，随交接卡带过去；交接卡不抄录原始材料和敏感信息。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户给材料时，或用户第一条消息就附了材料时，在起草说明末尾加一句保密提醒，同一会话只说一次。
   - 材料带密级标识，或标注“内部资料”“工作秘密”“不得外传”“内部使用”的，按第一条第2款立即停止，不建台账、不摘录、不转述。往期简报作格式参考、报头印有“内部资料”的同样停止，请用户删去标注和正文、只留报头报尾样式，或直接描述格式。
   - 出现身份证号、手机号、病案号、住院号、学号、家庭住址、患者或学生真实姓名的，提醒用户脱敏；台账和正文写“张某”“某患者”“138****0000”，起草说明“保密提示”写明已替换。对外稿连脱敏后的病情、成绩、救助情况也不写到能识别个人的程度。
2. 单位画像：先读 `.gongwen/单位画像.md`，没有再找 `~/.gongwen/单位画像.md`，用户贴在对话开头的按粘贴内容；有 `.gongwen/禁用词.md`、`领导偏好卡.md`、`文风参数.md` 的一并读取。再按单位类型读 `references/_shared/profiles/units/` 下对应文件和 `references/units.md` 对应小节。没有画像时按 `references/_shared/profiles/roles.md` 第九节推断和取默认值。
3. 按速查表定稿件类型。新闻稿、推文、门户网站稿、媒体供稿、标明对外印发的简报按对外处理，渠道不明的也按对外处理，写进“所作假设”。
4. 角色模式按 `references/_shared/profiles/roles.md` 第一节定，对外稿一律叠加严谨模式，差异见“角色适配”。
5. 守住辅助定位（`references/_shared/guardrails.md` 第二条、第六条），以下要求说明原因、不照做，其余工作照常：
   - “加几句群众夸我们的话”“给领导配句金句”“编个数据显得实在”：正文写【待补：某某原话，须本人同意引用】或【待补：数据】，起草说明写清怎么采集；
   - 人物稿没有本人事迹材料的：回复开头说明缺事迹，只出采访提纲和稿件框架，不编事迹、对话和心理活动；
   - “保证能被采用”“写得看不出是 AI 写的”：不承诺，按本 skill 的标准写；
   - 材料没有依据的“全国首创”“全市第一”：不写，或标【待核实：认定依据】。
6. 网页环境用户贴了交接卡的，按卡上的单位画像、模式、任务、本站和已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 稿件类型速查

| 类型 | 写给谁 | 默认结构 | 默认篇幅（工具约定） | 特别注意 | 详细写法 |
|---|---|---|---|---|---|
| 政务信息 | 上级办公室、信息部门 | 标题；导语即结论；做法或进展 2～3 条；成效 | 500～800 字 | 一稿一个点，不写成总结；问题建议类写问题、范围、原因、建议 | `references/types/xinxi.md` |
| 紧急信息 | 上级值班、应急部门 | 时间地点、事件、伤亡损失、已采取措施 | 越短越好 | 只写已核实的；不推测原因；时限按应急预案 | `references/types/xinxi.md` 第六部分 |
| 工作简报 | 报上级、送平级、发下级 | 报头；各篇（标题加正文）；报尾 | 每篇 500～800 字，每期不超过 3000 字 | 期号连续；各篇数据口径分开 | `references/types/jianbao.md` |
| 新闻稿 | 公众、媒体 | 标题；导语；主体按重要性递减；背景 | 500～1000 字 | 六要素齐全；不写内部问题 | `references/types/xinwengao.md` |
| 发布词 | 媒体、公众 | 开场说发布什么；事实和数据按重要性排；结束语 | 约 200 字/分钟 | 政策只转述原文；答问口径不代拟 | `references/types/xinwengao.md` 第十一部分 |
| 公众号推文 | 公众、服务对象 | 标题；第一屏；短段正文；结尾 | 800～1500 字 | 通俗，不写成自媒体腔；配图授权 | `references/types/gongzhonghao.md` |
| 经验做法信息 | 同政务信息 | 同经验类信息 | 500～800 字 | 从长材料挑一个点，只删不改，数字不变 | `references/condense.md` |

用户、画像或上级信息部门指定了字数、时长的，按指定，以±10%为目标，素材撑不起时按第五步第9条处理；“不超过/以内N字”是上限，素材只够写短的不算差距，不触发第五步第9条，起草说明一句话写明；没有指定的，按速查表，素材少可以写短。

## 工作流程

### 第一步　任务卡

先填任务卡，与稿件同一轮交付，不停下来等确认（高效模式不单独展示，只写进起草说明）：

```text
任务卡
稿件类型：政务信息（经验类）
写给谁：区委办信息科
发布渠道：内部报送
篇幅：600 字以内
事件时间：10月12日
单位画像：党政机关（区城管局，无画像，按用户所述）
角色模式：转译模式
```

1. 首轮交付按 `references/_shared/profiles/roles.md` 第十节：有题目，并且至少有一项具体事实（时间、主体、做法、数据之一）的，首轮就成稿，缺的标【待补】。只有四种情形停下，并在回复开头说明属于哪一种：缺本人事例；素材为零或只有题目；用户明确要求先看提纲或角度；材料涉密（提纲也不出）。
2. 提问不超过 3 个，连同无画像降级的问题合并计数，放在回复末尾，不阻塞起草。按此顺序取舍：稿件类型和渠道 → 篇幅要求 → 事件时间（材料里没有时）。单位类型、写给谁、角色模式能推断的不问，推断不出的取第九节默认值，写进“所作假设”。缺的数据、原话不靠提问补齐，正文标【待补】。
3. 用户说“直接写”“不用问了”的，不再提问，按默认值处理，写进“所作假设”。
4. 转译模式只问业务事实（时间、地点、谁参加、多少人、数据口径），不问“动态类还是经验类”这类术语。

### 第二步　素材台账

把材料拆成一条一条，整理成 `素材台账.md`，格式和规则见 `references/ledger.md`：

| 序号 | 类别 | 内容 | 来源 | 状态 |
|---|---|---|---|---|
| 1 | 数据 | 7—9月12个试点小区分类准确率由62%提高到85% | 《垃圾分类工作总结》第二部分 | 已确认 |
| 2 | 引语 | 居民王某：“早上倒垃圾有人指导，分得清了。” | 《入户走访记录》第5条 | 已确认 |

1. 类别只用七种：要素、做法、数据、成效、引语、问题、计划。来源写到文件名和段落，或写“用户消息”。正文换了说法的数（如台账“4月、7月各培训一次”，正文写“两次”），在内容栏补上正文的说法。由台账数据算出的比率、增幅、差值另起一行，内容栏写明算式（如“办结率98.1%，1790÷1824”），来源写“由第 3、5 条计算”。
2. 带“大概”“约”“多”的数字，没有时段或口径的数据，几份材料说法不一的，没有认定依据的“首创”“第一”，记“待核实”。待核实数字入稿时保留原说法（如“2公里多”）加【待核实】，不改成确数，不关键的可删并在起草说明列明。
3. 用户一条素材都没给、只有题目的（第十节情形②），回复开头说明，不起草正文，交付稿件框架和补料清单：时间、地点、主体、做了什么、数据、群众反馈或原话、照片情况。用户坚持要稿的，出框架稿，事实位置全部标【待补】。

### 第三步　选角度

1. 按“新、特、实”过一遍台账：事情新不新，做法有没有本单位特点，有没有数据和事例（`references/types/xinxi.md` 第二部分）。
2. 一稿一个点。材料是长篇经验材料、总结、调研报告的，按 `references/condense.md` 五步法挑点、删减。
3. 各模式都直接选推荐角度成稿，其他可选角度（每个一句话写依据的材料段落和数据）写进起草说明；教学模式写进“写作要点”并讲清取舍理由。用户明确要求先看角度的（第十节情形③），只交角度、标题和导语。
4. 三条都不满足的，照常成稿，在起草说明中如实写明采用可能性低，列出补哪些材料能改善，不靠拔高语气弥补。
5. 选题贴近上级关注点的，关注点只来自用户提供的约稿通知、领导批示、上级文件，不自行联系“上级重点工作”。

### 第四步　标题和导语

1. 标题一句话写出主体、做法、效果，有数据放数据；没有成效数据的（会议、刚启动的工作），标题写主体和做法或进展，不为标题补效果，含主体加做法或进展即可。不用“多措并举”“扎实推进”“取得明显成效”一类空词。
   - 误：某街道多措并举扎实推进垃圾分类工作
   - 正：某街道试行定时定点投放　12个小区分类准确率由62%提高到85%
   - 无成效数据的正：某镇召开人居环境整治现场推进会　要求年底前完成全部村验收；某区局对辖区食品经营户实行红黄绿三色分级管理
   - 以上示例的单位、数字均为虚构，不得带入正文。
2. 可以用主副标题，副题用破折号引出、另起一行。
3. 数字概括（“三项措施”“‘两张清单’”）的数目必须与正文分项条数一致；做法只有两条就写两条，不为凑整数补写做法。
4. 新闻稿标题写最重要的事实；推文标题写清和读者的关系，不做标题党。
5. 导语第一句就是结论：时间、主体、做了什么、效果。不用“为深入贯彻……”“随着……”“在……的正确领导下”开头。
   - 误：为深入贯彻落实市委部署，进一步提升人居环境水平，近日，某街道多措并举……
   - 正：今年7月以来，某街道在12个小区试行定时定点投放，生活垃圾分类准确率由62%提高到85%。
6. 标题给 2 套（高效模式 3 套），只要标题方案、要对仗式多套比较的，建议转 gongwen-title。

### 第五步　成稿

1. 每条做法按“动作、具体内容、数据或事例”写，一条一个意思。台账没有数据的，写【待补：说明】或不配数据，不改写成“大幅提升”“成效明显”。
2. 做法、作用、成效分开：系统上线、制度出台、会议召开只写已完成；有运行数据或反馈才写成效；计划写“将”“拟”，试点写“试点”（`references/ledger.md` 第四部分）。
3. 限定条件不丢：统计时段、范围、口径、基期照写；一个社区的做法不写成“全区”；比率变化用“百分点”（`references/_shared/rules/data-expression.md`）。用户只给“上周五”“月底”等相对时间的，保留原话或标【待补：具体日期】，不推算日期。
4. 原话只来自材料，照录不改字，可以节选连续的一段，交代说话人身份；转述不加引号。领导讲话的直接引语只用审定稿或用户提供的原文；内部稿转述讲话要点可以用会议记录，只写记录中有的并注明来源；对外稿转述只用审定稿或会议通稿（`references/ledger.md` 第三部分）。用户材料中加引号的做法名称、本单位提法原样照写。
5. 主办、承办、协办、参与照材料写；发稿单位的视角不等于补写“由我局主办”一类事实。
6. 宣传性评价放在事实和数字之后，一篇最多一处；没有依据的“领先”“首创”“第一”“唯一”不写。
7. 开门见山，不写形势背景和意义；结尾停在最后一个事实或下一步安排上，不写“让我们携手……”。
8. 避开 AI 腔和防御腔：不写“值得注意的是”“不是……而是……”、提示性冒号、“仅供参考”；“一是……二是……”、四字格照常使用（`references/_shared/style/ai-tone.md` 第三部分“信息（简报）”、`references/_shared/style/defensive.md`）。
9. 篇幅：用户、画像或上级指定了字数、时长的（发布词按约 200 字/分钟换算），按 `references/_shared/guardrails.md` 第四条第2款：素材不足时用工作性表述补足做法、意义、下一步等常规部分，不新增数字、事例、原话等事实，起草说明一句话说明哪几部分是常规表述，可附不超过 3 条补料建议（前后对比数据、具体事例、原话等）；必须由用户提供的缺项写【待补：该补什么】，不注水，【待补】不计入字数。超了按“铺垫、复述、空泛表态、重复举例”的顺序删。
10. 分类型写法按速查表最后一列的文件写；网页版读不到 `references/types/` 下文件的，按 `references/type-cards.md` 写。紧急信息只写已核实的，材料写明正在调查的才写“原因正在调查”，没写的不写原因或标【待核实：原因】，不写责任认定。

### 第六步　对外发布核对（对外稿必做）

按 `references/external-check.md` 第二部分 11 项逐项核对，结果写成起草说明末尾的“附：对外发布核对清单”；有照片的另列图片清单。起草说明“保密提示”中写明“本稿须按本单位规定履行审核程序后发布”。

### 第七步　自检与机检

1. 台账对账（必做）：正文每个数字、每句原话在台账中找出处。有 Python 环境时运行 `python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，“正文中有、台账中没有”的逐条补出处或改为【待补】。
2. 专项检查：`python scripts/brief_check.py 正文.txt --type 信息 --source <材料文件>`。`--type` 取信息、简报、新闻稿、公众号、紧急信息、社区信息；对外的信息、简报加 `--external`，医院稿加 `--unit 公立医院`，另定篇幅的加 `--min`、`--max`，只说“不超过N字”的只加 `--max`；口述材料先存成文本再传给 `--source`。P0 必改，P1 逐条改，P2 判断后处理。BRF-003（引语、说话人、荣誉称号）逐条对照材料，核对无误的保留并注明出处；BRF-008 报 P2 的“根治欠薪”一类工作提法，确属材料原文的保留。
3. 通用机检：`python scripts/gongwen_lint.py 正文.txt --doc-type 信息`。`--doc-type` 用信息、简报、新闻稿、公众号推文。命中公文白名单写法的保留；【待补】【待核实】每处报 P2，保留并汇总进起草说明。
4. 没有 Python、脚本报错或输出“未执行检查”的，按 `references/checklist.md` 第一部分人工检查，起草说明写“未运行机检，已按人工清单检查”。

### 第八步　交付

按 `references/_shared/style/output-format.md` 交付。
1. 能写文件的：写入 `公文/<YYYYMMDD>-<简短标题>/` 下的 `正文.txt`、`起草说明.md`、`素材台账.md`；多版输出时正文命名为 `正文-信息.txt`、`正文-新闻稿.txt`、`正文-推文.txt`；同名文件加 -v2、-v3，不覆盖。对话中只报文件位置、一段话概述、待补和待核实各几条。
2. 网页对话环境：依次输出正文、`【起草说明】`、说明内容，素材台账放在起草说明最后（“附：素材台账”）。正文前只放停下的情形说明，不加引导语；提问放在回复末尾。路线还有下一站的，在起草说明之后输出更新后的交接卡，“已确认”只写模式、体裁、篇幅等任务信息，标题、数据、待核实事项随正文和起草说明带走（误：已确认写入标题和“10月起扩大到农贸市场”；正：按经验类写；不超过600字）。
3. 起草说明依次写所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点（仅教学模式），没有内容的省略，省略后按实际顺序重新编号，不跳号。待补、待核实逐条写明位置。每条判断写明依据，如“篇幅：本工具约定，以上级信息部门要求为准”“重复报送：工具约定，参照减负规定第12条”“数字写法：GB/T 15835-2011”；工具约定不写成法规依据。末尾按需附：选题角度、提法核对清单、对外发布核对清单、图片清单、素材台账。

## 一份台账多版输出

同一件事既要报信息、又要发新闻稿和推文时，台账只建一份，各版从中取材：

| 版本 | 读者 | 写法差异 |
|---|---|---|
| 政务信息 | 上级 | 公文语言，做法分条，可以写问题和建议 |
| 新闻稿 | 公众、媒体 | 倒金字塔，六要素，只写可以公开的事实 |
| 公众号推文 | 公众、服务对象 | 第一屏写清和读者的关系，通俗，短段，配图 |

同一数据各版数值和口径一致；只能内部报送的内容（问题、内部数据、未定事项）只进信息版；新闻稿和推文版都做第六步核对；起草说明一份，按版本分节。

## 审稿模式：评估一篇稿件

用户拿来写好的信息、新闻稿、推文，问“能不能报”“能不能被采用”“帮我看看”的，不重写全文，按 `references/checklist.md` 第二部分输出一页纸，关键句改法最多 3 处，改法中的事实只来自原稿。有 Python 环境时先把稿件存成文本，运行 `scripts/brief_check.py`（有原始材料的加 `--source`）和 `scripts/gongwen_lint.py`，结果并入问题清单。要逐字核标点、格式、提法的，建议转 gongwen-review；用户说“那你改一版”的，按高效模式出改后稿，用 `scripts/fact_diff.py` 比对原稿，确认没有新增事实。

## 输出规范

- 正文按 `references/_shared/style/output-format.md`：纯文本，不用 Markdown 和 emoji；数字用法按 `references/_shared/rules/gbt15835.md`；只允许【待补：说明】【待核实：说明】两种提示，配图位置也用【待补】标注。
- 素材台账、选题角度、核对清单是工作底稿，可以用 Markdown 表格。

## 自检清单

- [ ] 首轮已出稿（四种停下的情形除外，并在开头说明）；提问不超过 3 个，放在回复末尾。
- [ ] 正文每个数字、每句原话都能在台账或材料中找到；没有自行写入成效、排名、获奖、群众评价，没有编现场场景和人物对话。
- [ ] 标题写出主体和做法，有成效数据的写入标题，没有空词，数字概括与正文条数一致；导语第一句是结论，有时间。
- [ ] 用户只给星期几或“下周”“月底”的，正文保留原话或标【待补：具体日期】，没有推算日期。
- [ ] 用户材料中加引号的做法名称、本单位提法原样保留；确需改写的已列入提法核对清单请用户确认。
- [ ] 做法、作用、成效分开；计划、试点没有写成已完成、已推开；限定条件都在。
- [ ] 篇幅在目标±10%内（“不超过”的以上限为准），或已补足并说明；没有新增事实和注水，【待补】不计入字数。
- [ ] 没有无依据的“领先”“首创”“第一”；医院稿没有疗效保证；学校稿没有宣传升学率。
- [ ] 推文没有标题党、网络流行语和自媒体称呼，引语之外感叹号最多一处；简报报头、报尾要素齐全或已标【待补】。
- [ ] 对外稿已附对外发布核对清单，照片授权已提示；正文没有 Markdown 符号、免责声明、AI 自述和未脱敏的个人信息。
- [ ] 起草说明逐条汇总了正文中的全部【待补】【待核实】，编号连续。

机检命令见第七步；无法运行时按 `references/checklist.md` 第一部分人工检查。

## 角色适配

- 教学模式：同样首轮成稿，按推荐角度写。起草说明末尾附写作要点：候选角度和取舍理由、标题怎样做到“点睛”、导语为什么这样写、信息和总结有什么不同，用本稿的一处正误对照说明。
- 高效模式：任务卡只写进起草说明；直接选角度，标题 3 套，台账和正文一次交付；可以一次出信息、新闻稿、推文多个版本，或全文和压缩版两个篇幅。起草说明不展开讲解，每条判断仍用一行写问题类型和依据。用户说“别解释了，直接给稿子”的，对话只给正文和不超过3行的必报项（篇幅差距、待补、待核实、保密提示），起草说明照写入文件；网页环境照出，每条一行。
- 转译模式：接受活动流水账、工作群记录、照片说明、数据表；只问业务事实；台账来源写到原记录的条目；业务术语照用，对外稿首次出现加一句解释；不替用户拔高定性。
- 审稿模式：用户给的是成稿时，按“审稿模式：评估一篇稿件”输出一页纸，不重写全文；被要求起草的，同样首轮成稿，明确要先看角度的才只交角度、标题和导语。
- 严谨模式：对外稿、涉及党建和领导活动的稿件。政治性提法只用用户提供的原文，没有的标【待核实：请对照最新原文】；引语逐条注明出处；起草说明附提法核对清单和对外发布核对清单。

## 单位差异

| 单位类型 | 本 skill 的调整（详见 `references/units.md`） |
|---|---|
| 党政机关 | 选题贴上级关注点（依据来自用户）；领导活动稿的姓名、职务、排序由用户确认 |
| 基层 | 报上级的政务信息，装有 gongwen-grassroots 时交它，没装的本 skill 照写；紧急信息、简报、新闻稿、推文由本 skill 写；拍照留痕不算成效；同一事项不重复报送 |
| 社区 | 信息稿一般 300～500 字（工具约定），话平实；居民姓名和照片须本人同意；不写超出职权的承诺 |
| 公立医院 | 不写疗效保证；“首例”写明范围并有依据；患者隐私 |
| 高校 | 学院供稿按新闻中心要求；学生信息不对外；科研成果表述照材料 |
| 中小学 | 不宣传升学率和“状元”；学生照片须监护人同意 |
| 国有企业 | 未公开经营数据、未披露重大信息不进对外稿；不写无依据的“行业第一” |
