# 政务信息

向上级办公室、信息部门报送的工作信息，按内容分动态类、经验类、问题建议类，另有紧急信息。读者是要据此掌握情况、作出判断的上级领导和信息编辑，写法围绕“能不能被采用”。

> 说明：本文件的结构、篇幅为公文写作通行做法和本项目的工具约定，不是法规条文。报送时限、字数、计分办法各地各单位不同，以上级信息部门的要求和单位画像为准。

## 一、三类信息怎么分

| 类型 | 回答上级的什么问题 | 典型材料 | 主体写法 |
|---|---|---|---|
| 动态类 | 最近干了什么、进展到哪一步 | 会议、活动、检查、阶段进展 | 事件经过和进展，结果先行 |
| 经验类 | 哪种做法管用、可以推广 | 专项工作总结、经验材料、试点情况 | 做法 2～3 条，每条配数据或事例 |
| 问题建议类 | 基层遇到了什么问题、怎么解决 | 调研记录、群众反映、工作中发现的情况 | 问题表现、涉及范围、原因、建议 |

判断不了的不问，按材料主体内容定（以做法和成效为主的按经验类，以事件经过为主的按动态类），写进“所作假设”。

## 二、选题：新、特、实

动笔前用三个问题过一遍材料，结论写进任务卡或起草说明。

1. 新：事情是不是最近发生的？做法是不是第一次用、或比原来有改进？数据是不是新出的？
2. 特：和别的单位相比，本单位的做法有没有自己的东西？材料里的做法如果各地都在做，特色要从具体做法、对象或机制里找，不靠形容词。
3. 实：有没有数据、事例、群众反馈？没有的，这条信息很难被采用。

三条都不满足的，照常成稿，在起草说明写明采用可能性低和补哪些材料能改善（如“补一组前后对比数据”）。上级关注点只来自用户提供的约稿通知、领导批示、上级文件。

## 三、标题

1. 写法和正误对照见 SKILL.md 第四步。标题是信息的结论，编辑只看标题就能决定要不要往下读。
2. 主副标题：主题概括做法和效果，副题补主体或具体事项。
3. 不超过两行（约 40 字）；标题末尾不加标点。
4. 不用“多措并举”“扎实推进”“亮点纷呈”一类空词，这类词放在任何单位的任何工作上都成立。

## 四、导语

1. 第一句就是结论（SKILL.md 第四步第5条）。确需交代依据的，压成半句放在主体后，如“某区按照市里部署，在12个街道推行……”。
2. 时间写具体：“今年以来”“9月以来”“10月12日”“近日”。材料里没有时间的，标【待补：时间】，不写“近期”糊弄过去；用户只给“上周五”等相对时间的，按今天推算为具体日期。
3. 导语中的数字与正文、标题一致。

## 五、主体写法（分类型）

### （一）动态类

1. 结构：导语 + 进展或做法（1～3 段）+ 下一步（材料有才写）。
2. 进展只写已经发生的；计划中的写“将”“拟”，不写成已完成。
3. 会议类动态写会议定了什么、部署了什么，不写会议议程和谁主持。讲话的直接引语只用审定稿或用户提供的原文；转述要点可用会议记录，只写记录中有的，注明来源，不补写（`references/ledger.md` 第三部分第 5 条）。

### （二）经验类

1. 结构：导语（做法和总体效果）+ 主要做法 2～3 条 + 取得成效（只用材料数据，可并入各条）+ 经验体会（一两句，工作性表述，不拔高）。
2. 每条做法按“动作 + 具体内容 + 数据或事例”写，一条一个意思。
3. 做法、作用、成效分开写：做了什么是做法；预期能起什么作用是作用，写“将”“有助于”；已经看到的变化才是成效，要有运行数据或反馈。系统上线、制度出台只能证明事情做了。
4. 不写“领导高度重视、成立领导小组”作为一条做法，除非领导小组本身有具体机制可讲。

### （三）问题建议类

1. 结构：导语（什么问题、涉及多大范围）+ 问题表现（具体事例和数据）+ 原因（材料中有的）+ 建议。
2. 问题表现只用材料里的事例和数据；样本只有几个乡镇、几家企业的，写明范围，不推到“普遍存在”。
3. 原因只写材料中提到的，或由材料事实能直接推出的；推不出的不写，起草说明里列“原因待调研”。
4. 建议写给能解决问题的上级：建议谁、做什么，具体到可以操作。上行信息可以用“建议”（`references/_shared/style/defensive.md` 第五部分）。
5. 涉及群众反映、舆情的，不写反映人身份细节，不写未经核实的说法。

## 六、紧急信息

突发事件、安全事故、灾情等需要第一时间报告的信息，按动态类写，另守以下几条：

1. 报送时限、格式、报送渠道以本单位应急预案和上级要求为准，本 skill 只组织文字。
2. 首报写已经掌握的：时间、地点、事件、伤亡和损失（据初步统计）、已采取的处置措施。没掌握的不写，不推测，列入起草说明。
3. 原因：材料写明已在调查的，写“原因正在调查”；材料没有的，不写原因，不推测原因。不写责任认定和处理意见，除非用户提供了结论。
4. 续报写新进展，与首报数字不一致的，写明变化和统计口径。
5. 需要上级批准、支持的事项，提醒用户另行请示；正式的事件情况报告（报告文种）也另行起草。

## 七、篇幅、时效与报送

1. 篇幅：一般 500～800 字（工具约定）；动态类可以更短；上级信息部门或单位画像另有要求的，从其要求。
2. 时效：动态信息越早报越有用；事过多日的动态，改从“效果”或“经验”角度写。
3. 同一事项已报过的，不换个标题重复报送（工具约定，参照减负规定第12条“同类材料最多报一次”的精神，该条约束的是上级向基层要材料）。有新进展的写续报，写明与上次的区别。
4. 拍照留痕、学习笔记、点赞转发量不写成工作成效（减负规定第8条、第14条，见 `references/_shared/rules/jianfu.md`）。

## 八、常见毛病和正误对照

常见毛病：写成总结，没有一个点；数据前后对不上（标题说“提高30%”，正文算出来是25%）；“试点”写成“全面推开”，一个社区写成“全区”。标题和导语的正误对照见 SKILL.md 第四步。

做法：
- 误：二是强化宣传引导。通过多种形式广泛开展宣传，营造了浓厚氛围，群众参与热情高涨。
- 正：二是入户讲解。网格员逐户上门讲分类标准，3个月走访4100户。（材料没有户数的不写户数）

成效：
- 误：智慧平台上线后，审批效率大幅提升，群众满意度显著提高。（材料只写了平台9月上线）
- 正：智慧平台于9月上线运行。（成效没有数据的不写，起草说明列“平台运行后的办件时长对比待补”）
