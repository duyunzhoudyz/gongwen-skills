# 新闻稿

单位对外发布的消息稿：发在本单位网站、上级门户网站，或向媒体供稿。读者是公众，写法按新闻的倒金字塔：最重要的事实放最前面，越往后越次要，删掉末尾几段不影响主干。

> 说明：本文件为新闻写作通行做法和本项目的工具约定。新闻稿属于对外发布，一律叠加严谨模式，发布前按 `references/external-check.md` 核对。

## 一、新闻稿和政务信息的区别

| 项目 | 政务信息 | 新闻稿 |
|---|---|---|
| 读者 | 上级领导、信息编辑 | 公众、媒体 |
| 目的 | 让上级掌握情况、推广经验 | 让公众知道发生了什么、和自己有什么关系 |
| 语言 | 公文语言，可以用“一是……二是……” | 新闻语言，少用公文套语和内部简称 |
| 内容 | 可以写问题、写建议 | 只写可以公开的事实；内部问题、未公开数据不写 |
| 发布 | 内部报送 | 对外发布，先审后发 |

用户要求同一件事既报信息又发新闻稿的，用同一份素材台账出两版（见 SKILL.md“一份台账多版输出”）。

## 二、六要素

动笔前对照素材台账逐项确认，缺的标【待补】，不靠推测补齐。

| 要素 | 写什么 | 常见缺失 |
|---|---|---|
| 何时 | 具体日期；跨年或日期不明显时写年份；用户只给星期几、“上周”的，按今天推算 | 只写“近日”，对外稿日期不准 |
| 何地 | 具体地点 | 只写“在我市” |
| 何人 | 主办、承办单位，参加人员身份和人数 | 主办、承办混写；人数用“众多”“数百名” |
| 何事 | 发生了什么 | 写成过程记录 |
| 为何 | 目的或起因，一句话 | 写成大段背景和意义 |
| 结果 | 产生了什么结果或影响 | 用“反响热烈”“圆满成功”代替结果 |

## 三、标题

1. 写最重要的事实，让读者只看标题就知道发生了什么。
2. 单行题为主；需要时用引题（在主题上方，交代背景或意义）或副题（在主题下方，补充事实）。
3. 用户材料里有关键数据的，放进标题。
4. 不用“隆重召开”“圆满落幕”“成功举办”作为标题的全部内容，要写出会议、活动的具体结果。
5. 不做标题党：不用“刚刚”“震惊”“重磅”、连续感叹号。

正误：
- 误：我院2026年大型义诊活动圆满落幕
- 正：某医院12个科室进社区义诊　现场为居民测血压血糖【待补：人次】人次

## 四、导语

1. 第一段交代最重要的事实，一般一到两句，包含时间、地点、主体、事件、结果。
2. 导语可以是叙述式（直接写事实），也可以是结论式（先写结果再交代事件）。不用描写式开头编造现场场景，现场细节只来自材料。
3. 不用“为……”“随着……”开头，不用“近日，……隆重召开”一类空泛开头。

正误：
- 误：为进一步增强居民健康意识，营造全民关注健康的良好氛围，近日，我院隆重举行大型义诊活动。
- 正：10月15日上午，某医院12个临床科室的医护人员在某社区广场开展义诊，为居民测量血压血糖、解答用药问题。

## 五、主体和背景

1. 按重要性递减写：先写结果和核心事实，再写过程细节，最后写背景。
2. 每段一个意思，段落短，一段两到四句。
3. 背景（为什么办、往年情况）放在后面，一段以内；与本次事件无关的单位介绍不写。
4. 数据写清口径：统计时段、范围、比较基准。“同比增长”写明与哪年比。
5. 结尾停在最后一个事实上，不写“让我们携手……”“未来可期”一类号召和展望。

## 六、会议新闻和领导活动稿

1. 写会议定了什么、部署了什么，不写成议程记录（“会议由……主持”“与会人员听取了……”可以压成一句）。
2. 出席领导的姓名、职务、排序只用用户提供的，排序由用户确认；职务写全称。
3. 讲话内容只用审定的讲话稿或会议通稿，不用会议记录转述（对外稿，见 `references/ledger.md` 第三部分第 5 条）；用户只给了“领导讲了话”的，写“某某出席并讲话”，不替领导概括讲话要点。
4. 领导活动稿在活动结束后发布，不提前发布领导行程（工具约定，以本单位宣传规定为准）。

## 七、活动新闻

1. 主办、承办、协办、支持、参与单位，材料分别写明的按各自身份写，不混写成“联合举办”。
2. 发稿单位的视角只决定叙述主语，不能据此补写“活动在本单位举办”“参加者来自本辖区”“本单位承担组织保障”等材料没有的事实。
3. 参加人数、服务人次、发放物品数量只用材料中的数，材料写“约”“左右”的照写，不改成确数。
4. 现场细节（“居民排起长队”“孩子们笑声不断”）只写材料提到的；材料没有的不写，不为生动编场景。
5. 活动效果写可以看到的结果（现场办理了多少件、收集了多少条意见），不写“反响热烈”“深受好评”。

## 八、引语和信源

1. 群众、患者、学生、专家、领导的原话，只能来自用户提供的材料（采访记录、发言稿、留言截图的文字），一字不改；可以节选连续的一段，不拼接、不润色。
2. 引语注明说话人身份：群众写“居民张某”“患者家属李某”，专家写“某医院心内科主任医师”，不写未经本人同意公开的全名。
3. 材料没有原话的，不写引语。确实需要的，在正文写【待补：受访居民原话，须本人同意引用】，起草说明列明怎么采集。
4. 不把转述改成直接引语：材料写“居民普遍反映方便了”，正文就写“居民反映……更方便了”，不加引号造一句“真是太方便了”。
5. 引用的政策、文件只用用户提供的名称和内容，书名号内的文件名与原文一致。

## 九、电头和署名

1. 电头（“本网讯”“本报讯”）和署名（“通讯员 张某”）按发布平台和本单位习惯写，用户没给的，署名写【待补：撰稿人】。
2. 照片说明以“图为”开头，写清时间、地点、人物和事件；照片使用前确认授权（`references/external-check.md` 第三部分）。

## 十、常见毛病

1. 把新闻稿写成信息或总结：满篇“一是……二是……”，读者看不出新闻点。
2. 六要素不全，尤其缺具体日期和人数。
3. 会议新闻只有议程，没有内容。
4. 用“圆满成功”“反响热烈”“好评如潮”代替结果。
5. 编现场场景、编群众原话。
6. 写进未公开的内部数据、未定的人事和决策、尚在调查的事件原因。

## 十一、新闻发布会发布词

发布会上由新闻发言人或单位负责人宣读的稿子，属于对外发布，叠加严谨模式，成稿后按 `references/external-check.md` 核对。领导在其他会议上的讲话、致辞交 gongwen-speech。

1. 结构：开场一两句说明发布什么；主体按重要性递减讲事实、数据和政策要点，一段一个意思；结尾按用户给的会议程序写（如“下面，我们回答记者提问”）。
2. 篇幅：按用户给的发布时长，约 200 字/分钟（工具约定，与 gongwen-speech 一致）。没给时长的按 10 分钟以内写，写进“所作假设”，可在回复末尾问一句，不因此停下。
3. 便于宣读：句子短，少用括号注释和长定语；数字读得顺，约数照材料写；专业术语、内部简称第一次出现加一句解释。
4. 政策内容只转述用户提供的原文，不扩大、不缩小适用范围；数据写清统计时段和口径。
5. 尚未公开的事项、尚在研究的政策、调查中的事件原因不写；计划中的写“将”“拟”，不说成已经实现。
6. 答记者问口径只整理用户或业务部门提供的口径，不代拟政策解释、办理时间、数据和表态；缺的写【待补：某问题的口径，由业务部门提供】。
7. 同时要发新闻通稿的，用同一份素材台账出两版，数据一致（SKILL.md“一份台账多版输出”）。
