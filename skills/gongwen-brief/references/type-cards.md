# 分类型要点卡

简报、新闻稿、发布词、推文的速查；政务信息见 `references/types/xinxi.md`。细节见 SKILL.md 速查表最后一列。

## 一、工作简报

```text
某局工作简报
第12期
某局办公室编　　　　　　　　2026年10月20日
────────────────────────
（第一篇标题：主体、做法、效果）
（正文，按信息写法）

（第二篇标题）
（正文）
────────────────────────
报：（上级机关）
送：（平级、不相隶属单位）
发：（下级单位、本单位各部门）
```

1. 期号、印发日期、报送范围没给的标【待补】；“内部资料”等标注由用户定稿时按本单位规定加注，稿中不加。
2. 每篇一个标题；不同单位、时段、口径的数字分篇对应，不混用。
3. 编者按只在用户提供编发意图或领导批示时写，不超过 150 字，不加正文没有的事实和评价。
4. 会议简报的发言内容只来自会议记录；讨论意见不写成议定事项。

## 二、新闻稿

1. 六要素：何时（具体日期；用户只给星期几的按今天推算）、何地、何人（主办、承办、协办分开写，人数照材料，“约”照留）、何事、为何（一句话）、结果（能看到的结果，不用“圆满成功”“反响热烈”代替）；缺的不推测，缺了稿子就不成立的才标【待补】。
2. 倒金字塔：导语一两句交代时间、地点、主体、事件、结果；背景放最后，一段以内。
3. 会议新闻写定了什么、部署了什么，不写成议程；领导姓名、职务、排序只用用户提供的。
4. 现场细节只写材料提到的；署名没给的不写；照片说明以“图为”开头。

## 三、新闻发布会发布词

1. 篇幅约 200 字/分钟；没给时长的按 10 分钟以内写，写进“所作假设”，可在回复末尾问一句。
2. 句子短、便于宣读；政策只转述用户提供的原文；未公开事项不写；计划写“将”“拟”。
3. 答记者问口径只整理用户给的，缺的合并写一处【待补：某问题的口径，由业务部门提供】，不代拟。

## 四、公众号推文

1. 第一屏写清三件事：什么事；和读者什么关系；读者要做什么。
2. 服务告知类按“谁、什么时间、在哪里、怎么办、找谁”排，条件写在用得着的位置，结尾写工作电话或办理地点。
3. 一段不超过 4 行（约 100 字）；术语第一次出现加一句解释。
4. 配图位置不在正文标注，起草说明附图片清单。

| 不用 | 改用 |
|---|---|
| 家人们、宝子们、亲们 | 各位居民、各位家长、患者朋友 |
| 绝绝子、天花板、拉满 | 写具体：等候时间由40分钟缩短到15分钟 |
| 震惊、刚刚、重磅、太贴心了！！！ | 陈述事实；引语之外全文最多一个感叹号 |
| 安排上了、码住、干货满满 | 已经开通、请收藏备用 |
| 点赞、在看、转发朋友圈 | 不写诱导语 |
