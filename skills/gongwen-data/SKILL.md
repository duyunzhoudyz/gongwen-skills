# 数据整理与图表（gongwen-data）

处理写材料前后的数据活：查报表毛病、汇总下级报表、算指标、把数写成公文句子、出能黑白打印的图。每个结果附算式，正文里的每个数都能在计算底稿里找到原样写法；缺的数标【待补】，口径对不上的不悄悄合并。脚本和图表都在本机运行，不调用任何外部服务。

## 适用范围

- 适用：
  1. 报表体检：空值和占位符、文本型数字、合并单元格、合计和小计校验、单位不一致、时段或口径不一致、重复行、个人信息。
  2. 多表合并：汇总科室、下级单位、子公司报来的同类报表。
  3. 指标计算：增减量、同比、环比、增速、百分点、占比、拉动、贡献率、完成率和时间进度、倍数、年均增速、平均值。
  4. 数据转文字：把结果写成可以直接放进总结、汇报、分析报告的句子和段落。
  5. 公文图表：柱状图、条形图、折线图、饼图、堆积图，黑白灰，标单位和数据来源。
- 不适用（转交）：

| 用户要的 | 转给 |
|---|---|
| 写整篇总结、汇报材料、调研报告；汇总文字材料 | gongwen-report |
| 医疗质量分析报告、经营分析报告等行业专用文书全文 | 对应行业包（gongwen-hospital、gongwen-soe 等）；没装行业包的交 gongwen-report |
| 政务信息、简报全文 | gongwen-brief |
| 已成稿件里的数字、百分点、前后一致核查 | gongwen-review |
| 整改台账、任务分解表、督办清单转 Excel | gongwen-rectify、gongwen-implement、gongwen-minutes |
| 把表格和图排进国标 Word | gongwen-format |

用户要整篇稿子的，本 skill 先交数据段落、计算底稿和图表，再说明下一步交哪个 skill（网页环境输出交接卡）。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户发数据时，或用户第一条消息就附了表格时，在本次回复开头附一句："请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。"同一会话只说一次。
   - 表格或文件带密级标识（"秘密★""机密★""绝密★"），或标注"内部资料""工作秘密""不得外传""内部使用""仅供内部参考"的，立即停止，不读数、不复述，告诉用户涉密信息不得输入联网 AI 工具。用户说明以下情况之一后再继续：用的是单位内网部署、允许处理此类材料的模型；已删去相关内容；标识系误加或材料已公开。表中只是出现"保密工作经费"之类的项目名称的，照常处理。
   - 明细表中有姓名、身份证号、手机号、病案号、住院号、学号、银行卡号、家庭住址的，提醒用户脱敏；分析只用汇总数，输出中一律写"张某""138****0000"，起草说明"保密提示"写明。脚本输出已自动脱敏。
   - 未公开的经营数据、统计数据、考核排名，提醒不进对外材料。
2. 数据不出本机：只用 `scripts/` 下的脚本和本机 Excel、WPS。不把数据发到在线图表网站、在线表格转换工具，不调用会把数据发到远程服务器渲染的图表插件。
3. 单位画像：工作目录存在 `.gongwen/单位画像.md` 时先读取，没有再找 `~/.gongwen/单位画像.md`，用户粘贴在对话开头的按粘贴内容处理。再读 `references/units.md` 对应小节。没有画像时按 `references/_shared/profiles/roles.md` 第九节"无画像降级"处理，单位类型能从表格判断的不问。
4. 角色模式：按 `references/_shared/profiles/roles.md` 第一节确定，本 skill 中的差异见"角色适配"。
5. 交接卡：网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务、本站和已确认事项开工，卡上有的不再问（`references/_shared/style/output-format.md` 第四部分）。
6. 定任务：判断要做五项中的哪几项。完整链条是"体检→合并→计算→转文字→出图"；用户只要其中一段的只做那段，但凡要引用表中的数，先做体检，至少核合计和单位。
7. 用户要求"把数调得好看点"、补上表里没有的数、改原始数据去凑考核目标的，说明不能这样做（`references/_shared/guardrails.md` 第二条、第六条），其余工作照常进行。

## 工作流程

### 第一步　登记数据

1. 给每张表编号（表A、表B……），登记：文件或工作表、报送单位、统计时段、计量单位、口径说明、数据来源系统。这份材料清单是计算底稿的第一部分。
2. 提问最多 3 个，只问业务口径，按此顺序取舍：统计时段 → 对比基期（同比还是环比、和哪年比）→ 计量单位或统计范围。表头、表注、文件名能看出来的不问；用户说"直接做"的不问，取默认值写进起草说明"所作假设"。
3. 用户没给任何数（如"帮我写一段今年的数据"）的，不编数，交付数据收集清单（指标、时段、基期、到哪里取数）和带【待补】的句式，如"1—9月，全院出院【待补：人次】人次，同比增长【待补：增速】%"。

### 第二步　报表体检

有 Python 环境时运行 `python scripts/data_tool.py inspect <表格> --json`（多个工作表加 `--all-sheets`），逐条复核结果，输出中的表头前说明（`pre_texts`）和表注（`notes`）登记为口径说明；不能运行时按 `references/inspect-checklist.md` 第二部分人工检查。重点：

| 查什么 | 发现后怎么办 |
|---|---|
| 文件、工作表、表头前、表注或单元格带密级、内部标注（DT-SEC-01，P0，脚本已停止） | 回到开工检查第1条，不读数、不复述；用户说明后才可加 `--marking-ok` 重跑，不自行添加 |
| 合计、小计与明细相加不符（P0），或超出修约容差（P1） | 不直接引用表中合计；正文要用的，写明细相加数并紧跟【待核实：说明】 |
| 同列单位不一致（P0） | 换算统一后再算，换算写进计算底稿 |
| 空值、"—""/"等占位符 | 空不等于 0。表注或用户说明了含义的（如"不开展此项"）按说明处理并写进起草说明；没说明的，正文涉及的写【待补：说明】 |
| 约数（"约20""30多"） | 不做精确计算，正文照写并标【待核实：准确数】 |
| 文本型数字、合并单元格 | 提醒在原表修正，Excel 求和会漏算 |
| 比率、平均数列的合计 | 用分子合计除以分母合计重算，不简单平均 |

表中自带的合计、小计行就是校验和，逐项相加去对，不凭目测：
- 误：看到"全院合计 6191"，直接写进正文。
- 正：30 个科室相加为 6171，与合计差 20，列为 P0；正文写"出院6171人次【待核实：表中合计为6191人次】"。

体检结果写成体检报告：一行结论，加问题清单（序号｜级别｜表｜位置｜问题｜处理建议），格式见 `references/inspect-checklist.md` 第四部分。

### 第三步　合并汇总（多张表时）

运行 `python scripts/data_tool.py merge <表A> <表B> ... --expect <应报单位名单> --out <汇总表.xlsx> --json`；不能运行时按 `references/inspect-checklist.md` 第三部分人工合并。规则：
1. 同量纲单位按多数表换算（元换万元÷10000），每次换算记一条；人与人次、户与人、件与次不换算、不相加。
2. 时段与多数表不同的表（1—8月混进1—9月）不计入合计，单列出来请对方重报。
3. 比率和平均数不相加；缺分子分母的写【待补：分子和分母数据】。
4. 同一单位报了两次的，先确认再加（脚本把重复的行先排除在合计外，另列含重复的合计）；应报未报的列入待补事项，正文写全口径合计时注明"不含……"。
5. 比不齐的不加总、不取平均、不挑大的，全部进"附：口径冲突表"，请用户确认。

### 第四步　指标计算

先按要说明的事选指标，公式和 Excel 写法见 `references/calc-sheet.md` 第一部分：

| 要说明的 | 用 |
|---|---|
| 比去年同期多了还是少了 | 增减量＋同比增速 |
| 比上个月 | 环比（只用于相邻两期） |
| 率、占比、增速本身的变化 | 百分点 |
| 某部分在总体中的分量；对总体增长的作用 | 占比；拉动（百分点）、贡献率 |
| 任务进度 | 完成率＋时间进度 |
| 多年变化 | 倍数、年均增速（水平法） |
| 全院、全系统的率或平均数 | 分子合计÷分母合计 |
| 台账、明细按类别统计件数 | 分类计数和占比 |

1. 有 Python 环境时用 `python scripts/data_tool.py phrase --type <类型> ... --md`，单个数用 `--current`、`--base` 等参数，整张表用 `--table` 加列名；明细按类别计数用 `python scripts/data_tool.py count <表格> --by <列名>`；命令详见 `references/scripts.md`。脚本给的提示（基期为0或负数、基数小、未写基期、合计不符、两期口径不同）逐条处理；合计不符的，脚本已改用明细相加数并在句后加【待核实】，不要改回表中合计；两期口径不同的，改用脚本给的同口径结果并注明"不含××"，或保留【待核实】。
2. 不能运行脚本时按 `references/calc-sheet.md` 第三部分人工演算：每个结果写出算式和中间值，最后一步四舍五入，再反算验证；超过 20 行或 5 列的表不在对话里硬算，给出 Excel 公式请用户在本机算。
3. 特殊情形：基期为 0 不算增速；亏损用"扭亏为盈""减亏"；本期和基期口径不同（如某科室上月未报）的，两边同口径剔除后计算并注明，或标【待核实】。
4. 所有结果记入计算底稿（`references/calc-sheet.md` 第四部分）：序号｜指标｜算式｜结果｜文字表述｜来源。算不了的记入"未计算的项目"并写明原因。

### 第五步　数据转文字

按 `references/_shared/rules/data-expression.md` 写。最常错的几条：
1. 两个百分数相减用"个百分点"；数量的变化用百分数。
   - 误：四级手术占比由24.1%升至26.6%，提高2.5%。
   - 正：四级手术占比由24.1%升至26.6%，提高2.5个百分点。
2. 先写本期数，再写变化，写明基期："出院6171人次，同比增长5.0%"。"同比"不与"比上年同期"叠用；"环比"只用于相邻两期，不写"环比去年"。
3. 下降写"下降X%"，不写"负增长""增长-X%"；倍数不用于减少；"是原来的3倍"等于"增长200%"。
4. 原因只写用户给的。材料里没有原因的，需要写就标【待补：变化原因】，不写"主要得益于……"。
   - 误：业务量大幅增长，主要得益于学科建设成效显著。
   - 正：全院出院6171人次，同比增长5.0%。【待补：变化原因】
5. 程度靠数字说明，少用"大幅""显著"；一句话不超过 3 组数据；一段只写一类指标，先总后分。
6. 正文不写算式、不写"据测算"之类的过程话，算式放计算底稿和起草说明。
7. 默认做减法：开门见山，不写形势背景和意义铺垫；只写用得上的指标，不为凑篇幅罗列数据。

### 第六步　公文图表

有 Python 环境时运行 `python scripts/chart_tool.py <表格> --type <bar|barh|line|pie|stacked> --y <列名[,列名]> --title <图题> --source <数据来源> --out 公文/<目录>/图表-<指标>.xlsx`，生成 Excel 原生图表，装有 matplotlib 时可加 `--png`。同期对比时两列都写（如 `--y 2026年,2025年`）；不写 `--title` 时脚本按"时段＋指标"拼图题，要核对。选图和要求见 `references/chart-guide.md`：
1. 比大小用柱状图、条形图（类别多时用条形图并排序）；看变化用折线图；看构成用饼图（不超过 6 类）。
2. 黑白灰，不用彩色、三维和渐变；纵轴从 0 开始；不用双坐标轴，不同单位分开出图。
3. 图题写时段和指标，纵轴写"单位：……"，图下写"数据来源：……"；没有来源的写【待补：数据来源】。
4. 合计、小计行不入图；空值留空，不画成 0。

不能运行脚本时，在起草说明末尾给"附：图表规格卡"和 Excel、WPS 操作步骤（`references/chart-guide.md` 第五部分）。

### 第七步　自检

1. 底稿对账（必做）：正文里的每个数都要在计算底稿"文字表述"列找到原样写法。有 Python 环境时运行 `python scripts/fact_diff.py 计算底稿.md 正文.txt --ledger`，输出的"正文中有、台账中没有"逐条处理：补进底稿并写明来源，或改为【待补】。
2. 机检：运行 `python scripts/gongwen_lint.py 正文.txt --doc-type <文书类型> --json`，文书类型取数据段落要放进的材料（总结、汇报材料、信息等），说不清的用"其他"。P0 必改，P1 逐条判断；【待补】【待核实】每处报 P2，保留并汇总进起草说明。
3. 不能运行脚本时按本文"自检清单"逐项检查，并在起草说明"所作假设"中写"未运行脚本，计算和核对为人工完成，请复核"。

### 第八步　交付

按 `references/_shared/style/output-format.md` 交付。
1. 能写文件的：在当前工作目录建 `公文/<YYYYMMDD>-<简短标题>/`，按需写入 `正文.txt`（数据段落）、`起草说明.md`、`计算底稿.md`、`体检报告.md`、汇总表 `.xlsx`、图表 `.xlsx` 或 `.png`。同名文件已存在时加 -v2、-v3，不覆盖。对话中只报文件位置、体检结论一句、主要数据一两句、待补和待核实各几条。
2. 网页环境：依次输出正文（数据段落）、`【起草说明】`、说明内容。起草说明依次写所作假设、待补事项、待核实事项、计算说明（用了哪些公式，是否运行脚本；表述判断写明依据，如"数据表述规范第三部分""GB/T 15835-2011 5.1.3"）、保密提示、写作要点（仅教学模式），末尾按需附"附：体检问题清单""附：口径冲突表""附：计算底稿""附：图表规格卡"。有计算的，各模式都附计算底稿，不省略算式。正文前不加引导语。
3. 用户只要体检或合并、不要文字的，交付体检报告（和汇总表），不硬写正文。
4. 路线还有下一站的（如交 gongwen-report 成稿），在起草说明之后输出更新后的交接卡：本站产出写"数据段落、计算底稿"，不抄原始数据，不带个人信息；告诉用户新开对话，先粘贴下一站的提示词文件，再粘贴交接卡和本站产出。

## 单位差异

| 单位类型 | 口径要点 | 特别注意 |
|---|---|---|
| 党政机关 | 对外引用的统计数以统计部门公布的为准；快报数、年报数、预计数分开 | 未公开统计数、考核排名不进对外材料 |
| 基层、社区 | 人与人次、户与人分清；多部门台账同一件事只计一次；保留原始记录来源 | 不虚报，不补记台账；居民信息脱敏 |
| 公立医院 | 国家监测指标不自行改变计算方法；全院比率用分子分母合计；率的变化用百分点 | 患者姓名、病案号、住院号脱敏 |
| 高校 | 学年与自然年分清；与高基报表、状态数据库口径一致 | 学生个人信息不进明细 |
| 中小学 | 学期与学年分清；达标率、及格率、优秀率、平均分用人数重算 | 义务教育阶段不对学生、班级排名，成绩图不排序 |
| 国有企业 | 金额单位全文统一；与财务快报一致；完成率配时间进度；合并口径与单体口径分开 | 未披露经营数据属商业秘密 |

## 输出规范

- 正文（数据段落）、起草说明按 `references/_shared/style/output-format.md`：纯文本，不用 Markdown；数字写法按 `references/_shared/rules/gbt15835.md`，数据表述按 `references/_shared/rules/data-expression.md`。
- 正文中只允许两种提示：【待补：说明】和【待核实：说明】，全部在起草说明中逐条汇总。
- 体检报告、口径冲突表、计算底稿、图表规格卡是工作底稿，可以用 Markdown 表格。

## 自检清单

- [ ] 引用表中数据前做了体检，合计是逐项相加核过的；合计不符的没有直接引用。
- [ ] 正文每个数都能在计算底稿找到原样写法；没有材料以外的数，没有推测的原因。
- [ ] 比率、平均数没有相加或简单平均；时段、单位、口径不同的数没有合并或比较。
- [ ] 百分点与百分数用对；同比、环比写明且没有叠用；下降没写成"负增长"；倍数没用于减少。
- [ ] 基期为 0 或负数的没有算增速；约数没有参与精确计算。
- [ ] 每个计算结果都有算式；没有运行脚本的已注明人工演算。
- [ ] 图表为黑白灰，有图题、单位、数据来源，纵轴从 0 开始，没有双坐标轴。
- [ ] 没有使用在线图表或远程渲染服务；输出中没有未脱敏的个人信息。
- [ ] 正文没有 Markdown 符号和免责声明，起草说明汇总了全部【待补】【待核实】。

有 Python 环境时运行：`python scripts/gongwen_lint.py 正文.txt --doc-type <文书类型>`。无法运行时按本清单人工检查。

## 角色适配

- 教学模式：有报表的，先交体检结果和计算底稿，确认后再写正文；没有报表、只问一两个数怎么写的，直接给句子和讲解。起草说明末尾附写作要点，用本次数据讲清"百分点和百分比""同比和环比"等用法各一处正误对照，以及每个【待补】一般到哪里取数（统计报表、业务系统、财务快报）。
- 高效模式：不提问，体检、计算、正文、图表一次交付；需要时数据段落给详、简两版。起草说明只写假设、待补、待核实和计算说明，不写写作要点；网页环境照常附计算底稿，可只列算式和结果两栏。
- 转译模式：接受原始表格和口头描述；只问统计时段、对比基期、计量单位；体检问题用大白话解释（如"这一列有数字被存成了文字，Excel 加总时会漏掉"）；计算底稿完整列出算式。
- 审稿模式：只出体检报告或数据表述问题清单，每条写位置、问题、依据、建议，不重写全文；是否采用由用户决定。整篇稿件要核稿的转 gongwen-review。
- 严谨模式：用于对外发布、报上级党组织的数据。每个数在计算底稿注明出处（报表名称、时段、口径）；未确认已公开的数据标【待核实：是否已对外公布】；起草说明附数据出处核对清单。
