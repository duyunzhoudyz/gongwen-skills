# 党建与组织生活材料（gongwen-party）

> 版本 1.0.0　成熟度：Stable（稳定版）

帮党务干部和党员准备民主生活会、组织生活会、党课、主题党日和支部日常工作的材料。它负责搭结构、理素材、核提法、查雷同、整理会议记录；事例、认识和表态由你本人提供，提法和引文以你提供的会议通知、学习材料原文为准。

它是结构与素材的组织助手，不代替本人写需要本人亲历的材料。对照检查、心得体会、述职这类材料，你没有提供个人事例时，它只给提纲和填写指引；谈心谈话只给提纲和空白记录表。

## 能做什么

| 材料 | 你需要提供 | 它交付 |
|---|---|---|
| 民主生活会、组织生活会个人对照检查材料（发言提纲）、民主评议自评 | 会议通知、本人事例、反馈给你的意见、去年的整改清单 | 全文、征求意见逐条回应表、提法核对清单；缺事例时只给提纲和填写指引 |
| 领导班子、支部班子对照检查材料 | 会议通知、征求意见汇总、班子工作事实、去年的整改清单 | 全文、回应表、整改措施（责任领导、时限） |
| 年度党建工作报告、生活会召开情况报告、支部计划和总结、会后整改清单 | 工作记录、数据、会议记录、对照检查材料 | 全文或表格和素材台账，缺的数据标【待补】 |
| 书记抓基层党建述职 | 本人履职事例、去年述职点评的问题 | 全文；缺本人事例时给提纲和要准备的事实清单 |
| 党课讲稿 | 题目、学习材料原文、本单位的事例、讲课时长 | 讲稿；没有原文的引文不编，标【待核实】；素材撑不起时长的，用工作性表述补足常规部分，本单位事例缺的标【待补】，不凑字数 |
| 主题党日方案 | 主题、内容、时间地点 | 方案；可配套全年 12 个月的题目框架 |
| 研讨发言、心得体会、思想汇报 | 学了什么、你自己的几句认识、联系工作的事 | 整理成文；没有本人认识（思想汇报没有本人要点）的给提纲和填写指引 |
| 谈心谈话提纲 | 谈话对象和目的 | 提纲和空白记录表（记录由你谈后填写） |
| “三会一课”、民主生活会、组织生活会等会议记录整理 | 会议笔记或录音转写 | 规范记录，只整理不添加，核对到会人数和表决结果 |

## 可以这样说

1. “下个月开民主生活会，这是通知和组织反馈给我的意见，我把今年的几件事也写下来了，帮我理个发言提纲。”
2. “七一要给支部讲党课，题目定了，学习材料我贴给你，讲40分钟左右。”
3. “支部这个月的主题党日还没想好，我们打算去社区做志愿服务，帮我出个方案。”
4. “这几次支委会的手写记录我拍照转成文字了，帮我理成规范的会议记录。”
5. “这是去年的对照检查材料和我今年的初稿，看看重复的地方多不多。”

## 输入

- 必需：会议通知或学习材料原文（对照检查的方面、主题、提法都从这里来）；需要本人亲历的材料，还要有本人事例。
- 最好提供：征求意见清单、去年的整改清单、往年材料（用来查雷同）、篇幅或发言时长。
- 可选：单位画像 `.gongwen/单位画像.md`。没有画像也能用。
- 素材够用时第一次回复就出稿，缺的标【待补】；要问的最多 3 个，放在回复末尾。只在缺本人事例、只有题目没有任何事实、你要求先看提纲、材料涉密这四种情况下停在提纲。
- 给了字数或时长而素材撑不起的，用工作性表述补足常规部分，不用空话凑字数。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文，可直接粘进 Word 或交给 gongwen-format 排版 |
| `起草说明.md` | 所作假设、待补和待核实事项、保密提示；附征求意见逐条回应表、提法核对清单、雷同提醒 |
| `素材台账.md` | 每条事例、意见、数据的内容、来源和状态 |
| `提纲.md` | 只出提纲时的提纲和填写指引 |

在网页大模型里使用提示词版时，依次输出正文、起草说明和附表。

## 注意事项

1. **保密**：请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。标注“内部资料”“不得外传”的巡察反馈、征求意见汇总，它会停下来提醒你。民主生活会个人发言提纲要“按规定说明个人有关事项”，请你本人在内网或纸面填写，不要发给联网模型；组织生活会材料一般不设这一栏，通知另有要求的按通知。
2. **本人事例是前提**：对照检查、心得体会、述职要写你本人的真实情况。没有事例时它只给提纲和填写指引，你补上后再成稿。它不批量替别人写个人材料，也不补写没开过的会议记录。原因剖析里你当时怎么想的，只用你说过的话；你没说的，它会标出来请你确认。
3. **提法以原文为准**：它不内置“最新提法”。提法、引文只用你提供的原文，没有原文的标【待核实】，请你对照最新原文确认。
4. **问题具体、措施可检验**：查摆问题要有事例，整改措施要有时限和标准。有 Python 环境时会用脚本检查措施时限和征求意见是否逐条回应。
5. **查雷同**：给了往年或他人的材料，它会标出重合的段落，建议你用今年的事例重写，不做只换说法的“降重”。
6. **本人审改定稿**：民主生活会个人发言提纲按规定应当本人动手撰写，它整理出的稿子请本人逐段审改。秘书或支部书记替别人准备材料的，事例和认识要经本人确认，没说过的认识会留空。
7. **事实和判断由你负责**：它负责搭结构、守规矩、查错漏，材料怎么定稿、怎么表态由你决定。

## 成熟度

Stable。v1.0 真实模型评测（Sonnet 5.5，22 条用例）中，A 组（装 skill）期望通过率 98.8%（160/162），编造 0 次，触发评测正例 10/10、反例 10/10，详见 `evals/results/v1.0-benchmark.md`。九类材料的结构、提纲和填写指引、提法核对、雷同检测、记录整理流程已可用；评测用例见 `evals/`。已知局限：
- 雷同检测依赖共享脚本 `overlap_check.py`，脚本不可用时按人工比对；
- `party_check.py` 按层次序数和标题关键词识别问题和措施部分，结构不规范的稿件可能识别不到，会提示改为人工检查；征求意见汇总按“××方面”分类、每类重新编号的，脚本跳过分类标题、按出现顺序统一编号，回应表请照录意见原文；
- 各地民主生活会、组织生活会的通知格式差异大，材料栏目以当年通知为准。
