# “三会一课”等会议记录整理

适用：党员大会、支委会、党小组会、党课、民主生活会、组织生活会、主题党日的记录整理，以及谈心谈话后的笔记整理。

## 一、底线

1. 只整理，不添加。记录反映实际召开的会议，内容只来自用户提供的笔记、录音转写或会议材料。
2. 不补造。没开过的会不写记录；笔记中没有的发言、人数、表决结果、时间地点不写，写【待补】。
3. 发言归属不变。谁说的就记在谁名下，记不清是谁说的写【待核实：发言人】，不猜。
4. 不改原意。口语转书面只改表达，不改观点、态度和数字；表态的强弱照原样（“原则同意”不改成“同意”）。
5. 记录整理后运行 `python scripts/fact_diff.py 原始笔记.txt 正文.txt --json`，逐项核对“改稿新增”：笔记中确实没有的（如用应到减实到推算出的缺席人数、补出的日期、添加的引语），删去或改为【待补】；只是加了单位或换了写法的（如“同意12”写成“同意12人”、电话号码脱敏），保留。

## 二、记录要素

```text
某党支部2026年第三季度党员大会记录

时间：2026年9月20日下午3时
地点：【待补】
主持人：支部书记张某
记录人：组织委员李某
应到：31人　实到：26人
缺席：王某（出差）；其余【待补：缺席人员及原因】
列席：【待补：列席人员，没有的写“无”】
议题：一、……　二、……

会议内容：
一、（议题一）
张某：……（发言要点）
……
表决情况：……（按笔记）
二、（议题二）
……

主持人小结：……
```

1. 要素按本单位记录本或上级制发的记录格式；用户给了格式的照用。模板中的“……”和括注是占位，成稿时换成笔记内容或【待补】，不照抄进记录。
2. 笔记没写缺席人数和原因的，写【待补】，不用应到减实到推算。
3. 人名的写法按用户笔记。用联网模型时，提醒用户可以先把姓名换成代号，定稿后再换回；脚本和模型都不增删人名。
4. 一般不加评价性语句（如“会议气氛热烈”“大家深受教育”），笔记中有的照录。

## 三、整理步骤

1. 按顺序列出议题，每个议题下按发言顺序整理，每人一段。
2. 表决的写表决结果，议定的写议定事项，只是讨论的写“会议进行了讨论”，不替会议下结论。
3. 逐项核对时间、人数、主持人、记录人，缺的标【待补】；缺失的要素、存疑的发言归属、人数或表决的问题列入起草说明。

## 四、表决事项的核对

| 会议 | 有效条件 | 核对方法 |
|---|---|---|
| 党员大会表决 | 半数以上有表决权的党员到会；赞成人数超过应到会有表决权党员的半数为通过（支部工作条例第十一条） | 用笔记中的应到、实到、赞成数核对；预备党员没有表决权，用户说明了的从有表决权人数中扣除 |
| 支委会 | 半数以上委员到会方可进行（第十二条） | 核对到会委员人数 |
| 民主生活会 | 到会人数达到应到会人数的三分之二以上（《若干规定》第七条） | 核对应到、实到；不足的照记，在起草说明提示请与上级党组织确认 |

1. 笔记中的数字不满足条件的，照记，不改数字，在起草说明中写明：“实到有表决权党员14人，未达到应到31人的半数，按支部工作条例第十一条，表决可能无效，请与上级党组织确认。”
2. 笔记没有表决人数的，写【待补：表决结果（赞成、反对、弃权人数）】，不写“全票通过”。笔记没写实到人数中是否含预备党员的，标【待核实：实到人数中是否含预备党员】。
3. 接收预备党员、预备党员转正等事项的表决，按上级党组织的程序要求核对，本 skill 只提示，不作程序认定。

## 五、口语转书面

误（加了意思）：笔记“老李说这个事还得再看看”，整理成“李某同志表示同意，建议进一步完善”。
正：李某：这件事还需要再研究。

误（改了强弱）：笔记“基本同意，费用那块有意见”，整理成“同意”。
正：李某：基本同意，对费用部分有不同意见。
