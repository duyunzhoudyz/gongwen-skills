# 人工自检清单（无法运行脚本时）

网页版、内网无 Python、脚本报错时，先逐项过本 skill 的“自检清单”，再按本清单代替脚本检查，在起草说明中写“未运行机检，已按人工清单检查”。

## 一、红线（自检清单之外的几项）

- [ ] 回复开头有保密提示（同一会话只说一次）；材料带密级标识或“内部资料”“工作秘密”“不得外传”等字样的，已停止处理。
- [ ] 身份证号、手机号、患者和学生姓名、他人处分情况已替换为代称。
- [ ] 没有补写未召开会议的记录，没有批量替他人写个人材料；替他人准备的，本人认识没有用转述人的推测代替。

## 二、措施和回应（代替 party_check.py）

- [ ] 数一数：查摆问题几条，整改措施几条；措施少于问题的，逐个核对是否每个问题都有措施。
- [ ] 每条措施都有时限（年月、期限或“每月”“每季度”等频次）；本人没有给出的写【待补：完成时限】，不替本人拟定日期或频次。只写“长期坚持”的不算时限；措施开头复述问题时提到的日期（“针对7月12日……的问题，”）也不算时限。
- [ ] 有征求意见清单的：清单按“班子建设方面”等分类、每类重新编号的，分类标题不算意见，按出现顺序统一编号后再核对；回应表条数等于清单条数，一条不少。
- [ ] 回应表中的意见与清单原文逐字一致，没有概括、弱化。
- [ ] 每条意见的“整改措施”栏不为空；不属于本人的写明了转交去向。

## 三、雷同（代替 overlap_check.py）

- [ ] 用户给了往年、他人或班子材料的，按 `references/writing-rules.md` 第九部分逐段比对，查摆问题、整改措施两部分重点比；照录通知、提法、引文的片段不算雷同；雷同提醒写进起草说明。

## 四、记录整理（代替 fact_diff.py）

- [ ] 记录中的每个数字（人数、表决数、时间）都在原始笔记中。
- [ ] 每段发言的发言人与笔记一致；记不清的标了【待核实：发言人】。
- [ ] “原则同意”“基本同意”“同意”等表态照原样。
- [ ] 表决事项核对了到会人数是否过半；民主生活会核对了到会人数是否达到应到的三分之二。

## 五、格式和文风（代替 gongwen_lint.py）

- [ ] 正文没有 Markdown 符号、emoji、“以下是为您撰写的”之类的话；层次序数 一、（一）1.（1）不跳级，用全角标点。
- [ ] 没有“值得注意的是”“不是……而是……”、破折号揭晓之类的 AI 句式；【待补：】【待核实：】用全角符号。
