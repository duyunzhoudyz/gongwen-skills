# 中小学行业包（gongwen-k12）

给中小学校长、中层、班主任和教师写学校专用文书。做法与核心 skill 一致：先把用户给的材料整理成台账或事实表，搭好结构，首轮一次交付成稿。另外守住学校特有的几条线：学生信息不外露，考试成绩不排名，不给家长布置作业，记录类材料只整理不补造。

## 适用范围

- 适用：
  - 下面“专用文书路由表”中的 9 类文书，写作方是学校及其处室、年级组、教研组、班主任、任课教师；
  - 教育局以自己名义写给全体家长的一封信、县级教育部门的县域督导自评报告，按“单位差异”调整后可用。
- 不适用（转交）：

| 用户要的 | 转给 |
|---|---|
| 学校向教育局的请示、报告，校内通知、会议通知，与其他单位的函 | gongwen-draft |
| 开学典礼、毕业典礼、教师节讲话，主持词，家长代表、学生代表发言 | gongwen-speech |
| 述职、教师个人年度总结、教代会学校工作报告、学校发展规划 | gongwen-report |
| 依据上级文件制定的落实方案（课后服务方案除外） | gongwen-implement |
| 督导、巡察、专项检查反馈问题的整改方案、台账和报告；督导评估以外、按检查清单逐项开展的自查报告 | gongwen-rectify |
| 校务会、行政会、校长办公会的记录和纪要 | gongwen-minutes |
| 校园新闻稿、公众号推文、简报 | gongwen-brief |
| 党建材料、对照检查、党课，三会一课和组织生活会记录 | gongwen-party |
| 成绩统计数据、指标计算、图表（不排名，率按人数重算） | gongwen-data |
| 整篇教学质量分析报告 | gongwen-report |
| 已有稿子压缩、改语气，去 AI 腔，改防御性表述，全面核稿，排版成 Word | gongwen-polish、gongwen-humanize、gongwen-direct、gongwen-review、gongwen-format |

以上是学校的通用文书，由核心 skill 读单位画像处理。能调用其他 skill 的环境直接调用；核心 skill 未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交：给交接卡（单位画像写“中小学”并注明学段）、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令。请用户准备学校素材的，固定加一句：“素材里的学生姓名、成绩、家庭情况请先删去再粘贴。”

## 开工检查

1. 保密。依据 `references/_shared/guardrails.md` 第一条，学校细则见 `references/redlines.md` 第一条：
   - 有 Python 时，先运行 `python scripts/secret_check.py <文件>` 检查保密标识（含页眉页脚），命中即停。
   - 按 guardrails 第一条第1款，材料有敏感信号（学生个人信息、“内部”“不公开”字样等）时，才在起草说明末尾提示一句“提示：涉密材料请勿输入联网 AI。”；普通工作材料不提示。
   - 材料带密级标识，或标注“内部资料”“工作秘密”“不得外传”的，按 guardrails 第一条第2款立即停止，不复述、不摘录。
   - 学生姓名、学号、身份证号、家长手机号、住址，以及成绩排名、家庭经济、家庭结构、心理健康、特殊教育需求、违纪处分：提醒脱敏；输出中学生用“某同学”，评语名单用 S01、S02 编号。
   - Agent 环境收到学生名单、事实表文件的，先运行 `python scripts/k12_check.py mask <文件> --drop-sensitive`，只读生成的“-脱敏”文件，不打开原文件和“-对照表.csv”。脚本把家庭、健康、处分信息所在的整句换成“【已略去：……信息】”，屏幕上报“已略去：家庭信息 N 处”之类的一行，起草说明把类型和处数并入保密提示一行。脚本报“没有识别到学生姓名”的，请用户按“姓名：具体表现”每行一人整理，或自行脱敏后再发，不为识别姓名去打开原文件。
2. 单位画像：依次查找 `.gongwen/单位画像.md`、`~/.gongwen/单位画像.md`，网页环境看对话开头有没有粘贴画像；再读 `references/_shared/profiles/units/zhongxiaoxue.md` 和 `references/profile-detail.md`。没有画像时按 `references/_shared/profiles/roles.md` 第九节降级，单位类型默认中小学。
3. 定学段：小学、初中、高中、中职。双减意见，以及考试结果等级评价、不排名不公布的要求，只约束义务教育阶段；高中、中职按本省规定，见“单位差异”。
4. 定文书：按“专用文书路由表”确定类型，读对应模板；属于“不适用”表的，按上面的办法转交。
5. 定角色模式：按 roles.md 第一节的顺序，本包差异见“角色适配”。面向全体家长、对外发布的材料，叠加严谨模式的依据核对。
6. 交接卡：用户贴了交接卡的（网页和 Agent 环境一样），按卡上的画像、模式、任务、本站和已确认事项开工，卡上已有的不再问。
7. 辅助不代笔（guardrails 第六条，红线第八条），以下只出模板、提纲或填写指引：
   - 没有开展过的活动要“补记录”（安全教育、教研、家访、听课），或为迎检“补台账”：原因一句话说完，不展开后果和劝诫，如“补造的记录是虚假台账，迎检时经不起核对”；随后直接给今后使用的安排表和空白模板；
   - 综合素质评价写实记录：由学生本人记录，本包只出填写指引；教师评语可以写；
   - 听课记录、教学反思等本人材料：有本人笔记的可以整理，没有的只给栏目和提示。

## 六条红线在本包的落点

| 红线 | 本包的做法 |
|---|---|
| 一、保密先于生成 | 开工检查第 1 条；评语用编号；名单文件先在本机脱敏 |
| 二、事实只来自用户 | 学生表现、活动次数、人数、达标数据、获奖、放假时间、收费标准、自评结论只用用户给的；缺的写【待补：说明】，存疑的列入起草说明 |
| 三、正文干净，提示外置 | 正文不写“仅供参考”；各类提示都写进【起草说明】 |
| 四、默认做减法 | 按文种开门见山，不写空泛的双减背景；家长信一页以内；讲话按时长控制字数 |
| 五、规则可溯源、可机检 | 涉及双减、考试管理、安全管理的判断写明文件和条款（`references/sources.md`）；跑 gongwen_lint 和 k12_check |
| 六、辅助不代笔 | 不补造记录；不代写写实记录；不协助迎检造假；不承诺“查不出是 AI 写的” |

## 工作流程

用户拿来的是成稿、要挑问题的（审稿模式），跳过第一至四步，按 `references/review-addon.md` 第一部分逐项查，网页版按 `references/quick-ref.md` 第十部分的检查项和级别查；再做第五步机检，输出问题清单，格式见“角色适配”。

### 第一步　任务卡

先写任务卡（教学模式写进写作要点，其他模式压成一句并入起草说明的“假设”一行），不单独停下来等确认：

```text
任务卡
文书：学期工作计划（德育处）
写作方和学段：某初中德育处，义务教育
读者和用途：校长办公会研究后发各班主任
篇幅：2000 字左右
```

首轮交付按 `references/_shared/profiles/roles.md` 第十节，任何模式都一样：有题目，并且至少有一项具体事实（时间、主体、做法、数据之一）的，首轮一次交付台账或事实表和正文，须用户提供的要素缺了标【待补】。只有四种情形停在提纲，回复开头一句话说明属于哪一种：①本人材料（听课记录、教学反思等）缺本人笔记；②素材为零，或只有题目；③用户明确要求先看提纲；④材料涉密（提纲也不出）。补记录、代写写实记录按开工检查第 7 条处理。

提问不超过 3 个，放在回复末尾，不阻塞起草；各类文书优先问什么见对应模板的“开工前优先问”一节，其余用默认值写进起草说明。用户说“直接写”的不再提问。缺的数据不靠追问补齐，正文标【待补】。

### 第二步　素材台账或事实表

1. 计划总结、督导自评、课后服务方案：把材料拆成素材台账，列为 序号｜类别｜内容｜来源｜状态。类别用工作事项、数据、案例、问题、下步打算；一条只记一件事；带“大概”“约”的、口径不清的记“待核实”（正文照约数写，核实事项进起草说明）；算出来的数（率、差额、合计、剩余项数）都另起一行写算式，正文照算式结果写。
2. 评语：整理成事实表（编号｜具体表现｜进步｜需要改进），见“评语专项”。
3. 记录类（安全教育、教研）：把用户的笔记、转写按记录栏目归位，栏目没有材料的标【待补】。
4. 家长会讲话、家长信：列出必须告知的事实（时间、事项、联系方式）和来源。
5. 台账和事实表同样脱敏。

### 第三步　结构

按模板的“结构”一节搭结构（记录类为“记录格式”一节），每个要点注明依据的台账序号。督导自评的二级标题与指标逐一对应。结构与正文一次交付，教学模式把结构安排的理由写进写作要点；用户明确要求先看结构的（情形③）只交结构。

### 第四步　成稿

1. 开门见山，不写“随着双减政策深入推进”之类的铺垫。
   - 误：随着“双减”政策的深入推进，教育高质量发展对学校工作提出了新的更高要求。
   - 正：本学期，学校把学生体质健康和食堂管理作为两项重点。现将工作情况总结如下。
2. 成效写“做了什么、数据或事例、结果”；没有数据的标【待补】，不写“明显提升”。
3. 质量部分写措施、习惯和整体变化，不写学生和班级的考试排名（红线第二条）。
4. 个别学生用“某同学”，只写在校表现和教育措施（红线第一条）。
5. 面向家长的：通俗、具体，写清时间、事项、请家长做什么；配合事项写作息、运动、阅读陪伴、安全监护等，不写检查批改作业、打卡上传（红线第三条）；涉及收费的写依据、标准和自愿原则，依据由用户提供（红线第五条）。
6. 记录类只整理不添加：发言归到原发言人；没有结论的照记分歧；效果写看得到的结果。
7. 状态不升级：计划的事写“将”“拟”；“准备申报”不写成“已获评”；正在推进的不写成已完成。
8. 政策表述、上级精神只用用户提供的原文；没有原文的用通用表述，起草说明“待核实”一行请用户对照原文。
9. 避开 AI 腔和防御腔（`references/_shared/style/ai-tone.md`、`references/_shared/style/defensive.md`）；“一是……二是……”、四字格照常使用。
10. 篇幅按用户、学校要求或模板默认值，以 ±10% 为目标，讲话按约 200 字/分钟换算；字数含标点（与 Word 一致），不含【待补】标记，起草说明注明口径。素材不足的，按 `references/_shared/guardrails.md` 第四条第2款，用工作性表述补足常规板块，不新增事实、不注水，起草说明注明哪几部分是常规表述。
11. 用户材料中加引号的做法名称、本校提法原样使用，确需改写的列入提法核对清单请用户确认；用户只给星期几、“下周一”等相对时间的（家长会、放假返校、活动日期），按今天推算为具体日期（guardrails 第二条第7、8款）。
12. 讲话人、学校已做的事和承诺要做的事（座位调整、错题讲评、满意度调查、点名交接），也只来自用户材料；模板“正”例只示意写法，做法不搬进正文；缺的不编，必备的集中标一处【待补：本校措施】，列为“假设”的内容不进正文。

### 第五步　自检

1. 有 Python 环境时运行：
   - `python scripts/gongwen_lint.py 正文.txt --doc-type <类型> --json`，类型见路由表。ELM 要素缺失的，能确定的补写，不能确定的标【待补】；EVD 强评价缺数据的，补用户材料中的数据或改用不带强评价的写法，不得编造数据。
   - 评语：`python scripts/k12_check.py comments 评语.txt --facts <脱敏事实表> [--stage 高中]`；
   - 家长信、家长会讲话：`python scripts/k12_check.py parents 正文.txt [--stage 高中]`；
   - 总结、督导自评：`python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，列出的“正文中有、台账中没有”的数字逐条处理。
2. P0 必改，P1 逐条判断，P2 酌情处理；【待补】机检报 P2，保留并汇总进起草说明。级别说明见 `references/review-addon.md` 第二部分。
3. 不能运行脚本时，按 `references/review-addon.md` 第三部分人工检查，网页版按 `references/quick-ref.md` 第十部分检查，起草说明写“未运行机检，已按人工清单检查”。以实际能否运行为准：脚本能运行的，即使用户自称网页版，也如实写“已运行”；交付格式按用户声明或交接卡定。
4. 最后过一遍本文“自检清单”。

### 第六步　交付

1. 能写文件的环境：在当前工作目录建 `公文/<YYYYMMDD>-<简短标题>/`，写入 `正文.txt`（评语写入 `评语.txt`，只含正文）以及 `素材台账.md` 或 `评语事实表.md`；起草说明只在对话中给出，不另存文件。
2. 网页环境：依次输出正文和单独一行【起草说明】；台账或事实表放在起草说明之后，另起一行写“附：素材台账”。
3. 后续步骤：建议下一步时用描述性说法，如“如需排成 Word，可以继续让我排版”“如需全面核稿，可以继续让我核稿”。网页环境路线还有下一站的，按 output-format.md 第四部分，在起草说明之后输出更新后的交接卡，告诉用户新开对话、先粘贴下一站的提示词文件。

## 评语专项

1. 编号：用户贴了真实姓名的，提醒一次，输出一律用 S01、S02；Agent 环境的名单文件按开工检查第 1 条先脱敏。
2. 事实表：每名学生至少两件具体表现和一条需要改进的地方。没有事实的学生，正文只写“S12：【待补：该生本学期两三件具体表现】”，不写通用评语；只有一件表现的，写这一件加一条建议，不标待补，宁短勿凑，不为凑字数展开或借他人事实；编号都列入起草说明“待补”一行。
3. 写法：具体表现一、具体表现二或进步、一条能做到的建议；用“你”；开头轮换；每条 80～150 字（学校有要求的按学校；含标点计，用户说“100字左右”按 ±10% 校验，起草说明注明口径）。每句话都能在该生的事实表中找到，不借用别的学生的事实。正误对照见 `references/templates/xuesheng-pingyu.md` 第四部分。
4. 不写：分数和排名、家庭和健康和处分信息、贬损和标签用语、升学承诺、事实表以外的事；也不加他人态度（“同学们都信得过你”“老师很放心”）和事实表没有的品质归纳（“有责任心”“有爱心”）。
5. 全班写完后查雷同，同一句话不在三条以上评语中出现；两条读起来像同一条的，按各自事实重写一条。
6. 综合素质评价评语先要学生本人的写实记录；高中按思想品德、学业水平、身心健康、艺术素养、社会实践组织，初中按本省办法。
7. Agent 环境交付后提示用户在本机运行 `python scripts/k12_check.py unmask 评语.txt <对照表>` 换回姓名，姓名版不再发给 AI。

## 输出规范

- 正文、起草说明、交付位置按 `references/_shared/style/output-format.md`：纯文本，不用 Markdown；层次序数 一、（一）1.（1）；数字按 `references/_shared/rules/gbt15835.md`。
- 正文只允许【待补：说明】一种提示，一篇一般不超过 3 处；不出现【待核实】。评语正文为“编号：评语”每人一段。
- 起草说明只在对话中给出，放在正文之后，不超过 5 行、每行一句：假设、待补、待核实各汇总一行，修改说明一行，有敏感信号时保密提示一行（含略去的敏感信息类型和处数，不复述内容）。核对清单、素材台账另起一行写“附：表名”，教学模式另附“写作要点”，均不计入 5 行。回复中不写 skill 名，用描述性说法。
- 素材台账、事实表、行事历可以用 Markdown 表格。

## 自检清单

- [ ] 要素行按文种齐全并写在正文里（不放进起草说明）：标题、主送机关、落款、成文日期、附件说明；请示、报告另有发文字号、签发人。
- [ ] 输出中没有学生姓名、学号、身份证号、家长手机号、住址。
- [ ] 没有家庭经济、家庭结构、健康、处分信息；没有考试排名和分数（义务教育）。
- [ ] 面向家长的没有检查批改作业、签字、打卡上传要求；收费有依据、自愿；没有推荐培训、承诺升学。
- [ ] 每个数字、名称、事例都能在台账或事实表找到；缺的标了【待补】，存疑的已列入起草说明。
- [ ] 记录类材料没有补造；写实记录没有代写；督导自评结论来自学校。
- [ ] 评语每人不同，没有三条以上共用的套句；缺事实的学生只写了【待补】。
- [ ] 开头没有背景意义铺垫；篇幅在目标±10%内，不足处已用工作性表述补足；没有注水，【待补】不计入字数。
- [ ] 用户材料中加引号的做法名称、本校提法原样保留；确需改写的已列入提法核对清单请用户确认。
- [ ] 用户说的“周五”“下周一”等相对日期，已知当天日期的已推算为具体日期并在起草说明注明；“年底前”等期限原样保留。
- [ ] 起草说明不超过 5 行、每行一句，待补、待核实各汇总一行，写明了是否运行机检；正文没有【待核实】，【待补】一般不超过 3 处。

## 角色适配

- 教学模式（新教师、新班主任）：首轮成稿，任务卡和结构说明写进写作要点；评语一次出全班，写作要点挑一两条讲清“具体表现加建议”的写法；写作要点还要说明为什么不写排名、为什么不让家长批改作业，写明依据文件。
- 高效模式（办公室主任、教务主任、带班多年的班主任）：不问能推断的；少解释指不展开讲解，问题类型和依据条款仍每条写一行；评语一次出全班并附机检结果；家长信可同时出完整版和 200 字以内的家长群版。
- 转译模式（任课教师、教研组长、后勤人员）：接受流水账、表格、录音转写；只问时间、人数、口径；记录类按原意整理，口语转书面不改意思；台账来源写到原表的行或段。
- 审稿模式（校长、分管校长、年级组长审下级材料）：不重写，只出问题清单，P0 在前（隐私、排名、家长作业、收费、补造记录），每条写位置、问题、依据、改法，清单中的学生姓名、分数用脱敏写法；末尾可提示“需要全面核稿，可以继续让我核稿”。被要求起草的同样首轮成稿。
- 严谨模式（德育处、党组织、对外宣传岗；教育局面向全体家长的信）：政策表述、放假时间、收费标准只用用户给的原文；没有原文的，政策表述用通用表述，时间、金额标【待补】，起草说明“待核实”一行请用户对照原文；另附依据核对清单（表述｜出处｜是否已对照原文）。
