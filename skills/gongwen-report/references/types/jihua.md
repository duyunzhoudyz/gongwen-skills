# 计划

## 一、用途

对下一阶段（年度、季度、学期）要做的工作作出安排，写清目标、任务、责任和时间。

与相邻材料的区别：
- 工作要点只列重点、较简，常以通知印发；计划写得更细，每项任务落到责任和时间。
- 实施方案针对某一项专项任务，写清怎么组织实施；计划覆盖一段时间内的全部工作。
- 总结中的“下一步打算”是计划的雏形。同一单位同时写总结和计划的，计划的任务要与总结的问题和打算对上。
- 以通知印发的，印发通知交 gongwen-draft。

## 二、常见结构框架

框架一：目标、任务、保障（最常用）

```text
某某单位2027年工作计划
开头：为……，结合……，制定本计划。（一句）
一、工作目标
二、主要任务和措施
（一）任务一（责任部门，完成时限）
（二）任务二
三、保障措施
```

框架二：按时间分解（适合季度推进明显的工作）

```text
一、总体目标
二、分阶段安排
（一）第一季度
（二）第二季度
……
三、工作要求
```

框架三：学期计划（中小学、高校院系）

```text
一、工作目标
二、主要工作（德育、教学、教研、安全、家校协同等板块）
三、行事历（按周或按月列主要活动）
```

用户要求时，行事历可以用表格；交付 Word 时由 gongwen-format 转换。

## 三、各部分写法

1. 开头：一句话写依据和目的。依据只写用户提供的文件名称，没有提供的不写“根据上级要求”一类虚指。
2. 工作目标：能量化的量化。目标值只来自用户、上级下达的任务或单位画像；没有的写【待补：目标值】。
3. 主要任务和措施：每项写清“谁来做、做什么、何时完成、做到什么程度”。四要素中台账没有的，部门只用已有的（没有的写“各部门按职责落实”），具体日期必须由用户定的才标【待补】，不编部门和日期。
4. 保障措施：两三条，每条有具体动作，如“每月第一周召开一次推进会，由办公室汇总进度”。删掉“高度重视”“加强领导”一类空表态（`references/_shared/rules/jianfu.md` JF-03）。
5. 措辞：部署内容用“要”“将”，不用“建议”“可以考虑”“尽量”（`references/_shared/style/defensive.md` 第五部分）。

## 四、篇幅建议

工具约定：单位年度计划 1500～3000 字；科室、部门计划 1000～2000 字；学期计划 1500～2500 字（含行事历另计）。以通知印发的部门计划属于“部署具体任务的文件”时，党政机关、基层、社区不超过 4000 字（`references/_shared/rules/jianfu.md` 第2条）。

## 五、常见毛病

1. 目标无法衡量。
   - 误：全面提升服务水平，努力开创工作新局面。
   - 正：2027年底前，窗口平均等候时间由【待补：现值】分钟压缩到15分钟以内。
2. 任务没有责任和时限。
   - 误：加强信息化建设，推进数据共享。
   - 正：二季度完成与人社系统的数据对接，由信息科牵头、业务科配合。
3. 照抄上级部署原文，没有本单位措施（`references/_shared/rules/jianfu.md` JF-04）。上级原文里的任务，要写成本单位怎么落实；措施缺失的，按上级要求和常规写出可执行措施。
4. 计划与上年总结脱节：总结里提的问题，计划里没有对应任务。
5. 保障部分比任务部分还长。

## 六、单位差异提示

- 党政机关：年度计划常与工作要点合一，按画像确定写哪一种。
- 中小学：以学期为单位，按板块写，附行事历；不给教师摊派与教育教学无关的任务。
- 高校：学院计划与学校党政工作要点对应，逐条承接。
- 医院：科室计划围绕质量指标、学科建设、新技术新项目，指标名称用所依据考核体系的正式名称。
- 国企：经营指标（收入、利润总额等）只用上级下达或用户提供的数，任务落到部门和时间。
- 基层：不把任务层层转嫁给村（社区），不写“签订责任状”“制度上墙”（`references/_shared/rules/jianfu.md` JF-12）。
