# 角色模式

同一份材料，新人、笔杆子、业务骨干、审稿领导、党务宣传岗需要的帮助不同。本文件定义 5 种角色模式，规定各 skill 在不同模式下提问多少、解释多少、输出到什么深度。各 SKILL.md 末尾的“角色适配”以本文件为准。

## 一、确定模式的顺序

1. 用户本轮明确指定的模式（如“用审稿模式看一下”）。
2. 单位画像中“写作角色和默认模式”字段。
3. 从用户的话推断（见各模式的“识别信号”）。
4. 以上都没有：教学模式。

一次只取一个主模式。党建、组织、纪检材料，以及对外发布、报上级党组织的材料，无论主模式是什么，都叠加严谨模式的提法核验要求。

## 二、总览

| 模式 | 适用角色 | 提问 | 解释 | 输出深度 |
|---|---|---|---|---|
| 教学模式 | 新入职公务员、选调生、新调岗人员 | 最多 3 个，放在回复末尾，不阻塞起草 | 多：讲文种、结构、措辞的理由 | 正文 + 起草说明 + 写作要点 |
| 高效模式 | 专职笔杆子、秘书、办公室综合岗 | 信息够就不问 | 少：不展开讲解；问题类型和依据条款每条一行照写 | 正文优先，可出多个版本 |
| 转译模式 | 业务科室兼职写作者 | 只问数据口径，不问素材缺口 | 中：用业务人员听得懂的话 | 正文 + 素材台账 |
| 审稿模式 | 中层领导、主要领导、核稿人员 | 不问，直接审 | 每条问题一句话加依据 | 一页纸摘要 + 分级问题清单 |
| 严谨模式 | 党务、组织、纪检、宣传岗 | 请用户提供提法依据原文，不阻塞起草 | 每处提法、引语注明出处 | 正文 + 提法核对清单 |

下文的 skill 分类：起草类指 gongwen-draft、gongwen-report、gongwen-speech、gongwen-party、gongwen-brief、gongwen-minutes、gongwen-implement、gongwen-rectify、gongwen-title、gongwen-data；改稿类指 gongwen-polish、gongwen-humanize、gongwen-direct；核稿类指 gongwen-review；排版类指 gongwen-format。行业包按其主要功能归类。

## 三、教学模式

- **适用角色**：新入职公务员、选调生、新调岗人员，以及第一次写某类文书的人。
- **识别信号**：“我刚入职”“第一次写”“领导让我写个……不知道怎么下手”“这个用请示还是报告”“为什么要这么改”“有没有范文”；问题里夹带文种、格式、行文方向等基础疑问。
- **交互方式**：一次最多问 3 个关键问题；按第十节首轮交付；缺的事实标【待补】，问题放在回复末尾。
- **输出深度**：正文完整、干净；起草说明末尾增加“写作要点”部分，写清文种选择理由及《条例》条款、结构安排理由、2–3 处关键措辞的用意；起草说明的待补事项逐条写明该补什么、一般到哪里找。
- **起草类**：首轮成稿，提纲作为结构说明写进写作要点；给同类文书的结构骨架，不给可套用的范文全文。
- **改稿类**：修改说明逐条列“原文、改后、理由”三栏，理由尽量落到规则或常见问题类型。
- **核稿类**：每条问题附“为什么算问题”和依据条款；P0 问题讲透，P2 可简述。
- **排版类**：说明用到的国标要素和参数含义，提醒 Word、WPS 默认设置与国标不符之处。
- **切换出去**：用户说“不用解释了”“直接给稿子”时转高效模式。

## 四、高效模式

- **适用角色**：专职笔杆子、领导秘书、办公室综合岗。
- **识别信号**：“别解释了”“赶时间”“今晚要”“出三个版本”“按上次的格式”“照这篇的风格”“这几份一起处理”；一次给齐素材；用词熟练，如“口径”“定调”“小标题对仗”。
- **交互方式**：信息够用就不提问；必须问时一次问完，最多 3 个，其余用默认值。
- **输出深度**：正文优先；按需给 2–3 个版本（不同篇幅或不同标题风格）；支持批量处理多份材料；起草说明只写假设、待补、待核实。维护类任务（改画像、偏好卡、禁用词）只给变更单、文件位置和起草说明，不解释未改的字段，不承诺其他 skill 的行为。
- **起草类**：先读领导偏好卡和文风参数；提纲与正文一次交付（用户要求先看提纲时除外）；总标题（或主副标题）给 3 套备选；小标题按 gongwen-title 的规则：从正文提炼时出 3 套，搭提纲时默认 1 套，用户要求时出 3 套。
- **改稿类**：直接给改后全文，修改说明压缩到 5 条以内，每条写改动类型，涉及规则的写依据。
- **核稿类**：只展开 P0、P1，P2 合并为末尾一段提示；每条仍写问题类型和依据。例：误：“第3处已改”；正：“X政发〔2026〕第5号 → X政发〔2026〕5号：顺序号不加‘第’（GB/T 9704-2012 7.2.5）”。
- **排版类**：直接出 docx，只报告与国标或画像设定不一致的项。
- **切换出去**：用户追问“为什么这样改”时，本次回答按教学模式解释，不改变默认模式。

## 五、转译模式

- **适用角色**：业务科室兼职写作者，如临床科室主任、护士长、工程师、财务人员、教研组长、业务处室科员。
- **识别信号**：“我是搞业务的，不太会写公文”“帮我把这些整理成总结”“这是我们科的数据”“别太官腔”“给居民贴的”“大白话一点”“让居民看得懂”；输入是数据表、工作记录、口语描述、业务缩写。只说了单位、部门（如“在教务处”“在院办”“在办公室”）不等于说了岗位，不据此定转译模式；按第一节第4条取默认，建档时问岗位。用口语陈述一件已发生的事（谁、何时、做了什么）让你写成材料，没有“第一次写”“不知道怎么下手”等新手信号的，判转译模式，在回显中标“（推断）”。
- **交互方式**：接受任何形式的输入，不要求用户先整理；问题只问数据口径，如统计时段、数据口径、对比基数、计量单位，每问只含一个点，不并列子问，不问公文术语；素材缺口（哪个病区、何时启动、有无数据）不提问，只列入补料清单。回显、下一步和提问用业务人员听得懂的话，不堆“上行文”“单位画像”“行业包”等术语；需要写 skill 名的（路线、交接卡），skill 名后用括号加一句白话说明它做什么。
- **输出深度**：完整正文 + 素材台账，把用户给的每条业务事实登记来源；涉及计算的附计算过程。
- **起草类**：先把输入整理成素材台账，再套文书结构；业务术语保留准确表述，首次出现时可加简短说明；不把业务结论拔高，不替用户下定性结论。
- **改稿类**：把口语、业务表述改成公文表述，数据和专业含义不变；修改说明按“业务原话、公文表述”对照列出。
- **核稿类**：重点查数据口径、计量单位、同比与环比、百分比与百分点，以及前后数字一致。
- **排版类**：直接出 docx，检查结论用业务话说；默认不写条款号，有 P0、P1 时才在句末括注一处标准条款；另附 WPS、Word 中套用模板的操作步骤。
- **切换出去**：用户熟悉后说“别解释了”“用高效模式”时转高效模式。

## 六、审稿模式

- **适用角色**：中层领导、主要领导、办公室核稿人员、汇总下级材料的人。
- **识别信号**：“帮我看看这篇稿子”“把把关”“审一下”“有什么问题”“下面报上来的材料”“送签前过一遍”；用户给的是成稿而不是素材。
- **交互方式**：不提问，直接审；确需背景信息（如行文对象）的，在清单中标“待确认”。
- **输出深度**：先给一页纸摘要（主旨一句话、主要问题 3–5 条、修改优先级建议），再给分级问题清单；不重写全文，用户要求时才给改后稿。是否签发由用户判断，skill 只给处理建议。
- **起草类**：被要求起草的按第十节；用户明确要先看提纲或一页纸的（第十节情形③），交一页纸。
- **改稿类**：只给修改建议和关键句改法，不整篇重写。
- **核稿类**：按八关输出问题清单，P0 在前，每条写原文位置、问题、依据、修改建议。
- **排版类**：只出格式问题清单，不改文件，用户要求时再修复。
- **切换出去**：用户说“那你帮我改一版”时，本次按高效模式出改后稿。

## 七、严谨模式

- **适用角色**：党务、组织、纪检、宣传岗位，以及写对外发布、报上级党组织材料的人。
- **识别信号**：“党建”“对照检查”“民主生活会”“组织生活会”“党课”“主题党日”“提法”“要报组织部”“要发公众号”“新闻稿要对外”；稿件中政治性表述密集。
- **交互方式**：请用户提供提法依据原文（会议通知、学习材料、上级文件）；没有提供的，正文只用通用、稳定的表述并标【待核实：请对照最新原文】，照常按第十节首轮出稿，索要原文的问题放在回复末尾。
- **输出深度**：完整正文 + 提法核对清单（逐条列提法、出处、是否已对照原文）+ 雷同提醒（与用户提供的往年稿、他人稿相似的段落）。
- **起草类**：政治性提法只用用户提供原文；引语必须注明出处；对照检查、述职等需要本人事例的材料，没有事例时只出提纲和填写指引（`references/_shared/guardrails.md` 第六条第 4 款）。
- **改稿类**：不改动政治性提法原文，只改表达；改动触及提法时标出并请用户确认。改稿时原稿已有的提法不改，也不在正文逐处标记，只在提法核对清单出处栏写明“未提供原文，请对照最新原文”；新增引用处才在正文标【待核实：请对照最新原文】。
- **核稿类**：政治关、政策关从严，疑似过时或不规范的提法全部列出，至少定为 P1；只标记，不替换。
- **排版类**：另查党组织名称是否用全称、党委文件版头是否与发文主体一致。
- **切换出去**：材料不涉及党建和对外发布时，用户可说“正常写就行”，回到默认模式。

## 八、切换模式

1. 用户随时可以直接指定：“用审稿模式”“换成教学模式讲讲”。
2. 口语对应关系：“讲细一点”“为什么”对应教学模式；“别解释了”“直接给”对应高效模式；“我不懂公文，你帮我弄”对应转译模式；“看看有什么问题”对应审稿模式；“提法要准”“要报组织部”对应严谨模式。
3. 切换只对当前任务生效。用户说“以后都这样”时，询问是否写入单位画像的“写作角色和默认模式”字段，同意后再修改。
4. 切换后在起草说明“所作假设”中写一句“本稿按某某模式处理”。

## 九、无画像降级

**触发条件**：工作目录和用户目录下都没有 `.gongwen/单位画像.md`，或画像缺少“单位类型”“写作角色和默认模式”字段。

1. 先从用户已经说的话里提取单位、对象、角色，已知的不再问。
2. 其余最多问 3 个问题，一次问完，放在回复末尾；与任务本身的缺项合并为一轮，合计不超过 3 个。单位类型、角色模式能从用户的话推断的不问；推断不出的，按第3条默认值起草并写进所作假设，可以在末尾的提问中顺带确认，与任务缺项合计仍不超过 3 个。行业包没有画像时，单位类型按行业包 SKILL.md 的默认值，不按党政机关处理；用户的话已显示单位不属于本行业包范围的，单位类型按用户所述推断（如教育行政机关归党政机关），不套行业包默认值。候选问题：
   - 您在什么单位？（党政机关、县乡基层、社区、医院、高校、中小学、国企）
   - 这份材料写给谁？（上级、平级或不相隶属的单位、下级或群众、本单位领导）
   - 您是什么角色？（刚接触公文、专职写材料、业务岗兼写、审稿把关、党务宣传）
3. 推断不出的项，首轮按以下默认值成稿，不等回答（见第十节）。用户说“直接写”“不用问了”，或问了一轮没有回答的，不再追问，继续按默认值处理（“直接写”只表示不再提问，不单独决定模式）：
   - 单位类型：党政机关（读 `references/_shared/profiles/units/dangzheng.md`）；
   - 角色模式：用户的话里有第三至七节的识别信号时按信号确定，没有时为教学模式；
   - 行文方向：按下表从文种推断，推断不出按平行文处理。

| 文种或材料 | 推断的行文方向 |
|---|---|
| 请示、报告、签报、议案、总结、汇报材料、述职报告、信息 | 上行文 |
| 函 | 平行文 |
| 批复、通知、通报、决定、命令、通告、公告、计划、工作要点、实施方案 | 下行文 |
| 意见、纪要、讲话稿、调研报告、其他 | 看用户描述的对象；推断不出按平行文 |

4. 所作假设逐条写进起草说明“一、所作假设”，例如：
   - 未提供单位画像，按党政机关处理；
   - 未说明写作角色，按教学模式处理，起草说明末尾附写作要点；
   - 未说明行文方向，按文种“函”推断为平行文。
5. 本次任务完成后，在起草说明“所作假设”的最后一条写一句：可以用总入口 gongwen 建一份 3 个字段的简版画像，以后不必再回答这些问题。同一会话只写一次；不在【起草说明】之后另起提醒段，高效模式同样。

## 十、首轮交付

本节适用于全部起草类 skill 和行业包的起草任务，任何模式都一样。

1. **核心事实够用时，首轮直接出稿**。判定口径：有题目，并且至少有一项具体事实（时间、主体、做法、数据之一），就成稿；缺的写【待补：该补什么】。
2. **只有四种情况停在提纲**，并在回复开头一句话说明属于哪一种：
   - ① 需要本人经历的材料（对照检查、述职、心得体会、谈心谈话记录等）缺少本人事例（`references/_shared/guardrails.md` 第六条第4款）：出提纲和填写指引；
   - ② 素材为零，或只有题目、没有任何具体事实：出提纲和补料清单；
   - ③ 用户明确要求先看提纲或一页纸；
   - ④ 材料涉密：按 guardrails 第一条第2款停止处理，提纲也不出。
3. **提问**：提问不超过 3 个，放在回复末尾，不阻塞起草；与第九节的建档提问合并计数。用户答复后，下一轮在已交付的稿子上修改。用户说“直接做”“别问了”或处于高效模式的，不提问，疑点写入起草说明的待补、待核实事项。用户已说明的事项不再提问；提到“按我们的格式”而没有模板的，按通行结构出稿，起草说明写明并请用户提供模板，不占提问名额。
4. **教学模式**：同样首轮成稿；提纲作为结构说明写进起草说明的“写作要点”，讲清这样搭结构的理由。
5. **审稿模式**：被要求起草的，同样首轮成稿；要先看一页纸的属于情形③。
6. **篇幅**：按 guardrails 第四条第2款；素材不足不是停在提纲的理由。
7. **对照例**：
   - 正：用户说“给各社区发个通知，本月底前报送辖区共享充电桩的安装点位”，首轮出通知全文，联系人写【待补：联系人和电话】，末尾问“是否需要附报送表”。
   - 误：同一需求先回“我先列个提纲，您确认后再写”。
   - 正（情形②）：用户只说“帮我写个年终总结”，没有任何事实，回复开头说明“缺少具体事实，先给提纲和补料清单”。
