# 文种量化基线（公开公文语料）

本文件回答一个问题：真实公文大致长什么样。数据来自 300 篇政府官方网站公开发布的公文和政务文稿，覆盖 11 个文种，由 `tools/build_baseline.py` 重算，机读版是仓库里的 `shared/style/baseline.json`（约 250 KB，只随 draft、speech、report、polish、humanize、review 分发，供 `gongwen_lint.py --baseline` 使用）。仓库只存统计结果和出处（标题、发文机关、日期、URL、字数、文本哈希），不存全文。

四条使用原则：
1. 基线是参照，不是规定。篇幅和层次以上级要求、既有模板、事项复杂程度为准。偏离基线时先问有没有理由，有理由就不改。
2. 只在同一文种、相近篇幅里比较。表中给的是中位数和四分位区间（括号内为第一四分位～第三四分位），区间内都算常见。
3. 标“样本偏少”或机关数不足 3 个的行，只作方向参考。
4. 判断 AI 腔时看“是否远离真实区间”。真实公文里常见的词，单看出现与否没有意义，要看密度和位置。

读表说明：
- 字数为全文非空白字符数，含标点；“自然段数”含标题、署名行。
- 句长按句号、问号、叹号、分号切分，取每篇平均值后再统计。
- 一至三级标题分别指 一、 / （一） / 1. 开头的自然段。四级标题（1）在语料里几乎不出现，未列。
- 四字格比例是近似指标：以标点和数字为界切出连续汉字片段，恰为四个字的片段占全部片段的比例，不做成语词典匹配。
- 开头、结语方式由固定规则归类（见 `tools/build_baseline.py` 的 `OPENING_RULES`、`CLOSING_RULES`），没有人工标注复核，百分比只看大势。
- 词表规则表中，带阈值的规则“命中文档占比”只表示出现过至少一次，没有判断意义（顿号、冒号几乎每篇都有），要看“超阈值文档占比”；它按机检的口径计算，即命中不少于 2 处且每千字密度大于阈值。

## 三、怎么用

### （一）起草时定篇幅和层次

按文种和篇幅查表。以下是语料里的典型对应（样本不大，作量级参考）：

- 通知（部署类）：1000～2000 字时一般 3 个一级标题、5 个二级标题；2000～4000 字时约 6 个一级、10 个二级；不足 1000 字多数只有 1 个一级标题或不设标题。
- 意见：一半以上在 2000～4000 字，一般 5 个一级标题、13 个二级标题；4000～8000 字时一级仍是 5 个，二级增到 16 个。篇幅加长靠增加二级标题，不靠增加一级。
- 方案：4000～8000 字时一般 8 个一级、22 个二级标题；8000～16000 字时约 10 个一级、36 个二级。平均每个一级标题统领 600～1000 字。
- 批复、函：批复约 680 字、9 个自然段，77% 用“一、二、三、四”分条，中位 4 条；函约 420 字、8 个自然段，一半不分条。
- 政府工作报告：全文 1.6 万～1.9 万字；一级标题多为 3 个，二级标题 10～17 个；自然段长度中位约 200 字。
- 讲话（部委工作会议）：4000～8000 字时一般 3 个一级标题，不设二级；16000 字以上仍是 3 个一级，二级约 10 个。写“三点意见”是最常见的结构。国家领导人的外事讲话篇幅短（约 1300～1900 字），不分级。

### （二）句子和段落

- 平均句长 40～55 字是常态：通知 52、意见 49、方案 45、政府工作报告 42、讲话 47。批复（66）和通报（58）一句话里常含多层意思，可以更长，但第三四分位以上的句子读起来已经吃力。
- 含句末标点的自然段，长度中位数：通知 138 字、意见 182 字、方案 149 字、政府工作报告 200 字、讲话约 200 字。
- 顿号每千字 20～25 个是常态，专项报告偏低（14）。机检的顿号阈值已按本基线由 35 调为每千字 45 个，见本文第四部分（六）。

### （三）开头和结语

- 通知：约一半以“为……，现就……通知如下”这类目的句起笔；“特此通知”只占 13%，近七成没有固定结语，以最后一项要求收束。
- 批复：82% 以“你单位关于……请示收悉”起笔；国务院批复的结尾 46% 用“重大事项及时按程序请示报告”，“特此批复”只占 9%。
- 函：53% 以来文答复式起笔，78% 没有固定结语。
- 意见、方案：几乎不用套语结尾（84%、80% 以实质要求收束）。
- 政府工作报告：84% 以“现在，我代表……向大会报告工作”起笔，68% 以号召或致谢收束。
- 讲话：开头多为“今天”“刚才”“这次会议”一类会议起笔（70%），95% 以号召、致谢收束。
- 提醒：现行公文里“特此通知”“特此函复”不是必选项。不要为了像公文硬加固定结语，也不要把“无结语”当成缺陷。

### （四）“一是……二是……”

- 通知、意见、方案、批复、函、通报里几乎不用：有“一是”的文档占 0%～11%。
- 政府工作报告 58%、讲话 75%、专项报告 83%、工作总结（年报）58% 的文档用，但每篇中位只有 1 组，专项报告约 7～8 组（篇幅在万字以上）。
- 所以通知、意见里一篇出现两三组“一是……二是……”，已经超出真实区间；讲话、报告里一两组属正常。

### （五）套话和评价词的基准

“进一步”“加强”“推进”“落实”是最高频的动词和副词，在多数文种里每千字出现 0.3～3 次，出现比例 50%～100%，不要因为词表里有就删光。需要警惕的是：“打造”“赋能”“助力”“闭环”等新词在通知、通报里极少（每千字不到 0.2），在政府工作报告里才常见（“打造”每千字约 1.1，100% 的篇有）。把这些词放进通知、函、批复，比放进政府工作报告更像 AI 腔。评价词也是同样的分布：“显著”在通知里只有 3% 的篇出现、批复 4%、函 6%，在政府工作报告里 58%、讲话里 75%。通知、批复、函里的评价多靠事实和数据，不靠形容词。

## 四、与 style_patterns.json 词表的对照

本部分（一）至（五）是词表首版（校准前）的对照发现，处理结果见（六）。口径与机检一致：逐自然段匹配，剔除白名单和 exclude 重叠的命中，并按规则的 doc_types、exempt_doc_types 判断是否适用。

### （一）总体

82 条规则中，57 条在 300 篇真实公文里一次都没有命中，包括段首评论语（AI-001～003）、“不是……而是”对举（AI-006～009）、空话引列表（AI-012）、总结标签（AI-038、039）、防御性表述中的免责、划边界和多数对冲类（DEF-001～011 等）。这些规则在真实公文里的底噪为零，命中时可以更放心地判为问题（前提是正则本身没有误报）。完整清单见 `baseline.json` 的 `style_patterns_zero_hit`。

### （二）阈值偏紧，真实公文会被误报的规则

- AI-051 顿号罗列过密（阈值 35）：7.3% 的真实公文超阈值；通报 18%、印发转发类通知 16%、函 9%、通知 8%。这些文种的列项式写法（逐项列出名单、数据）顿号天然多。建议对通报、函和印发转发类通知放宽或豁免。
- AI-026 新八股词（阈值 2）：48% 的真实公文含有其中至少一个词，6.7% 超阈值；意见、政府工作报告各 16%，方案 12%。主要来自“打造”“赋能”“助力”。建议对政府工作报告、意见、方案、讲话提高阈值，或把“打造”从词表里去掉（它在政府工作报告里每千字约 1.1 次）。
- AI-013 冒号过密（阈值 3）：批复、函、通报各有 9%～11% 超阈值（“同意……：”“现将……如下：”后接多项）。
- DEF-019 “这一”（阈值 3）：55% 的文档含有，超阈值 2.3%，在专项报告和政府工作报告里 100% 出现，正常现象，可以只在通知、函、批复里计较。

### （三）没有阈值、真实公文里会被逐处报告的规则

- AI-023 概括代替数据（“显著提升”“明显增强”）：政府工作报告 53%、讲话 40%、专项报告 33% 的文档命中。这是总结性文种的正当写法，建议对这三类文种豁免或降级。
- AI-028 新八股词（里程碑、划时代等）：讲话 40%、政府工作报告 21% 命中，几乎都是“具有里程碑意义”的政治性提法。建议对讲话、政府工作报告、专项报告豁免。
- AI-029“至关重要、意义深远”：政府工作报告 16%、讲话 15% 命中，同类处理。
- AI-025 新八股词里的“出圈”：政府工作报告 21% 命中（如“火爆出圈”），是对文旅消费的陈述，不是 AI 腔。

### （四）正则本身的误报（在真实公文里能直接看到）

- AI-004 段首评论语中的“划重点”：命中“规划重点项目”“规划重点任务”，共 5 篇（意见、方案、通知、专项报告等）。应改为不被“规”“计”“策”等字前置的写法。
- AI-018 译文腔：命中“每低一个百分点扣 0.1 分……的不得分”“一个违法行为……的情形”一类固定表述。
- AI-022 拟人化喻体中的“灯塔”：命中“灯塔工厂”“灯塔市”。“双刃剑”在讲话里是正当用法。
- DEF-012、DEF-022 对“尽可能”的处理：通知、方案、讲话里的“尽可能提高接种率”“尽可能稳在企业”是有明确指向的要求，不是回避表态。

### （五）可以直接拿来当“AI 腔信号”的

破折号过密（AI-010）在真实公文中只有 2.3% 的篇出现，超阈值为 0；段首评论语、翻案句式、元评论、总结标签几乎不出现。这些信号在真实公文里的底噪接近零，命中就值得改。

### （六）据此做的校准

- 正则误报：AI-004“划重点”不再匹配“规划重点”“计划重点”等；AI-018 只在“是、有、要、需、建立”等动词后的“一个/一套……的”处匹配，且长定语中含数字、百分号时不报；AI-022“灯塔”不再匹配“灯塔工厂”“灯塔市”；DEF-012 不再把“尽可能提高”当作“可能提高”；DEF-022 排除“尽可能提高”“尽量依托”“尽量减少”等有明确指向的要求。上述修改后，300 篇语料里 AI-004、AI-018、DEF-012 零命中。
- 文种豁免：AI-023、AI-028、AI-029 对讲话稿、党课讲稿、报告（机检把政府工作报告、专项报告都归为“报告”）不再报告。
- 阈值调整，括号内为超阈值文档占比的前后变化：
  - AI-051 顿号由 35 调为 45（7.3% 降到 3.8%）。
  - AI-026 新八股词由 2 调为 2.5（6.7% 降到 3.0%）。
  - AI-013 冒号由 3 调为 4（约 3% 降到 2%）。
  - AI-025“出圈”和 DEF-019 未改。
- 新增 `gongwen_lint.py --baseline`：对已识别文种比较篇幅、一级标题数、“一是”组数、顿号密度，偏离 P10～P90 区间的给 P2 提示，只提示不判错。

## 五、局限

1. 样本量：单个文种 12～40 篇，按篇幅分档后，有的档只有 3 篇，只能看量级。批复只有 8 个机关（国务院占 13 篇），专项报告只有 3 个机关，讲话中生态环境部占 6 篇。
2. 来源偏向：全部来自政府官方网站公开发布的文件，偏中央部委、国务院办公厅和省市政府门户；乡镇、街道、社区、企事业单位、党委系统的公文几乎没有。发布时间偏近（2025—2026 年占 54%）。
3. 内部流转文种缺失：请示、上报型“情况报告”、会议纪要、签报、没有公开的讲话稿都拿不到。表中的“报告”是国务院向人大的法定报告，不代表机关日常的工作报告；“工作总结”用政府信息公开年报替代，格式化程度高，也不代表一般的年度工作总结。
4. 公开稿不等于起草稿：网页发布版已经过编辑，没有版头版记，换行和标题层次受网页结构影响。部署类通知以首个落款日期为界截掉附件；少数页面可能误切。
5. 指标是近似的：句长、层次、一是二是的计数基于正则；开头和结语分类基于固定规则，没有做人工标注评估；四字格是代理指标。
6. 讲话一栏混合了部委全国工作会议讲话（长，万字上下）和国家领导人讲话（短，含外事场合），已分开列出子类。写县、市、局级会议讲话时，更接近“部委工作会议”子类的结构，但篇幅通常更短。
7. 机检对照只是“真实公文里的底噪”，不能反推“AI 生成文本里的命中率”。要定阈值，还需要一批 AI 生成文本做对照。

## 六、重算与复现

语料放在仓库外的临时目录，结构如下：

```
<语料目录>/
  sources.json          来源清单（{"meta": {...}, "docs": [...]}）
  通知/xxx.txt          纯文本，UTF-8，一行一个自然段
  意见/xxx.txt
  ...
```

`sources.json` 每项含 `doc_type`（与子目录同名）、`file`（相对语料目录）、`title`、`org`、`date`、`url`，可选 `subtype`（子类，如“讲话”下的“部委工作会议”）和 `segment`（`main` 为正文，`attachment` 为所附文件）。

```
python tools/build_baseline.py --corpus <语料目录>             # 写入 shared/style/baseline.json
python tools/build_baseline.py --corpus <语料目录> --check     # 只比较，不一致返回 1
python tools/build_baseline.py --corpus <语料目录> --print-tables   # 输出本文第二部分的表格
```

输出是确定性的：同样的语料得到逐字节相同的 JSON。`baseline.json` 的 `sources` 里记录了每篇的出处和文本哈希前 16 位（`sha256_16`），按 URL 重新抓取后可核对网页是否有变动。取样时间 2026-10-21。来源登记见 `docs/借鉴记录/baseline.md`。

补充语料的做法：按 URL 抓取网页正文，去掉导航、页脚、脚本和发文字号，整理成每行一个自然段的纯文本，在 `sources.json` 里登记后重算即可。新文种直接新建子目录，工具会自动成组；`LINT_DOC_TYPE` 里没有对应关系的文种，词表规则按文种名原样判断适用性。
