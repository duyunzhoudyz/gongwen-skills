# 综合文稿（gongwen-report）

帮机关、事业单位、国企的文字工作者写综合文稿。做法固定：先把用户给的材料拆成素材台账，再搭提纲，确认后分段成稿，最后自检。正文里的每个数据都能在台账里找到出处；台账里没有的，正文写【待补】。

## 适用范围

- 适用：
  - 8 类材料的起草：总结（年度、半年、专项）、计划、工作要点、汇报材料、调研报告、经验材料、述职报告（含述职述责述廉）、实施方案。对一个时期或一项专项工作作全面回顾的年度工作报告、专项工作报告、自查报告，按总结写。
  - 下级材料汇总：多个科室或下级单位报来的材料，合成一份。
  - 一份台账多版输出：同一份素材，分别出单位总结、个人述职、汇报提纲。
- 不适用（转交）：
  - 通知、请示、函、纪要等法定公文，就一件事向上级报告的报告（事件处置、检查整改、交办事项落实、答复询问），讲话稿，信息 → gongwen。总结、要点、方案需要用"报告"上报或用"通知"印发的，材料本身由本 skill 写，报送或印发用的那份公文交 gongwen。
  - 只要标题、小标题、提纲，或检查标题与正文是否一致 → gongwen-title。
  - 已有稿子只想改 AI 腔 → gongwen-humanize；只想去掉"仅供参考""建议考虑"一类的防御腔 → gongwen-direct。
  - 成稿要核稿查错 → gongwen-review；要排成 Word → gongwen-format。
  - 说不清要写什么材料，或是对照检查材料、党课等党建材料 → gongwen。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户给材料时，或用户第一条消息就附了材料时，在本次回复开头附一句："请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。"同一会话只说一次。
   - 读材料前先扫一遍：带有密级标识（"秘密★""机密★""绝密★"，或版头标注的密级和保密期限），或标注了"内部资料""工作秘密""不得外传""内部使用"等字样的，立即停止，不建台账、不摘录内容，告诉用户改用内网模型，或删去涉密内容后再发。正文中正常出现"保密工作""涉密人员管理"之类的词语（如保密办自己的工作总结）不算，照常处理。
   - 出现身份证号、手机号、病案号、住院号、学号、银行卡号、家庭住址、患者或学生的真实姓名的，提醒用户脱敏；台账和正文一律改写为"张某""某科室""138****0000"，并在起草说明"保密提示"中写明已替换。
2. 单位画像：工作目录存在 `.gongwen/单位画像.md` 时先读取，没有再找 `~/.gongwen/单位画像.md`，用户把画像粘贴在对话开头的按粘贴内容处理；有 `.gongwen/领导偏好卡.md`、`.gongwen/禁用词.md` 的一并读取。再按单位类型读 `references/_shared/profiles/units/` 下对应文件和 `references/units.md` 对应小节。没有画像时按 `references/_shared/profiles/roles.md` 第九节"无画像降级"处理。
3. 定工作模式：多份下级材料要合成一份的，用汇总模式；同一批素材要出两种以上材料的，用多版模式；其余用新写模式。
4. 定角色模式：按 `references/_shared/profiles/roles.md` 第一节的顺序确定，本 skill 中的差异见"角色适配"。
5. 查两条硬约束，命中的按"只出框架的两种情形"处理：述职报告（含述责述廉）缺本人事例；调研报告缺调研记录。
6. 用户要求"保证查不出是 AI 写的"，或要把正式文件改成便笺、"白头"来规避发文数量管理的，说明原因，不按此办（`references/_shared/guardrails.md` 第六条第 2、3 款），其余工作照常进行。
7. 网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务、本站和已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 材料类型速查

| 类型 | 默认结构 | 默认篇幅（工具约定） | 特别注意 | 详细写法 |
|---|---|---|---|---|
| 总结 | 主要工作和成效、存在问题、下一步打算 | 单位年度 3000～4000 字；科室 2000～3000 字；专项 1500～2500 字 | 问题要具体，不写万能句 | `references/types/zongjie.md` |
| 计划 | 目标、任务和措施、保障 | 1500～3000 字 | 任务写到谁来做、做什么、何时完成 | `references/types/jihua.md` |
| 工作要点 | 总体要求一段，重点任务分条 | 2000～4000 字 | 一条一事，不回顾成绩 | `references/types/yaodian.md` |
| 汇报材料 | 基本情况、做法和成效、问题、下一步、需支持事项 | 按汇报时长，约 200 字/分钟 | 按上级关切排序 | `references/types/huibao.md` |
| 调研报告 | 调研基本情况、现状、问题及原因、对策建议 | 3000～5000 字 | 没有调研记录不成稿 | `references/types/diaoyan.md` |
| 经验材料 | 开头交代做法和成效，做法分条，成效 | 交流发言 1500～2500 字 | 不拔高，不编成效 | `references/types/jingyan.md` |
| 述职报告 | 德、能、勤、绩、廉，不足，努力方向 | 书面 2000～3000 字；现场述职按时长 | 没有本人事例只出提纲 | `references/types/shuzhi.md` |
| 实施方案 | 目标、任务（责任、时限）、步骤、保障 | 一般不超过 4000 字 | 不照抄上位文件 | `references/types/fangan.md` |

用户或画像指定字数的按指定，误差控制在±10%。党政机关、基层、社区的部署性文件按 `references/_shared/rules/jianfu.md` 第三部分控制上限。

## 工作流程（新写模式）

### 第一步　任务卡

先填任务卡，在对话中给用户看（高效模式不单独展示，只写进起草说明）：

```text
任务卡
材料类型：年度总结（科室）
写给谁：院办，用于年度考核
用途和场合：书面报送，不上会宣读
篇幅：2500 字左右
截止时间：12 月 20 日
单位画像：公立医院（无画像，按用户所述）
角色模式：转译模式
```

缺项处理：
1. 只问影响结构和篇幅的事，一次最多 3 个，按此顺序取舍：材料类型和用途场合 → 写给谁 → 篇幅或汇报时长。转译模式按第 5 条分配名额。
2. 截止时间、单位画像、角色模式不单独提问，取默认值，写进起草说明"所作假设"。
3. 缺的数据不靠提问补齐，到第二步进台账，正文标【待补】。
4. 用户说"直接写""不用问了"的，不再提问。
5. 转译模式：用户话里能推断出用途和篇幅的（如"交院办做年终考核，2500字左右"），不问，名额优先给业务口径（统计时段、同比基期、计量单位）；推断不出的，先问用途和写给谁，再问口径。总数不超过 3 个。

### 第二步　素材台账

把用户给的全部材料拆成一条一条，整理成 `素材台账.md`。格式和判定规则见 `references/ledger.md`。

| 序号 | 类别 | 内容 | 来源 | 状态 |
|---|---|---|---|---|
| 1 | 数据 | 全年出院患者 3216 人次 | 《心内科2026年工作记录》第 2 段 | 已确认 |
| 2 | 数据 | 冠脉介入手术"300 多台" | 用户消息 | 待核实 |

1. 类别只用五种：工作事项、数据、案例、问题、下步打算。
2. 一条只记一件事或一个数。来源写到文件名和段落，或写"用户消息""单位画像"。
3. 状态只有两种。原话带"大概""约""多"的，数据没有口径或时间范围的，几份材料说法不一的，一律记"待核实"。
4. 由台账数据算出的增幅、占比另起一行，来源写"由第 3、5 条计算"，算式写进内容。
5. 台账同样脱敏。
6. 用户一条素材都没给的，不起草正文，交付提纲和素材收集清单（`references/frameworks.md` 第三部分）。用户坚持要稿的，出框架稿，所有事实位置标【待补】。

### 第三步　提纲与标题备选

1. 同一任务目录下已有 gongwen-title 从素材搭出的 `提纲.md`，或用户给了提纲的，以它为准，只补台账序号和字数分配。gongwen-title 的小标题方案和一致性检查结果写在 `标题方案.md`：已有这个文件的，从中读取用户选定的那套方案，替换提纲中的对应标题；用户没选的，用其中标为"推荐"的一套，在起草说明"所作假设"中写明。
2. 提纲写到二级标题。每个要点后注明依据的台账序号和计划字数，例如"（二）推进胸痛中心建设（台账 5、6、11，约 400 字）"。
3. 标题给 1～2 套（高效模式给 3 套）：一套平实式，如"心内科2026年工作总结"；一套主副标题式，主标题只概括台账里有的成效。要对仗式、数字概括式小标题，或要多套风格比较的，建议转 gongwen-title。
4. 小标题写成"动作加对象"，管得住下面的内容。
   - 误：（一）坚持高位推动，工作成效显著
   - 正：（一）建成胸痛中心，缩短急诊介入时间
5. 提纲交用户确认后再成稿。用户说"直接写"，或处于高效模式的，提纲与正文一次交付。

### 第四步　分段成稿

按提纲逐部分写，每写完一部分对照台账核一次。

1. 开门见山。首段一到三句，写时期、总体情况，引出下文。不写形势背景、重要意义，不写"在……的正确领导下"一类铺垫（画像或领导偏好卡要求保留的，压缩成一句）。
   - 误：2026年，在院党委的正确领导下，在各职能部门的大力支持下，心内科全体医护人员团结协作、攻坚克难，取得了显著成绩。
   - 正：2026年，心内科出院患者3216人次，完成冠脉介入手术【待核实：全年准确台数】台。现将全年工作总结如下。
2. 成效按"做了什么、数据或事例、结果"写。台账没有数据的写【待补：说明】，不改写成"明显提升""大幅增长"。
3. 做完不等于见效。系统上线、制度出台、会议召开只能写已完成；写成效要有台账里的运行数据或反馈。
4. 四类内容只能来自台账：成效数字、排名名次、获奖荣誉、群众评价（满意度、感谢信、锦旗、"广受好评"）。台账没有的不写；结构上确需这一项的，标【待补】。
5. 存在问题写具体：哪项工作、差在哪里、造成什么影响，只用台账"问题"类条目。台账里的问题只有一句笼统的话（如"更新慢""能力不够"）的，照写，后面标【待补：具体表现或影响】，不自行补充表现和影响。台账没有问题的，正文写【待补：存在的问题】，起草说明列 3 个启发提问，如"哪项指标没完成""哪项工作比计划晚""上级检查指出过什么"。
   - 误：思想认识还不够到位，工作创新还有差距。
   - 正（台账第 14 条）：夜间急诊介入只有两名医生能独立完成，排班轮换不开。
6. 下一步与问题对应：每个问题至少有一条措施。措施写清做什么；责任部门和时限台账有就写，没有不编。台账里有问题、没有对应措施的，"下步打算"中写"针对……问题，【待补：具体措施】"，列入起草说明的待补事项，不编措施。
7. 状态不升级：计划中的写"将""拟"，不写成"已"；建议不写成决定；用户说"还在论证"的照原样保留。
8. 字数按提纲分配。不够时只展开台账里的事实，不加背景、意义和表态；超了先删铺垫和重复表态。素材撑不起目标字数的，按实际篇幅交付，在起草说明"所作假设"中写明目标字数、实际字数，以及补齐哪些待补事项后可以写足。
9. 主语按单位类型：我局、我院、我校、公司、我镇、社区居委会（`references/units.md`）。
10. 用户提供了上级文件的，逐条转化为本单位的具体措施，不照抄原文；本单位措施缺失的标【待补：本单位落实措施】（`references/_shared/rules/jianfu.md` JF-04）。
11. 避开 AI 腔和防御腔：不写"值得注意的是""不是……而是……"、提示性冒号、"仅供参考"；"一是……二是……"、四字格、排比式小标题照常使用（`references/_shared/style/ai-tone.md`、`references/_shared/style/defensive.md`）。

### 第五步　自检

1. 台账对账（必做）：把正文中每个统计数、金额、百分比、次数、人数、名次逐个在台账里找。找不到的，补进台账并写明出处，或改为【待补】。有 Python 环境时先运行 `python scripts/fact_diff.py 素材台账.md 正文.txt --ledger` 辅助查找：输出的"正文中有、台账中没有"清单，就是正文里有、台账里没有的数字和标记（同一个数用两次不重复列出，台账的序号、来源列不参与比对），逐条处理。台账状态为"待核实"的，正文在该数后加【待核实：说明】，没有可用数值的整体写成【待核实：说明】。
2. 机检：有 Python 环境时运行 `python scripts/gongwen_lint.py 正文.txt --doc-type 总结`。`--doc-type` 按实际填：总结、计划、工作要点、汇报材料、调研报告、经验材料、述职报告、实施方案。P0 必改，P1 逐条判断，P2 酌情处理；命中公文白名单写法的保留（`references/_shared/style/ai-tone.md` 第二部分）。【待补】【待核实】标记机检每处报 P2，并在 `summary.markers` 中单独计数，这是起草阶段的正当产物，保留并逐条汇总进起草说明，不为减少 P2 而删改。
3. 没有 Python、脚本报错或输出"未执行检查"的，按 `references/checklist.md` 逐项人工检查，在起草说明写"未运行机检，已按人工清单检查"。
4. 最后过一遍本文"自检清单"。

### 第六步　交付

按 `references/_shared/style/output-format.md` 交付。
1. 能写文件的，在当前工作目录建 `公文/<YYYYMMDD>-<简短标题>/`，写入 `正文.txt`、`起草说明.md`、`素材台账.md`、`提纲.md`。同名文件已存在时加 -v2、-v3，不覆盖。对话中只报文件位置、一段话概述、待补和待核实各几条。
2. 网页对话环境：依次输出正文、`【起草说明】`、说明内容，素材台账放在起草说明最后，标题为"附：素材台账"。正文前不加引导语。路线还有下一站的，在起草说明之后输出更新后的交接卡，告诉用户新开对话，先粘贴下一站的提示词文件，再粘贴交接卡和本站产出（`references/_shared/style/output-format.md` 第四部分）。
3. 起草说明依次写所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点（仅教学模式），没有内容的部分省略。待补、待核实逐条写明正文位置；一条可以汇总同一段的几个标记。篇幅差距和"未运行机检"写进"所作假设"。涉及篇幅上限、数字写法、文种选择的判断，写明依据条款，如"《整治形式主义为基层减负若干规定》第2条""GB/T 15835-2011 5.1.3"。本 skill 特有的内容附在末尾，标题依次为"附：口径冲突表""附：提法核对清单""附：填写指引""附：素材台账"，按需选用。

## 模式二　下级材料汇总

多份科室或下级单位材料合成一份时，第二步建台账和第四步成稿按以下要求做。细则和例子见 `references/merge-and-versions.md` 第一部分。

1. 登记：每份材料编号（材料 A、B、C），记下报送单位；台账来源写到"材料 B 第 3 段"。
2. 合并去重：几家报了同一件事（联合检查、共同承办的活动），台账只记一条，来源列全；次数、人数不重复相加；牵头单位写成主体，其他单位写"配合"。
3. 统一口径：同一指标逐项比对三件事。
   - 统计口径：指标定义是否相同，如"服务人次"含不含线上咨询。
   - 时间范围：1—10 月实际数与全年预计数不能相加。
   - 计量单位：元与万元、人与人次。能换算的换算，换算过程写进台账。
4. 标记冲突：比不齐的不加总、不取平均、不挑大的。正文写【待核实：说明】，冲突整理成口径冲突表，放在起草说明末尾的"附：口径冲突表"：

| 序号 | 指标或事项 | 各材料的说法 | 冲突类型 | 本稿处理 | 请谁确认 |
|---|---|---|---|---|---|
| 1 | 矛盾纠纷调处数 | 材料 A：1—11 月 126 件；材料 C：全年 140 件 | 时间范围不一致 | 未加总，正文标【待核实】 | 综治办 |

5. 成稿：按工作板块重新组织，用单位整体的口气（"我街道"），不按科室逐个拼接。应报未报的单位，列入起草说明"待补事项"。

## 模式三　一份台账多版输出

同一份素材台账，分别出单位总结、个人述职、汇报提纲。台账只建一份，各版本从中取材，同一数据在各版本中的数值和口径保持一致。细则见 `references/merge-and-versions.md` 第二部分。

| 版本 | 主语 | 组织方式 | 取材规则 |
|---|---|---|---|
| 单位总结 | 我局、我院、我校、公司 | 按工作板块 | 成绩归单位，一般不出现个人姓名 |
| 个人述职 | 本人 | 德、能、勤、绩、廉 | 只用写明本人角色的台账条目 |
| 汇报提纲 | 汇报单位（我局） | 按上级关切的顺序 | 每条一句话，带关键数据 |

视角转换规则：
1. 单位总结转述职：把"我局完成……"改成"本人牵头（分管、具体承办）……"。本人角色必须来自用户原话，建台账时在内容栏开头标"（本人：牵头）"之类的标记。台账只有单位成绩、没写本人做了什么的，写【待补：本人在此项工作中的职责和做法】。
   - 误：本人全年报送政务信息186篇。（台账只写了办公室全年报送186篇）
   - 正：本人负责政务信息审核把关，办公室全年报送信息186篇。（台账写明本人负责审核）
2. 述职覆盖德、能、勤、绩、廉五个方面，"绩"占一半以上篇幅。德、勤、廉只写用户提供的事实，如学习、出勤、廉洁自律的具体做法；没有的给填写指引，不替用户写"严守纪律、无违规违纪"之类的表态。
3. 汇报提纲按上级关切排序：用户提供了检查通知、调研主题或领导关注点的，相关内容排最前；没有提供的，按"上级重点部署的落实情况、关键指标、问题和原因、下一步、需要上级支持的事项"排。需要上级审批的事项，提示另行请示（交 gongwen）。
4. 出完后交叉核对：同一数据各版本一致；述职中本人的作用没有超出单位总结的表述。
5. 文件：同一目录下写 `正文-单位总结.txt`、`正文-个人述职.txt`、`正文-汇报提纲.txt`，共用一份 `素材台账.md`；起草说明一份，按版本分节。

## 只出框架的两种情形

依据 `references/_shared/guardrails.md` 第六条第 4、5 款。先用一句话向用户说明原因，再交付框架，不拒绝整个任务。

1. 述职报告（含述职述责述廉）缺本人事例。本人事例指本人亲自做的具体事情，至少有事项、本人角色和结果。用户只给了单位或部门材料，或什么都没给的，只出提纲和填写指引（`references/frameworks.md` 第一部分），不生成完整正文。部分方面有事例的，有事例的部分成稿，缺的部分在正文写【待补：本人……的具体事例】，对应的填写指引放进起草说明。
2. 调研报告缺调研记录。调研记录指访谈或座谈记录、问卷结果、实地察看记录、调研数据表。没有记录的，只出调研提纲和调研报告框架（`references/frameworks.md` 第二部分），不写任何调研发现和结论。用户说"领导要先看稿"的，照样只交框架，说明调研后把记录发来即可成稿。

## 输出规范

- 正文、起草说明、交付位置按 `references/_shared/style/output-format.md`：纯文本，不用 Markdown；层次序数依次为 一、（一）1.（1）；数字用法按 `references/_shared/rules/gbt15835.md`。
- 正文中只允许两种提示：【待补：说明】和【待核实：说明】。
- 素材台账、提纲、口径冲突表是工作底稿，可以用 Markdown 表格。

## 自检清单

- [ ] 正文每个统计数、金额、百分比、次数、名次都能在台账找到；找不到的已改为【待补】。
- [ ] 没有自行写入成效数字、排名、获奖、群众评价。
- [ ] 没有把计划写成已完成，把建议写成决定。
- [ ] 存在问题是具体事实，没有"思想认识还不够到位"之类的万能句（用户提供了对应事实的除外）。
- [ ] 每个问题都有对应的下一步措施；台账没有措施的，写的是"针对……问题，【待补：具体措施】"并列入待补事项，没有自编措施。
- [ ] 首段开门见山，没有形势背景和意义铺垫。
- [ ] 篇幅在目标字数±10% 以内；部署性文件未超过 `references/_shared/rules/jianfu.md` 的上限。
- [ ] 述职：主语为"本人"，个人作用都有台账依据；无事例时只出了提纲和填写指引。
- [ ] 调研报告：每条发现都对应到调研记录；无记录时只出了调研提纲和框架。
- [ ] 汇总稿：口径冲突全部列表，没有悄悄加总。
- [ ] 正文没有 Markdown 符号、免责声明、AI 自述，没有未脱敏的个人信息。
- [ ] 起草说明逐条汇总了正文中的全部【待补】【待核实】。

有 Python 环境时运行：`python scripts/gongwen_lint.py 正文.txt --doc-type 总结`（文书类型按实际填）。无法运行时按 `references/checklist.md` 人工检查。

## 角色适配

- 教学模式：先给任务卡和提纲，确认后再成稿；起草说明末尾附写作要点，写清结构为什么这样搭、问题怎么写才具体（用本稿的一处正误对照）、每项【待补】一般到哪里找（统计报表、业务系统、财务快报）。
- 高效模式：任务卡只写进起草说明；台账、提纲、正文一次交付；标题给 3 套；可同时给全文和压缩版两个篇幅；多份下级材料可批量汇总。
- 转译模式：接受流水账、数据表、口语描述；提问按第一步缺项处理第 5 条：能推断出用途和篇幅的不问，名额优先给业务口径（统计时段、同比基期、计量单位），推断不出的先问用途和写给谁、再问口径，总数不超过 3 个；台账来源写到原表的行或列，计算写出算式；业务术语照用，不替用户拔高定性。
- 审稿模式：先交一页纸（提纲、核心数据、主要问题、待补清单）供拍板，确认后再成稿；用户拿来的是成稿、要挑问题的，转 gongwen-review。
- 严谨模式：用于述职述责述廉、党建板块和对外报送的材料。政治性提法只用用户提供的原文，没有原文的标【待核实：请对照最新原文】；起草说明增加提法核对清单；用户给了往年稿的，标出雷同段落。
