# 综合文稿（gongwen-report）

> 版本 0.1.0　成熟度：Beta（测试版）

帮机关、事业单位、国企的文字工作者写总结、计划、汇报这类综合文稿。它先把你给的材料整理成一份素材台账，再搭提纲，你确认后分段成稿。正文里的每个数据都能在台账里找到出处，你没给的数据一律标【待补】，不替你编。

## 能做什么

| 功能 | 说明 |
|---|---|
| 起草 8 类材料 | 总结（年度、半年、专项，含年度工作报告、专项工作报告）、计划、工作要点、汇报材料、调研报告、经验材料、述职报告（含述职述责述廉）、实施方案 |
| 下级材料汇总 | 把几个科室或下级单位报来的材料合成一份：合并重复事项，统一统计口径、时间范围和计量单位，比不齐的数据列成"口径冲突表"请你确认 |
| 一份台账多版输出 | 同一批素材，分别出单位年终总结、个人述职报告、向上级汇报的提纲，三份稿子的数据保持一致 |

## 可以这样说

1. "下周要交科室年终总结，这是我们科一年的工作记录，帮我整理一下。"
2. "市里领导周四来街道调研垃圾分类，给我弄个 10 分钟的汇报材料。"
3. "8 个科室的总结都报上来了，帮我汇总成全院的，数据对不上的标出来。"
4. "我是办公室主任，用这份台账同时出一份局里的年终总结和我自己的述职报告。"
5. "下个月要去乡镇调研报表负担的问题，领导让我先准备一下调研报告。"（调研还没做的，会先给调研提纲和报告框架）

## 输入

- 必需：你手头的素材。工作记录、月报、数据表、科室报上来的材料、会议纪要、口头描述都可以，不用先整理。
- 最好说明：写给谁、在什么场合用、要多少字（或汇报几分钟）。没说的按默认处理，并在起草说明里写明。
- 可选：单位画像 `.gongwen/单位画像.md`、领导偏好卡、往年同类材料。没有画像也能用，最多问 3 个问题。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文，不含 Markdown，可直接粘进 Word 或交给 gongwen-format 排版 |
| `起草说明.md` | 所作假设、待补事项、待核实事项、口径冲突表（汇总时）、保密提示 |
| `素材台账.md` | 每条事实的内容、来源和状态（已确认或待核实） |
| `提纲.md` | 提纲和标题备选 |

在网页大模型里使用提示词版时，依次输出正文、起草说明和素材台账。

## 注意事项

1. **保密**：请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。材料中出现密级标识时会停止处理；出现患者、学生姓名和证件号时会提醒你脱敏，并在稿中改用"张某"等代称。
2. **不编造**：成效数字、排名、获奖、群众评价只用你提供的。缺的标【待补】，存疑的标【待核实】，都汇总在起草说明里，补齐后再定稿。
3. **述职和调研有前提**：述职报告要写本人的真实经历，没有个人事例时只给提纲和填写指引；调研报告必须基于调研记录，调研前只给调研提纲和报告框架。
4. **做减法**：默认不写形势背景和意义铺垫，问题写具体，措施写到谁来做、何时完成。篇幅按《整治形式主义为基层减负若干规定》和你的要求控制。
5. **事实和判断由你负责**：它负责搭结构、守规矩、查错漏，稿子是否报送、怎么定调由你决定。
6. **机检**：有 Python 环境时会调用 `scripts/gongwen_lint.py` 检查标点、数字、格式和残留；没有运行时会按人工清单自检，并在起草说明中注明。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 通知、请示、函、纪要等法定公文，就一件事向上级报告的报告，讲话稿，信息；不确定该写什么 | gongwen |
| 只要标题、小标题、提纲 | gongwen-title |
| 已有稿子 AI 味重 | gongwen-humanize |
| 稿子里"建议考虑""仅供参考"太多，态度不明确 | gongwen-direct |
| 成稿核稿、查错 | gongwen-review |
| 排成国标格式的 Word | gongwen-format |

一份年终总结的完整链路：gongwen-report 建台账、搭提纲 → gongwen-title 定标题 → gongwen-report 成稿 → gongwen-direct、gongwen-humanize 清理文风 → gongwen-review 核稿 → gongwen-format 出 docx。

## 成熟度

Beta。8 类材料的结构、素材台账、汇总和多版输出流程已可用；评测用例见 `evals/`。已知局限：
- 台账对账（正文数字逐个回查台账）有 Python 时用 `scripts/fact_diff.py --ledger` 辅助找出台账里没有的数字，逐条判断仍靠模型按清单执行；
- 行业专用材料（等级评审自评、审核评估自评、ESG 报告等）未单独适配，留待行业包。
