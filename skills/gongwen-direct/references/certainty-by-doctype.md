# 各文种的确定性要求

改稿前先定文书类型和行文对象，再按本文件确定"必须明确什么、可以保留什么、缺了怎么标"。措辞层级（必须、应当、要、可以、鼓励）见 `references/_shared/style/defensive.md` 第六部分，文种结构见 `references/_shared/rules/doc-types.md`。条款引自《党政机关公文处理工作条例》（下称《条例》），标"实务"的是通行做法。例句全部虚构。

## 目录

一、请示（含签报）
二、批复

## 一、请示（含签报）

必须明确：
1. 请求事项：批准什么、拨付多少、同意哪个方案。一文一事（《条例》第十五条第（四）项）。
2. 本单位倾向性意见：有两个以上方案的，写明倾向和理由（实务，`references/_shared/rules/doc-types.md` 2.11 把"缺本单位意见"列为常见错误）；以本机关名义转报下级请示的，必须提出倾向性意见，不得原文转报（第十五条第（三）项）。只有一个方案的，请求事项本身就是倾向。
3. 结语："妥否，请批示。""当否，请批示。""以上请示，请予审批。"

改法：
1. 缺倾向性意见：不替用户编。在比较内容之后写【待补：本单位倾向性意见及理由】，起草说明写明要补什么（选哪个方案、为什么）。
2. 只写"请领导研究"、没有具体请求事项：写【待补：请求事项，即请求批准的具体内容】。
3. 结语为"供领导参考""请领导研究决定""如果可以的话"：改为"妥否，请批示。"结语是惯用语，可以直接改。
4. 请示里的"建议采用方案二""建议拨付"是本单位意见，保留。
5. 一文多事、多头主送：不擅自拆分，起草说明提示拆分（第十五条第（一）（四）项）。

误：两种方式各有利弊，需要综合权衡。以上内容仅供领导参考，请领导研究决定。
正：【待补：本单位倾向性意见，即倾向采购或租赁及理由】妥否，请批示。

## 二、批复

必须明确：开头表态"同意""原则同意"或"不同意"；不同意的写理由；同意的写执行要求；引叙来文标题和文号。

改法：
1. 态度不明（"原则上可行，待条件成熟后再议""待研究后再行答复""视情况而定"）：写【待补：同意/不同意】，不替用户定。
2. 态度定了才能写的执行要求或理由，一并标【待补：执行要求或不同意的理由】。
3. "原则同意"后附修改要求，是正当写法，保留。
4. 来文标题、文号缺失的，标【待补：来文标题和文号】，不编。

误：你校《关于扩建学生食堂的请示》（某小〔2026〕6号）收悉。经研究，你校提出的扩建方案在一定程度上具有可行性，或许可以待条件成熟后再议。以上意见仅供参考。
正：你校《关于扩建学生食堂的请示》（某小〔2026〕6号）收悉。经研究，【待补：同意/不同意】。【待补：执行要求或不同意的理由】此复。

## 三、部署性文件

范围：通知、下行的意见、决定、实施方案、工作要点、计划，通报中的要求部分。

必须明确：谁做、做什么、何时完成、做到什么标准。

措辞：按"必须、应当、要、可以"分层，不用"建议""可以考虑""不妨""希望……能够""尽量"。默认用"要"；"必须""严禁"只保留原稿已有的，不因改稿新增。

注意：
1. "原则上"：确有例外时是正当用法，保留。例："原则上不得跨区调剂，确需调剂的，报市局备案。"找不到例外的也不删，修改说明请用户确认。
2. 联合发文中对协作单位、平行的意见：用"请"。
3. 部门对下级人民政府：不提指令性要求（第十六条第（二）项），"建议"改"请"，起草说明提示核对行文关系。
4. 面向群众的通知、通告：用"请"；"必须""严禁"只用于有法律依据的事项，依据由用户提供；不添加原稿没有的罚则。原稿已有的强制措施和罚则不删不改，列入"转交事项"，交 gongwen-review 按法规关核查。
5. 预期目标："可能会缩短至30分钟以内"改为"力争缩短至30分钟以内"。
6. 通报：事故原因未查清的写"原因正在调查中"，不写"可能是由于"。

## 四、报告（含总结、汇报材料、述职报告）

必须明确：陈述事实，不夹带请示事项（第十五条第（四）项）。

改法：
1. 夹带的请求事项：正文删去请求性语句（"建议上级拨付""请予批准"）和"妥否，请批示"，结语改"特此报告。"；删去的原句连同金额、数量完整移入起草说明，建议另行请示（请示交 gongwen 起草）。
2. 成效：有数据的写数据；"在一定程度上提升了效率"而材料没有数据的，标【待补：具体数据】，不直接改成"明显提升"。
3. 问题查摆中的"一定程度上存在""不同程度存在"保留。
4. 下一步打算中的"力争""争取"是目标表述，保留。
5. 汇报材料、述职报告结尾"不妥之处，请批评指正"保留。

## 五、函

1. 平行文。对不相隶属单位提请求用"请""商请""恳请"，不改成"要""必须"。
2. 条件式请求"如果方便的话，请……"改为"请……"。
3. 复函对来函事项要有明确答复；"我们将认真研究"之类的，标【待补：答复意见】。
4. 征求意见复函中的"以上意见供参考"保留。

## 六、讲话稿

1. 语气可以更有力："要"可以多用；设问、"希望大家……"、号召式结尾保留（DEF-011、014、020、021、022、027 对讲话稿豁免）。
2. 承诺不说死。用户没有确认的时间、金额、数量、对外表态，去对冲只改到"力争……"，不改成"一定""确保"；起草说明逐条列出，请用户确认讲话人是否同意公开表态。
3. 已发生的成绩去掉"或许""可能"，直接陈述。

误：明年我们或许有可能实现全面扭亏为盈。
正：明年力争实现全面扭亏为盈。（起草说明：讲话对"明年扭亏"作了公开表态，请确认）
改过头：明年我们一定实现全面扭亏为盈。

## 七、其他材料

| 文书类型 | 确定性要求 | 正当保留 |
|---|---|---|
| 调研报告 | 结论明确；对策建议具体到谁做什么；没有结论的标【待补：调研结论】 | 利弊分析、对不确定性的分析、"建议" |
| 纪要 | 议定事项写明结论、责任单位、时限，缺的标【待补】 | 对讨论过程的如实记录；未形成一致的不写成议定事项 |
| 信息、经验材料 | 成效写事实和数据 | 有事实在前的适度评价 |
| 总结 | 成效写数据，没有的标【待补】 | 问题查摆用语；结尾谦辞 |
| 通告 | 要求明确，写清起止时间 | 有法律依据的"严禁""不得" |

## 八、文种不明时

1. 依次看：标题中的文种词；结语（"妥否，请批示"→请示或签报，"此复"→批复，"特此通知"→通知，"特此报告"→报告，"请予函复""特此函告"→函）；主送对象（"公司领导""院领导"→签报）；用户描述。
2. 仍不能确定的，问一句"这份稿子是什么文种、发给谁？"，与其他问题合并，一次最多 3 个。
3. 用户不答或说"直接改"：按"其他"处理，逐句判断是否在对下级提要求；起草说明写明"未确定文种，按其他处理，机检中'建议'类命中已逐条人工复核"。
