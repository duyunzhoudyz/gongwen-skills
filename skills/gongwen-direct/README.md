# gongwen-direct：去防御性写作

让公文说话有态度。AI 写的公文常常给自己留后路：结尾挂"仅供参考"，部署写成"建议各单位可以考虑"，请示不说倾向哪个方案，批复不说同意还是不同意。这个 skill 把这些话改成态度明确、措辞分层的公文表述。

它同时守两条底线：风险提示、法律依据这类必要的谨慎不删；倾向性意见、同意与否这类该由您决定的事，不替您决定。

## 能做什么

- 删掉正文里的免责声明和套话提醒："以上内容仅供参考""请结合实际情况调整""如有疏漏欢迎指正"。
- 清理对冲语气："可能""或许""在一定程度上"。有事实撑着的直接说，没事实撑着的标【待核实】，不硬说成确定。
- 处理平衡腔："各有利弊，需综合权衡，视情况而定"。
- 把部署性文件里的"建议""可以考虑""希望……能够""尽量"改成"要""应当""可以"等分层措辞；对平级单位、对群众改成"请"。
- 点明模糊主体："有关部门要加强配合"。原稿里找得到单位的就点名，找不到的标【待补】。
- 让请示有倾向性意见、批复明确表态、报告不夹带请示。原稿没写的，标【待补】请您补，不编。
- 删掉稿子首尾的 AI 对话残留："以下是为您起草的……""如需修改请随时告诉我"。

另外，这个 skill 里的写作规则（`references/_shared/style/defensive.md`）已经内置进全部 gongwen skill，用其他 skill 起草时会自动避开防御腔。

## 怎么说

- "这份通知是 AI 写的，满篇'建议各单位'，帮我改成部署的口气。"
- "稿子结尾那句'仅供参考，请结合实际调整'帮我删干净，别的别动。"
- "这个批复写得模棱两可，领导还没定同不同意，你先把能改的改了。"
- "请示里两个方案都列了，就是没说我们倾向哪个，帮我看看。"
- "这篇讲话稿太软了，处处留余地，帮我把语气提起来，但别替领导乱表态。"

## 输入和输出

**输入**：一篇已有稿件，粘贴文字或给出 .txt、.md、.docx 文件路径都可以。最好说明文种和发给谁；没说的，skill 会从标题和结语推断。

**输出**：
1. 改后正文：纯文本公文体，可以直接用，也可以交给 gongwen-format 排成 Word。
2. 起草说明：改了哪几类、多少处；哪些谨慎表述特意保留了、为什么；哪些地方标了【待补】【待核实】、需要您补什么；哪些事项需要您拍板（是否允许例外、讲话里的承诺能不能公开说）。
3. 在 Claude Code、Codex 等能写文件的工具里，结果存到 `公文/<日期>-<简短标题>/` 下的 `正文.txt`、`起草说明.md`，粘贴的原稿另存为 `原稿.txt`，不覆盖已有文件。

有 Python 时，skill 会调用机检脚本诊断防御性表述，改完后用事实比对脚本确认数字、日期、文号没有变动；没有 Python 时按清单人工检查，并在起草说明里写明。

## 注意事项

- **请勿输入涉密信息和内部敏感信息**。材料带有密级标识，或标注了"内部资料""工作秘密"等字样的，skill 会停止处理；材料涉密的，请使用单位内网部署的模型。
- **只改说法，不改事实**。数字、日期、人名、单位名、文号、引文、政治性提法和上级文件原文都不动。
- **不替您做决定**。请示倾向哪个方案、批复同不同意、讲话敢不敢承诺，原稿没写的一律标【待补】。
- **不改过头**。不会把"要"都换成"必须"，不会添加原稿没有的罚则，风险提示里的"可能"、问题查摆里的"一定程度上存在"会保留。
- **AI 腔不归这里**。"值得注意的是""不是……而是……"、赋能闭环这类问题请用 gongwen-humanize；格式、标点、数字和全面核稿请用 gongwen-review。
- 改后稿件由您审定后使用，签发责任在您和您的单位。

## 成熟度

Beta（v0.1.0）。改写流程、各文种确定性要求和评测用例已经齐备。没有 Python 或脚本运行出错时，skill 会改为按清单人工检查。欢迎在 issue 中反馈误改、漏改的例子。
