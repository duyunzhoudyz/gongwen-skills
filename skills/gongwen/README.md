# gongwen 公文写作总入口

gongwen-skills 的总入口。说不清要写什么、第一次用、不知道该找哪个 skill 时，先找它。它帮你判断这份材料该怎么写、要走哪几步，再把你交给对应的 skill。在网页大模型（DeepSeek、豆包、Kimi 等）里使用时，它就是统一入口。

## 能做什么

1. **判断任务**：从你的话里判断单位类型、写作角色、文书类型、行文方向，判断不出的最多问 3 个问题。
2. **规划路线**：告诉你要走哪几个 skill、按什么顺序。比如年终总结要经过素材台账、提纲、标题、成稿、去防御腔、去 AI 味、核稿、排版几步。
3. **判断文种**：请示还是报告，请示还是函，纪要还是会议记录，并写明《党政机关公文处理工作条例》的依据。
4. **建简版单位画像**：第一次使用时，用 3 个字段（单位类型、写作角色和默认模式、常写文书）建档，以后不必每次说明。
5. **写作日历**：你没有具体需求，或问"最近要写什么"时，按当前月份和单位类型，提示最近一般要写的材料，最多 3 条。
6. **基础起草（v0.1 过渡能力）**：通知、请示、报告（就一件事报告情况）、函、批复、通报、纪要、签报等公文，以及讲话稿、信息。年度工作报告这类全面回顾由 gongwen-report 起草。专门的起草 skill 发布后，这部分转交给它们。
7. **回答"你能做什么"**：列出现有能力和计划中的能力，不夸大。

## 可以这样说

- "领导让我给区财政局写个东西，要一笔经费，用什么文？"
- "我刚到医院院办，第一次用，帮我看看能做什么。"
- "下周市里来督查，要准备哪些材料？"
- "把这份会议记录整理成纪要，发给各科室。"
- "局长下周三在推进会上讲 15 分钟，帮我写个讲话稿。"

## 输入和输出

**输入**：一句话需求即可。起草时提供事实材料（工作记录、数据、会议记录、上级文件原文等），请先删去涉密内容和个人敏感信息。

**输出**：
- 一行判断（单位｜模式｜文书类型和方向｜路线），以及下一步做什么。
- 起草类：纯文本公文正文，后附【起草说明】（所作假设、待补事项、待核实事项）。缺的事实写成【待补：说明】，不会编造。
- 在 Claude Code、Codex 等能写文件的工具里：画像写入 `.gongwen/单位画像.md`，文稿写入 `公文/<日期>-<标题>/`，不覆盖已有文件。
- 在网页版里：输出画像文本请你保存；需要换到其他 skill 时，给你一张交接卡，并告诉你复制哪个提示词文件（`dist/prompts/<skill名>.md`）。

## 注意事项

- 请勿输入涉密信息和内部敏感信息。材料涉密的，请使用单位内网部署的模型。
- 数据、案例、人名、文号、引语只来自你提供的材料。缺什么就标【待补】，请逐条补齐后再用。
- 政治性提法以你提供的原文为准，工具不联网核对最新提法。
- 对照检查材料、个人述职等需要本人经历的材料，没有本人事例时只出提纲和填写指引。
- 不承诺"检测不出 AI"，不协助规避发文管理。
- 单位画像可能含内部信息，不要提交到公开仓库。
- 生成的文稿是初稿，事实和判断由你负责，按本单位程序审核、签发。

## 成熟度

- 版本：0.1.0
- 状态：Beta（已用样例测试，边界情况可能还有问题）
- 基础起草是 v0.1 的过渡能力，只覆盖常用文种的基本结构和行文规则检查。决议、命令、公报、议案只给结构说明。
- 讲话、党建、改稿润色、信息简报、纪要议题、数据图表等专门 skill 计划在后续版本发布。

## 目录

```text
gongwen/
├── SKILL.md                 # 给模型的工作流程
├── manifest.json            # 版本、共享资料清单、提示词版打包清单
├── references/
│   ├── routes.md            # 路线表、未发布 skill 的替代、交接卡
│   ├── skill-map.md         # 能力地图
│   ├── intake.md            # 任务识别、补问、建档
│   ├── interim-drafting.md  # 法定公文、讲话稿、纪要、信息的起草细则
│   ├── adaptation.md        # 角色模式与单位类型的差异
│   ├── quick-ref.md         # 提示词版速查表
│   └── _shared/             # 共享资料（自动同步，勿手改）
├── scripts/                 # 机检脚本（自动同步，勿手改）
└── evals/                   # 评测用例与虚构材料
```

修改 `routes.md`、`skill-map.md`、`interim-drafting.md` 时，同步检查 `quick-ref.md` 中对应的精简内容。
