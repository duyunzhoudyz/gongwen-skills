v0.1 没有法定公文、讲话稿、纪要、信息的专门 skill，由总入口做基础起草。本文件是第六步的操作细则。专门 skill（gongwen-draft、gongwen-speech、gongwen-minutes、gongwen-brief）发布后，这几类转交给它们。

## 一、四类文书共用的步骤

1. 保密：按 SKILL.md 开工检查第 1 条处理。纪要、通报最容易带进人名和敏感事项，先查一遍再动笔。
2. 收事实：只用用户输入、用户提供的文件和单位画像中的内容。动笔前把可用的事实列成素材清单（时间、数据、事项、来源）；转译模式把清单展示给用户，其他模式在内部使用。
3. 定篇幅：
   - 文件类：部署专项工作或具体任务的一般不超过 4000 字，其他文件一般不超过 5000 字（《整治形式主义为基层减负若干规定》第2条，统计口径见 `references/_shared/rules/jianfu.md` 第三部分）。医院、学校、国企的内部发文不受这一字数直接约束，同样从严控制，超限时只作提示（jianfu.md 第一部分）。
   - 讲话稿按时长，见第三部分；信息见第五部分。
   - 用户指定字数的按用户要求，误差 ±10%；超过上限的在起草说明中提示。
4. 开门见山：第一段写目的、依据或事项。用户没有要求的，不写形势背景、重要意义。
   - 误：当前，安全生产形势复杂严峻，做好今冬明春安全生产工作具有十分重要的意义。为此，现将有关事项通知如下：
   - 正：为做好今冬明春安全生产工作，现将有关事项通知如下：
5. 先提纲还是直接成稿：教学模式先给提纲（各部分标题、每部分写什么、需要用户补哪些素材），确认后成稿；用户说"直接写"的直接成稿。审稿模式先给提纲和要点一页纸。高效、转译、严谨模式直接成稿。
6. 输出：正文，然后另起一行写【起草说明】，格式见 `references/_shared/style/output-format.md`。

## 二、法定公文

### （一）定文种

按顺序回答四个问题：

1. 以谁的名义发？本单位、办公室，还是内设部门。内设部门除办公厅（室）外不对外正式行文（《党政机关公文处理工作条例》第十七条第三款），企事业单位以本单位制度为准。
2. 写给谁？有隶属关系的上级、下级、不相隶属的单位、本单位领导、社会公众。
3. 要办什么事？请求批准、汇报、部署、告知、商洽、答复。
4. 本单位能用哪些文种？看画像的"可用文种"；没有画像的，企事业单位默认不用命令、公报、议案，公告慎用（`references/_shared/rules/doc-types.md` 第五部分）。

用 2、3 两项查 doc-types.md 第六部分的决策表，得出文种。容易混的几组，用一句话判断：

| 易混 | 判断 | 依据 |
|---|---|---|
| 请示与报告 | 只要有一项需要上级表态，这一项单独写请示；报告不夹带请示事项 | 第八条第（十）（十一）项，第十五条第（四）项 |
| 请示与函 | 对方是有隶属关系的上级，用请示；对方不相隶属，即使是审批部门，也用函 | 第八条第（十一）（十四）项 |
| 通知、通告与公告 | 有明确受文机关的用通知；面向社会、有遵守要求的用通告；向国内外宣布重要事项或法定事项的用公告 | 第八条第（五）（六）（八）项 |
| 批复与复函 | 来文是下级的请示，用批复；来文是函，用复函 | 第八条第（十二）（十四）项 |
| 通报与通知 | 重点是"发生了什么、怎么看"用通报；重点是"要做什么"用通知 | 第八条第（八）（九）项 |
| 意见与通知 | 提出一整套政策措施用意见；布置一项具体工作用通知 | 第八条第（七）（八）项 |
| 签报与请示 | 内设部门向本单位领导请求批准，有签报制度的用签报；以本单位名义向上级机关请求批准用请示 | doc-types.md 第三部分 |

正误对照：

- 误：标题"某区教育局关于申请追加学生营养餐补助经费的请示"，主送区财政局。
- 正：标题"某区教育局关于商请追加学生营养餐补助经费的函"。区教育局与区财政局不相隶属，请求批准用函。
- 误：给县卫健委的"院感防控工作情况报告"末尾写"另，拟购置消毒设备一批，所需经费30万元，妥否，请批示。"
- 正：报告只汇报院感防控工作，结尾"特此报告。"；购置设备另写"关于购置消毒设备的请示"。

用户指定的文种与关系、目的不符时：
1. 先指出，写明依据。例如："您说写请示，但区财政局和区教育局没有隶属关系，请求批准应当用函（《党政机关公文处理工作条例》第八条第（十四）项）。我按函来写。"
2. 按正确文种起草，起草说明"所作假设"写明改动理由。
3. 用户坚持原文种的，照用户要求写，在起草说明中保留这条提示。

### （二）查行文规则

起草前和成稿后各查一遍（`references/_shared/rules/tiaoli.md` 第五部分）：

| 检查项 | 怎么查 | 发现问题怎么办 | 依据 |
|---|---|---|---|
| 一文一事 | 数请示事项的个数 | 多于一项的，建议拆成几份；用户不同意的，在起草说明中提示 | 第十五条第（四）项 |
| 报告不夹带请示 | 报告里有"请批准""请拨付""妥否，请批示" | 把请求事项抽出来另写请示 | 第十五条第（四）项 |
| 主送唯一 | 上行文主送了几个上级机关 | 只留一个主送，其他列抄送 | 第十五条第（一）项 |
| 不抄送下级 | 上行文抄送栏有下级机关 | 删去 | 第十五条第（一）项 |
| 不越级 | 是否越过了直接上级 | 提示用户；确需越级的，同时抄送被越过的机关 | 第十四条 |
| 不送领导个人 | 主送写成"某局长""某主任" | 改为主送机关 | 第十五条第（五）项 |
| 请示有本单位意见 | 请示是否写清请求事项和本单位的意见或方案 | 有两个以上方案的，写明倾向和理由；用户没给意见的，标【待补：本单位意见】 | `references/_shared/style/defensive.md` 第七部分 |
| 转报下级请示有倾向性意见 | 是否原文转报 | 用户没给本机关意见的，标【待补：本机关倾向性意见】 | 第十五条第（三）项 |
| 部门不向下级党委政府发指令 | 部门名义的下行文是否主送下级党委、政府并提指令性要求 | 提示改由党委、政府办公厅（室）行文，或改为商洽口吻 | 第十六条第（二）项 |
| 涉及其他部门职权 | 是否需要其他部门会签 | 起草说明列出需要会签、征求意见的部门 | 第十六条第（四）项、第十九条第（六）项 |
| 经政府同意的事项 | 职能部门就需政府审批的事项行文 | 正文注明"经某某人民政府同意" | 第十六条第（二）项 |

### （三）按文种起草

各文种的标题、结构、惯用语、常见错误见 doc-types.md 第二、三部分。常用文种的骨架：

请示
- 标题：某某关于……的请示（不写"请示报告"，不写"关于申请……的请示"）。
- 主送：一个上级机关。
- 正文：请示缘由（依据、现状、必要性，用事实和数据）→ 请示事项（批准什么、拨付多少、同意哪个方案）→ 本单位意见或方案。
- 结语："妥否，请批示。"或"以上请示，请予审批。"
- 附注：联系人和电话，没有的标【待补：联系人及电话】。
- 误："我们考虑了几种办法，各有利弊，请领导研究。"
- 正："恳请县政府拨付敬老院改造资金【待补：金额】万元，用于……。妥否，请批示。"

报告
- 范围：本 skill 写向上级报告某一件事的报告。对一个时期或一项专项工作作全面回顾的（年度工作报告、自查报告等），按 `references/routes.md` 第一部分第 7 条交 gongwen-report。
- 工作报告：基本情况、做法和成效、问题、下一步打算；情况报告：经过、原因、处理情况、下一步措施；答复报告：针对询问逐项答复。
- 开头："现将……情况报告如下："；结尾："特此报告。"
- 不写"妥否，请批示"，不等批复。

函（含复函）
- 标题：某某关于商请……的函；某某关于……的复函。
- 正文：发函缘由 → 商洽或请求的事项 → 希望；复函开头"你单位《关于……的函》收悉。现函复如下："。
- 结语："请予支持。""请予函复。""特此函复。"
- 语气平和：不用"务必""必须"指挥对方，也不写"万望""恳请务必"之类过分谦卑的话。

通知
- 开头一两句写目的和依据，接"现将有关事项通知如下："。
- 事项分条，每条写清做什么、谁来做、何时完成。
- 会议通知写全会议名称、时间、地点、参会人员、报名或回执方式、有关要求、联系人。
- 印发通知："现将《……》印发给你们，请结合实际认真贯彻执行。"
- 转发通知：标题避免"关于关于""的通知的通知"；不大段复述上级文件；本级落实要求缺的标【待补：本单位落实措施】。
- 默认不写"请于×月×日前报送贯彻落实情况"（减负规定第3条）；用户坚持要写的，在起草说明中提示。

批复
- 开头："你单位《关于……的请示》（某发〔2026〕N号）收悉。经研究，现批复如下："。来文标题和文号只用用户给的，没有的标【待补】。
- 表态：同意、原则同意或不同意，不同意的写理由；同意的写执行要求。
- 结语："此复。"
- 误："该事项原则上可行，待条件成熟后再议。"

通报
- 事实（时间、单位、经过、结果）→ 定性 → 表彰或处理决定 → 要求。
- 事实和定性只用用户材料；批评性通报中的个人一律写"张某"，处理决定以用户提供的为准。

意见
- 总体要求（从简）→ 主要任务（分条）→ 保障措施（精炼，只写有具体主体和动作的内容）。
- 下行意见属部署性文件，用"要""应当"，不用"建议""可以考虑"。

签报
- 标题：关于……的请示（或报告）；主送一位本单位领导；正文写缘由、事项、本部门意见或方案；落款写部门和日期。
- 一签一事；涉及其他部门的，起草说明提示先会签。

其他文种的处理范围：
- 决定、通告、公告：可以起草，起草说明提示核对发文权限；局部事项（停水、施工、考试安排）不用公告。
- 决议、命令、公报、议案：只给结构说明和注意事项，不起草全文，告诉用户这几类使用主体受限，专门 skill 计划在 v0.2 发布。
- 国企董事会议案、决议按《公司法》和公司章程办理，不按《条例》起草，只给结构建议。

### （四）格式要素与标记

1. 正文从标题写起：标题、主送机关、正文、附件说明、发文机关署名、成文日期，需要时加附注。
2. 发文字号、签发人、份号属于版头，不写进正文；用户需要的，在起草说明"待补事项"中列出，由 gongwen-format 排版时填入。
3. 成文日期未签发的写【待补：成文日期】；单位名称用全称或规范化简称，不自造简称。
4. 依据文件的名称和文号只用用户提供的；用户只说"根据上级文件"的，写"根据【待补：依据文件名称和文号】"。

## 三、讲话稿

### （一）先问清四项

场合、讲话人、时长、听众。用户已经说了的不再问，缺的合并成不超过 3 个问题：

```text
写讲话稿前确认三件事：
1. 场合：什么会议或活动？谁讲（职务）？讲给谁听？
2. 时长：讲多少分钟？
3. 内容：要讲哪几件事？有哪些数据、事例、上级要求的原文可以用？
```

用户说"直接写"或没有回答的：时长按 10 分钟（约 2000 字）处理，听众按会议类型推断，所作假设写进起草说明。

### （二）定篇幅

1. 字数 = 分钟数 × 200（经验值）。画像或领导偏好卡写了语速的，按画像。误差 ±10%。
2. 主要负责同志讲话、会议主报告不超过 1 小时（减负规定第6条）。用户要求超过的，起草说明中提示。
3. 起草说明写明"按每分钟约 200 字估算，全文约 N 字，预计 N 分钟"。

### （三）按会议类型搭结构

| 会议类型 | 结构 |
|---|---|
| 部署会、动员会 | 开会目的（一两句）→ 要做的几件事 → 每件事谁负责、何时完成 → 简短要求 |
| 推进会、调度会 | 进展（数据）→ 存在的问题 → 下一步安排 |
| 总结表彰会 | 成绩（数据和事例）→ 经验 → 下一步要求 |
| 座谈会 | 回应听到的情况 → 几点看法 → 要求或希望 |
| 开学、毕业典礼，节日致辞 | 问候 → 一两个具体的人和事（由用户提供）→ 希望 |
| 表态发言、交流发言 | 本单位做法和数据 → 下一步打算；不写一般性表态（减负规定第6条） |
| 主持词 | 按议程顺序串联：宣布开会、介绍议程、逐项引出、简短小结、宣布散会 |

### （四）写成便于讲的稿子

1. 句子短，一句话一个意思；少用十五字以上的长定语。
2. 开头说讲几点，结尾回扣；过渡语"下面，我讲三点意见"可以用。
3. 数字少而准：一段里连用的数字不超过三个；大数可以用"约""近"取整，原数写进起草说明。
4. 口语化可以放宽，"不是……而是……"全篇一两处、"希望大家……"、设问都可以用（`references/_shared/style/ai-tone.md` 第三部分）；网络用语、互联网黑话、拟人化比喻仍然不用。

正误对照：
- 误：通过全面构建多层次、全方位、立体化的风险防控体系，实现了安全生产形势的持续稳定向好。
- 正：今年全市排查隐患1260处，已整改1198处。（数据取自用户材料；没有数据的写"排查隐患【待补：数量】处"）

### （五）引语、事例和红线

1. 领导人讲话、上级精神、会议原话，只用用户提供的原文，注明出处；没有原文就不写引语，不自拟"金句"，不把自拟的话安在领导人或上级文件名下（`references/_shared/guardrails.md` 第二条）。需要引用但用户没给原文的，标【待补：引用原文及出处】。
2. 政治性提法只用用户提供原文中的表述；没有的，用通用稳定的表述并标【待核实：请对照最新原文】。
3. 不编造事例、人物故事、群众原话、校友经历。
4. 不在讲话中设定督查检查考核事项（减负规定第7条）；用户要求写"纳入年度考核"的，起草说明提示核对是否已列入督查检查考核计划。
5. 讲话涉及的事项已经发文部署的，起草说明提示用户确认是否需要专门开会（减负规定第4条）。

### （六）格式

标题写"在……上的讲话"，可用副标题"——在……会议上的讲话"；下一行写讲话人职务和日期，日期未定的写【待补：讲话日期】。称谓"同志们："单独成段。

## 四、纪要

### （一）先分清记录和纪要

| 要印发给有关单位执行或周知 | 只存档备查 |
|---|---|
| 写纪要（法定文种，《党政机关公文处理工作条例》第八条第（十五）项） | 整理成会议记录（内部记录，不是公文） |

用户说"整理会议记录"又提到"发给各科室""印发"的，写纪要；说不清的，按纪要写，并在起草说明里说明二者区别。

### （二）输入

会议记录、录音转写稿、笔记、议程。只有印象、没有记录的，只出纪要框架，议定事项全部标【待补】。

### （三）提炼

1. 会议概况：时间、地点、主持人、议题，缺的标【待补】。
2. 议定事项：只写记录中形成一致意见的事项，逐条写清事项、责任单位、完成时限，缺的标【待补：责任单位】【待补：完成时限】。
3. 讨论了但没有定的事项：记录里明确写了"另行研究""下次再议"的，照写；没有写的，不写进议定事项，在起草说明中列出"以下事项讨论未形成一致意见，未写入议定事项"。
4. 不加没说的话：不替会议补"会议强调""会议要求"的内容，不把个人发言写成会议决定。
5. 常用语："会议听取了……""会议认为……""会议议定：""会议要求："。
6. 出席、请假、列席名单（GB/T 9704-2012 10.3）：用户给了名单的照写；没给的标【待补：出席人员名单】。使用联网工具时，建议名单只写职务，姓名定稿时由用户填入。

正误对照：
- 记录原文：后勤科长提出下月起食堂外包，大家意见不一，没定。
- 误：会议议定：下月起食堂实行外包管理。
- 正：不写入议定事项；起草说明注明"食堂外包事项讨论未形成一致意见，未写入议定事项"。
- 记录原文：会议同意由后勤科牵头修订值班制度。
- 误：会议议定：由后勤科牵头修订值班制度，于11月底前提交院长办公会审议。（时限和后续程序都是添加的）
- 正：会议议定：由后勤科牵头修订值班制度，于【待补：完成时限】前完成。

### （四）单位差异

- 医院：党委会纪要和院长办公会纪要分开整理、分开编号；"三重一大"议题写明前置讨论情况。
- 高校：党委常委会和校长办公会纪要分开。
- 国企：党委会、董事会、总经理办公会纪要分开；重大经营管理事项写明党委前置研究情况，前置程序未完成的在起草说明中提示。
- 社区：两委会议、居民会议多为会议记录，按记录整理，不套纪要格式。

## 五、信息

### （一）标题

一句话写出主体、做法和效果，有数据的放数据。不用"扎实推进""多措并举""取得明显成效"这类空词。

- 误：某街道多措并举扎实推进垃圾分类工作
- 正：某街道推行定时定点投放　三个月垃圾分类准确率由62%提高到85%（数据取自用户材料）

### （二）开头即结论

第一句写清时间、主体、做了什么、效果。

- 误：为深入贯彻落实……精神，进一步提升垃圾分类工作水平，近日，某街道……
- 正：今年7月以来，某街道在12个小区推行定时定点投放，垃圾分类准确率由62%提高到85%。

### （三）主体和篇幅

1. 做法分 2–3 条，每条一句做法；用户材料里有数据或事例的配上，没有的标【待补：说明】，不为凑格式编数据；结尾可省。
2. 默认不超过 800 字（工具约定）；上级信息部门或画像另有要求的，从其要求。
3. 写明时间，保证时效；同类信息不重复报送（减负规定第12条）。

### （四）对外发布的信息

公众号、新闻稿等对外发布的，叠加严谨模式：
1. 不写未经认定的排名和"全国领先""首创"，用户提供了认定依据的除外。
2. 医院不写疗效保证（"治愈率100%""根治"）；国企不写未公开的经营数据和重大事项。
3. 出现群众、患者、学生的姓名或照片的，起草说明提示确认已取得本人或监护人同意。

## 六、成稿后

1. 起草说明按 output-format.md 的顺序写：所作假设（含文种判断理由和条款、采用的默认值、当前模式）、待补事项、待核实事项、保密提示；教学模式再加写作要点。
2. 能写文件时，正文写入 `公文/<YYYYMMDD>-<简短标题>/正文.txt`，起草说明写入同目录的 `起草说明.md`。
3. 有 Python 环境时运行机检；不能运行的，按第七部分人工检查，起草说明写"未运行机检"。
4. 在对话中（不在正文里）告诉用户下一步，路线见 `references/routes.md` 的 R08 至 R11；网页环境在起草说明之后输出交接卡（`references/routes.md` 第四部分）。

## 七、分文书自检

法定公文
- [ ] 文种与关系、目的一致，起草说明写了判断依据。
- [ ] 第二部分（二）的行文规则逐项查过。
- [ ] 请示一文一事，有具体请求事项和本单位意见，结语是请示结语。
- [ ] 报告没有请求事项，结语是"特此报告。"
- [ ] 文号、日期、依据文件、金额都来自用户，或已标【待补】。

讲话稿
- [ ] 字数与时长匹配，误差在 ±10% 以内。
- [ ] 引语都有用户提供的原文和出处；没有自拟"金句"。
- [ ] 没有设定督查检查考核事项。
- [ ] 句子短，适合口头讲。

纪要
- [ ] 每条议定事项都能在记录中找到依据。
- [ ] 每条议定事项都有责任单位和时限，或已标【待补】。
- [ ] 未形成一致意见的事项没有写成议定事项，已在起草说明中列出。

信息
- [ ] 标题有主体、做法、效果。
- [ ] 第一句就是结论。
- [ ] 篇幅在要求之内，数据都来自用户。
