## 一、四个维度的识别信号

### （一）单位类型

先看画像；没有画像，从用户的话里找下表的词。一个词也没有、又影响路线的，作为问题放在回复末尾（第二部分）。

| 用户的话里出现 | 判断为 | 读取 |
|---|---|---|
| 市委、市政府、厅、局、委、办（省市级）、机关、处室 | 党政机关 | `references/_shared/profiles/units/dangzheng.md` |
| 县、区、乡镇、街道、站所、包村、迎检、政务信息积分 | 基层 | `references/_shared/profiles/units/jiceng.md` |
| 社区、居委会、村委会、两委、网格员、居民通知 | 社区 | `references/_shared/profiles/units/shequ.md` |
| 医院、院办、科室、护士长、院长办公会、国考、病案 | 公立医院 | `references/_shared/profiles/units/yiyuan.md` |
| 大学、学院、辅导员、校长办公会、审核评估、教代会（高校） | 高校 | `references/_shared/profiles/units/gaoxiao.md` |
| 中学、小学、班主任、教研组、教务处、家长会；教育局（仅限用户身份是学校时，见下方第 2 条） | 中小学 | `references/_shared/profiles/units/zhongxiaoxue.md` |
| 集团、公司、国企、董事会、总经理办公会、签报、经营分析 | 国有企业 | `references/_shared/profiles/units/guoqi.md` |

一句话同时命中几行时，按以下顺序判断：

1. 先分清写材料的是谁。写材料的一方是教育局、卫健委等行业主管部门本身的，按层级判断：区、县的归基层，市级以上的归党政机关。例：“我在区教育局办公室”判基层；“我在市卫健委”判党政机关。
2. “教育局”只有在用户身份是学校时（如“学校要给区教育局报个材料”），才作为中小学的信号。其他行业主管部门同理：“卫健委”不等于医院，用户身份是医院时，它只说明行文对象。
3. “局”既可能是市级机关，也可能是县级部门：用户说了“县”“区”的按基层，否则按党政机关。两者的行文规则相同，差别主要在日历节点和红线。

### （二）写作角色（模式）

按 `references/_shared/profiles/roles.md` 第一节的顺序确定：本轮指定、画像、识别信号、教学模式。识别信号速查：

| 信号 | 模式 |
|---|---|
| 发来一篇成稿，说“帮我看看”“把把关”“审一下”“送签前过一遍” | 审稿模式 |
| 发来数据表、工作记录、口述的大白话；“我是搞业务的”“不太会写公文”；用口语陈述一件已发生的事让你写成材料，没有新手信号 | 转译模式 |
| “我刚入职”“第一次写”“不知道怎么下手”“用请示还是报告”“为什么这么改” | 教学模式 |
| “赶时间”“今晚要”“出三个版本”“照这篇的格式”；用词熟练，如“口径”“定调” | 高效模式 |
| 党建、对照检查、民主生活会、党课、“提法要准”“要报组织部”“要发公众号” | 严谨模式 |

规则：
1. 一次只取一个主模式。党建、对外发布的材料另外叠加严谨模式的提法核对。
2. “直接写”“不用问了”只表示不再提问，不决定模式。用户说“直接写”、话里又没有其他信号的，按教学模式处理：不提问，交接卡写教学模式，下一站成稿后附写作要点。
3. 发来成稿但要求“帮我改一版”的，本次按高效模式交改稿 skill（roles.md 第六节）；“帮我看看”的交 gongwen-review，不改写。
4. 只说了单位或部门（如“在德育处”“在院办”）不算说了岗位，不据此定模式（第三部分（一））。

### （三）文书类型

文种初判只写一句，具体判断和起草交 gongwen-draft。用统一词表名称：法定文种（决议、决定、命令、公报、公告、通告、意见、通知、通报、报告、请示、批复、议案、函、纪要），内部文种（签报），常用材料（总结、计划、工作要点、汇报材料、调研报告、经验材料、述职报告、实施方案、讲话稿、信息、其他）。

用户说的名称和实际文种不一致时，按目的初判：

| 用户的说法 | 实际要写的 | 依据 |
|---|---|---|
| “请示报告” | 请求批准的写请示；只汇报的写报告 | 不写“请示报告”，见 `references/_shared/rules/doc-types.md` 2.11 |
| “申请”“申请书”（本单位向上级） | 请示 | doc-types.md 第六部分 |
| “申请”（向不相隶属的部门，如向财政局要经费） | 函 | 《党政机关公文处理工作条例》第八条第（十四）项 |
| “打个报告要钱” | 请示 | 第八条第（十一）项；报告不得夹带请示，第十五条第（四）项 |
| “会议记录整理一下” | 要印发执行的写纪要；只存档的整理成会议记录 | doc-types.md 7.5 |
| “发个公告”（局部事项，如停水、施工） | 通告或通知 | doc-types.md 2.5 |
| “科室给院长写个请示” | 有签报制度的用签报 | doc-types.md 第三部分 |

### （四）行文方向

| 写给谁 | 方向 |
|---|---|
| 有隶属关系的上级机关、上级主管部门 | 上行文 |
| 不相隶属的单位（同级部门、外单位、无隶属关系的审批部门） | 平行文 |
| 下级单位、所属单位、群众、家长、居民 | 下行文 |
| 本单位领导（内设部门报送） | 内部上行文（签报） |

用户没说写给谁、文种又能推断方向的，按 `references/_shared/profiles/roles.md` 第九节的推断表处理，不再问。

## 二、补问：问什么、怎么问

### （一）问不问

只问会改变路线或文种的维度，最多 3 个，放在回复末尾，不阻塞交接。按下表决定：

| 缺的维度 | 问不问 |
|---|---|
| 写给谁、办什么事（决定文种和方向） | 问，排第一 |
| 单位类型 | 影响路线的才问（如本行业专用文书要不要走行业包）；建档时问 |
| 角色 | 一般不问，按信号或默认教学模式；建档时问 |
| 篇幅、时间、附件等细节 | 不问；用户给了的原样写进交接卡，没给的由下一站用默认值 |

### （二）怎么问

一次问完，编号列出，每个问题给选项，用户能一个字回答。

```text
为了选对文种，先确认两件事：
1. 这份材料写给谁？（上级主管部门／不相隶属的单位，如财政局／下级或群众／本单位领导）
2. 主要是要办什么？（请求批准／汇报情况／布置工作／商量事情）
```

### （三）不问的情形

1. 用户说“直接写”“不用问了”。
2. 已经问过一轮，用户没有回答。
3. 审稿模式：不提问，确需的背景在问题清单里标“待确认”。

这三种情形一律按 roles.md 第九节默认值处理：单位按党政机关；模式按识别信号，没有信号按教学模式；方向从文种推断，推断不出按平行文。推断项在回显中标“（推断）”，交接卡写成“按……处理（推断）”，由下一站写进起草说明的所作假设。

### （四）回显

判断完成后，用一行写出四个维度和路线，然后接着做：

```text
判断：基层｜教学模式｜函（平行文）｜路线：gongwen-draft → gongwen-direct → gongwen-humanize → gongwen-review → gongwen-format
```

推断出来的项后面加“（推断）”，方便用户纠正，例如“函（平行文，推断）”。

### （五）带具体需求的首轮回复

依次给出四维回显、文种初判、下一步、素材清单、问题、保密提示（SKILL.md 第三步第 4 条）。首轮就把任务交到下一站，不等用户答完问题；问题最多 3 个，建档缺的字段算在内，放在最后；素材清单不算提问，给了交接卡的写在“请准备”一栏，不再另列。不附写作日历提示。

例：用户第一次使用，说“我刚到镇政府党政办，领导让我给县交通运输局写个请示，要一笔村道水毁修复补助”，当前环境没有安装 gongwen-draft。

```text
判断：基层｜教学模式｜函（平行文）｜路线：gongwen-draft → gongwen-direct → gongwen-humanize → gongwen-review → gongwen-format
文种初判：镇政府和县交通运输局不相隶属，请求批准用函，不用请示（《党政机关公文处理工作条例》第八条第（十四）项）。具体写法由 gongwen-draft 完成。
下一步：这里没有安装 gongwen-draft。新开一个对话，先粘贴 dist/prompts/gongwen-draft.md 全文，再粘贴下面的交接卡和材料；也可以安装后直接调用。
【交接卡】
单位画像：无
单位类型：基层；镇政府；党政办（推断），未提供画像
当前模式：教学模式
任务：镇政府向县交通运输局申请村道水毁修复补助，文种用函，平行文
路线：draft → direct → humanize → review → format
本站：第1站 gongwen-draft，成稿
已确认：无
本站产出：无
请准备：受损路段和受损情况；补助金额和测算依据；联系人
安装命令：（照输出格式规范第四部分写，Claude Code 和其他工具各一条）
顺便建一份简版画像，还差一项：
1. 您平时最常写哪几类材料？（如通知、信息、汇报材料）
请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。
```

能调用 skill 且已安装 gongwen-draft 的环境，“下一步”改为直接调用，带上画像字段和已知事实，不出交接卡和安装命令。

## 三、建档：提取、补问、写入

### （一）先提取

从用户已经说过的话里取三个字段：

| 字段 | 例：用户的话 | 提取结果 |
|---|---|---|
| 单位类型 | “我在县医院院办” | 公立医院（县级） |
| 写作角色和默认模式 | “院办秘书，天天写材料” | 院办秘书；高效模式 |
| 常写文书 | “主要写院长办公会纪要和签报” | 院长办公会纪要、签报 |

岗位后面用分号接模式。只说了单位或部门（如“在中学的德育处”“在医院的医务部”）不算说了岗位，不据此定模式，建档时必须问岗位。学校的教务处、德育处，医院的院办、医务部，机关的办公室，都是职能处室，岗位按本人回答：综合岗写高效模式，新入职写教学模式，兼写材料的业务人员写转译模式。

用户说了岗位、没有模式信号的，按岗位对应：新入职、选调生写教学模式；办公室秘书、综合岗写高效模式；业务科室人员写转译模式；领导、核稿人员写审稿模式；党务、宣传岗写严谨模式。

### （二）再补问

缺几个字段问几个，一次问完，最多 3 问：

```text
建个简版画像，以后就不用每次说明了。还差两项：
1. 您是什么岗位？（刚接触公文／专职写材料／业务岗兼写／审稿把关／党务宣传）
2. 平时最常写哪几类材料？（如通知、汇报材料、纪要）
```

用户不答的字段留空，不猜。不问单位全称、领导姓名、电话、业务数据。

### （三）写入

能写文件时：
1. 依次查 `.gongwen/单位画像.md`、`~/.gongwen/单位画像.md`。
2. 都没有：在当前工作目录创建 `.gongwen/` 目录，写入 `.gongwen/单位画像.md`：

```markdown
# 单位画像

- 单位类型：公立医院（县级）
- 写作角色和默认模式：院办秘书；高效模式
- 常写文书：院长办公会纪要、签报
```

3. 已有画像：不覆盖。空缺字段直接补上；已有字段内容不同的，列出“原内容、改为”，用户同意后只改那一行。字段名按 `references/_shared/profiles/profile-template.md`，其他 skill 按这些字段名读取。
4. 写完告诉用户：文件位置；可以随时手改；更多字段（发文字号、可用文种、篇幅偏好等）、领导偏好卡、禁用词和文风学习交 gongwen-profile 完整建档；画像可能含内部信息，不要提交到公开仓库。
5. 带着具体需求来的，画像写完不另占一轮，问题仍放在回复末尾，首轮照常交到下一站。

网页环境：输出同样格式的画像文本，告诉用户“请保存这段文字，下次使用时粘贴在对话开头”。

## 四、正误对照

| 场景 | 误 | 正 |
|---|---|---|
| 用户说“我刚到区教育局办公室，要给辖区学校发个通知” | “教育局”命中中小学一行，按中小学画像处理 | 写材料的是区教育局本身，按层级判为基层（推断） |
| 首次使用的用户带着具体需求来 | 先问完建档问题，等用户答复后再交给起草 skill；或者另附写作日历提示 | 首轮就给下一步（调用，或交接卡、提示词说明、安装命令），建档问题放在末尾，不附日历 |
| 用户说“我在一所中学的德育处，平时写计划总结” | 把“德育处”当成岗位，直接定转译模式 | 单位类型定中小学；岗位作为问题之一 |
| 用户说“我是县医院院办的，领导让我写个东西” | 连问五个问题：单位全称、领导是谁、写什么、多少字、什么时候要 | 单位已知，只问“写给谁、要办什么事”；篇幅和时间不问 |
| 用户说“直接写，别问了” | 再追问一句“请问是写给上级还是平级？” | 不问，按文种推断方向，交接卡写“按……处理（推断）” |
| 用户说“周四开会，帮我发个通知” | 交接卡写成具体日期 | 交接卡照写“周四”，不推算日期 |
| 已有画像，用户说“我调到党办了” | 重写整份画像 | 列出“写作角色和默认模式：院办秘书；高效模式 → 党办干事；严谨模式”，用户同意后只改这一行 |
| 建档 | 画像里写“单位：某某市第一人民医院，院长张三” | 单位类型写“公立医院”，名称不写或写代号，领导只写职务 |
