# 路线表

用户的需求对应走哪几个 skill、按什么顺序。表中 skill 名省略 `gongwen-` 前缀，如 report 即 gongwen-report；"本 skill"指总入口 gongwen。

## 目录

一、使用规则
二、路线决策表
三、尚未发布的 skill 怎么替代
四、交接卡（网页提示词版）
五、拆分示例

## 一、使用规则

1. 按用户的话找最贴近的一行。同时符合几行的，以"文书类型"为准。
2. "（停）"表示这一步做完停下，等用户确认后再往下走。另外，review 之后、format 之前一律停下，等用户处理核稿意见、确认定稿。
3. 用户已有成稿的，跳过起草环节，从改稿或核稿开始。
4. 用户只要其中一步，只走那一步。用户要跳过某一步（如不排版），照办，不劝。
5. 一句话里有几件事的，按第五部分拆开，每件事一条路线。
6. 行文方向、单位类型只影响各 skill 内部的写法，不改变路线。
7. "报告"的分界：向上级报告某一件事的（事件经过和处置、检查整改情况、交办事项落实情况、答复询问），走 R08，由本 skill 起草；对一个时期或一项专项工作作全面回顾的（年度工作报告、党建工作报告、自查报告、某项专项工作开展情况的全面汇报），按总结走 R01，由 gongwen-report 起草。综合材料要正式上报的，作为报告的附件报送，或由本 skill 补上报告的标题、主送和结语（`references/_shared/rules/doc-types.md` 第六部分"上报总结、调研报告等材料"一行）。

## 三、尚未发布的 skill 怎么替代

写作日历、单位画像里会出现以下 skill，它们计划在后续版本发布。v0.1 按右列处理，并告诉用户这是过渡做法。

| 未发布的 skill | v0.1 怎么办 |
|---|---|
| gongwen-draft 法定公文 | 本 skill 过渡起草（R08） |
| gongwen-speech 讲话类 | 本 skill 过渡起草（R09） |
| gongwen-brief 信息简报 | 本 skill 过渡起草（R11） |
| gongwen-minutes 纪要与议题 | 纪要由本 skill 过渡起草（R10）；上会议题材料、督办清单暂不支持 |
| gongwen-party 党建 | 党建工作报告、总结走 report（严谨模式）；对照检查材料、党课讲稿不起草全文，本 skill 只给结构提纲和填写指引，事例由用户本人填写 |
| gongwen-implement 上级文件转化 | 实施方案走 report；转发通知走本 skill |
| gongwen-rectify 整改 | 整改方案走 report；整改报告走本 skill；整改台账一致性检查暂不支持 |
| gongwen-data 数据图表 | 数据的文字表述走 report，只用用户给的数据；报表汇总、指标计算、图表暂不支持 |
| gongwen-polish 改稿润色 | 措辞和态度走 direct，AI 腔走 humanize；按领导批注改稿、压缩篇幅暂无专门能力 |
| gongwen-profile 画像与文风学习 | 简版画像由本 skill 建；完整画像可照模板手工补；文风学习、花脸稿学习暂不支持 |
| 行业包（grassroots、hospital、university、k12、soe） | 按画像的单位类型读 units 画像文件，各 skill 照常使用 |

## 四、交接卡（网页提示词版）

网页版不能调用其他 skill。路线的下一站不是本 skill 时，输出交接卡，并告诉用户：新开一个对话，先粘贴下一站的提示词文件全文（项目 dist/prompts/ 目录下，文件名为 skill 名，如 gongwen-report.md），再粘贴交接卡和材料。

```text
【交接卡】
单位画像：（粘贴画像全文；没有写"无"）
当前模式：转译模式
任务：科室2026年工作总结，上行文，报医院
路线：report（台账、提纲）→ title → report（成稿）→ direct → humanize → review → format
本站：第1站 gongwen-report，建素材台账、搭提纲
已确认：按科室名义；篇幅不超过3000字
请准备：全年工作记录、数据表（先删去患者姓名、病案号等）
```

要求：
1. 交接卡只写任务信息，不抄录用户原始材料，不带敏感信息。
2. 每站做完，该站 skill 会在起草说明之后输出更新后的交接卡（`references/_shared/style/output-format.md` 第四部分）。用户也可以回到总入口，贴上交接卡和这一站的产出，本 skill 把"本站"改为下一站，重新给出交接卡。
3. 用户只用网页版且不愿换提示词的，告诉用户：本 skill 能做的只有路线规划、建档、日历和过渡起草，其余环节需要换对应的提示词。

## 五、拆分示例

（一）"下周市里来督查，要准备什么？"（基层）
1. 汇报材料：R03。
2. 自查报告：按检查通知逐项自查，走 report。
3. 佐证台账：report 可建素材台账，专门的台账整理暂不支持；台账数据只能来自用户。
先问用户：有没有督查通知或检查清单？三件事哪件最急？

（二）"年底了，科室总结和我的述职都要交"
走 R07：一份素材台账，分别出科室总结和个人述职，述职只用本人事例。

（三）"给县政府写个报告，汇报这次强降雨的受灾和处置情况，顺便要点经费"
拆成两件：报告走 R08；经费另写请示走 R08；两件都由本 skill 起草，材料够的依次写完（《党政机关公文处理工作条例》第十五条第（四）项：报告不得夹带请示事项）。
