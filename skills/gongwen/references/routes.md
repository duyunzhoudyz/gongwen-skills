# 路线表

用户的需求对应走哪几个 skill、按什么顺序。表中 skill 名省略 `gongwen-` 前缀，如 report 即 gongwen-report。总入口 gongwen 只规划路线和交接，路线中的起草、改稿都由具体 skill 完成。

## 一、使用规则

1. 按用户的话找最贴近的一行。同时符合几行的，以“文书类型”为准。
2. “（停）”表示这一步做完停下，等用户确认后再往下走。review 之后、format 之前一律停下，等用户处理核稿意见、确认定稿。“停”只用在两站之间；每一站自己的首轮交付按 `references/_shared/profiles/roles.md` 第十节，起草 skill 首轮照常成稿。
3. 用户已有成稿的，跳过起草环节，从改稿或核稿开始。
4. 用户只要其中一步，只走那一步。用户要跳过某一步（如不排版），照办，不劝。
5. 一句话里有几件事的，按第五部分拆开，每件事一条路线。
6. 行文方向、单位类型只影响各 skill 内部的写法，不改变路线；只有本行业专用文书按第三部分改走行业包。
7. “报告”的分界：向上级报告某一件事的（事件经过和处置、交办事项落实情况、答复询问），走 R08；对一个时期或一项专项工作作全面回顾的（年度、专项工作报告），走 R01；年度党建工作报告走 R22；含“整改”的报告（整改进展、整改落实情况）优先走 R25；上级文件的贯彻落实情况报告走 R24。

## 三、行业包与未安装兜底

（一）分工

1. 本行业专用文书归行业包；本行业的通用文书（通知、总结、讲话等）仍归核心 skill，核心 skill 读单位画像。
2. 行业包没有安装的，本行业专用文书交下表的核心 skill，按单位画像处理，不拒绝；可以顺带给出行业包的安装命令。

| 行业包 | 未安装时交给 |
|---|---|
| grassroots（乡镇、街道、村、社区） | 迎检汇报 → report；迎检自查和佐证台账 → rectify；居民通知、告知书、倡议书、应急通知 → draft；报上级的政务信息 → brief |
| hospital（公立医院） | 评审自评、绩效考核分析、质量分析、科室主任述职（含口头稿）→ report；党委会和院长办公会议题 → minutes；九项准则自查、院感整改 → rectify |
| university（高校） | 学院年度总结 → report；审核评估自评 → rectify；校内签报、两级发文判断 → draft；辅导员与学生的谈心谈话提纲 → party |
| k12（中小学） | 学期和班主任计划总结 → report；督导评估自评 → rectify；致家长的一封信 → draft；家长会讲话 → speech；教研和安全教育记录 → minutes；课后服务方案 → implement |
| soe（国有企业） | 经营分析、ESG 报告 → report；三重一大议题、董事会议案和决议、总经理办公会纪要 → minutes；改革任务台账 → implement；党建与经营融合经验材料 → party |

其余专用文书按文书性质交对应的核心 skill。

（二）目标 skill 未安装

按 `SKILL.md` 第五步和 `references/_shared/style/output-format.md` 第四部分：直接调用，或同时给交接卡（写法见本文件第四部分）、新开对话粘贴 `dist/prompts/<skill 名>.md` 的说明、安装命令（行业包把插件名换成包名）。

## 四、交接卡

网页版一次只加载一个 skill 的提示词，Agent 环境里目标 skill 也可能没有安装，这两种情况都给交接卡，连同提示词说明和安装命令一起给（第三部分（二））。

```text
【交接卡】
单位画像：（粘贴画像全文；没有写“无”）
单位类型：医院；科室；科主任（推断），未提供画像
当前模式：转译模式
任务：科室年度工作总结，上行文，报医院
路线：report（台账、提纲、成稿）→ direct → humanize → review → format
本站：第1站 gongwen-report，建素材台账、搭提纲、成稿
已确认：按科室名义；字数（用户给了才写，原话照抄）
本站产出：无
请准备：全年工作记录、数据表（先删去患者姓名、病案号等）
```

要求：
1. 交接卡只写任务信息，不抄录用户原始材料，不带敏感信息；示例卡里的字数、名称只示格式，不得照抄。
2. 用户给的事实原样写，不改写、不推算：字数或时长写进“已确认”（如“讲20分钟”），由下一站按 `references/_shared/guardrails.md` 第四条第2款执行；“下周三”“月底”等相对时间照写，不换算成日期；加引号的做法名称、本单位提法照写。
3. 推断出来的项写成“按……处理（推断）”，不写进“已确认”。“单位类型”必填，没有画像时按用户所述推断，注明“未提供画像”（见 output-format 第四部分）。
4. 缺本人事例的材料（对照检查、述职等），在“任务”中注明“缺本人事例”；要先看提纲或一页纸的，在“已确认”中写明。
5. 用户回到总入口贴来交接卡和这一站的产出的，本 skill 把“本站”改为下一站，把用户带回的上一站产出中下一站要接着用的结果（如标题全文，注明“推荐，待确认”）写进“本站产出”，重新给出交接卡。

## 五、拆分示例

（一）“下个月县里来考核我们镇的安全生产工作，要准备什么？”（基层）
1. 迎检汇报材料：装有 grassroots 走 grassroots；未安装走 R03（report）。
2. 自查报告：装有 grassroots 走 grassroots；未安装走 R25（rectify），按考核细则逐项自查。
3. 佐证台账：随自查一起做，装有 grassroots 走 grassroots，未安装走 rectify；台账数据只能来自用户。
先给第一件的下一步，末尾问：有没有考核通知或细则？三件事哪件最急？

（二）“年底了，科室总结和我的述职都要交”
走 R07：一份素材台账，分别出科室总结和个人述职，述职只用本人事例。

（三）“给县政府写个报告，汇报这次强降雨的受灾和处置情况，顺便要点经费”
拆成两件：报告走 R08；经费另写请示走 R08。两件都交 draft，合成一次交接（《党政机关公文处理工作条例》第十五条第（四）项：报告不得夹带请示事项）。

（四）“给县卫健委写个报告，汇报我院落实院感整改情况，顺便申请经费买设备”
拆成两件：含“整改”的报告走 R25，首站 rectify；经费请示走 R08，首站 draft。分属不同 skill，先给报告的下一步，末尾问“两份都要，还是先出报告”。交接卡只写用户给的数字。
