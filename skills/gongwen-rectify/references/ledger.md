# 整改台账规范

台账是整改材料的唯一事实源：方案里的任务、进展报告和情况报告里的状态、数字，都从台账来。文件名 `整改台账.md`，用 Markdown 表格；要 Excel 时用 `scripts/md2xlsx.py` 转换。

## 一、列和填法

| 列 | 填法（缺的写【待补：列名】，另有说明的除外） |
|---|---|
| 编号 | 见第二部分 |
| 问题来源 | 反馈文件名和条目，如“市委第六巡察组反馈意见第一部分第3条” |
| 问题表现 | 照录反馈原文（第三部分）；只有转述的照录转述，“问题来源”栏注明“用户转述，待对照反馈原文” |
| 原因分析 | 用户提供或确认过的原因；缺的另附“原因分析提示” |
| 整改措施 | 用户提出的措施，改成“做什么、做到什么程度、何时完成”的公文表述；多条编 1. 2. |
| 责任领导 | 写职务，如“分管副院长”；用户要求写姓名的照写 |
| 责任部门 | 牵头部门在前，配合部门写“（配合）” |
| 完成时限 | 用户给的期限原话，材料写明年份的补年份，如“2026年10月底前”“2026年12月31日前”；不推算具体日 |
| 成效标准 | 可检验：做到什么程度、凭什么验证 |
| 整改状态 | 按 `references/status.md`；方案阶段记“未启动”，检查期间已改完的记“立行立改” |
| 进展情况 | “日期＋事实”，逐次追加；方案阶段不设 |
| 佐证材料 | 文件名、文号、记录或凭证名称；已完成、立行立改的必须有，没有就不能记完成 |

1. 方案阶段至少要有前十列；进展和情况报告阶段加“进展情况”“佐证材料”两列。
2. 表头用上表的列名。`scripts/rectify_check.py` 靠“编号”和“整改状态”两列对账，这两列的列名不要改。
3. 单元格不留空，缺的写【待补：说明】，起草说明汇总。
4. 同一单元格内换行用 `<br>`，转 Excel 时会变成单元格内换行。

## 二、编号

1. 按反馈意见的顺序从 1 编起。反馈意见本身有编号的，沿用它的编号。
2. 一条反馈里含几个不同问题的，拆成子项 4-1、4-2；措施的责任部门或时限各不相同的，也拆成子项。子项分别填状态。
3. 几个来源合在一张台账的，编号加前缀：巡-1、审-1、督-1。前缀和数字之间用连接号，对账脚本据此认出编号；子项写成 巡-4-1。
4. 编号一经确定不再改动，反馈问题不删减、不合并。拆出的条数与反馈意见列明的问题数不一致时，在起草说明中写明怎样拆的。

## 三、问题表现照录原文

问题表现是检查机关的结论，整改材料不能改写它。照录时：

1. 原文的限定词照留，如“部分”“个别”“长期”；不加原文没有的“有待”“进一步”“一定程度上”。
2. 原文的数字、对象、时间照留，不删不改。标点可以按 GB/T 15834 改成规范写法（直引号改为“”），文字不动。
3. 原文很长的，可以另设“问题简称”一列写短名，“问题表现”仍保留原文。

- 原文：部分科室高值耗材领用登记不全，账实不符，2025年盘亏金额12.6万元。
- 误（弱化）：耗材管理工作有待进一步规范。
- 误（删数字）：部分科室耗材领用登记不全。
- 正：照录原文。需要短名时，“问题简称”写“高值耗材账实不符”。

用户要求“写轻一点”“换个说法”的，说明问题表述须与反馈意见一致、弱化会被认定为整改态度不端正，照录原文；用户坚持要改的，正文保留原文，在起草说明中写明用户意见，由用户自行决定。

## 四、措施、责任、时限、成效标准

措施对着问题和原因写，每条措施是一个能检查的动作：

- 误：加强耗材管理，切实提高管理水平。
- 正：1. 11月20日前完成全院高值耗材盘点，账实不符的逐项查明原因；2. 12月31日前上线耗材二级库管理系统，高值耗材扫码出入库。（措施和日期来自用户）

1. 用户没给措施的，按问题和原因写成计划措施，不夹带新数字、项目名、制度名，并附“措施提示”（从制度、流程、系统、人员、资金、追责几方面各问一句），请用户核对补充。
2. 举一反三的措施（建制度、堵漏洞）单列一条，写明制度名称；名称用户没给的标【待补】。
3. 责任领导写职务，一条措施一个牵头部门。不把整改任务层层转给下级单位、社区或个人，确需下级配合的写“（配合）”。
4. 时限写明确期限（用户给的原话，材料写明年份的补年份，如“2026年年底前”），不写“近期”“尽快”“长期”。巡视整改的时限一般不晚于集中整改期结束（`references/sources.md` 第一部分）；需要长期坚持的，写“长期坚持，阶段目标于××前完成”。
5. 成效标准写完成的样子和验证办法：制度印发（文号）、系统上线运行、资金退回（凭证）、账实相符（盘点报告）。由措施直接推出的完成标志可以写，不另加用户没提的材料项；数值目标只用用户给的，没给的标【待补：目标值】。
   - 误：管理水平明显提升。
   - 正：盘点报告显示账实相符；高值耗材扫码出入库率达到【待补：目标值】。

## 五、三清单

问题清单、任务清单、责任清单是同一张台账的三个视图，编号三张一致：

| 清单 | 取哪几列 |
|---|---|
| 问题清单 | 编号、问题来源、问题表现、原因分析 |
| 任务清单 | 编号、整改措施、完成时限、成效标准 |
| 责任清单 | 编号、责任领导、责任部门 |

整改方案的附件可以按三张清单分别出，也可以合成一张“整改任务清单”。检查机关给了表样的，按表样的列和顺序出，只要保留“编号”和“整改状态”两列即可对账。

## 六、更新台账

每月或每阶段写进展报告前，先更新台账：

1. 把用户给的新进展逐条对到编号，进展栏追加“日期＋事实”。
2. 按 `references/status.md` 第二部分重新判定状态；状态有变化的列入“附：台账状态变化”（编号、原状态、新状态、依据）。
3. 新增问题（如追加反馈）接着往后编号。
4. 更新后的台账另存为新文件（如 `整改台账-v2.md`），原文件不改，留作底账。
5. 用户这次没提到的条目，状态保持不变，不推测进展。
6. 用户给的台账是 Excel 的：Agent 环境用 openpyxl 读出表头和各行（合并单元格的续行并入上一条），按原列名写成 `整改台账-v2.md`，更新后用 md2xlsx 转出新版 Excel（不覆盖原文件）。网页环境请用户把表格内容复制粘贴进来。

## 七、转 Excel

有 Python 时运行 `python scripts/md2xlsx.py 整改台账.md 整改台账.xlsx --title <台账表题>`，几张表（如三张清单）一起转的加 `--all-tables`；同名文件已存在时自动加 -v2。没有 Python 时，把表格复制到 Excel 或 WPS 表格中，设为宋体、表头加粗。

## 八、示例

材料（虚构）：巡察反馈“部分科室高值耗材领用登记不全，账实不符”；用户说“设备科牵头，分管副院长负责，11月中旬盘点完，年底上系统”。

| 编号 | 问题来源 | 问题表现 | 原因分析 | 整改措施 | 责任领导 | 责任部门 | 完成时限 | 成效标准 | 整改状态 |
|---|---|---|---|---|---|---|---|---|---|
| 3 | 市委第一巡察组反馈意见第二部分第1条 | 部分科室高值耗材领用登记不全，账实不符 | 【待补：原因分析】 | 1. 完成全院高值耗材盘点，逐项查明账实不符原因<br>2. 上线耗材二级库管理系统，实行扫码出入库 | 分管副院长 | 设备科 | 1. 2026年11月中旬前<br>2. 2026年年底前 | 盘点报告显示账实相符；系统上线运行 | 未启动 |

用户说的“11月中旬”“年底”照原话写，材料已写明年份的补上年份（2026年11月中旬前、2026年年底前），不折算成具体日期。
