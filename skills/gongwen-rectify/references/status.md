# 整改状态口径

台账“整改状态”一栏只用四种口径：已完成、立行立改、持续推进、长期坚持；还没动手的事项可以临时记“未启动”。台账状态只凭用户提供的进展和佐证认定。

四种口径、“基本完成”不算状态、长期坚持不计入完成数，以及完成率算法，都是本项目的工具约定。检查机关表样或通知另有口径的（如设“基本完成”栏、长期坚持另计），按其口径填报并在“所作假设”中写明，对账脚本的 RC-204 和统计差异改由人工判断。

## 一、认定标准

| 状态 | 认定标准（同时满足） | 佐证 | 计入完成数 |
|---|---|---|---|
| 已完成 | 1. 台账所列措施全部落实；2. 成效标准已达到；3. 有佐证材料；4. 要求验收或销号的，已通过验收或销号 | 必须有 | 是 |
| 立行立改 | 在巡视巡察、审计、督查期间，或收到反馈后、整改方案印发前已整改完毕，有佐证材料 | 必须有 | 是，并单列“其中立行立改 n 个” |
| 持续推进 | 措施已有实际动作，但没有全部落实，或成效标准尚未达到 | 已完成的部分附佐证 | 否 |
| 长期坚持 | 阶段性目标已达成、长效机制已建立，问题性质需要长期抓（作风、制度执行、队伍能力、意识形态等） | 阶段性成果附佐证 | 否，单列 |
| 未启动（临时） | 措施一项都没有实际动作（只开会、定分工和时限也算） | 无 | 否 |

佐证的认定：用户明确说出具体材料的（“有会议纪要”“资产卡片都建了”），即视为有佐证，佐证栏写材料名称，文号、日期标【待补】；不得自拟用户没提的材料作完成门槛。

报告中的状态句见 `references/writing.md` 第四部分。

“立行立改”的时间界限是本项目的工具约定。没有整改方案的（如审计整改只有审计报告和整改情况报告），以检查（审计）期间为限：检查期间改完的记立行立改，收到反馈后改完的记已完成。单位或检查机关另有规定的，按其规定，并在起草说明“所作假设”中写明。

## 二、判定顺序

逐条按下列顺序问，第一个“是”就是该条的状态：

1. 措施一项都没有实际动作（只开会、定分工和时限也算）？→ 未启动。
2. 在检查期间或方案印发前（没有整改方案的，在检查期间）已整改完毕，有佐证？→ 立行立改。
3. 措施全部落实、成效标准达到、有佐证（要求验收的已验收）？→ 已完成。
4. 问题性质需要长期抓，且阶段性目标已达成、机制已建立？→ 长期坚持。
5. 其余 → 持续推进。

一条问题拆成子项（3-1、3-2）的，子项分别判定；大项以全部子项完成为完成，有一个子项未完成即为持续推进。

## 三、不能升级的情形

1. 开了会、发了部署通知、印了整改方案，只算部署，不算完成。
   - 误：已召开专题会议研究部署，该问题已完成整改。
   - 正：已于10月13日召开专题会议部署，制度修订正在推进，预计12月10日前完成。
2. 制度出台了，执行结果还没有的，按成效标准判断。成效标准写的是“制度印发”的，可以记已完成；写的是“执行到位”“账实相符”的，记持续推进。
3. 事情做完了但拿不出佐证的，记持续推进，进展栏写“已完成，佐证材料【待补：材料名称】”。
4. “基本完成”“大部分完成”“初步完成”“基本整改到位”不是状态口径，一律按持续推进处理，报告里不用这些词。
5. 长期坚持不计入完成数。有明确完成标准的具体问题（资金未追回、台账未建立、制度未修订）不能记长期坚持；不能为了提高完成率把持续推进改记长期坚持。
6. 用户只说“差不多了”“应该弄完了”的，记持续推进，进展栏写原话并加【待核实：是否已全部完成，佐证材料】。
7. 验收不通过、问题反弹的，退回持续推进，进展栏写明日期和原因。

## 四、统计与完成率

1. 完成数＝已完成＋立行立改；完成率＝完成数÷问题总数×100%，保留一位小数。
2. 统计句固定写法，各项之和等于总数；有未启动的，加“尚未启动 n 个”：
   - 正：巡察反馈的9个问题，已完成整改5个（其中立行立改2个），持续推进3个，需长期坚持1个，整改完成率55.6%。
   - 误：通过集中整改，9个问题已基本完成整改，取得明显成效。
3. 台账拆了子项的，写清统计单位是“问题”还是“整改任务”，如“9个问题细化为23项整改任务，已完成17项”。
4. 审计问题涉及金额的，整改金额只写用户提供的，并写清口径：已追回、已归还原资金渠道、已调整账目、已完善手续，各是多少。不估算，不合并口径不同的金额。
5. 状态待定（台账写了【待补】或不在口径内）的条目不计入任何一类，统计句后补一句“另有 n 个问题的整改状态待确认”，起草说明列出编号。

## 五、更新状态

按 `references/ledger.md` 第六部分更新，只依据用户本次提供的进展和佐证。进展栏追加“日期＋事实”，如“10月23日：耗材二级库系统上线运行”；日期写实际发生日，不补记、不倒签，不把本月才做的事写成上月完成。

## 六、与审计“整改要求类型”的关系

审计机关常按立行立改、分阶段整改、持续整改三类提出整改要求（`references/sources.md` 第二部分）。这是“要求类型”，可单设“整改要求”一栏照录；“整改状态”仍用本文件口径：完成的记已完成，未完成的记持续推进，确需长期抓的才记长期坚持。
