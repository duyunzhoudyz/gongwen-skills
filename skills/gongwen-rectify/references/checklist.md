# 人工检查清单

没有 Python、脚本报错，或在网页版使用时，按本清单逐项检查，并在起草说明“假设”一行写“未运行机检和对账脚本，已按人工清单检查”。

## 一、台账自检（替代 rectify_check.py 的台账部分）

1. 编号连续、不重复；拆出的条数与反馈意见列明的问题数一致，不一致的已在起草说明说明。
2. 问题表现、空栏、状态口径和佐证，按 SKILL.md 自检清单第2至4条逐条核对。
3. 时限是明确期限（用户给的原话，材料写明年份的补年份，不推算具体日）；巡视整改的时限不晚于集中整改期结束日，长期坚持的除外。
4. 超过完成时限仍未完成的已标出，报告中如实写明。

## 二、报告对账（替代 rectify_check.py 的对账部分）

1. 按台账数出各状态条数：已完成 a、立行立改 b、持续推进 c、长期坚持 d、未启动 e，总数 n。
2. 算完成数 a＋b，完成率（a＋b）÷n×100%，保留一位小数。
3. 报告统计句的总数、完成数、立行立改数、持续推进数、长期坚持数、完成率，逐个与第 1、2 步比对。
4. 在报告中逐条找“问题1”“问题2”……，每条段末的状态句与台账一致；台账每条都在报告中出现（进展报告中，本期无变化的已完成条目可以不写）。
5. 搜“已完成整改”“整改到位”“已销号”“全部完成”“基本完成”：用在台账未完成的条目上，或台账未全部完成却写“全部完成”的，一律改掉；“将于……前完成整改”是计划，不算。
6. 成效中的每个数字都能在台账进展或佐证栏找到；找不到的改为【待补：说明】。

## 三、正文通用检查（替代 gongwen_lint.py）

1. 逐项过一遍 SKILL.md 的“自检清单”。
2. 层次序数依次为一、（一）1.（1），不跳级；数字写法符合 `references/_shared/rules/gbt15835.md`。
3. 没有“值得注意的是”“不是……而是……”、提示性冒号、“可能”“在一定程度上”之类的对冲语气。
