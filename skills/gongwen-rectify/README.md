# 整改材料（gongwen-rectify）

> 版本 1.0.0　成熟度：Stable（稳定版）

巡视巡察、审计、督查、考核反馈了问题，要写整改方案、建整改台账、按月报进展、最后报整改情况，用这个 skill。它先把反馈意见拆成编号的问题清单，再建一张整改台账（问题、任务、责任三清单合一），方案和报告都从台账取材。报告里每个问题的整改状态、完成数和完成率都要和台账对得上，有 Python 时用脚本逐条对账。

## 能做什么

| 功能 | 说明 |
|---|---|
| 整改方案 | 按反馈意见逐条落实措施、责任领导、责任部门、完成时限、成效标准，附整改任务清单 |
| 整改台账 | 问题、任务、责任三清单合在一张表里，可以一键转成公文样式的 Excel |
| 整改进展报告 | 按月或按阶段，先更新台账，再写本期进展、未完成的问题和下一步安排 |
| 整改情况报告 | 集中整改期结束或审计整改期满时，逐条报告整改落实情况和长效机制 |
| 自查报告 | 上级发了检查清单的，逐项自查，发现的问题进入台账 |
| 对账 | 你已经写好了报告，它帮你查报告和台账哪里对不上 |

## 可以这样说

1. “县委巡察组反馈了9个问题，原文发你，帮我们镇弄个整改方案和台账。”
2. “审计报告出来了，指出我们学校7个问题，月底前要报整改情况。”
3. “这是更新后的台账，帮我写这个月的整改进展报告。”
4. “上面发了个自查表，一共18项，帮我对着写自查报告。”
5. “整改报告写好了，你帮我看看和台账对不对得上，别给我改全文。”

## 输入和输出

- 输入：
  - 必需：反馈意见原文（巡察反馈、审计报告、督查通报中列问题的部分）。只有口头转述也能写，但起草说明会提醒你对照反馈原文。有了具体问题，第一轮就出台账和正文，措施按常规写出，时限等须你提供的标【待补】，要问的放在最后（最多 3 个）。
  - 最好提供：已经想好的整改措施和分工、完成时限、已经做了的事和佐证（文件、凭证、记录）。
  - 写报告时：最新的整改台账（.md 或 .xlsx）和本期进展。
- 输出（在 Claude Code、Codex、Cursor 等能写文件的工具里，放在 `公文/<日期>-<标题>/` 下）：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 方案或报告正文（只含正文），纯文本，可直接交给 gongwen-format 排版 |
| `整改台账.md`、`整改台账.xlsx` | 整改台账；Excel 为宋体、表头加粗、全边框、冻结表头 |
| `对账意见.md` | 只对账、不改稿时输出：一页纸摘要、分级问题清单（每条写位置、问题、依据、改法）和对账脚本结果 |

起草说明（假设、待补、待核实、台账状态变化、对账结果，不超过 5 行）只在对话中给出，不另存文件。在网页大模型里使用提示词版时，依次输出正文、起草说明和“附：整改台账”。

## 注意事项

1. **保密**：涉密材料请勿输入联网 AI。巡察反馈、审计报告带密级或“内部资料”标识的，它会先停下来提醒你。问题线索、举报人、被处理人员、患者和学生的信息不会写进台账和报告。
2. **问题照录原文**：台账和报告里的问题表述与反馈意见一字不差。想“写轻一点”的要求不会照办，因为弱化问题会被认定为整改态度不端正。
3. **未完成不写成已完成**：状态只用已完成、立行立改、持续推进、长期坚持四种口径，已完成必须有佐证；“基本完成”不算完成，长期坚持不计入完成率。
4. **不编造**：成效数字、追回金额、处理人数、已完成的进展只用你提供的，缺的标【待补】，存疑的写进起草说明的“待核实”一行；计划措施按常规写足，不夹带新数字和制度名。日期写实际日期，不倒签、不补记。
5. **事实和判断由你负责**：它负责搭结构、守口径、查错漏，台账状态怎么认定、报告是否报送，由你和单位决定。
6. **脚本**：对账脚本 `scripts/rectify_check.py`、台账转 Excel `scripts/md2xlsx.py` 需要 Python 3.9 及以上，读写 Excel 需要 `pip install openpyxl`，读 Word 需要 `pip install python-docx`。没有 Python 时，会按人工清单对账，并在起草说明中注明。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 一般工作总结、迎检汇报材料（没有检查清单） | gongwen-report |
| 以上级文件为依据的实施方案、任务分解表 | gongwen-implement |
| 整改专题民主生活会对照检查材料；民主生活会、组织生活会查摆问题的整改清单 | gongwen-party |
| 印发整改方案的通知、报送整改报告的请示或函 | gongwen-draft |
| 成稿核稿、排成 Word | gongwen-review、gongwen-format |
| 装有行业包时：乡镇街道迎检汇报和迎检自查；医院九项准则自查、院感与安全检查整改、等级评审自评；高校审核评估自评报告；中小学督导评估自评报告 | gongwen-grassroots、gongwen-hospital、gongwen-university、gongwen-k12（未安装的由本 skill 或上表对应 skill 处理） |

能调用其他 skill 的环境直接调用；目标 skill 没装，或在网页版使用的，会给你交接卡、“新开对话先粘贴 `dist/prompts/<skill 名>.md` 再继续”的说明和安装命令（见 `references/_shared/style/output-format.md` 第四部分）。

一次巡察整改的完整链路：gongwen-rectify 出整改方案和台账 → gongwen-draft 起草印发方案的通知 → 每月 gongwen-rectify 更新台账、写进展报告 → 集中整改期满写整改情况报告 → gongwen-review 核稿 → gongwen-format 出 docx。

## 成熟度

Stable。v1.0 真实模型评测（Sonnet 5.5，14 条用例）中，A 组（装 skill）期望通过率 97.5%（118/121），编造 0 次，触发评测正例 10/10、反例 10/10，详见 `evals/results/v1.0-benchmark.md`。整改方案、台账、进展报告、情况报告、自查报告的流程和状态口径已可用，评测用例见 `evals/`。已知局限：
- 对账脚本认得这些编号写法：“问题3”“问题3-1”“第3项问题”“台账第3项”，带前缀的“XC-03”“巡-1”“自-2”，以及合写的“问题1、4、5”“问题1和2”“问题2至4”“第1、4项问题”（合写的编号共用后面的状态文字）。报告里没有写编号的，只能核对统计句；
- 状态口径和完成率算法是本 skill 的约定，检查机关表样另有口径（如设“基本完成”栏）的，按表样填，脚本的相应提示由你判断；
- 状态判断靠关键词（“已完成整改”“正在推进”等），写法特别的句子会漏报或误报，结果需要人工复核；
- 各省、各部门的巡察工作规定和审计整改办法没有内置，你提供时以你给的原文为准。
