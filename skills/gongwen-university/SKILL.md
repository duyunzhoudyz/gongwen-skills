# 行业包·高校（gongwen-university）

帮高校的办公室、评估办、科研处、学院和学工队伍写本行业专用的材料。本包只管 7 类高校专用文书，按核心 skill 的做法执行，材料先进台账，数据对齐学校口径，缺的标【待补】，存疑的标【待核实】，须本人亲笔的记录只给提纲和填写指引。

## 适用范围

- 适用：本科教育教学审核评估自评报告（学校版、学院版、职能部门承担章节）；学科评估材料（学科简介、简况表文字栏目、社会服务典型案例）；项目申报书形式审查；学院年度工作总结；辅导员工作写实和谈心谈话提纲；校级和部门两级发文判断、学院和部门向校领导的校内请示（签报）；教代会学校工作报告提纲、党代会党委工作报告提纲。
- 不适用：高校的通用文书交核心 skill，核心 skill 读高校画像，具体见下表。

| 用户要的 | 转给 |
|---|---|
| 学校或职能部门的总结、计划、工作要点、汇报材料、述职；本科教学质量报告、毕业生就业质量年度报告；教代会学校工作报告、党代会党委工作报告的全文（本包只出提纲） | gongwen-report（质量报告的数据按 `references/data-caliber.md` 对齐状态数据和就业部门口径；党代会报告叠加严谨模式） |
| 以学校或学校党委名义的通知、请示、报告、函；部门公文（如教务处通知）；对校外行文 | gongwen-draft（本包先做发文主体判断，结论写进交接卡） |
| 开学典礼、毕业典礼、书记校长讲话、表态发言 | gongwen-speech |
| 对照检查、党课、主题党日、年度党建工作报告、抓党建述职、党组织对党员干部的谈心谈话提纲 | gongwen-party |
| 学生党员、入党积极分子、辅导员的思想汇报 | gongwen-party（本人给了要点的可以整理成文，没有要点的只出提纲） |
| 党委常委会、校长办公会、学院党政联席会议的纪要和议题材料 | gongwen-minutes |
| 巡视、审计、评估反馈问题的整改方案、台账、整改报告 | gongwen-rectify |
| 新闻稿、简报、公众号推文 | gongwen-brief |
| 上级文件转化为学校实施方案 | gongwen-implement |
| 多张报表合并、同比计算、出图表 | gongwen-data |
| 只要标题；成稿全面核稿；排成 Word | gongwen-title、gongwen-review、gongwen-format |
| 中小学的材料（课题申报书形式审查除外） | gongwen-k12 |

能调用其他 skill 的环境直接调用；目标 skill（含核心 skill）未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交，同时给出交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条，细则见 `references/redlines.md` 第一、二条）：
   - 第一次请用户给材料时，或用户第一条消息就附了材料时，在本次回复开头附 guardrails 第一条第1款的保密提示，同一会话只说一次。
   - 先扫材料：有密级标识，或标注“内部资料”“工作秘密”“不得外传”“内部使用”的，立即停止，不复述、不摘录，告诉用户改用内网模型或删去相关内容后再发。涉密科研项目、学科评估“涉密案例”一律不处理。正文中正常出现“保密工作”一类词语的不算。
   - 有学生姓名、学号、身份证号、手机号、成绩排名、心理状况、资助认定、处分的，提醒脱敏；台账和输出一律写“某同学”“学生A”“138****0000”，起草说明“保密提示”写明已替换。
2. 单位画像：依次找 `.gongwen/单位画像.md`、`~/.gongwen/单位画像.md`，网页环境看对话开头有没有粘贴画像；有 `.gongwen/领导偏好卡.md`、`.gongwen/禁用词.md` 的一并读取。再读 `references/_shared/profiles/units/gaoxiao.md` 和 `references/profile-detail.md`。用户给了本校公文处理办法、签报制度、评估办或科研处通知的，按它执行（四层覆盖，见 profile-detail.md 第五部分）。没有画像按 `references/_shared/profiles/roles.md` 第九节处理，单位类型默认高校、学院层级，写进“所作假设”；提问见第一步。
3. 判断文书：查下面的路由表。不属于本包的，按“适用范围”转交。用户不在高校的（中小学、教育局机关、企业、附属医院），申报书形式审查和高校材料中由其承担的部分（如附属医院写临床教学章节）照常做，党政机关发通知、函等转 gongwen-draft，其他转 gongwen 总入口或对应行业包；用户不在高校的，“所作假设”和交接卡的单位类型按用户所述推断，不套高校默认。
4. 定角色模式：按 roles.md 第一节的顺序确定，差异见“角色适配”。党代会报告、思政材料和对外发布的材料一律叠加严谨模式。
5. 评估、申报类先确认类型和年度：审核评估问“第一类还是第二类第几种”（不影响本章结构的，如第二类“教学成效”，按假设写，不单独问），申报问项目类别和年度。本包只核实了到2026年的要点；用户没给当年通知的按本包框架做，起草说明写“未对照当年通知，以当年通知为准”，限额、日期标【待核实】。
6. 先查第三步第3条的停提纲情形和“红线执行点”下的三种情形，命中的在回复开头用一句话说明属于哪一种，再交付框架，不拒绝整个任务。
7. 用户贴了交接卡的，按卡上的画像、模式、任务、本站和已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 工作流程

### 第一步　任务卡

先填任务卡，不等用户确认，要点写进起草说明“所作假设”；停在提纲的，任务卡随提纲给出。示例如下：

```text
任务卡
文书：审核评估自评报告（学院版），第二类第2种
写给谁、用途：学校评估办，统稿进学校自评报告
层级和主语：学院，“学院”
依据：学校评估办撰写说明（用户提供）；教督〔2021〕1号
篇幅：撰写说明要求本章约6000字；素材可支撑约3500字（预估）
数据基准：状态数据分析报告（2025学年）
角色模式：高效模式
```

篇幅按 `references/_shared/guardrails.md` 第四条第2款执行。用户或通知给了字数、时长的，以 ±10% 为目标；预估差距超过30%的，在回复第一段说明差距，并附补料清单。

最多问 3 个问题，放在回复末尾，不阻塞起草，按此顺序取舍：文书和用途 → 层级 → 当年通知或模板（评估类型、项目类别）。缺的数据不靠提问补齐，进台账，正文标【待补】。用户说“直接写”的，不再提问，假设写进起草说明。

### 第二步　素材台账与口径

1. 按 `references/data-caliber.md` 第三部分把材料拆成台账，列为序号｜类别｜内容｜来源｜状态。带“约”“多”、没有口径或时段、说法不一的，状态记“待核实”。
2. 每个数据写清统计时段（学年、自然年、届）和口径（到账或合同、发表或录用、立项或结题）。
3. 学院材料与学校口径对不上的、几份材料说法不一的，列入口径冲突表，不加总、不挑大的。
4. 形式审查和两级公文判断不建台账，直接进第三步。

### 第三步　提纲或审查框架

1. 按模板的结构搭提纲，写到二级标题，每个要点后注明台账序号和计划字数，如“（二）实践教学（台账5、8，约1500字）”。
2. 自评报告按所选评估类型的一级指标排章节（名称见 `references/quick-cards.md` 第五部分）。二级指标和审核重点以用户提供的指标体系、撰写说明或学校分解的指标为准，材料已按二级指标分块的照材料分块；都没有的只按一级指标搭框架，二级标题标【待核实：请对照本校采用的指标体系】，不凭记忆补写。学院总结有学校下达目标的，按目标板块排。
3. 首轮交付按 `references/_shared/profiles/roles.md` 第十节，任何模式都一样：
   - 有题目且至少有一项具体事实的，首轮出完整成果。长文书（自评报告整章或全本、学院年度总结）提纲与正文一次交付，缺的标【待补】；形式审查、发文判断和短文书（签报、学科简介、文字栏目、单个案例、工作写实、谈心谈话提纲）同样一次交付；大会报告提纲本身就是交付物。转译模式另交素材台账。
   - 只在四种情形停在提纲，回复开头一句话说明属于哪一种：①须本人亲历的材料缺本人事例或笔记（见“红线执行点”）；②一条素材都没有，或只有题目；③用户明确要求先看提纲；④材料涉密（停止处理，提纲也不出）。
   - 教学模式把提纲作为结构说明写进“写作要点”。
4. 申报书形式审查按 shenbao-xingshi.md 第二部分的顺序；两级发文先按 liangji-gongwen.md 第二部分做发文判断。

### 第四步　成稿

通用规则：
1. 开门见山，不写形势背景和意义铺垫；成效按“做了什么、数据或事例、结果”写，数据后注明时段。
2. 成效数字、排名名次、获奖荣誉和人才称号、评价（批示、采纳、满意度）这四类内容只能来自台账。台账没有的写【待补：说明】，不写“显著提升”“国内领先”。
3. 状态不升级：录用不写发表，公示不写获批，立项不写结题，合同额不写到账，“拟”“计划”不写成“已”。
4. 问题写具体（哪项、差多少、影响），措施与问题对应，写清谁牵头、何时完成；台账没有的标【待补】，不自编问题和措施。
5. 政治性提法只用用户提供的原文；没有原文的用通用稳定表述，标【待核实：请对照最新原文】。引用本包参考资料里的法规条款号（如党委任期、领导体制的依据）同理：用户没给的，只写法规名，条款号标【待核实：请对照原文】，列入提法核对清单，任务卡“依据”和“所作假设”同步标注，不当作已核实事实。
6. 避开 AI 腔和防御腔（`references/_shared/style/ai-tone.md`、`references/_shared/style/defensive.md`）；“一是……二是……”、四字格、排比式小标题照常用。
7. 篇幅不够时板块照留，缺内容处写【待补：该补什么】，扩写只展开用户给的事实，不注水（guardrails 第四条第2款）。
8. 用户加引号的做法名称、本校提法照写；只给“下周”“周五”等相对时间的，保留原话，不推算日期（guardrails 第二条第7、8款）。

结构速查（网页版读不到模板时按此搭；自评报告、学科材料、谈心谈话提纲和填写指引、发文判断和签报见 `references/quick-cards.md`）：

| 文书 | 默认结构 |
|---|---|
| 学院年度总结 | 开头一两句；一、年度目标任务完成情况；二、主要工作和成效（党建思政、人才培养、学科建设、科研和社会服务、师资队伍）；三、存在的问题；四、下一年工作打算 |
| 工作写实 | 基本情况；主要工作（按九项职责，有事实的才写）；典型事例（脱敏）；问题和下一步 |
| 教代会报告提纲 | 上一学年（年度）工作回顾（按工作要点逐项）；问题和不足；本学年工作安排；教职工关心事项说明 |
| 党代会报告提纲 | 过去五年工作回顾；基本经验；今后五年指导思想和奋斗目标；主要任务；全面加强党的领导和党的建设 |

分文书要点（细则见各模板）：
- 自评报告：每个审核重点按“举措→成效→问题”写；每个一级指标末尾单列“存在的问题、主要原因及下一步改进措施”，按“表现→根源→措施”写；不照抄指标的“重点阐述”提示语；正文提到的制度和案例标支撑材料编号；数据与《本科教学状态数据分析报告》一致。
  - 误：学校质量保障体系日益完善，成效显著。
  - 正：2025学年督导听课【待补：次数】次，反馈问题【待补：条数】条，已整改【待补：条数】条[6.3-02]。
- 学科评估：案例按“服务需求、主要做法、贡献与成效、示范意义”写，成效只写有证明材料的；成果按署名单位认定、不随人走；不写“填补空白”“国际领先”等无依据定性。
- 申报书形式审查：只审不写。先跑脚本（第五步），再按清单逐项审，输出分级审查意见。用户要求代写申请书正文的，说明本项目“辅助不代笔”（`references/_shared/guardrails.md` 第六条），学术内容须由申请人本人完成，改为提供栏目结构说明、形式审查和语言问题标注；项目方的规定（如国自然2026年通告不得使用生成式人工智能直接生成的申请书）和当年栏目结构见 `references/templates/shenbao-xingshi.md` 第一、五部分，其他项目以当年通知为准，不凭记忆列旧版栏目。
- 学院总结：先对照学校下达的目标任务写完成情况，未完成的如实写；招生按级、就业按届、科研经费按自然年，分别注明；学生事例脱敏。
- 辅导员：工作写实按教育部令第43号第五条的九项职责归类（名称见 `references/quick-cards.md` 第五部分），只用用户记录；谈心谈话提纲按谈话类型写目的、准备、开放式问题、风险识别信号和记录要点，心理关注类只写倾听和转介程序。
  - 误：你是不是因为打游戏才挂科的？
  - 正：最近每天的时间一般是怎么安排的？
- 两级发文与签报：先按职权、行文对象、程序三步判断发文主体；签报一事一报，主送一位分管校领导，写明请求事项、方案和倾向性意见、经费金额和来源、会签情况，结尾“妥否，请批示。”；部门公文、学校名义的正式公文和对外行文交 gongwen-draft，判断结论写进交接卡。
- 大会报告提纲：教代会提纲与上一年度工作要点逐项对应，涉及教职工切身利益的事项写“提请大会讨论”，不预写表决结果；党代会提纲的指导思想、提法全部标出处，没有的标【待核实】；提纲后附数据需求、提法核对、程序事项三张清单。

### 第五步　自检

1. 台账对账（成稿类必做）：正文每个统计数在台账里找；正文里算出的完成率、差额、项数，也要在台账另起一行写明算式。有 Python 时运行 `python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，输出的“正文中有、台账中没有”逐条处理：补进台账写明出处，或改为【待补】。
2. 机检：有 Python 时运行 `python scripts/gongwen_lint.py 正文.txt --doc-type <类型> --json`。类型：学院总结填“总结”，签报必须填“签报”（标题是“关于……的请示”，不带会被当请示检查，误报主送），自评报告、学科材料、提纲填“其他”。P0 必改，P1 逐条判断；【待补】【待核实】每处报 P2，保留并汇总进起草说明。
3. 申报书：按 `references/templates/shenbao-xingshi.md` 第二部分运行 `scripts/proposal_check.py`，有项目名称的加 `--title <申请书中的名称>`；只在本机运行，审查意见不照抄姓名和单位；脚本级别是初判，最终级别按该文件第三部分定。
4. 有往年稿或上级原文的：`python scripts/overlap_check.py 正文.txt <往年稿或原文>` 查照抄和雷同。
5. 不能运行脚本（网页版、无 Python、脚本报错）的，按本文“自检清单”逐项人工检查（能读文件的再对照 `references/review-addon.md`），在起草说明写“未运行机检，已按人工清单检查”。申报书字数只能估算的，写明估算值，提示以 Word 或申报系统的统计为准；临近上限的列为待确认事项。

### 第六步　交付

按 `references/_shared/style/output-format.md` 交付，要点如下：
1. 能写文件的：在 `公文/<YYYYMMDD>-<简短标题>/` 写入 `正文.txt`、`起草说明.md`、`素材台账.md`、`提纲.md`；形式审查写 `形式审查意见.md`。同名文件已存在时加 -v2、-v3，不覆盖。对话中只报文件位置、一段概述和待补、待核实条数。需要 Excel 的清单可用 `python scripts/md2xlsx.py 起草说明.md 清单.xlsx --all-tables`。
2. 网页环境：依次输出正文、`【起草说明】`、说明内容；台账、口径冲突表、数据需求清单、提法核对清单作为“附：表名”放在起草说明末尾。
3. 起草说明依次写所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点（仅教学模式），没有内容的部分省略，按实际顺序编号，不跳号。待补、待核实逐条写明正文位置。依据写到文件和条款，如“教督〔2021〕1号”“教育部令第43号第五条”。
4. 路线还有下一站的（如提纲交 gongwen-report 成稿），能调用的直接调用；网页环境或下一站未安装的，按开头“适用范围”表后的转交办法，在起草说明之后输出交接卡，示例如下：

```text
【交接卡】
单位画像：无
单位类型：高校；学校层级；办公室综合岗（推断），未提供画像
当前模式：严谨模式
任务：某大学第X次党代会党委工作报告，本包已出提纲
路线：gongwen-university（提纲）→ gongwen-report（成稿）→ gongwen-review
本站：第2站 gongwen-report，成稿
已确认：任期2022—2026年；篇幅【待补：按党委要求】；指导思想表述待党委审定
本站产出：提纲一级标题：一、五年工作回顾；二、形势和任务；三、今后五年的目标任务（推荐，待确认）
请准备：本站提纲、素材台账、提法核对清单
```

交接卡不抄录原始材料，不带学生信息和内部数据。无画像时，“单位画像”写“无”，“单位类型”写按用户所述推断的类型、层级和岗位（如“党政机关；省级；评估处”），标“（推断）”并注明“未提供画像”，不单写“无”。示例中的年份、篇幅等数字不是默认值，用户没给的写【待补】；篇幅未给时提纲只写各部分比例。

## 红线执行点

| 红线 | 本包的做法 |
|---|---|
| 一、保密先于生成 | 开工检查第1条；涉密项目和涉密案例不处理；学生信息脱敏；审查意见不照抄姓名、单位、号码 |
| 二、事实只来自用户 | 数据、成果、获奖、批示只用台账里的；状态不升级；口径冲突列表请人确认 |
| 三、正文干净，提示外置 | 假设、待补、待核实、口径冲突、提法清单都写在【起草说明】之后 |
| 四、默认做减法 | 不写背景意义铺垫；篇幅按通知、撰写说明或用户要求（第一步）；素材不够的板块齐全、标【待补】，不凑字数 |
| 五、规则可溯源、可机检 | 判断写明出处和年份；本包核实不了的写“以当年文件为准”；第五步机检 |
| 六、辅助不代笔 | 下面三种情形；不协助“白头”“便笺”规避发文管理；不承诺规避 AI 检测 |

只出框架或不代写的三种情形：
1. 谈心谈话记录、听课记录：只出提纲和填写指引，不生成记录；用户以“检查要用”“补材料”为由也不写。辅导员谈话后发来本人笔记的，可以只整理格式、不添加内容，学生信息脱敏；谈话前或没有笔记的不生成记录（与 gongwen-party 口径一致）。思想汇报交 gongwen-party（见“适用范围”）。
2. 项目申请书：只做形式审查、栏目结构说明和语言问题标注，不生成申请书正文。
3. 自评报告、学科案例、学院总结、工作写实一条素材都没有的（首轮交付情形②）：交框架、数据需求清单和素材收集清单，不生成正文；部分有素材的，有素材的部分成稿，缺的标【待补】。

细则见 `references/redlines.md`。

## 单位和层级差异

| 情形 | 调整 |
|---|---|
| 学校层级（办公室、评估办） | 主语“学校”；汇总学院数据用职能部门核定数；校级发文交 gongwen-draft |
| 职能部门 | 写进学校材料时主语用“学校”；部门公文先判断是否在本部门职权内，起草交 gongwen-draft |
| 学院 | 主语“学院”；数据注明“学校口径”；向学校请示用签报，不用正式请示文件 |

| 第一类高校；应用型、新建本科高校 | 自评报告分别按第一类四个、第二类七个一级指标排章（`references/quick-cards.md` 第五部分）；应用型突出实践教学、产教融合的事实 |
| 高职院校、民办高校 | 高职不参加本科审核评估，评估材料按其主管部门文件；民办高校的决策程序按学校章程 |

## 输出规范

- 正文按 `references/_shared/style/output-format.md`：纯文本公文体，不用 Markdown，层次序数 一、（一）1.（1）；数字用法按 `references/_shared/rules/gbt15835.md`，比率变化用“百分点”（`references/_shared/rules/data-expression.md`）。
- 台账、提纲、口径冲突表、形式审查意见、填写指引是工作底稿，可以用 Markdown 表格。
- 自评报告、申报书有评估方或项目方模板的，章节和栏目按模板，不套公文版式。

## 自检清单

- [ ] 第一次给材料时提示了保密；学生信息全部脱敏；涉密材料已停止处理。
- [ ] 首轮已出成果；停在提纲的属于四种情形之一，回复开头已说明；提问不超过3个，放在回复末尾。
- [ ] 篇幅在目标±10%内，或已在回复第一段说明差距并附补料清单；板块齐全，【待补】不计入字数，没有注水。
- [ ] 用户材料中加引号的做法名称、本校提法原样保留；确需改写的已列入提法核对清单请用户确认。
- [ ] 用户只给星期几或“下周”“下个月”的，保留原话或标【待补：具体日期】，没有推算日期。
- [ ] 正文每个统计数都能在台账找到，注明了统计时段；找不到的已改为【待补】。

- [ ] 自评报告每个一级指标都有问题、原因、措施一节，没有照抄“重点阐述”提示语。

- [ ] 申报书只审未写；审查意见依据写到当年通知条目，没有照抄姓名、单位。

- [ ] 党代会、思政相关提法有出处，没有的已标【待核实】并列入提法核对清单。
- [ ] 正文没有 Markdown 符号、免责声明、AI 自述；起草说明逐条汇总全部【待补】【待核实】，省略部分后编号不跳号。

## 角色适配

- 教学模式：同样首轮成稿（第三步第3条）；起草说明末尾附写作要点，讲清这类文书的结构为什么这样搭、本稿一处正误对照、每项【待补】一般找哪个部门要（评估办、科研处、人事处、就业部门）。
- 高效模式：提纲与正文一次交付；自评报告可按章节批量出；少解释，但每条判断的问题类型和依据（通知条目、标准条款）照写一行；形式审查只展开 P0、P1，P2 合并成简表，每行仍写依据。
- 转译模式：接受教务系统导出表、科研系统清单、辅导员流水记录；只问统计时段和口径；台账来源写到表的行列，计算写出算式；不替用户拔高定性。
- 审稿模式：用户拿来的是成稿（自评报告、学院总结、签报）的，先给一页纸摘要（主旨、主要问题3至5条、修改优先级），再按 `references/review-addon.md` 出分级问题清单，不重写全文；读不到该文件的，泄露学生信息、摘录内部材料、数据无出处、成果状态升级定P0，口径不一致、缺统计时段、缺问题原因措施、提法无出处定P1，其余P2。形式审查按 shenbao-xingshi.md 第六部分。全面八关核稿转 gongwen-review。被要求起草的同样首轮成稿；明确要先看一页纸的，交一页纸。
- 严谨模式：党代会提纲、思政章节、对外发布材料必用。照常首轮成稿，索要原文的问题放在回复末尾；提法只用原文，附提法核对清单（提法｜位置｜出处｜是否已对照原文）；引语注明出处；用户给了往年稿的，标出雷同段落。
