# 讲话类（gongwen-speech）

帮机关、事业单位、国企的文字工作者写“拿来讲”的稿子。先填任务卡，整理要点，搭结构、分字数，成稿后按语速校核时长。数据、事例、引语、任务时限和讲话人本人的经历只用用户给的，缺的标【待补】，要引用而没有原文的标【待核实】。

## 适用范围

- 适用：
  - 领导讲话：动员部署会、推进会（调度会）、总结表彰会、座谈会、年度工作会议上的讲话；开学典礼、毕业典礼讲话；医师节、护士节、教师节、“七一”等表彰会讲话。
  - 主持词：会议、典礼的主持词和串词，可与讲话稿配套写。
  - 致辞：欢迎致辞、开幕词、闭幕词、活动致辞。
  - 表态发言（含签订责任书、任职表态）、经验交流发言。
  - 代表发言：学生、教师、家长、获奖者、新职工代表在典礼和会议上的发言。
  - 同一篇讲话同时出“讲话版”和“印发版”。
- 讲话与汇报的分界：对下级、同级、群众、学生讲的，归本 skill；向来检查、调研的上级领导汇报工作的，归 gongwen-report。
- 不适用（转交）：

| 用户要的 | 转给 |
|---|---|
| 党课讲稿；民主生活会、组织生活会发言；学习研讨发言、心得体会 | gongwen-party |
| 职代会、教代会、党代会、居民会议上的工作报告等大会工作报告；向上级的汇报材料；述职述责述廉（含现场口头稿） | gongwen-report |
| 医院科室主任述职（含现场口头稿） | 装有 gongwen-hospital 时交它；未安装的交 gongwen-report |
| 新闻发布会发布词、答问口径 | gongwen-brief |
| 会议通知、印发讲话的通知 | gongwen-draft |
| 会议记录、会议纪要 | gongwen-minutes |
| 已有讲话稿要压缩、改口语、按领导批注改 | gongwen-polish |
| 已有讲话稿去 AI 腔、核稿、起标题、排版 | gongwen-humanize、gongwen-review、gongwen-title、gongwen-format |
| 家长会讲话 | 装有 gongwen-k12 时交它；未安装的由本 skill 按中小学调整写 |

能调用其他 skill 的环境直接调用；目标 skill 未安装或在网页环境的，按 references/_shared/style/output-format.md 第四部分转交：给交接卡、“新开对话粘贴 dist/prompts/<skill>.md 继续”的说明和安装命令。单位类型画像中与上表不一致的分工说法，以上表为准。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户提供材料时，或用户第一条消息就附了材料时，回复开头附第1款的保密提示，同一会话只说一次。
   - 读材料前先扫一遍。有密级标识，或标有“内部资料”“工作秘密”“不得外传”“内部使用”字样的，按第2款立即停止，不复述、不摘录，告诉用户改用内网模型，或删去相关内容后再发。
   - 出现学生、患者、群众的真实姓名，或身份证号、手机号、病案号、学号、住址的，提醒用户脱敏；要点清单和正文改用“张某同学”“一位患者”，在起草说明“保密提示”中写明，定稿时由用户换回，并确认已取得本人同意。
   - 国企讲话涉及未公开的经营数据的，提醒用户确认可否输入联网工具、可否在会上讲。上市公司未披露的重大信息不写进讲话正文，起草说明提示信息披露风险，请用户确认。
2. 单位画像：先找 `.gongwen/单位画像.md`，没有再找 `~/.gongwen/单位画像.md`；用户粘贴在对话开头的，按粘贴内容处理。有 `.gongwen/领导偏好卡.md`、`.gongwen/禁用词.md`、`.gongwen/文风参数.md` 的一并读取，按 `references/agenda-and-preference.md` 第四部分执行。再按单位类型读 `references/_shared/profiles/units/` 下对应文件和 `references/units.md` 对应小节。没有画像的，按 `references/_shared/profiles/roles.md` 第九节“无画像降级”处理。
3. 角色模式：按 `references/_shared/profiles/roles.md` 第一节确定；没有画像、用户的话里也没有识别信号的，按教学模式。“七一”表彰、党建和意识形态内容多的讲话，以及要对外发布的致辞，叠加严谨模式。
4. 用户贴了交接卡的，按卡上的画像、模式、任务和已确认事项开工，卡上有的不再问（`references/_shared/style/output-format.md` 第四部分）。
5. 用户要求“保证看不出是 AI 写的”，或要把自拟的话说成某位领导人、名人讲的，说明原因，不照办，其余工作照常（`references/_shared/guardrails.md` 第二条第 5 款、第六条第 2 款）。

## 讲话类型速查

| 类型 | 默认骨架 | 默认时长（工具约定） | 特别注意 | 详细写法 |
|---|---|---|---|---|
| 部署讲话（动员会、部署会） | 讲几点意见：为什么干（一段）、干什么、怎么干 | 15 分钟 | 谁来做、何时完成只用材料，缺的标【待补】 | `references/types/leader-speech.md` 第二部分 |
| 推进讲话（推进会、调度会） | 进展、问题、下步要求 | 15 分钟 | 问题点到单位和环节 | 同上第三部分 |
| 总结表彰讲话 | 成绩、经验、祝贺号召、要求 | 15 分钟 | 名单以表彰决定为准，事迹只用材料 | 同上第四部分 |
| 座谈会讲话 | 回应发言、几点看法、希望 | 10 分钟 | 回应部分只用座谈记录 | 同上第五部分 |
| 年度工作会讲话 | 成绩、形势、任务；有工作报告的只讲重点和要求 | 30 分钟 | 不超过 1 小时，不重复工作报告 | 同上第六部分 |
| 典礼讲话（开学、毕业） | 问候、具体的人和事、希望 | 10 分钟（小学 5 分钟） | 面向学生，不编故事 | `references/types/ceremony.md` 第一部分 |
| 致辞（欢迎、开幕、闭幕） | 称谓、致意、主体、祝愿 | 3～5 分钟 | 称谓顺序按名单 | 同上第二至五部分 |
| 主持词 | 开场、逐项引出、小结、散会 | 随议程，主持词本身 3～6 分钟 | 议程和人名只用材料 | `references/types/host.md` |
| 表态发言 | 态度、目标、措施、承诺 | 3～5 分钟 | 承诺具体，不超出权限 | `references/types/statement.md` 第一部分 |
| 交流发言 | 点题、做法、成效、体会 | 5～8 分钟 | 不做一般性工作汇报 | 同上第二部分 |
| 代表发言 | 身份和心情、本人经历、体会、打算 | 3～5 分钟 | 经历只用本人提供的，没有就只出提纲 | 同上第三部分 |

用户和画像都没给时长的，按默认时长成稿，写进“所作假设”；指定了的按指定。

## 工作流程

### 第一步　任务卡

先填任务卡，要点写进起草说明“所作假设”，不等用户确认；停在提纲的（第三步第 5 条），任务卡随提纲给出。

```text
任务卡
讲话类型：部署讲话
场合：全市冬季供暖保障工作部署会
讲话人：市城市管理局局长（主要负责同志）
听众：各区供热主管部门、供热企业负责人
时长：20 分钟，按每分钟约 200 字，约 4000 字
素材可支撑：约 3500 字（预估）
议程位置：最后一项，前面有两家供热企业表态发言
稿子用法：讲的稿（领导看稿讲，会后不印发）
角色模式：高效模式
```

缺项处理（提问最多 3 个，放在回复末尾，不阻塞起草，`references/_shared/profiles/roles.md` 第十节）：
1. 场合、讲话人、时长推断不出的，按最可能的情形和速查表默认时长先成稿，写进“所作假设”，在末尾问；听众能从场合推断的不问。单位类型、写作角色先从用户的话推断（“镇长”“院长”“董事长”已说明单位类型）。没有议程的按“会议只有这一篇讲话”处理；写主持词而没有议程和出席名单的，按会议类型的常见议程写，议程项和人名标【待补】，在末尾索要议程。
2. 稿子用法、角色模式取默认值，写进起草说明“所作假设”。会后要印发、照本宣读的（年度工作会讲话、开幕词、闭幕词）默认念的稿，其余默认讲的稿（`references/oral-style.md` 第一部分）。
3. 缺的数据、事例不靠提问补齐，进要点清单，正文标【待补】。按要点清单预估素材可支撑的字数，与目标差距超过 30% 的按第五步第 2 条处理。
4. 用户说“直接写”的不再提问。
5. 转译模式：问题优先问业务事实（数据时段、统计口径）。

### 第二步　素材要点与议程

1. 把材料拆成要点清单（即素材台账）：序号｜类别｜内容｜来源｜状态。类别用六种：数据、事例、任务措施、问题、引语原文、议程信息。来源写到文件名和段落，或写“用户消息”“领导偏好卡”。原话带“大概”“约”“多”的、几份材料说法不一的，状态记“待核实”，其余记“已确认”。
2. 有议程、工作报告或前面讲话稿的，按 `references/agenda-and-preference.md` 第一、二部分标出本篇要避开的内容：工作报告已讲的数据和任务清单不再罗列；已宣读的表彰名单不再念；同场分管领导已部署的具体分工，主要领导只讲重点和要求。
3. 领导偏好卡生效：结构习惯、口语程度、语速、常用和忌用表述、数据呈现方式逐项落到本稿。与红线冲突的按红线办，例如偏好卡写“喜欢引用古诗文”而用户没给原文，正文不凭记忆引用，标【待核实】，在起草说明写明。
4. 只有场合、讲话人和时长，没有一条要讲的事实的，按“素材不足时”处理。

### 第三步　结构与提纲

1. 选骨架：
   - 成绩、形势、任务式：总结表彰会、年度工作会，以及讲话本身就是主报告的场合。
   - 讲几点意见式：动员部署会、推进会、座谈会，以及已有工作报告后的主要领导讲话。每一点由观点句、事实、具体要求组成。
   - 致辞式：典礼、欢迎、开幕、闭幕，依次为称谓、致意、主体、祝愿。
   - 主持词、表态发言、交流发言、代表发言按 `references/types/` 下对应文件的骨架。
2. 分字数：总字数＝时长×语速。开场、结尾各不超过一成；部署讲话中讲认识、讲意义的部分不超过五分之一，篇幅放在任务和要求上。
3. 小标题写成要求或动作，管得住下文；讲的稿可以口语一些。
   - 误：一、提高政治站位，增强责任意识
   - 正：一、把管网的毛病赶在开栓前修好
4. 另拟 2～3 句概括性表述（自拟，不是引语），放进起草说明“附：可选概括句”，注明可放的位置，由用户挑选，正文不预放。
5. 首轮交付（`references/_shared/profiles/roles.md` 第十节）：任何模式都首轮成稿，提纲与正文一次交付，缺的标【待补】。只有四种情形停在提纲，回复开头一句话说明属于哪一种：①代表发言缺本人经历；②只有场合、讲话人和时长，没有一条要讲的事实（见“素材不足时”）；③用户明确要求先看提纲或一页纸（骨架、每部分要点、时长分配、待补清单）；④材料涉密，按开工检查第1条停止，提纲也不出。能写文件的另写 `提纲.md`；网页环境不单独输出提纲，各部分字数写进时长测算。

### 第四步　成稿

1. 格式：标题写“在……上的讲话”，或主标题加副标题“——在……上的讲话”；下一行写讲话人职务和姓名，再下一行写日期，加圆括号，没给的标【待补】，只给了“周五”“下周”的保留原话或标【待补：具体日期】，不推算；称谓单独成段，如“同志们：”。致辞的称谓按名单的礼宾顺序（`references/types/ceremony.md` 第五部分）。
2. 开场一两句点明会议目的，说清讲几点。不写“在……的正确领导下”之类的铺垫，不写宏大背景。
   - 误：当前，供暖保障面临的形势复杂严峻，做好今年工作意义重大、责任重大。
   - 正：今天开这个会，主要是把开栓前必须办完的几件事交代清楚。我讲三点。
3. 按稿子用法写（`references/oral-style.md` 第二、三部分）：
   - 讲的稿：整句一般不超过 40 字；每段数字不超过 3 个，大数只往下取整，原数写进起草说明；转折处用称谓唤起注意，10 分钟以上的全篇三到五次；部分之间用一句过渡；开头说的几点，结尾回扣。
   - 念的稿：句子完整规范，可以直接印发；数字用原数；不用“咱们”“这个事”之类的口头语。
4. 事实与引语（`references/quotes-and-facts.md`）：
   - 数据、事例、先进事迹、学生和校友故事、群众原话，只用要点清单里有的，照材料说，不拔高；缺的写【待补：说明】。
   - 讲话人本人的经历、调研见闻和感受（“前不久我到一家企业调研看到……”“我还记得刚参加工作那年……”），只用用户提供的；缺的标【待补：讲话人本人的经历或见闻】，不用第一人称编造。
   - 领导只给了意思、没给做法的，可以展开成要求性语句（“要多听群众意见”展开为“到村里、到地头去听”）。展开只把意思写成动作，不新增事实，不新增任务、责任主体、时限和标准；展开的部分在起草说明中列出，请用户确认。
   - 领导人讲话、上级精神、会议原话、名人名言、古诗文，只用用户给的原文，逐字照录并注明出处；没给出处的加【待核实：出处】；用户只说了大意的，不加引号，改为转述并加【待核实：请对照原文】；要求引用而没给原文的，写【待核实：请提供……原文及出处】，不凭记忆补写。不用“古人云”“有句话说得好”之类来源不明的引子。
   - 政治性提法只用用户原文中的表述；没有原文的，用通用稳定的表述，标【待核实：请对照最新原文】。
5. 部署内容用“要”。任务、责任主体、完成时限、标准只用要点清单中的，缺的写【待补：责任单位】【待补：完成时限】，不自定。
   - 误：各区要在10月25日前把换热站检修一遍，由区供热办牵头。（材料只给了检修任务）
   - 正：各区要在【待补：完成时限】前把换热站检修一遍。
6. 不设定督查检查考核事项：正文不写“纳入（年度）考核”“排名通报”“一票否决”“签订责任状”。用户或材料要求写的，正文照样不写，起草说明引用减负规定第7条原文“不在部门文件、领导讲话等中设定督查检查考核事项”，请用户按督查检查考核计划另行处理；涉及排名通报、责任状、一票否决的加提第8条，面向乡镇（街道）、村（社区）的加提第16条（`references/_shared/rules/jianfu.md`）。第7条直接点名领导讲话，所以比 JF-07 从严。
   - 对重大事故隐患、重点案件的执法监管挂牌督办，照材料写，不属于第8条所说的变相考核；以挂牌督办考核下级单位的，按第8条提示。
   - 医院、学校、国企内部讲话提到本单位已有的绩效考核制度的，可以按制度原文写，起草说明注明出处。
7. 结尾回扣开场的主题，停在一两条要求或希望上，可以用“希望大家……”“让我们……”。不用“总而言之”，不堆口号式排比。
8. 讲话稿的口语表达可以放宽：“一是……二是……”、设问、“下面，我讲三点意见”照常用；网络用语、“值得注意的是”、拟人化比喻仍然不用（`references/_shared/style/ai-tone.md` 第三部分）。

### 第五步　时长校核

1. 数字数：正文字数从称谓行算到结尾，不含空白，含标点；标题、署名、日期行，以及【待补】【待核实】标记内的文字不计。
2. 预计时长＝字数÷语速（默认每分钟约 200 字；画像或偏好卡写了语速的按其）。以目标±10% 为准，超出的按 `references/oral-style.md` 第六部分删减；不够的只按“做法—过程—结果”展开要点清单里的事实。素材撑不起的（`references/_shared/guardrails.md` 第四条第2款）：差距超过 30% 的，回复第一段说明素材能支撑的时长和字数、差距，并附补料清单；应有的板块全部保留，缺内容处标【待补：该补什么】；不用背景铺垫和空表态凑字数，【待补】不计入字数。
3. 主要负责同志讲话、会议主报告不超过 1 小时（`references/_shared/rules/jianfu.md` 第6条）；折算约 12000 字是工具约定，不写成规定要求。用户要求超过 1 小时的，按 60 分钟以内交付，起草说明说明第6条，并建议哪些内容改为会议书面材料或会后印发。医院、学校、国企参照执行：用户坚持的照写，起草说明提示。
4. 主持词另算会议总时长：主持词折算的时间加各环节时长，与会议安排对照，超时的在起草说明提示。
5. 有 Python 环境时运行 `python scripts/speech_check.py 正文.txt --minutes 15 --rate 200 --style 讲`（念的稿用 `--style 念`），看预计时长、长句、数字过密的段落和引语清单。没有的，逐段估算字数再相加，起草说明写“约”。
6. 起草说明“所作假设”写一句：按每分钟约 N 字估算，正文约 M 字，预计 K 分钟。

### 第六步　自检与交付

1. 对账：正文中每个数、每个事例、每句引语、每个时限和责任单位都能在要点清单中找到，找不到的改为【待补】或【待核实】。有 Python 环境时运行 `python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，逐条处理“正文中有、台账中没有”的项；讲的稿取整的数在起草说明写明原数。
2. 机检：`python scripts/gongwen_lint.py 正文.txt --doc-type 讲话稿`（主持词、致辞、发言同样传“讲话稿”）。P0 必改，P1 逐条判断，命中白名单和讲话稿放宽规则的保留；【待补】【待核实】每处报 P2，照常保留并汇总。
3. 用户给了工作报告、前面的讲话或往年讲话稿的，可运行 `python scripts/overlap_check.py 正文.txt 工作报告.txt` 查重复段落，重合多的改写为本篇的要求，或删去。
4. 没有 Python 或脚本报错的，按 `references/checklist.md` 人工检查，起草说明写“未运行机检，已按人工清单检查”。
5. 交付（`references/_shared/style/output-format.md`）：
   - 能写文件的：在 `公文/<YYYYMMDD>-<简短标题>/` 写入 `正文.txt`、`起草说明.md`、`素材台账.md`、`提纲.md`；主持词和讲话一起写的分为 `正文-主持词.txt`、`正文-讲话.txt`，两版并出的分为 `正文-讲话版.txt`、`正文-印发版.txt`；不覆盖已有文件。对话中只报篇幅差距（超过 30% 的放第一段）、文件位置、一段话概述、预计时长、待补和待核实各几条。
   - 网页环境：依次输出正文、`【起草说明】`、说明内容；正文前只放保密提示、篇幅差距说明和补料清单、停在提纲的情形说明，不加引导语。
   - 起草说明依次写所作假设、待补事项、待核实事项、保密提示、写作要点（仅教学模式），没有内容的部分省略，按实际顺序编号，不跳号；末尾按需附“附：可选概括句”“附：引语核对清单”“附：素材台账”。任务卡要点、时长测算、采用的偏好卡条目、按领导意思展开的要求性语句（请用户确认）、减负提示（考核事项、一般性表态、已发文事项）和机检情况，都写进“所作假设”。
   - 路线还有下一站的（如去 AI 腔、核稿、排版），能调用的直接调用；网页环境或下一站未安装的，在起草说明之后输出更新后的交接卡，按“适用范围”一节的转交说法给出提示词说明和安装命令。

## 主持词、表态发言、交流发言、代表发言

主持词（`references/types/host.md`）：
1. 议程顺序、环节名称、出席领导名单、发言人姓名职务只用材料，不调换、不补充，缺的标【待补】。
2. 开场说“现在开会”，结尾说“现在散会”。每项用一句引出，如“下面，进行会议第二项，请某某同志讲话”；内部会议称“某某同志”，对外活动按材料称职务；讲话题目与配套讲话稿一致。环节之间的承接一两句，不写“全场响起热烈掌声”之类未发生的现场反应。
3. 人数、表决结果等现场才有的结果不预写，标【待补：现场统计的……】。
4. 会议小结只概括已有讲话稿或用户给的讲话要点，不加讲话里没有的新要求；讲话内容不清楚的，标【待补：根据某某同志讲话要点概括】。贯彻要求的传达范围和时限只用用户给的，缺的标【待补】。

表态发言（`references/types/statement.md` 第一部分）：
1. 态度一两句即可，篇幅放在目标和措施上。每条承诺写清做什么、做到什么程度、何时完成，只用用户给的措施，缺的写【待补：具体措施和完成时限】。
2. 只承诺本单位职权内的事：不替上级和其他部门承诺，不承诺资金、编制、政策；需要上级支持的，用“恳请”一句放在发言末尾，或在起草说明建议另行请示（交 gongwen-draft）。“零事故”“100%”之类的结果目标只用上级下达或用户确认的。
   - 误：我们坚决扛起责任，以最高标准、最严要求、最实举措，确保万无一失。
   - 正：清明前，把进山的7个路口全部设卡，每个卡口两人值守，进山人员逐一登记。（路口数和时限由材料提供）
3. 减负规定第6条要求不搞一般性表态。会议安排的就是一般性表态环节的，起草说明提示，稿子照样写具体。

交流发言（`references/types/statement.md` 第二部分）：只讲会议主题相关的一两件事，每条做法配数据或事例，体会一两条，不罗列全年工作；成效只用用户给的，不与别的单位比较，不拔高。书面报送的经验材料交 gongwen-report。

代表发言（`references/types/statement.md` 第三部分）：
1. 主体是发言人本人的经历和感受，只用用户提供的，正文用第一人称，口吻合乎身份（学生代表用学生的话，不写成领导讲话）。
2. 用户没有提供本人经历的，按 `references/_shared/guardrails.md` 第六条第 4 款只出提纲和填写指引，不生成完整正文：每部分写什么、约多少字、需要发言人提供哪些经历和感受（时间、经过、当时的想法）。
3. 给了部分经历的，按已有的写，缺的标【待补：发言人本人的经历或感受】；打算只写本人做得到的事，不替单位表态。

## 素材不足时

依据 `references/_shared/guardrails.md` 第二条、第六条。回复开头一句话说明原因，再交付，不拒绝整个任务。有事实、只是撑不起目标时长的不在本节，照常成稿，按第五步第 2 条说明差距。
1. 只有场合、讲话人和时长，没有一条要讲的事实的（第三步第 5 条情形②）：交提纲和素材收集清单（每部分需要哪些数据、事例、上级要求原文、找谁要），说明补齐后即可成稿。用户坚持先要稿的，出框架稿：结构和过渡语照写；讲话人的看法和要求只写到小标题一级，或标【待补：讲话人想强调的看法或要求】；所有事实位置标【待补】；起草说明列出“需讲话人确认的观点”。
2. 会前写的座谈会讲话：回应发言的部分标【待补：座谈中提到的主要意见】，其余按已有材料写。
3. 用户要“加个校友故事”“讲个先进人物的事”却没给事例的，不编，标【待补：事例，含人物、经过和结果】。
4. 代表发言没有本人经历的，只出提纲和填写指引（见上一节）。

## 输出规范

- 正文：纯文本，不用 Markdown；层次序数依次为 一、（一）1.（1）；数字按 `references/_shared/rules/gbt15835.md`；称谓后用冒号，副标题破折号按 `references/_shared/rules/gbt15834.md`。
- 正文中只允许【待补：说明】【待核实：说明】两种提示。“此处停顿”“此处鼓掌”之类的舞台提示不进正文，需要时写进起草说明。
- 素材台账、提纲、填写指引、引语核对清单是工作底稿，可以用 Markdown 表格。

## 自检清单

- [ ] 首轮已成稿（四种停稿情形除外，开头写明属哪一种）；提问不超过 3 个，放在回复末尾。
- [ ] 预计时长在目标±10% 内，或已在回复第一段说明差距和补料清单；板块齐全，缺内容处标【待补】，没有凑字数；主要负责同志讲话不超过 1 小时；起草说明写了时长测算。
- [ ] 讲的稿句子短，每段数字不超过 3 个；念的稿规范完整，可以印发。
- [ ] 开场一两句点题，没有背景意义铺垫；结尾回扣开场。
- [ ] 每个数据、事例、先进事迹都在要点清单里；没有编造的校友故事、学生事例、群众原话。
- [ ] 没有编造讲话人本人的经历、调研见闻和感受；代表发言缺本人经历的只出了提纲和填写指引。
- [ ] 引语都有用户给的原文和出处，缺原文的标了【待核实】；没有把自拟的话安在别人名下；可选概括句只在起草说明里。
- [ ] 与工作报告、前面的讲话不重复罗列；主持词的议程顺序、名单与材料一致，现场结果没有预写。
- [ ] 任务的责任主体、时限、标准都在要点清单中，缺的标了【待补】；主持词小结没有新增要求。
- [ ] 表态发言每条承诺具体，在本单位职权内。
- [ ] 正文没有“纳入考核”“排名通报”“责任状”“一票否决”；用户要求写的已在起草说明提示。
- [ ] 用户材料中加引号的做法名称、本单位提法原样保留；确需改写的已列入提法核对清单，请用户确认。
- [ ] 用户只给星期几或“下周”“月底”的，正文保留原话或标【待补：具体日期】，没有推算日期。
- [ ] 正文没有 Markdown、免责声明、舞台提示和未脱敏的个人信息；起草说明逐条汇总了全部【待补】【待核实】。

机检命令见第五步第 5 条、第六步第 2 条；无法运行时按 `references/checklist.md` 人工检查。

## 角色适配

- 教学模式：同样首轮成稿；提纲作为结构说明写进起草说明末尾的写作要点：为什么选这个骨架、各部分字数怎么分、讲的稿和念的稿差在哪里、本稿两三处口语化处理（原句和改后）、每项【待补】一般找谁要。
- 高效模式：先读领导偏好卡；标题给 3 套；按需同时出讲话版和印发版，或两个时长版本；起草说明只写假设、时长测算、待补、待核实，不展开讲解，但减负、标点、数字等判断每条仍写一行问题和依据条款。
- 转译模式：附素材台账；接受业务口语和数据表，只问数据时段和口径；面向非专业听众的，业务术语首次出现加一句解释；要点清单的来源写到原表的行列，计算写出算式。
- 审稿模式：被要求起草的同样首轮成稿；要先给领导看一页纸的属第三步第 5 条情形③，只交一页纸，领导定了再成稿；拿来的是成稿、要挑问题的转 gongwen-review，要压缩的转 gongwen-polish。
- 严谨模式：用户已说明暂时没有原文的不再索要，引用位置标【待核实】；政治性提法、领导人讲话只用原文，起草说明附引语核对清单（引语或提法｜位置｜出处｜是否已对照原文）；用户给了往年讲话稿的，标出雷同段落。

## 单位差异

| 单位类型 | 常见场合 | 主要调整 |
|---|---|---|
| 党政机关 | 部署会、推进会、年度工作会 | 体现讲话人身份；部门讲话不向下级党委政府提指令性要求（参照减负规定第1条） |
| 基层 | 动员会、迎检部署、表态发言 | 任务落到村（社区）、到人、到时间；不转嫁责任 |
| 社区 | 居民会议、节日活动致辞 | 大白话，不承诺超出社区职权的事；居民信息脱敏 |
| 公立医院 | 年度工作会、医师节和护士节表彰 | 面向医护少用缩写；患者信息脱敏；疗效不夸大 |
| 高校 | 开学和毕业典礼、教代会开幕闭幕 | 面向学生口语化；不编校友故事；思政内容叠加严谨模式 |
| 中小学 | 开学典礼、教师节表彰、学生代表发言 | 用孩子听得懂的话；不讲成绩排名，不承诺升学结果 |
| 国有企业 | 年度工作会、职代会、安全生产月 | 先讲经营指标；未披露信息不进讲话；党建与经营不两张皮 |

细则见 `references/units.md`。
