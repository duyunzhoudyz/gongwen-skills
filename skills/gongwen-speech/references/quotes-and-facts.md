# 引语、提法与事例

讲话稿最容易出事的地方是引语和事例：把记不准的话安在领导人名下，把没发生的事讲成先进事迹。本文件把 `references/_shared/guardrails.md` 第二条落实到讲话稿的写法上。

## 一、只能来自用户的六类内容

| 内容 | 来源要求 | 缺失时 |
|---|---|---|
| 领导人讲话、上级精神、会议原话 | 用户提供的原文，照录，注明出处 | 【待核实：请提供……原文及出处】 |
| 政治性提法 | 用户提供的会议通知、学习材料、上级文件中的表述 | 稿中确需出现的，用通用稳定的表述，标【待核实：请对照最新原文】；用户要求引用的论述、会议精神不在此列，见第三部分 |
| 名人名言、古诗文、俗语典故 | 用户提供的原文和出处 | 不引用；偏好卡要求引用的，标【待核实：请提供拟引用的原文及出处】 |
| 事例：先进事迹、学生和校友故事、群众原话、患者故事 | 用户材料 | 【待补：事例，含人物、经过和结果】 |
| 数据：统计数、金额、比例、名次 | 用户材料，计算的写明算式 | 【待补：说明】 |
| 讲话人本人的经历、调研见闻、感受 | 用户提供 | 【待补：讲话人本人的经历或见闻】；不用第一人称编造 |

常见成语、四字格、公文惯用语不算引语，照常使用。

## 二、引语的处理

1. 用户给了原文和出处：引号内逐字照录，不改字、不删字；出处写在正文中（写法：某某在某某会议上指出：“……”），或写进起草说明的引语核对清单。
2. 给了原文、没给出处：照录，后加【待核实：出处】。
3. 用户凭记忆说了大意（“大概是这么说的”）：不加引号，改为转述，后加【待核实：请对照原文】；用户坚持用引号的，引语后加【待核实：请对照原文逐字核对】。
4. 用户要求引用、但一个字也没给：“要引用总书记关于生态环境保护的重要论述”之类，正文写【待核实：请提供……原文及出处】，不凭记忆补写任何文字。
5. 不把自拟的话写成引语，不加“古人云”“有句话说得好”“正如……所说”之类来源不明的引子。

误：总书记指出：“……”（用户没提供原文，凭记忆写出一段论述）
正：【待核实：请提供总书记关于生态环境保护重要论述的原文及出处】

误：古人云：“一年之计在于春。”我们一定要……（用户没提供，属于自加引文）
正：开年这两个月，要把……几件事办完。我们一定要……（删去引子，正文只用平实陈述；有记忆点的句子放进起草说明“附：可选概括句”）

## 三、政治性提法

1. 只用用户原文中的表述，不自行“更新”提法，不改写原文中的提法。
2. 没有原文时按下表写：

| 情形 | 写法 | 标签 |
|---|---|---|
| 用户要求引用某论述、某会议精神，没给原文（含“原文找不到，你先按你知道的写”） | 不写任何内容，不用通用表述顶替；用户已说找不到的不再催要 | 【待核实：请提供……原文及出处】 |
| 用户凭记忆说了大意 | 不加引号，转述 | 【待核实：请对照原文】 |
| 稿中自拟的句子确需政治性提法，没有原文 | 通用、稳定的表述，能不写就不写 | 【待核实：请对照最新原文】 |

3. 严谨模式下，正文中的每处政治性提法和引语都列入引语核对清单。

## 四、可选概括句

讲话需要有记忆点，但“金句”不能编在别人名下。做法：

1. 正文用平实的概括。
2. 另拟 2～3 句概括性表述，写进起草说明“附：可选概括句”，每句注明“自拟”和建议放的位置，由用户挑选后再放入正文。
3. 概括句只概括本稿已有的事实和要求，不引入新事实。

```text
附：可选概括句（均为自拟，非引语）
1. “暖气热不热，群众说了算。”建议放在第一部分末尾。
2. “管网多查一处，冬天就少一次抢修。”建议放在第二部分开头。
```

## 五、事例和人物

1. 事例只用用户提供的；用户说“加个故事”却没给的，标【待补】，起草说明写明要补的要素：人物（代称即可）、时间、经过、结果。
2. 学生、患者、群众用代称，如“张某同学”“一位患者”；起草说明提醒定稿时换回，并确认已取得本人同意。
3. 事例不加工、不拔高：材料说“全年带队巡河90多次”，不写成“守护了全县的一河碧水”。
4. 表彰名单、先进事迹以表彰决定和用户材料为准。
5. 讲话人本人的经历和见闻（“前不久我到一家企业调研看到……”“我还记得刚参加工作那年……”）只用用户提供的；没有的标【待补：讲话人本人的经历或见闻】。代表发言以本人经历为主体，没有素材时只出提纲和填写指引（`references/types/statement.md` 第三部分）。

误：前不久，我到一家供热企业调研，看到几位老师傅在零下十几度的管沟里抢修了一整夜。（用户没提供）
正：【待补：讲话人本人的调研见闻，含时间、单位和看到的情况】

## 六、引语核对清单

严谨模式必附，其他模式有引语时附。放在起草说明末尾：

| 序号 | 引语或提法（前十余字） | 正文位置 | 出处 | 是否已对照原文 |
|---|---|---|---|---|
| 1 | 某某会议提出的“三查三改”要求 | 第一部分第2段 | 用户提供的某某会议通知 | 已对照 |
| 2 | 【待核实】某某重要论述 | 第二部分第1段 | 待用户提供 | 未对照 |

有 Python 环境时，`python scripts/speech_check.py 正文.txt` 输出的引语清单可以作为这张表的底稿。

## 七、雷同提醒

用户提供了往年讲话稿、他人讲话稿或同场工作报告的，比对重复段落：有 Python 环境时运行 `python scripts/overlap_check.py 正文.txt 往年讲话.txt`；没有的，人工比对开头、结尾和各部分首句。重合多的改写，或在起草说明中提示。
