## 一、check_docx.py 检查项

级别含义同开发规范第 8 节：P0 必须改；P1 建议改；P2 提示。同类问题按段合并，消息中写“共 N 段”。“第 N 段”按文档中的段落序号计，空段也计数。

`--allow` 列出的检查项（逗号分隔，如 `--allow DOCX-050`）用于本单位制度明文规定、与国标不同的写法：命中时降为 P2，消息前加“按本单位制度保留：”，不计入 `--strict`；JSON 的 `notes` 中写明降级处数。不存在的检查项忽略并提示。build_docx.py、fix_docx.py 的 `--allow` 原样传给回读检查。

`--unit-fonts "仿宋=方正仿宋_GBK,小标宋=方正小标宋_GBK"` 用于本单位制度明文规定了字体的情形（角色限 gbt9704_params.json 中 `fonts.standard` 的键：仿宋、楷体、黑体、小标宋、宋体；未知角色或空字体名退出码 2）：该角色使用单位字体视为合规，使用国标字体按 DOCX-016 报；JSON 的 `unit_fonts` 为 `{角色: {unit_font, standard_font}}`，`notes` 写明“按单位规定使用字体”。build_docx.py、fix_docx.py 的 `--unit-fonts` 原样传给回读检查。

## 二、段落角色识别规则（build、check、fix 共用）

1. 版头：开头的 6 位以内纯数字行为份号；“绝密、机密、秘密”开头为密级；“特急、加急”为紧急程度；以“文件”结尾的短行为发文机关标志；“某发〔2026〕5号”这类行（可带“签发人：”）为发文字号，序号还没编、写成“某发〔2026〕【待补：序号】号”的同样识别。
2. 标题：首个非空行以“关于”开头或以文种结尾。首行没有以文种结尾、下一行是以文种结尾的短行时，两行合并为标题。都不符合时，首行较短且没有句末标点的，推断为标题并提示核对。
3. 副标题、题注：标题后以“——”开头的行为副标题；“（2026年1月5日）”这类行和讲话人行为题注。
4. 主送机关：标题后第一个以冒号结尾、不超过 80 字的行。讲话稿的“同志们：”按同样方式顶格排；称呼不紧跟标题（隔着几行题注，或在正文中间）时识别为“称呼”，同样顶格。讲话人行可含顿号、不超过 40 字，后面三行内有称呼的按题注识别。
5. 层次标题：行首“一、”（整行不含句号、不超过 50 字）为一级；“（一）”为二级；“1.”为三级；“（1）”为四级。文档含“1.1”“1.1.1”这类多级阿拉伯数字序号时，改按首次出现时的嵌套深度定层级（第一种序号为一级，其下新出现的写法依次为二、三、四级），序号文字不改，DOCX-033 提示改为标准序号。一级标题必须独占一行（同段时无法与以“一、”开头的正文长句区分，按正文排）；二至四级与正文同段时，第一个句号及以前的部分是标题。
6. 出席、请假、列席：以“出席：”“请假：”“列席：”开头的行。
7. 附件说明：主体末尾以“附件：”开头的行，及其后以“2.”“3.”开头的行。
7a. 命令（令）：红色短行以“令”结尾、下一行是“第12号”（或【待补：令号】）的，标志后的这一行是令号；有令号的文档没有标题，令号之后直接是正文。
7b. 附件页：docx 中独占一行的“附件”“附件1”段落是附件页标识，其后第一个非空段是附件标题；主文识别到标识之前为止，附件页另查。正文文件中用“【附件1】标题”分界行引出附件（只在 build_docx.py 读取）。
8. 表格：build_docx.py 读到的 Markdown 管道表格（表头行、分隔行、数据行），check_docx.py、fix_docx.py 读到的 docx 正文表格（不含版记表格），在识别时占一个位置，不参与标题、署名的判断；表格上一行以“表1”“附表2”开头，或以“表”“清单”“台账”结尾的短行（不超过 40 字、没有句号）为表题。
9. 从末尾倒推：“××××年×月×日印发”行为印发机关和印发日期；“抄送：”行为抄送；成文日期下一行的括号行或“联系人：”“联系电话：”行为附注；“××××年×月×日”行为成文日期；日期前不超过 3 行、不含标点的短行为发文机关署名。“特此通知”“妥否，请批示”等结束语按正文处理。
10. 简报（简报无国家标准格式，以下按常见做法识别，各单位以往期样式为准）：开头第一行以“简报”“动态”“信息”等结尾（指定简报版式时放宽为不带句末标点的短行）、红色，后接“第12期（总第68期）”“编印单位　日期”行的，是报头；“────”分隔线忽略；末尾的“报：”“送：”“发：”“抄送：”“（共印X份）”行是报尾（docx 中报尾是贴版心底部的表格）。报头、报尾之间，不带句末标点、不超过 50 字的短行是篇目标题（连续几行都算标题，末尾孤立的标题行按正文），标题下的括号注（如“（某街道供稿）”）是题注，其余按层次标题、表格、正文识别。报头、报尾要素不当作正文检查。

## 三、fix_docx.py 修改范围

| 改 | 不改 |
|---|---|
| 纸张、页边距、页脚距离、文档网格 | 文字内容（段首用于缩进的空格除外） |
| 各角色段落的对齐、缩进、行距、段前段后 | 发文机关标志的字号、颜色和位置 |
| 各角色文字的字体、字号；正文非黑色文字改黑色 | 正文中的表格（只统一版记表格的字体） |
| 署名和成文日期按是否盖章重新排列；正文最后一段至落款、末尾不带句号且独占一行的层次标题、表题设“与下段同页” | 页眉内容（有内容时在报告中提示） |
| 纪要第一个出席段前空一行（没有空段时用段前距） | 正文表格本身（只统一表题格式） |
| 页码（重设奇数页、偶数页页脚） | 信函格式的首页页眉页脚 |
| 上行文发文字号补足左缩进一字（不改文字） | 命令（令）的签发人职务和日期、联合行文的版头和署名表格、套打留白（只提示） |
| 附件页的标识、标题和正文格式（识别到“附件”“附件1”标识段时） | 附件标识与标题之间的空行（不增删，报告提示核对） |
| 多余空段压到 1 磅高（不删除） | 发文字号、日期等写法错误（列入报告，由用户确认后改原文） |
| `--keep-text`：以上格式照常调整，段首空格也保留 | `--keep-text` 时一个字都不改；标点、数字、写法问题只在报告“文字类问题”中列出，保存前核对文字与原文件一致 |
| 简报：篇间、标题后的空行，篇目标题、题注、正文、层次标题，报尾表格的字体 | 简报报头（名称、期号行、编印行和红线）保持原样，缺项由 check_docx.py 报出 |

## 四、annotate_docx.py 批注写法

1. 定位：先在各段（含表格中的段落）中逐字查找 excerpt；找不到时忽略空格再查。同一片段出现多处时，依次批注尚未批注的位置。
2. 批注内容：第一行“【级别｜关口｜类别】问题说明”，第二行“建议：……”，第三行“依据：……”；作者默认“gongwen-review”，缩写“GR”。
3. 列入未定位清单的情况：excerpt 为空；原文中找不到（跨段、已改动、在页眉页脚或文本框中）；所在文字含域代码、图片或超链接，无法拆分；同一片段的每一处都已有批注。
4. 只写批注，不写修订，不改正文文字。
5. 批注加在由送审稿排出的 docx 上：核稿意见的 excerpt 取自送审稿（JSON 的 `source_file`）。按核稿意见改过的终稿不加批注，excerpt 多已改掉，大部分条目会定位不到。

## 五、退出码与输出文件

| 脚本 | 输出 | 退出码 |
|---|---|---|
| build_docx.py | 不写 -o 时输出到输入文件同目录：正文.txt 输出“成稿.docx”，正文-××.txt 输出“成稿-××.docx”，其他输入输出“<输入文件名>.docx”（如 送审稿.txt 输出“送审稿.docx”）；已存在时加 -v2、-v3 | 0 成功；2 输入错误或缺少依赖 |
| check_docx.py | 屏幕输出，--json 为机检 JSON | 0；--strict 且有 P0 时 1（`--allow` 降级的不计）；2 输入错误 |
| fix_docx.py | “原名-修复.docx”和“原名-修复-修复报告.md” | 0 成功；2 输入错误 |
| annotate_docx.py | “原名-批注.docx”和“原名-批注-批注报告.md” | 0 成功；2 输入错误或 python-docx 低于 1.2.0 |
| preview_docx.py | “原名-预览/”下的 PDF 和逐页 PNG（需 LibreOffice，PNG 另需 pymupdf）；本机缺任一标准字体或无法检测时拒绝渲染，无绕过选项 | 0 完成或找不到 LibreOffice（只提示）；2 输入错误或转换失败；3 缺标准字体或无法检测，拒绝渲染 |
| gw_fonts.py | 屏幕输出各标准字体是否已安装、缺失时的获取与安装方法，`--json` 为结构化输出 | 0 标准字体齐全；3 缺字体或无法检测；2 参数文件读取失败 |

build_docx.py、fix_docx.py 的字体核对结果（`font_status`、`font_method`、`missing_fonts`、`unverified_fonts`、`font_notice`、`unit_fonts`）并入 JSON 报告，屏幕报告和修复报告开头有醒目的“字体缺失”区块；文件中一律写入标准字体名（指定了 `--unit-fonts` 的角色写入单位字体名，同样要求本机装有），不降级、不替代。

脚本只读写本地文件，不访问网络。原文件一律不修改。
