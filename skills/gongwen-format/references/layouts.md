## 一、上行文发文字号居左空一字

- 依据：7.2.5“上行文发文字号居左空一字，与最后一个签发人姓名处在同一行”；7.2.6 签发人居右空一字。
- 生成：红头版式的请示、报告（文种按标题末尾判断，另含议案）。发文字号段左缩进一字，签发人用右对齐制表位排在同一行、右空一字。多个签发人时，前面几行只排姓名，最后一行与发文字号同行。不再用行首制表符定位，改用段落左缩进一字。
- 检查：DOCX-056（P1）。发文字号的左缩进、行首制表符或空格合计不是一字（容差半字），或居中、居右，报问题。行首制表符加制表位、行首一个全角空格的旧写法也认作空一字。
- 修复：fix_docx.py 对上行文发文字号补足左缩进，不改文字。

## 二、fix_docx.py --keep-text（内容别动）

用户说“内容别动”“一个字都别改”“只调格式”“不要动文字”时使用：

```text
python scripts/fix_docx.py 旧稿.docx --keep-text
```

- 照常调页面、字体字号、行距、缩进、页码、署名位置。
- 不改任何文字：不删段首空格，不改标点、数字、文字写法。用空格缩进的段落保留空格，首行缩进设为 0（缩进仍由空格承担，不叠加）。
- 标点、数字、发文字号写法、层次序数、附注括号、残留标记等要改文字才能消除的问题，只在修复报告的“文字类问题（按 --keep-text 未改动，需人工处理）”中列出，由用户自行决定。
- 保存前脚本核对正文段落和表格的全部文字与原文件一致，不一致则中止，不保存新文件。
- 默认（不加该参数）时，fix_docx.py 只删除段首用于缩进的空格，不改标点和文字。
- build_docx.py 同样支持 `--keep-text`（`python scripts/build_docx.py 正文.txt --keep-text`）：不补主送机关的全角冒号、不给附注加圆括号、不去段首空格（空格缩进的正文段落保留空格，首行缩进设为 0）、不转换版式信息中的日期写法、不按附件页补写“附件：”说明行，附件说明和抄送照原文排；这些问题列入报告的“文字类问题（按 --keep-text 未改动，需人工处理）”。缺失要素仍写【待补】（那是补要素，不是改用户的文字）。
- 保存前核对：输入的每一行文字（去掉行首行尾空白）、表格单元格文字都须原样出现在文档中，已还原段首空格的行须逐字一致；不一致则中止、不保存，并列出不一致的文字（标题分行时按相邻段落拼接比对）。简报版式的期号行等会被重新排写的内容，在该模式下会触发中止，此时请改用 fix_docx.py --keep-text 处理已排好的 docx。

## 三、命令（令）格式

依据 10.2（格式要点见 gbt9704.md 第七部分）。用法：

```text
python scripts/build_docx.py 正文.txt --meta 版式信息.json --layout 命令
```

版式信息：

```json
{"版式": "命令", "发文机关标志": "某市人民政府令", "令号": "第12号", "签发人职务": "市长", "签发人姓名": "张某", "成文日期": "2026-10-01"}
```

正文文件首行可直接写“第12号”（识别为令号），末尾写“市长　张某”和日期行，也可全部写在版式信息中。“令号”只写数字时补成“第×号”。

| 要素 | 排法 | 依据 |
|---|---|---|
| 发文机关标志 | 发文机关全称加“令”或“命令”，居中，红色小标宋，上边缘距版心上边缘 20 mm | 10.2 |
| 令号 | 标志下空二行，居中，三号仿宋 | 10.2；字体为 5.2.2 |
| 正文 | 令号下空二行；没有标题、主送机关和红色分隔线 | 10.2 |
| 签发人职务、签名章 | 正文下空二行；签名章右空四字，签名章左空二字标签发人职务 | 7.3.5.3 |
| 签名章占位 | 按三个字宽估算；版式信息给了“签发人姓名”的，姓名排在占位处，只是排印占位，不代替签名章；没给的只排职务、留白 | 实践值 |
| 成文日期 | 签名章下空一行，右空四字（用左缩进定位） | 7.3.5.3 |

- 签名章不生成图片；联合发布等多人签发的令只排第一位，其余在报告中提示。
- 不加盖印章（`seal_default` 中命令为否）；页码同其他版式。
- 检查：DOCX-120（标志不是“令”结尾或缺标志）、121（标志不居中）、122（缺令号或令号不居中）、123（标志与令号间不是空二行）、124（令号与正文间不是空二行）、125（成文日期不是右空四字，或缺成文日期）、126（职务与日期间不是空一行，P2）。自动识别：红色标志以“令”结尾且下一行是令号的，判为命令版式。
- fix_docx.py：识别为命令版式时只调字体字号、居中和段间空行，不重排签发人职务和日期（报告“未处理”中提示用 build_docx.py 重排）。

## 四、附件另面编排

依据 7.3.7（要点见 gbt9704.md 第四部分）。用法：在正文文件落款（成文日期、附注）之后，用分界行引出每个附件：

```text
……请认真贯彻落实。

某市应急管理局
2027年1月8日

【附件1】冬季消防安全检查表
一、检查内容
……
【附件2】整改通知书（样式）
……
```

- 分界行格式：`【附件1】标题`；只有一个附件时可写 `【附件】标题`（标识为“附件”）；多个附件没写序号的按出现顺序编号并提示。标题没写的写【待补】。
- 附件正文用同正文的规则排：层次标题（一、（一）1.（1））、简单管道表格和表题。
- 版面：每个附件另起一页（标识段“段前分页”）；第一行顶格“附件”或“附件1”，三号黑体；空一行；第三行居中附件标题（二号小标宋，较长时自动分行）；标题下空一行排正文。全文同一节，页码连续（7.5）；版记（抄送、印发）排在最后一个附件页的版心底部，位于所有附件之后。
- 附件说明与附件对应：正文没写“附件：”说明的，按附件页标题生成；写了的，与附件页的顺序号、名称、个数逐一核对，不一致报警告，不改文字。
- 附件标识、标题、位置的参数：标识三号黑体（7.3.7），标识与标题间空一行（7.3.7，标题在第三行），标题下空一行（实践值）。
- 不支持：附件不与正文一起装订时，在附件左上角第一行编发文字号再标“附件”（7.3.7 末句），需人工处理。
- 检查：DOCX-130（标识不是三号黑体或未顶格）、131（附件前没有分页）、132（标题缺失、未居中或不在第三行）、133（正文缺附件说明，或说明与附件页的顺序号、名称、个数不一致）、134（附件所在节重新起页码）。附件页的正文按主文规则查字体、字号、缩进、行距。
- fix_docx.py：识别“附件”“附件1”独占一行的段落为附件页，调标识（黑体顶格、段前分页）、标题（居中）、正文格式；标识与标题间的空行不增删，报告提示核对。

## 五、联合行文版头与署名

依据 7.2.4（联合行文版头）、7.3.5.1（联合行文加盖印章）。用法：版式信息中把“发文机关标志”写成数组，主办机关在前；发文机关署名同样写数组：

```json
{"版式": "红头", "发文机关标志": ["某市应急管理局", "某市公安局"], "发文机关署名": ["某市应急管理局", "某市公安局"], "印章": "是", "联合行文": "是"}
```

| 要素 | 排法 | 依据 |
|---|---|---|
| 发文机关标志 | 联署机关名称自上而下并列，主办机关在前，红色小标宋，名称在列内居中；“文件”二字置于名称右侧，以联署机关名称为准上下居中（两列无框线表格，右列单元格垂直居中） | 7.2.4 |
| 字号 | 按最长名称自动取：名称列宽加“文件”列宽不超过版心的 92%，最大 36 磅（三个及以上机关最大 28 磅），最小 18 磅 | 实践值 |
| 位置 | 标志上边缘距版心上边缘 35 mm，之后的发文字号、红线、标题同单一机关红头 | 7.2.4 |
| 署名（加盖印章） | 署名按机关顺序各占一格并居中，每行最多并排 3 个，超过换行；每格宽不小于印章直径 42 mm（印章互不相交），总宽不超出版心；印章一一对应下压署名 | 7.3.5.1；印章直径 42 mm 与每行 3 个为实践值 |
| 成文日期 | 署名下一行，右空四字 | 7.3.5.1 |

- 署名并排表格只在“联合行文”为“是”，或红头版式的发文机关标志写了多个机关时启用；其他场合多个署名仍按原来的竖排处理并提示。
- 信函、纪要版式写了多个机关时只取主办机关，并提示。
- 检查：DOCX-140（版头少于两个机关名称，或文字不是红色）、141（“文件”不在名称右侧或未上下居中）、143（署名格宽小于印章直径）、144（署名表格超出版心）。版头、署名表格用 `tblCaption` 标记，回读时不当作正文表格或版记。
- 印章不生成图片，加盖位置需人工核对。联署机关多、名称很长时，版头可能占较多版面，打印核对。

## 六、预印红头纸套打

用于单位已有预印红头纸（红色标志和红线已印好）的场合。用法：

```text
python scripts/build_docx.py 正文.txt --meta 版式信息.json --overprint
python scripts/check_docx.py 成稿.docx --overprint
```

也可在版式信息中写 `"套打": "是"`。只支持红头版式，其他版式忽略并提示。

- 不输出红色发文机关标志（联合行文也不画名称表格）和红色分隔线。
- 留白：版心上边缘到发文字号上沿的高度，默认与正式红头版头完全一致（标志上边缘距版心上边缘 35 mm，加标志行高，加标志下空二行），所以发文字号、签发人、标题、正文的位置与正式版头相同。标志行高按“发文机关标志”文字估算；没写标志文字时按 36 磅字号估算（实践值）。红线不画，但其占的空间（线与文字间距加线宽）保留。
- 预印纸的版头尺寸与默认不同时，在版式信息写 `"套打版头高度": 62`（毫米，发文字号上沿距版心上边缘），按预印纸实际尺寸留白。报告写明发文字号上沿的实际位置。
- 发文字号、签发人、份号、密级等黑色要素的位置、字体同正式版头；上行文的发文字号居左空一字同样适用。
- 检查：DOCX-150（套打稿里有红色文字、红色分隔线或联合行文版头表格）、151（发文字号上沿距版心上边缘小于 44 mm，会压到预印版头；44 mm 为推算值：35 mm 加 22 磅×1.2 的最小标志行高）。
- 正式打印前先用预印纸试印，核对发文字号与预印红线的位置；各家预印纸版头尺寸不一，以套打版头高度为准。

## 七、脚本行为细节（从 SKILL.md 移入）

1. 标题分行：二号字每行约 20 字，超过时脚本在词意完整处自动分行，上行不短于下行（7.3.1），并在报告中写出分行结果；断行不合适的，在版式信息“标题”中用 `\n` 指定，或在正文文件中把标题分成两行；用户分好的行不再改动。
2. 表格：正文中的 Markdown 管道表格（表头行、分隔行“|---|”、数据行）转成全框线、表头加粗、仿宋四号（版式信息可改“表格字体”“表格字号”）、与版心同宽的 Word 表格；上一行是“表1　××情况表”这类表题的，居中排在表格上方。不支持合并单元格；缺分隔行的竖线行不转换，报告会提示。已有 docx 中的正文表格，fix_docx.py 不调整，check_docx.py 只查宽度和字体字号。
3. 版头位置：发文机关标志距版心上边缘 35 mm、红线在发文字号下 4 mm，由段前距和段落边框近似实现，误差约 1～2 mm，正式印发前打印核对。
4. 落款不单独成页：正文最后一段（或附件说明）、空行、署名、成文日期、附注依次设“与下段同页”，不带句号、独占一行的层次标题和表题同样处理；换页时至少一行正文随落款下移，末页可能留较多空白。7.3.5.5 允许空间不足时调整行距、字距，脚本不自动压缩，需要时人工微调。
5. 署名和日期：不加盖印章时用左缩进定位，日期首字比署名首字右移二字是精确的；加盖印章时二者中心对齐是精确的，日期“右空四字”按半角数字 0.5 字估算，LibreOffice 下实测约右空 3.4 字。
6. 批注只按 excerpt 文字定位，跨段、在页眉页脚或文本框中的意见无法定位；不写修订。
7. 段落角色靠文字模式识别。没有“关于”、不以文种结尾的标题，或不按“一、（一）1.（1）”编号的层次，可能认错，须看识别结果。
8. 版记用浮动表格固定在最后一页版心底部。WPS 部分版本可能不按底端定位，改动正文后要重新检查；版记页落在单页、需要加空白页的情况（7.5），脚本不处理，需人工调整。
9. 不生成印章、院徽、签名章图片，只预留位置；联合行文印章的对应关系只排到每格一个署名，加盖位置需人工核对。
10. 标题自动分行按常用词表找断点，须看分行结果。
