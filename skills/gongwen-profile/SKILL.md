# 单位画像与文风学习（gongwen-profile）

把"这个单位怎么写材料、这位领导喜欢怎么改"记成四个纯文本文件，放在 `.gongwen/` 目录，其他 gongwen skill 起草、改稿、核稿时读取。本 skill 只负责建档、学习和维护，不起草、不改稿。文件里的每一条都来自用户的回答、用户提供的制度文件或稿件；不存人名电话，不存原文段落。

## 适用范围

- 适用：
  1. 完整建档：分轮问卷，或从本单位公文处理办法、议事规则、签报管理办法和已发的红头文件中提取字段，生成完整版单位画像；把总入口建的简版画像补全。
  2. 文风学习：读 3～10 篇本单位历史稿，得出文风参数。
  3. 花脸稿学习：原稿和领导改稿两份，或一份带修订痕迹、批注的 docx，归纳领导偏好卡；录入用户或领导本人口述的偏好；把改稿记录中反复出现的偏好归纳成条目。
  4. 禁用词管理：增、删、改禁用和慎用表述。
  5. 画像体检：查字段缺漏、与单位类型默认值的差异、可能过期的信息、隐私问题。
- 不适用（转交）：

| 用户要的 | 转给 |
|---|---|
| 第一次用，只想用 3 个问题建简版画像；说不清要写什么 | gongwen |
| 照本单位文风或领导口味起草 | 对应起草 skill：法定公文 gongwen-draft，总结汇报 gongwen-report，讲话 gongwen-speech，党建材料 gongwen-party，信息简报 gongwen-brief，纪要 gongwen-minutes |
| 按领导批注把稿子改好；压缩、润色 | gongwen-polish（改完可回到本 skill，把批注归纳进偏好卡） |
| 去 AI 腔、去防御腔 | gongwen-humanize、gongwen-direct |
| 核稿 | gongwen-review（目前只读单位画像，暂不逐条比对禁用词） |

学完偏好后用户顺口说"那你照这个把稿子改了"的，说明改稿交 gongwen-polish，本 skill 不顺手改稿。

## 四个文件

| 文件 | 内容 | 模板 |
|---|---|---|
| `.gongwen/单位画像.md` | 单位类型、发文体系、决策程序、写作角色、篇幅偏好、红线等 17 个字段 | `references/_shared/profiles/profile-template.md` 第一部分完整版 |
| `.gongwen/领导偏好卡.md` | 一位领导一张卡：讲话风格、用词、忌用、数据呈现、篇幅、引用习惯、历次改稿记录 | 同上第二部分 |
| `.gongwen/禁用词.md` | 禁用、慎用表述 | 同上第三部分 |
| `.gongwen/文风参数.md` | 各类文书的量化参数和表述习惯 | `references/style-params.md` 第一部分 |

单位画像所有 gongwen skill 都读；其余三个文件由起草、改稿类 skill 按各自的开工检查读取，详见各 skill。

读写约定（四个文件通用，细则见 `references/maintenance.md` 第一部分）：
1. 位置：先找工作目录下的 `.gongwen/`，再找 `~/.gongwen/`；网页环境看对话开头有没有粘贴。新建时默认放工作目录；用户说"所有项目通用"的放 `~/.gongwen/`。用户直接给出画像文件（上传或指定路径）的，改完写回原处，备份照第 4 条放 `.gongwen/历史/`，并问用户是否移入 `.gongwen/`。
2. 先读后写，不整份覆盖。原来没有的文件可以直接新建，写完报位置；已有文件只追加或修改相关条目，先出变更单，用户同意后再写。用户已明确说了改哪一项、改成什么的，视为同意，列出变更单后直接写；由本 skill 推断出的改动仍要先问。
3. 变更单一条一行：`［修改］单位画像·写作角色和默认模式：院办秘书；高效模式 → 党办干事；严谨模式（来源：用户告知，2026-10-16）`。新增写［新增］，删除写［删除］。
4. 改前备份：Agent 环境修改已有文件前，复制到 `.gongwen/历史/<原文件名>-<YYYYMMDD-HHMM>.md`，不覆盖已有备份。
5. 每个文件末尾保留"## 维护记录"，每次改动追加一行：日期、做了什么、来源。体检据此判断是否过期。
6. 领导偏好卡一位领导一张，同放一个文件，每张以"# 领导偏好卡（职务）"开头，不写姓名。
7. 工作目录是 git 仓库的，提醒用户把 `.gongwen/` 加进 .gitignore，加不加由用户决定。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户提供材料时，或用户第一条消息就附了材料时，在本次回复开头附一句："请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。"同一会话只说一次。
   - 读制度文件、历史稿、花脸稿前先看每份的首尾几行和页眉页脚：带有密级标识（"秘密★""机密★""绝密★"，或版头标注的密级和保密期限），或标注"内部资料""工作秘密""不得外传""严禁外传""内部使用""内部参阅""仅供内部参考"、写明"未公开""未披露"的，这一份立即停止，不摘录、不统计，告诉用户涉密信息不得输入联网 AI 工具，其余各份照常。用户说明以下情形之一后可以继续：在单位内网部署、允许处理此类材料的模型上使用（带密级标识的国家秘密，只能在经批准的涉密信息系统中处理）；已删除相关内容；标识系误加或材料已公开。正文中提到"保密工作""涉密人员管理"之类的词语不算。
   - 脚本没有跳过，不代表没有标注，仍须按上一条自己看。
   - 有身份证号、手机号、病案号、学号、家庭住址、真实姓名的，提醒用户先脱敏。学习照常进行，四个文件里一律不出现这些内容，例证改写成"张某""138****0000"，在起草说明"保密提示"中写明。
   - 有 Python 时可先运行 `python scripts/gongwen_lint.py <文件> --checks privacy --json` 辅助扫描，输出已脱敏。它不识别不带标签的人名（如"院长孙某某"），也读不到修订稿中新增的文字，这两类看 draft_diff.py 的输出或人工通读。
2. 读已有文件：按读写约定第 1 条找齐四个文件，先用一行告诉用户读到了什么，例如"已读取：单位画像（公立医院，已填 12/17 个字段）；领导偏好卡 1 张（院长）；禁用词 6 条；文风参数无"。
3. 定功能，一次做一项；一句话里有几项的，按建档、文风、花脸稿、禁用词、体检的顺序依次做：

| 用户的话 | 功能 |
|---|---|
| "建个完整画像""把画像补全""这是我们的公文处理办法" | 一　完整建档 |
| "学学我们单位的文风""这几篇是我们以前的稿子" | 二　文风学习 |
| "领导改过的稿子你学一下""这是带修订的版本""花脸稿""把改稿记录归纳一下" | 三　花脸稿学习 |
| "记住局长不爱用'着力'""偏好卡里给院长加一条" | 三　口述偏好录入（功能三末） |
| "以后别用某词""把某词去掉""加个禁用词" | 四　禁用词管理 |
| "看看画像有什么问题""画像还缺什么""是不是过时了" | 五　画像体检 |

4. 角色模式（`references/_shared/profiles/roles.md` 第一节），依次取：用户指定；画像"写作角色和默认模式"；从话语推断（新人、第一次写→教学，秘书、专职笔杆子→高效，业务科室→转译，领导本人→审稿，党务、组织、纪检、宣传岗→严谨）；以上都没有的用教学。本 skill 中的差异见"角色适配"。
5. 网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务、已确认事项开工，卡上已有的不再问（`references/_shared/style/output-format.md` 第四部分）。
6. 用户要求在偏好卡里记领导的脾气、对人的评价，或要求"学完保证查不出是 AI 写的"，说明原因，不按此办，其余照常（`references/_shared/guardrails.md` 第六条）。

## 六条红线的落实

| 红线 | 本 skill 的做法 |
|---|---|
| 一、保密先于生成 | 开工检查第 1 条；四个文件不存人名、电话、证件号和患者、学生信息；领导只写职务；修订人姓名不记录 |
| 二、事实只来自用户 | 字段值只来自用户回答、制度文件（注明条款）和样本统计；问不到的留空，不拿单位类型默认值冒充本单位情况；存疑的写【待核实：说明】 |
| 三、正文干净，提示外置 | 文件里只放画像内容；假设、待补字段、变更单、保密提示写进【起草说明】 |
| 四、默认做减法 | 每轮最多 3 问，能从材料提取的不问；偏好卡只记有例证的条目；文风参数只记会影响起草的参数 |
| 五、规则可溯源 | 每个字段注明来源（用户告知、某办法第几条、几篇样本统计）；本单位规定与国标不同的，注明国标条款 |
| 六、辅助不代笔 | 只学习和记录，不起草、不改稿；文风参数不存原文段落，偏好例证不超过 20 字 |

## 功能一　完整建档

### 第一步　定来源

用户给了制度文件（公文处理办法、议事规则、签报管理办法、发文目录）或历史文件（已发的红头文件）的，先提取再用问卷补缺；没给的直接问卷。

### 第二步　从制度文件和已发文件提取

1. 制度文件按 `references/intake.md` 第二部分（一）的"字段与条文"对照表逐项找。找到的写入字段，括注来源，如"X医发〔2026〕N号（《某医院公文处理办法》第十二条）"。
2. 已发文件按 intake.md 第二部分（三）只看版式：版头取发文机关标志，发文字号取格式（序号写 N），版记取印发机关；来源写"据 2025 年已发文件版式"，只有 1 份样本的标【待核实】；正文内容、主送和抄送不进画像。
3. 文件没写的字段留空，不用单位类型默认值填。
4. 本单位规定与国标不同的（如年份用方括号），照本单位写，括注"与 GB/T 9704-2012 7.2.5 不同，按本单位办法执行"。
5. 文件印发已超过 5 年，或条文含糊的，字段后写【待核实：说明】。
6. 文件里的人名、电话、经办人、签发人不进画像。
   - 误：决策程序：院长办公会由王某某院长主持，每周一召开，联系人李某，手机号138****1111
   - 正：决策程序：重要行政、业务事项先经院长办公会讨论，再由党委会研究决定（《某医院议事规则》第五条）

### 第三步　分轮问卷

1. 按 `references/intake.md` 第一部分的轮次提问，每轮最多 3 问，一次问完；已知的、已从文件提取的跳过，空出的名额由下一轮的问题补上。默认四轮：基本情况、发文体系、写作习惯、约束和配套文件。
2. 问法带上该单位类型的常见情形作选项（取自 intake.md 第三部分，能读文件时再查 `references/_shared/profiles/units/` 对应文件），用户答"一样"的按选项填，来源写"用户确认"。
3. 用户要求直接给画像，或第一条消息已给出主要字段的，不先问卷：先出画像，空缺字段列入待补，下一轮问题（不超过 3 个）附在起草说明"待补事项"之后。
4. 用户说"就这些""其他你看着填"，停止提问；没答的字段留空（读取时自动采用单位类型默认值），列入起草说明"待补事项"。"单位类型""写作角色和默认模式"两项空着会触发无画像降级，用户没答的按其话语推断（模式按开工检查第 4 条），字段后写【待核实：推断，请确认】。
5. 不问单位全称、领导姓名、电话、人员名单和业务数据。

### 第四步　生成和写入

1. 按完整版模板生成，字段名一字不改，其他 skill 按字段名读取。末尾加"## 维护记录"。
2. 已有简版画像的，原有字段原文保留，空缺字段补上；与原有内容不同的列进变更单，同意后再改。
3. 能写文件的写入 `.gongwen/单位画像.md`；网页环境输出全文（见"输出规范"）。

## 功能二　文风学习

### 第一步　收稿

1. 收 3～10 篇本单位历史稿（txt、docx、md 或直接粘贴），已脱敏。文书类型不同的按类型分组，每组 2 篇以上才单独出参数。
2. 少于 3 篇的照做，参数注明"样本 n 篇，代表性有限"；多于 10 篇的，取最近、最常写的 10 篇。
3. 问一句（可与其他问题合并）：这些稿子是否经过领导审定。未审定的初稿反映的是起草人的习惯，在文风参数中注明。

### 第二步　量化统计

有 Python 时运行 `python scripts/style_profile.py <文件或目录> --json`（第一步分了组的，每组的文件单独运行一次），输出只有参数和短语。要归纳标题句式的加 `--examples`，标题示例只用于归纳，不写进文件。脚本跳过的文件（有密级或内部标注）按提示告诉用户。没有 Python 或脚本报错的，按 `references/style-params.md` 第三部分人工估算，参数后注明"人工估算"。历史稿是红头文件、画像又缺发文体系字段的，征得用户同意后按功能一第二步第 2 条顺带补上。

### 第三步　不采纳检查

1. 有 Python 时对每篇运行 `python scripts/gongwen_lint.py <稿件> --checks style,defensive --json`；没有时按 `references/style-params.md` 第四部分人工查。
2. 2 篇以上都有的毛病（段首评论语、"不是……而是……"、破折号过密、背景铺垫开头、免责句等）写进文风参数"五、不采纳的习惯"，起草时不模仿。style_profile.py 的"开头方式"为铺垫式的篇数也在此处理。
3. 历史稿中的政治性提法不作为"常用表述"记录，提法以用户提供的最新原文为准。

### 第四步　定性观察

按 `references/style-params.md` 第二部分的 7 项逐项看：开头方式、结构安排、标题风格、语气与措辞层级、数据呈现、结尾方式、常用过渡。每项写成"做法＋频次"，不抄原句。
- 误：开头："2025年，在局党组的坚强领导下，全局上下团结一心……"
- 正：开头：4 篇中 3 篇先用一句领导关怀类铺垫，再写总体数据（铺垫列入"不采纳的习惯"）

### 第五步　写入

1. 按 `references/style-params.md` 第一部分的模板写，按文书类型分节；已有文件只更新对应类型一节，变更单列出新旧数值。
2. 脚本统计的写中位数（P25～P75）；人工估算的写"约 N（最短 a～最长 b），人工估算"，不写四分位。每项配一条"起草时怎么做"。
3. 不写入：原文段落和整句、标题原文（写抽象句式，如"动词＋对象，8 字左右"）、人名、业务数据。

## 功能三　花脸稿学习

### 第一步　收稿和确认

1. 四种输入：原稿和改稿两份文件；一份带修订痕迹或批注的 docx；网页环境粘贴的两段文字；偏好卡已有的"历次改稿记录"（含 gongwen-polish 追加的行，用户说"把改稿记录归纳一下"时直接做第四、五步）。网页环境上传的 docx 读不出修订痕迹的，请用户在 Word 中另存"拒绝全部修订"和"接受全部修订"两份，或分别粘贴原稿和改稿。
2. 只比交给领导的那一稿和领导改完的那一稿，起草人自己中间改的版本不算。
3. 确认三件事，已知的不问：改稿的是哪位领导（写职务）、稿件类型、改稿日期。docx 有多位修订人的，脚本列出"修订人1、修订人2"，请用户指明哪位是这位领导；用户指明前，可先按修订处数最多的修订人归纳，写进所作假设，请用户确认，确认前不写入偏好卡。

### 第二步　对齐

有 Python 时运行 `python scripts/draft_diff.py <原稿> <改稿> --json`，或 `python scripts/draft_diff.py <修订稿.docx> --json`（只看某位修订人加 `--author N`）。多份花脸稿逐份对比，再按偏好合并计数。没有 Python 的，按 `references/edit-patterns.md` 第一部分逐段逐句人工对照。对比清单含原文，只在对话中使用，不存进 `.gongwen/`。

### 第三步　剔除和归类

1. 先剔除不属于写作偏好的改动：事实更正（原有数字改成另一个数字，日期、名称、文号改了）、错别字和标点更正、一次性的内容取舍。事实更正单列在起草说明"修改说明"中，提醒用户核对原始数据，不进偏好卡。概括词换成具体数字的（"大幅增加"改为"由18个增至24个"）不算事实更正，归为"数据代替评价"偏好，新数字本身仍提醒用户核对。脚本标签"数字改动"对应前一种，"改为具体数字"对应后一种。
2. 其余按 `references/edit-patterns.md` 第二部分归类：删减、换词、结构、语气、数据呈现、标题、篇幅、批注意见。脚本给的标签只是线索，逐条看上下文确认。

### 第四步　归纳偏好条目

1. 每条写成一个做法，带例证、次数、来源：`- 不用"着力"，改为"重点"或删去（例："着力推进"改为"重点推进"；1 份稿件 3 处；2026-10-12 三季度经营分析汇报；用户确认）`。
2. 例证不超过 20 字，去掉人名、单位全称和具体数据。
3. 写入门槛：同一偏好在 2 份以上稿件中出现的，写入偏好条目；只在 1 份稿件中出现的，只记入"历次改稿记录"，标"观察中"；1 份稿件中出现 3 处以上、用户确认是一贯习惯的，也可写入，注明"用户确认"。
4. 批注只归纳写作要求（如"成效要有数据""开头直接说结论"），对人的评价和情绪化的话不记。
   - 误：院长脾气急，嫌啰嗦，批了"写的什么东西"。
   - 正：汇报材料删去背景铺垫，开头直接写结果（例：删去"在……领导下"一句；2 份稿件共 4 处）。

### 第五步　冲突检查和写入

1. 逐条与已有偏好卡、禁用词、文风参数比对。冲突的（原卡写"常用'着力'"，新稿每次删掉）一次问完，最多 3 条，每条给三个选项：以新为准；保留原条目；按文书类型区分（如讲话保留、汇报不用）。用户不答的，原条目不动，新条目记"观察中"。
2. 已有且不冲突的条目：次数累加，来源追加日期。
3. 查"历次改稿记录"中同一偏好标"观察中"的记录（含 gongwen-polish 追加的行，每行按 1 份计）：与本次合计达到 2 份的，升级为偏好条目，份数、处数和来源合并，原记录的"（观察中）"改为"（已归纳）"。
4. "历次改稿记录"每份稿件追加一行：日期、稿件、领导改动、归纳的偏好。只进改稿记录的"观察中"条目，在变更单中逐条附例证和处数，供用户确认。
5. 反复被删改的词，问用户是否加入禁用词（慎用），同意后按功能四写入。
6. 变更单经用户同意后写入。

### 口述偏好录入

用户或领导本人直接说出的写作偏好，以及 gongwen-speech 转来的偏好，不需要花脸稿：
1. 直接写入偏好卡对应节，来源写"用户告知（2026-10-16）"或"本人口述（2026-10-16）"，不受份数门槛限制。
2. 只收写作偏好，对人的评价不记。
3. 去向：只针对某位领导的，写进这位领导的卡（不用的词进"忌用表述"）；全单位都不用的，按功能四写进禁用词；说不清的问一句"只是写局长的材料不用，还是全单位都不用？"
4. 按第五步第 1 条做冲突检查，先出变更单；用户已说清改哪一项、改成什么的，列出后直接写（读写约定第 2 条）。还没有这位领导的卡的，新建一张，只填适用对象和这一条。

## 功能四　禁用词管理

1. 每条写全五列：词语或表述、级别、原因、替换建议、适用范围（`references/_shared/profiles/profile-template.md` 第三部分）。
2. 级别：用户说"别用""不能用"的为禁用；说"少用""尽量不用"的为慎用；说不清的按慎用，写进"所作假设"。
3. 原因写来源和日期，如"院长改稿删除 3 次（2026-10-12）""用户告知（2026-10-16）""《某单位宣传工作规定》第八条"。
4. 用户没给替换建议的，给 1～2 个中性词；没有合适替换的写"删去，直接写具体做法"。
5. 政治性提法的停用、更新以用户提供的上级原文为准。用户要求加入但没给原文的，照加，原因写"用户告知，【待核实：请提供上级原文】"；本 skill 不主动增删这类条目。
6. 删除或改级别：列出原行和改后，用户同意后改，被删的行记入维护记录。
7. 新条目与偏好卡"常用"冲突、与已有条目重复的，合并或询问。

## 功能五　画像体检

逐项查以下 13 项（细则和示例见 `references/maintenance.md` 第二、三部分），输出体检单，不直接改文件：

| 序号 | 检查项 | 怎么查 | 级别 |
|---|---|---|---|
| 1 | 关键字段缺失 | "单位类型""写作角色和默认模式"为空，会触发无画像降级（roles.md 第九节） | P1 |
| 2 | 其他字段空缺 | 17 个字段逐个看，列出空着的，说明读取时用单位类型默认值 | P2 |
| 3 | 个人信息 | 带真名的人名、手机号、证件号、住址 | P0 |
| 4 | 对个人的评价 | 偏好卡中写了脾气、性格、对某人的看法 | P0 |
| 5 | 与单位类型默认值不同 | 对照 `references/_shared/profiles/units/` 对应文件第二、三、四、六部分（读不到时只查本格所列情形），本单位实际如此的不列。明显不合常规的列 P1 待核实（医院没有党委会、国企没有党委前置研究、高校学院对校外正式行文）；社区写了发文字号的列 P2 | P1 或 P2 |
| 6～9 | 可能过期或不足 | 维护记录、偏好卡更新日期超过 12 个月或领导已调整；制度文件印发超过 5 年或没写年份；文风参数样本都在 3 年以前、少于 3 篇或为人工估算 | P2 |
| 10 | 文件之间矛盾 | 禁用词与偏好卡"常用"冲突；画像角色与偏好卡适用对象不符 | P1 |
| 11 | 篇幅偏好超上限 | 只查通知、意见、实施方案等文件类篇幅偏好，总结、汇报材料、讲话不适用本项。部署专项工作的文件超过 4000 字、其他文件超过 5000 字（`references/_shared/rules/jianfu.md` 第三部分）；部署综合性工作的文件不设上限，超过 5000 字只作 P2 提示 | 党政机关、基层、社区 P1；医院、高校、中小学、国企 P2（参照减负规定第2条） |
| 12 | 字段名被改动 | 与模板不一致，其他 skill 读不到 | P1 |
| 13 | 政治性提法条目无依据 | 禁用词中的提法条目没写上级原文出处 | P1 |

体检单先写总体（已填几个字段，P0、P1、P2 各几条），再列：序号｜级别｜文件和字段｜问题｜依据｜建议改法。手机号等只写类别，不照抄。最后问用户改哪几条，同意后按变更单修改。

## 输出规范

1. 四个文件是 Markdown 工作文件，按模板写，可用标题、列表、表格；文件里除【待核实：说明】外不放提示语。
2. 能写文件的环境：写入 `.gongwen/`。对话中报写了哪些文件、新增和修改几条、留空字段几项，不必重复全文；所作假设、待补事项、保密提示等在对话回复末尾的【起草说明】中给出，不写入 `.gongwen/`。
3. 网页环境：每个文件先写一行"文件：.gongwen/单位画像.md"，再给出完整内容，放在代码块中便于复制；更新已有文件时同样给完整新版本。之后另起一行写【起草说明】，按需写：一、所作假设；二、待补事项（留空的字段）；三、待核实事项；四、修改说明（变更单、事实更正提醒）；五、保密提示；六、写作要点（仅教学模式，写画像怎么用）。最后提醒用户保存这些文本，以后使用时粘贴在对话开头。
4. 交接卡：路线还有下一站的（如先建档再写讲话），在起草说明之后输出更新后的交接卡，"单位画像"栏填新画像全文，"请准备"栏写明要一并粘贴的领导偏好卡、文风参数；告诉用户新开对话，先粘贴下一站的提示词文件（`dist/prompts/<skill 名>.md`），再粘贴交接卡和本站产出。交接卡只写任务信息，不抄录用户原始材料。能直接调用其他 skill 的环境不需要交接卡。

```text
【交接卡】
单位画像：（新画像全文）
当前模式：转译模式
任务：院长在护士节表彰会上的讲话，约10分钟
路线：profile（建档、学偏好）→ speech → review
本站：第2站 gongwen-speech，起草
已确认：讲话人为院长；面向全院护理人员
请准备：上一站（gongwen-profile）产出的领导偏好卡（院长）全文
```

## 自检清单

- [ ] 第一次索要材料时给了保密提示；有密级或内部标注的材料没有摘录和统计。
- [ ] 四个文件中没有人名、电话、证件号、患者和学生信息；领导只写职务；修订人姓名没有记录。
- [ ] 每个字段的值来自用户回答、制度文件（注明条款）或样本统计；问不到的留空，没有拿单位类型默认值冒充本单位情况。
- [ ] 改已有文件前出了变更单并取得同意，已备份；没有整份覆盖；维护记录已追加。
- [ ] 文风参数没有原文段落、整句和标题原文；不采纳的习惯已列出；样本数和是否人工估算已注明。
- [ ] 偏好条目都有例证、次数、来源日期；事实更正没有混进偏好；只在 1 份稿件出现、未经用户确认的，只进了改稿记录；与"观察中"记录合计达 2 份的已升级；口述偏好写明"用户告知"或"本人口述"和日期。
- [ ] 与已有条目冲突的已询问，没有悄悄覆盖。
- [ ] 禁用词五列齐全；政治性提法条目有原文依据或标了【待核实】。
- [ ] 网页环境输出了完整文件文本和【起草说明】。

有 Python 时，写完对四个文件分别运行 `python scripts/gongwen_lint.py <文件> --checks privacy --json`，人名仍按本清单第 2 条人工看一遍；无法运行时全部人工检查，在起草说明中写"未运行机检"。

## 单位类型差异

党政机关指省、市两级；县、乡两级和街道（含县直部门）归基层。各类型的问法、选项和常见误填见 `references/intake.md` 第三部分。

| 单位类型 | 建档重点 | 学习时注意 |
|---|---|---|
| 党政机关 | 两套代字；签报或呈批件；签发权限 | 讲话稿与文件分开统计；提法不进常用表述 |
| 基层 | 当地减负清单；迎检和信息报送要求 | 政务信息篇幅短，单独成组 |
| 社区 | 多数没有发文字号；通知发布渠道 | 居民通知句子更短，单独成组；居民姓名电话先脱敏 |
| 公立医院 | 两套代字；签报；先院长办公会讨论、再党委会决定 | 质量分析与汇报材料分开；历史稿先删患者信息 |
| 高校 | 校级和部门两级发文；部门不对校外正式行文 | 学院稿与机关稿分开；学生信息先脱敏 |
| 中小学 | 校发；党组织会议、校长办公会 | 家长通知、致家长的信单独成组 |
| 国有企业 | 两套代字；党委前置，再到董事会或经理层 | 未披露的经营数据不进样本 |

## 角色适配

- 教学模式：问卷每题附一句"为什么问、哪些 skill 会用到"；文风参数和偏好条目各附"起草时怎么用"；起草说明末尾写画像的使用方法。
- 高效模式：能从材料提取的一律不问，问卷压成两轮；多份花脸稿一次批量处理；变更单一次确认；对话只报改动条数和文件位置。
- 转译模式：问题用大白话，不用公文术语（问"你们发文件的编号长什么样"，不问"发文字号格式"）；优先从用户给的文件里提取。
- 审稿模式：用户多是领导本人，口述的写作偏好按"口述偏好录入"写进偏好卡，来源写"本人口述"；画像体检只出体检单和一页纸摘要，不主动改文件。
- 严谨模式：禁用词中的提法条目必须有上级原文出处；文风学习不记录提法；偏好卡的引用习惯只写"引用注明出处，只用用户提供的原文"。
