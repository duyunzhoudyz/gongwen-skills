# 改稿润色（gongwen-polish）

> 版本 1.0.0　成熟度：Stable（稳定版）

稿子已经有了，要按要求改：压短、扩一扩、换个口气、把大白话改成公文、按领导批注改、几稿合一稿。它只动表达和取舍，不替你加事实：改后稿里的每个数字和事例都能在原稿或你给的材料里找到，缺的标【待补】，几稿说法不一的列出来请你定。每次都附修改说明，写清改了什么、为什么改。

## 能做什么

| 功能 | 说明 |
|---|---|
| 压缩 | 按你给的字数、讲话时长，或《整治形式主义为基层减负若干规定》的篇幅上限压。先删铺垫，再删复述、空泛表态、重复举例，数据和措施保留；压到只剩干货还超的，告诉你差多少，请你决定 |
| 扩写 | 只展开原稿和你给的材料里已有的事实；素材离目标差得多的，回复第一段就说明差多少、补什么材料能写足，缺内容的地方标【待补】，不凑字数 |
| 调语气 | 新文种和受文对象定了以后，在上行、平行、下行之间互转，称谓、开头语、要求措辞、结语和标题文种一起改，新方向缺的要素（时限、责任单位）标【待补】；向上请求的事项不会改成对下的任务；部门发给下级政府的，不写指令性要求。拿不准该用什么文种的，请用 gongwen-draft |
| 转译 | 把业务人员写的大白话改成公文语言，术语和指标原样保留，不拔高 |
| 口语化、书面化 | 讲话稿改得好讲，按每分钟约 200 字核算时长；讲话整理稿改成书面材料 |
| 按领导批注改 | “太虚”“数据呢”“压一压”逐条落实，出一张批注落实对照表；能从 Word 文件里直接读出批注，领导用修订直接改的字按改后的算；顺带整理一行领导偏好记录，你同意后存进偏好卡 |
| 多稿合并 | 两三个版本取长补短，数字、表态、时限不一致的不替你选，列成冲突清单 |

## 你可以这样说

1. “这个汇报8000多字，领导说压到3000字以内，数据别丢。”
2. “这是我们教育局写给区政府的报告，现在要改成发给各学校的通知。”
3. “我们主任写的总结全是大白话，帮我改成像样的公文。”
4. “领导在稿子上批了‘太虚’‘数据呢’，你帮我按批注改一下。”
5. “办公室和分管领导各改了一版，帮我合成一稿，有冲突的标出来。”

## 输入和输出

- 输入：要改的稿子（文字，或 .txt、.md、.docx 文件），加上要求：目标字数、改给谁、批注原话、几个版本。要补数据的，一并给出数据来源材料。
- 输出：改后正文（纯文本，不含 Markdown），正文之后是起草说明：所作假设、待补和待核实事项、修改说明（字数变化、改了哪几处、删去的数据、转交事项）。按需附批注落实对照表、合并说明、合并冲突清单、偏好卡改稿记录。
- 在 Claude Code、Codex 等能写文件的工具里，原稿留底为当前目录下 `公文/<日期>-<标题>/原稿.txt`（Word 文件先转成文字稿，带修订痕迹的按接受全部修订后的文字），改稿写入同一目录的 `正文.txt`（已存在时加 -v2），不覆盖你的文件；在网页对话里，直接在回复中给出。网页版读不出 Word 批注的，请把批注按“位置、原文片段、批注原话”逐条贴上。

## 注意事项

1. 请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。稿中有姓名、身份证号、手机号、病案号的，会提醒你脱敏，并在改稿中用“张某”等代称。
2. 不新增事实。领导批“数据呢”而材料里没有的，会标【待补】并告诉你要补什么，不会编一个数。
3. 默认做减法。压缩不删数据和措施；扩写不加背景、意义和表态。
4. 政治性提法、上级文件原文、领导原话不改写，只会整句保留或整句删去并告诉你。
5. 只做你点名的修改。稿子里的 AI 腔、对冲语气、格式标点问题会列出来，建议分别用 gongwen-humanize、gongwen-direct、gongwen-review 处理。
6. 有 Python 环境时，用 `scripts/polish_stat.py` 统计字数、对照改动（含每段多出的文字，以及“拟”改“已”、“可以”改“必须”这类状态和强度词的变化）、核对合并稿每句的来源、读取 Word 批注、把 Word 文件转成文字稿，用 `scripts/fact_diff.py` 核对改稿前后的数字、日期、文号没有变。没有 Python 时按人工清单核对，并在说明中注明。
7. 你说“3000字以内”，就按 3000 字封顶核对，多 1 字也会继续删，但不会为了凑字数加内容；只说“3000字左右”的，按上下浮动一成核对，【待补】不算字数。
8. 首轮直接给改后稿，不先交修改计划等你确认；需要问的（最多 3 个）放在回复末尾，答复后在这一稿上接着改。只有调语气时没说改给谁、改成什么文种，又看不出来的，先给措辞对照建议，问清后再改全文。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 去 AI 腔（“值得注意的是”、翻案句、新八股词） | gongwen-humanize |
| 删免责声明和对冲语气，让下行文口气明确 | gongwen-direct |
| 核稿查错 | gongwen-review |
| 改标题、小标题 | gongwen-title |
| 只有素材还没有稿子；结构要推倒重写 | gongwen-report、gongwen-draft、gongwen-speech 等起草 skill |
| 判断该用请示、报告还是函；文种用错要改 | gongwen-draft |
| 长材料压成政务信息、简报 | gongwen-brief |
| 拿领导改过的稿子总结领导习惯 | gongwen-profile |
| 排成国标格式的 Word | gongwen-format |

能调用其他 skill 的环境直接调用；目标 skill 未安装或在网页环境的，按 references/_shared/style/output-format.md 第四部分转交：给交接卡、“新开对话粘贴 dist/prompts/<skill>.md 继续”的说明和安装命令。

## 成熟度

Stable。v1.0 真实模型评测（Sonnet 5.5，18 条用例）中，A 组（装 skill）期望通过率 99.2%（131/132），编造 0 次，触发评测正例 10/10、反例 10/10，详见 `evals/results/v1.0-benchmark.md`。七项功能的流程、对照表和评测用例已齐备，`polish_stat.py` 配有单元测试（含必错和必过标本）。已知局限如下。
- 字数统计口径为“标题之后、【起草说明】之前，不含空白”，折行标题的识别与机检一致，与 Word 的字数统计可能略有出入；带份号、密级、版记的正式文件以机检的篇幅为准；
- 合并溯源和改动对照按文字相似度判断来源，改动较大的句子可能误报“未找到来源”或列出较多“多出的文字”，需逐条人工确认；
- Word 修订痕迹按“接受全部修订”读取，不区分哪处修订该接受；要拒绝某处修订，请先在 Word 中处理。修订习惯的学习交 gongwen-profile。
