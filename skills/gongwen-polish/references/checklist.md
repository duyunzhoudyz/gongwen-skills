# 人工复核清单（无法运行脚本时）

网页版、内网无 Python、脚本出错时，按本清单逐项核对，并在起草说明“所作假设”中写“未运行机检和事实比对，已人工逐段核对”。

## 一、字数

1. 逐段估算字数（汉字、数字、标点都算，空格不算），标题和【起草说明】之后的内容不算。
2. 说明中写“约N字（估算）”，不写成精确数。
3. 用户说“以内”“不超过”的，估算结果超过上限就继续删（估算误差大的，按上限的九成五控制）；其余在目标的±10% 以外的，按 `references/length.md` 继续删或说明原因。扩写时【待补】不计入字数，差距超过 30% 的在回复第一段说明并附补料清单。

## 二、事实逐项对照

把原稿（合并时为各稿，用了补充材料时连同材料）和改稿并排，逐段核对：

- [ ] 数字、百分数、金额：改稿中的每一个都能在原稿或材料中找到，数值和单位一致。
- [ ] 日期、时限：没有新增，没有改动；原稿的相对日期照写原话；用户新给的“周五”等已按今天推算。
- [ ] 人名、职务、单位名称、责任分工：没有新增，没有改动（脱敏替换除外）。
- [ ] 书名号和引号内的内容（含加引号的做法名称、本单位提法）、发文字号：逐字一致。
- [ ] 状态：原稿“拟”“将”“正在”的，改稿没有写成“已”；“基本完成”没有写成“全面完成”。
- [ ] 义务强度：“可以”没有改成“必须”，“必须”没有改成“要”（调语气按 `references/tone.md` 调整、按批注调语气强度、讲话人本人讲话书面化或口语化的除外，并已写进修改说明）。
- [ ] 政治性提法、上级文件原文、领导原话：没有改写、没有截断。
- [ ] 【待补】【待核实】：原稿已有的都在；新增的只有【待补】，一般不超过 3 处，都已汇总进起草说明。
- [ ] 删去的数据（压缩、合并去重、按删减类批注、调语气删去不适用事项）都写进了“删去的数据”，并写明理由。

## 三、改动范围

- [ ] 每处改动都属于本次任务；按批注改稿时，每处改动都对应到某条批注。
- [ ] 批注以外、任务以外的问题没有顺手改，已写进“转交事项”或“批注以外的建议”。

## 四、文面

- [ ] 正文没有 Markdown 符号（#、**、-、>）和 emoji。
- [ ] 正文没有“仅供参考”“以下是修改后的稿子”之类的话。
- [ ] 层次序数依次为 一、（一）1.（1），没有跳级。
- [ ] 改稿没有新出现“值得注意的是”“不是……而是……”和成串的破折号（`references/_shared/style/ai-tone.md`）。
- [ ] 正文之后单独一行【起草说明】。
