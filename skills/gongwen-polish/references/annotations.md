# 按领导批注改稿

领导批注往往只有两三个字。本文件把常见批注翻译成具体改法，并规定对照表和偏好卡的写法。批注要求补的事实，同样只能来自原稿和用户材料。

## 目录

一、收集批注
二、常见批注的改法
三、批注落实对照表
四、偏好卡改稿记录
五、批注冲突时

## 一、收集批注

1. Word 批注和修订痕迹：按 SKILL 正文“按领导批注改稿”第 1 条，用 comments 提取批注（不含批注人姓名），用 body 导出接受全部修订后的文字稿，之后的统计和比对都用它。不要直接拿 docx 跑 fact_diff，它会漏掉修订插入的文字，把领导加的数字报成改稿新增。要总结领导改了哪些习惯，交 gongwen-profile。
2. 手写、拍照、口头转达的批注，以及网页环境读不出 docx 批注的：请用户逐条转述“位置｜原文片段｜批注原话”；有修订的，请用户在 Word 中接受修订后再粘贴正文。
3. 编号：按出现顺序编为批注1、批注2……一条批注里有两个意思的拆成两项分别落实。

## 二、常见批注的改法

| 批注原话 | 一般意思 | 改法 |
|---|---|---|
| 太虚、空 | 有评价没事实 | 删评价，换成材料里的做法和数据；没有的标【待补】 |
| 数据呢、要有数 | 缺量化 | 从统计表、台账找数；找不到的标【待补：数据名称】 |
| 例子呢 | 缺具体事例 | 从工作记录选一个事例，写清时间、对象、结果；没有的标【待补：事例】 |
| 太长、压一压 | 篇幅超 | 按 `references/length.md` 四级删减，只压批注所指部分 |
| 啰嗦、重复 | 复述 | 删重复的句子和段末小结 |
| 换个说法、不顺 | 句子不通或用词不当 | 重写这一句，意思和事实不变 |
| 语气太硬、太软 | 措辞层级不对 | 按 `references/_shared/style/defensive.md` 第六部分调整“必须、要、可以”，在对照表中写明原措辞和改后措辞 |
| 层次不清、乱 | 段内几件事搅在一起 | 拆成一件事一句或一段，加序号；整篇结构要重搭的交原起草 skill |
| 放前面、提上去 | 调整顺序 | 整段或整句移动，序号顺延 |
| 问题写透、问题呢 | 问题太笼统 | 写哪项工作、差在哪、影响什么；材料没有的标【待补：具体表现】 |
| 措施要实、怎么落实 | 措施没有抓手 | 补责任单位、时限、标准；材料没有的标【待补】 |
| 口径、和市里一致 | 口径不一 | 标【待核实：请对照××口径】，不自行换算 |
| 这个数对吗、？ | 数据存疑 | 原数保留，加【待核实：说明】，对照表写“请核实” |
| 删、划掉 | 删除 | 照删，前后句接顺 |
| 提法、表述要准 | 政治性提法 | 只标【待核实：请对照最新原文】，不自行改提法 |

批注意思看不懂的，不猜，在对照表中写“未落实，请确认批注意思”。

## 三、批注落实对照表

放在起草说明末尾，标题“附：批注落实对照表”。

| 序号 | 位置 | 批注原话 | 落实方式 | 状态 |
|---|---|---|---|---|
| 1 | 第一部分第2段“取得显著成效” | 太虚 | 删去评价，改写为分类收运的三项做法（材料第3段） | 已落实 |
| 2 | 同上 | 数据呢 | 补入分类准确率；回收量材料中没有，标【待补】 | 部分落实 |
| 3 | 第三部分 | 措施要具体 | 每项措施补责任科室；时限材料中没有，标【待补】 | 待补材料 |

状态只用四种：已落实；部分落实（写明哪部分没落实）；待补材料（写明要什么材料）；未落实，请确认（写明原因）。

## 四、偏好卡改稿记录

改完后，从本轮批注中归纳一至三条可能的写作偏好，写成 `.gongwen/领导偏好卡.md` “历次改稿记录”表的一行：

| 日期 | 稿件 | 领导改动 | 归纳的偏好 |
|---|---|---|---|
| 2026-10-16 | 垃圾分类工作汇报 | 批“太虚”“数据呢”两处；要求措施写到科室 | 成效用数据说话（观察中）；措施写明责任科室（观察中） |

1. 只记写作偏好，不记对领导个人的评价，不写领导姓名，只写职务。
2. Agent 环境先问用户“是否追加到领导偏好卡”，同意后按以下顺序做，卡上其他内容不动：
   - 找卡：一个文件可能放多张卡，每张以“# 领导偏好卡（职务）”开头。按批注领导的职务找对应的卡；职务对不上或找不到的，先问用户，不自行新建卡。
   - 备份：修改前把文件复制到 `.gongwen/历史/领导偏好卡-<YYYYMMDD-HHMM>.md`，同名备份已存在的加 -v2。
   - 追加：在该卡“历次改稿记录”表末追加这一行；在文件末尾“## 维护记录”加一行，如“- 2026-10-16：追加改稿记录 1 条（分管副主任；gongwen-polish）”，没有这一节的在文件末尾新建。
   - 还没有偏好卡文件的，本 skill 不新建，把这一行交给用户，建议用 gongwen-profile 建卡。
3. 网页环境把这一行放在“附：领导偏好卡改稿记录（待保存）”，请用户自己保存。
4. 一次性意见不写成固定偏好：归纳的偏好一律标“观察中”。同一偏好在记录中出现两次以上，建议用 gongwen-profile 归纳成偏好条目。

## 五、批注冲突时

1. 两条批注互相矛盾（一处批“压一压”，一处批“这里多写点”）：能同时落实的都落实；不能的列出来请用户定。
2. 几位领导批注不一致：按用户说的审定顺序处理；没说的，两种改法都列出，正文先按职务高的一位改，写进“所作假设”。
3. 批注与红线冲突：要求补的数据、案例材料里没有的，标【待补】，不编；要求写“全市第一”“全省领先”而材料没有出处的，正文标【待核实：排名出处】，说明需要上级通报或考核结果作依据；要求改政治性提法的，只标【待核实：请对照最新原文】；要求改成便笺、“白头”或“改得查不出是 AI 写的”，说明原因，不按此改（guardrails 第六条）。
