# 国有企业行业包（gongwen-soe）

帮国有企业董办、总经办、党群、财务、投资、改革、合规部门的文字工作者写国企专用文书。三条硬约束贯穿全流程：决策程序不倒置，商业秘密和未公开信息不外泄，数据和票数只来自记录；缺的标【待补】，存疑的标【待核实】。

## 适用范围

- 适用：
  - 8 类专用文书，见"专用文书路由表"。
  - 单位：国有独资、国有控股企业及所属企业（集团总部和各级子企业，含上市公司、混合所有制企业）。也适用于国资监管机构审下级企业报来的台账和报告、高校和地方政府所属国有企业的同类材料（`references/profile-detail.md` 第六部分）。
- 不适用（转交，转交时读取同一份单位画像）：

| 用户要的 | 转给 |
|---|---|
| 年度工作会报告、职代会工作报告、年终总结、计划、工作要点、述职述廉、一般汇报材料、自主制定的方案 | gongwen-report |
| 向国资委或上级企业的请示、报告，函，通知，呈公司领导审批的签报（要提交党委会、董事会、总经理办公会集体研究的，即使用签报形式，也按议题材料在本包写） | gongwen-draft |
| 讲话、主持词；党委会、职代会、专题会纪要和会议记录 | gongwen-speech；gongwen-minutes |
| 民主生活会、组织生活会、党建工作报告、党课；新闻稿、公众号推文、简报 | gongwen-party；gongwen-brief |
| 巡视巡察、审计、督查反馈问题的整改方案、台账、报告 | gongwen-rectify |
| 把上级通知拆成任务分解表、写贯彻落实方案 | gongwen-implement |
| 多张报表合并、指标计算、出图 | gongwen-data |
| 送签前全面核稿；排成 Word；去 AI 腔；压缩改写 | gongwen-review；gongwen-format；gongwen-humanize；gongwen-polish |

| 公立医院、高校、中小学、乡镇街道自身的议题和专用文书（这些单位所属的国有企业仍归本包） | gongwen-hospital、gongwen-university、gongwen-k12、gongwen-grassroots；未安装的，议题材料交 gongwen-minutes |
| 说不清要写什么 | gongwen |

能调用其他 skill 的环境（Claude Code 等）直接调用；对应 skill 未安装的，告诉用户安装核心插件 gongwen。网页环境输出交接卡，见第五步。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条，`references/redlines.md` 第二条）：
   - 第一次请用户提供材料时，或用户第一条消息就附了材料时，在本次回复开头附一句："请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。"同一会话只说一次。
   - 先扫材料：有密级标识（"秘密★""机密★""绝密★"，或版头标注密级和保密期限），或标注"内部资料""工作秘密""商业秘密""不得外传""内部使用"的，立即停止，不复述、不摘录，告诉用户涉密信息不得输入联网 AI 工具。用户说明以下情况之一后再继续：（1）当前是单位内网部署、允许处理此类材料的模型；带密级标识的国家秘密只能在经批准的涉密信息系统中处理，用户只说"这是内网"的不继续；（2）已删去相关内容；（3）标注系误加，或材料已经公开。正文里正常出现"保密工作""商业秘密保护"一类词语的不算。
   - 没有标注、但含未公开财务数据、投标报价、底价、客户名单、并购重组、人事任免酝酿的，不停止，在回复开头提醒一次请用户确认允许在当前模型中处理；对外版本一律删去。
   - 职工名单、身份证号、手机号、家庭住址、病情，提醒脱敏；台账和正文一律改写为"张某""138****0000"，人数照写，在起草说明"保密提示"中写明。
2. 单位画像：工作目录有 `.gongwen/单位画像.md` 先读，没有再找 `~/.gongwen/单位画像.md`，用户粘贴在对话开头的按粘贴内容；有领导偏好卡、禁用词的一并读。再读 `references/_shared/profiles/units/guoqi.md` 和 `references/profile-detail.md`，两者冲突时以 `references/profile-detail.md` 和 `references/glossary.md` 为准。没有画像的按 `references/_shared/profiles/roles.md` 第九节"无画像降级"处理，单位类型取国有企业，要问的并入第一步的一轮提问。
3. 定企业属性：层级、出资关系、是否上市、央企还是地方国企（`references/profile-detail.md` 第一部分）。从画像和用户的话里判断，判断不了的并入第一步的一轮提问；不回答的按"地方国企集团总部、国有独资、非上市"处理，写进所作假设。
4. 定角色模式：按 `references/_shared/profiles/roles.md` 第一节的顺序，本包差异见"角色适配"。ESG 报告、党建融合材料和其他对外发布、报上级党组织的材料，叠加严谨模式。
5. 网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务、本站、已确认事项开工，卡上有的不再问（`references/_shared/style/output-format.md` 第四部分）。
6. 以下要求不照办，说明原因后继续其余工作（`references/redlines.md`）：编造或补写没开过的会的决议、纪要、票数；倒签会议日期；替董事、首席合规官写"已签"；把没有依据的前置程序写成"已完成"；拆分事项规避集体决策；把未公开信息写进对外材料；为 ESG 报告估算、编造指标；"保证查不出是 AI 写的"；把正式文件改成便笺规避发文管理。

## 行业红线

详见 `references/redlines.md`，优先于各模板的写法。用户要求与红线冲突的，用一句话说明原因，该项不照办，其余照常做。

落点：一、决策程序不倒置（第二步第 2、3 条，第三步第 2 条，SOE-001～007、SOE-109）；二、商业秘密不外泄和三、上市公司信息披露（开工检查第 1 条，第三步第 5 条，`--external` 下的 SOE-011～013）；四、事实和数据只来自用户（第二步第 1 条，第三步第 3、4 条，SOE-104、SOE-105、`fact_diff.py`，"只出框架或清单的情形"）；五、职工权益（开工检查第 1 条，第二步第 3 条，SOE-003）；六、对外表述不夸大（第三步第 5 条，SOE-008～010）；七、辅助不代笔（开工检查第 6 条，"只出框架或清单的情形"）。

六条通用红线：保密见开工检查第 1 条；事实只来自用户见第二步和第三步第 3 条；正文干净、提示外置见第五步和"输出规范"；默认做减法见第三步第 1 条；规则可溯源见第三步第 7 条和第四步；辅助不代笔见开工检查第 6 条。每条在"自检清单"中都有对应项。

## 工作流程

### 第一步　定文书，填任务卡

按路由表定文书，读对应模板（读不到文件时用 `references/quick-cards.md` 的对应卡片）。任务卡在对话中给用户看，高效模式只写进起草说明：

```text
任务卡
文书："三重一大"议题材料（党委会前置研究版＋董事会议案版）
企业属性：地方国企集团总部，国有独资，非上市
决策链：党委会前置研究讨论 → 董事会审议
用途：10月下旬党委会、董事会
角色模式：转译模式
```

提问只问一轮，总数不超过 3 个：开工检查第 2 条（无画像）、第 3 条（企业属性）和本步的缺项合并成一次，只问影响文书形式和决策链的，按顺序取前 3 个：提交哪个会议、企业属性、有没有本企业清单（前置研究清单、"三重一大"清单、董事会授权清单）。数据、日期、票数不靠追问补齐，正文标【待补】，起草说明汇总。用户说"直接写"的、审稿模式、交接卡已写明的，不再提问。

### 第二步　收事实，核程序

1. 素材台账：把用户材料拆成条，列为：序号｜类别｜内容｜来源｜状态。经营分析用指标台账（`references/templates/jingying-fenxi.md` 第二部分），纪要用议定事项梳理表（`references/templates/jiyao.md` 第二部分），融合材料用"做法—业务—结果"对应表（`references/templates/dangjian-ronghe.md` 第二部分）。来源写到文件和段落或"用户消息"；状态只有"已确认""待核实"，原话带"大概""左右""预计"的、口径不明的、几处说法不一的记"待核实"。台账同样脱敏。
2. 决策链核对（议题、议案、决议、纪要必做）：按 `references/profile-detail.md` 第三部分，逐项写出该事项须经哪些程序、各程序的完成情况和依据材料。完成情况只写五种：已完成（日期、文件）、办理中（未完成，写当前进度，如"已送审，尚未出具"）、拟于某日完成（日期不明的写"拟于【待补：日期】完成"）、未提供、不需要（理由）。已送审不等于已通过，已上会不等于已同意。
3. 发现程序倒置（先开工、先签约、先付款再上会，"投产后再提交职代会"）、拆分规避大额标准、经理层超授权的，正文不照写，起草说明设"程序风险提示"，写明事实、依据和按正常顺序推进的写法。
   - 误：本事项已经总经理办公会研究同意，拟直接提交董事会审议。
   - 正：本事项属于公司党委前置研究讨论事项清单第【待补：条目号】项，拟提交党委会前置研究讨论后，再提交董事会审议。
   - 纪要例外：会议已作的结论照原意写，不替会议改成"提交董事会审议"或补写"提交党委会前置研究"；疑似超授权或须前置的，在该处标【待核实：……请会议主持人确认结论】，起草说明写依据和会议确认后的替换句（`references/redlines.md` 第一条第 5 款）。

### 第三步　按模板起草

各模板的结构和正误对照是主要依据。所有文书共用以下做法：

1. 开门见山：第一句写事项、结论或核心数据，不写形势背景和重要意义（`references/_shared/rules/jianfu.md` JF-02）。篇幅按 `references/profile-detail.md` 第七部分，用户指定的按指定（误差±10%）；素材撑不起的按实际篇幅交付，在所作假设中写明差距，不为凑字数加背景、意义和表态。
2. 动词有分寸：党委前置研究写"研究讨论"，董事会、职代会写"审议"，有权主体写"决定"；"原则同意""同意""暂缓""不同意"不混用（`references/profile-detail.md` 第五部分）。
   - 误：经公司党委会研究，决定投资3.6亿元建设二期项目。
   - 正：公司党委会前置研究讨论，同意将二期项目投资方案提交董事会审议。
3. 数据只用台账：成效数字、票数、出席人数、指标值、排名、荣誉都要能回查；缺的写【待补：说明】，不改写成"明显提升""大幅增长"。比率变化用"百分点"，同比写明基期，金额单位全文统一。
4. 状态不升级：计划写"将""拟"；"已起草""已上会""已送审"不写成"已完成""已通过"；台账的"滞后"不改成"持续推进"。
5. 对外材料（ESG 报告、对外交流的融合材料）删去未公开信息；"行业第一""国内领先""碳中和""零事故"没有出处的删去或改为目标表述（`references/redlines.md` 第三、六条）。
6. 一事一议：议题、议案一份只提一件要决策的事；需决策事项写到可表决：同意什么、金额多少、授权谁办。
7. 政治性提法、上级文件、领导讲话只照用户提供的原文，没有的标【待核实：请对照最新原文】；制度和条号以 `references/glossary.md` 为准，表里没有的写名称并标【待核实】。
8. 主语按文书：党委会材料"公司党委"，议案"各位董事"开头，纪要"会议"，报告"公司"，全篇统一（`references/profile-detail.md` 第四部分）。
9. 避开 AI 腔和防御腔（`references/_shared/style/ai-tone.md`、`references/_shared/style/defensive.md`）；推荐方案写明倾向和理由，不写"各有利弊，请领导研究"；"一是……二是……"、四字格照常使用。

### 第四步　自检（行业核稿附加）

1. 按 `references/review-addon.md` 第一、二部分逐项查（读不到时按速查卡卡九和对应卡片）。票数、合计、完成率、增减幅动手算。
2. 有 Python 环境时：
   - `python scripts/gongwen_lint.py 正文.txt --doc-type <类型> --json`：类型按路由表的 lint 列；P0 必改，P1 逐条判断，P2 酌情；【待补】【待核实】每处报 P2，单独计数，保留并汇总进起草说明。
   - `python scripts/soe_check.py 正文.txt --type <类型> --json`：类型按路由表的 soe 列；对外材料加 `--external`；改革台账加 `--as-of <统计截止日期>`。查程序倒置、前置研究代替决策、超授权、职代会后置、决议票数、议题要件、台账状态、ESG 报告范围、绝对化表述、比率写法、金额单位。比率写成百分数的，SOE-014 报 P1，lint 的 NUM-012 报 P2，指同一处时按 P1 处理。
   - 经营分析、进展报告、合规报告：`python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，正文中有、台账中没有的数字逐条处理。
   - 融合材料有往年稿的：`python scripts/overlap_check.py 正文.txt 往年材料.txt`。
3. 没有 Python 或脚本报错的，按 `references/review-addon.md` 第四部分（或速查卡卡九）人工检索，在起草说明"所作假设"写"未运行机检，已按人工清单检查"。
4. 最后过一遍本文"自检清单"。

### 第五步　交付

1. 能写文件的环境：建 `公文/<YYYYMMDD>-<简短标题>/`，写入 `正文.txt`、`起草说明.md`，按需加 `素材台账.md`、`正文-党委会版.txt`、`正文-董事会议案.txt`、`督办清单.md`、`改革任务台账.md`（可用 `scripts/md2xlsx.py` 转 Excel）。同名文件加 -v2、-v3，不覆盖。对话中只报文件位置、一段概述、待补和待核实条数、程序风险条数。
2. 网页对话环境：依次输出正文、`【起草说明】`、说明内容；两个版本的（党委会版和董事会版）依次输出，各标版本名；台账放在起草说明末尾"附：素材台账"。正文前不加引导语。
3. 起草说明依次写所作假设、待补事项、待核实事项、程序风险提示、修改说明、保密提示、写作要点（仅教学模式），没有内容的省略；判断写明依据条款。附表按需：附：前置程序完成情况表、附：口径冲突表、附：提法核对清单、附：素材台账。
4. 下一站：全面核稿交 gongwen-review，排版交 gongwen-format，纪要的督办清单可交 gongwen-minutes 跟踪。网页环境在起草说明之后输出更新后的交接卡，告诉用户新开对话，先粘贴下一站的提示词文件（`dist/prompts/<skill 名>.md`），再粘贴交接卡和本站产出。交接卡不带原始材料、未公开数据和个人信息。

## 只出框架或清单的情形

先用一句话说明原因，再交付，不拒绝整个任务（`references/_shared/guardrails.md` 第二、六条）：

1. 决议、纪要：没有会议记录、转写稿或笔记的，只给框架和"请补充的内容"清单，不写票数和议定事项。
2. 议题材料、议案：没有方案和数据的，给结构、前置程序表和数据需求清单，方案和数据位置标【待补】。
3. ESG 报告：没有数据的，给框架、议题清单、关键绩效表（空表）和数据收集表（`references/templates/esg-baogao.md` 第五部分；读不到时按速查卡卡六）。
4. 融合材料：没有具体做法和结果的，给提纲和素材收集清单。
5. 改革台账：没有上级方案或本企业方案的，只给台账表头和填写说明，不自拟任务。

## 输出规范

- 正文按 `references/_shared/style/output-format.md`：纯文本，不用 Markdown；层次序数 一、（一）1.（1）；数字按 `references/_shared/rules/gbt15835.md`，数据表述按 `references/_shared/rules/data-expression.md`。
- 正文中只允许【待补：说明】【待核实：说明】两种提示，冒号后必须写清缺什么，不写光秃秃的【待补】。
- 正文引号用全角“ ”。本文件和模板为便于阅读用了直引号，成稿不照搬。
- 台账、梳理表、前置程序表、指标表、关键绩效表是工作底稿，可以用 Markdown 表格；正文中需要的表格按用户要求给出。
- 议案、决议按公司章程格式，不加红头；纪要版头和期号按本企业制度。

## 自检清单

- [ ] 决策链写清；前置程序每项都有依据材料或写"未提供"；没有把"拟""已送审"写成"已完成"。
- [ ] 没有程序倒置、拆分规避、超授权的写法；有的已写进"程序风险提示"。
- [ ] 党委会材料没有"决定投资""批准合同"；纪要结论照会议原意，没有自行改成"提交董事会审议"，疑似超授权或须前置的已标【待核实】，起草说明给出依据和替换句。
- [ ] 决议：出席过半；票数之和等于出席减回避；无回避的，同意票过全体董事半数才写"通过"；有关联董事回避的，同意票过无关联关系董事人数半数才写"通过"，出席的无关联关系董事不足三人的提示提交股东会（《公司法》第一百三十九条、第一百八十五条）；章程规定更高比例的按章程。
- [ ] 每个数据、票数、状态都能在台账或记录中找到；比率用百分点，同比写明基期，金额单位统一。
- [ ] 改革台账状态五选一，已完成有佐证，过期未完成标"滞后"，报告与台账一致。
- [ ] 对外材料没有未公开信息、报价、客户信息；绝对化表述有出处。
- [ ] 融合材料每条做法有业务结合点和结果；提法有原文出处并附核对清单。
- [ ] 没有个人敏感信息；人事事项只写职务。
- [ ] 开头直接写事项、结论或核心数据，没有形势背景和意义铺垫；篇幅按 `references/profile-detail.md` 第七部分或用户要求，没有为凑字数扩写。
- [ ] 程序、格式、数字的判断写明依据条款；没有替任何人写"已签"，没有代出合规审查、法律意见结论；未运行机检的已在起草说明写明。
- [ ] 正文没有 Markdown、免责声明、AI 自述；起草说明逐条汇总了全部【待补】【待核实】。

有 Python 环境时运行：`python scripts/gongwen_lint.py 正文.txt --doc-type 议题材料` 和 `python scripts/soe_check.py 正文.txt --type 议题材料`（类型按实际填）。无法运行时按第四步第 3 条人工检查。

## 角色适配

- 教学模式（新到董办、总经办、党群部的员工）：先讲决策链、前置研究的道理、议案和决议和纪要的区别；先给判定表或提纲，确认后成稿；起草说明附写作要点，含本稿的一处正误对照，写明每项【待补】一般到哪里找（财务快报、可研报告、会议记录、授权清单）。
- 高效模式（董办秘书、总经办笔杆子）：任务卡只写进起草说明；党委会版和董事会版、纪要和督办清单一次交付；决议按记录直接出；经营分析给全文和一页纸摘要两个篇幅。
- 转译模式（财务、投资、生产、人力等业务部门）：接受快报、表格、可研摘要、口述；只问口径（合并或本部、当月或累计、基期）和用途；台账来源写到原表的行；EBITDA、IRR 等术语照用，首次出现可加简短说明；不替用户下"风险可控""前景良好"的结论。
- 审稿模式（分管领导、董事会秘书、国资委处室审下级材料）：不提问，先给一页纸摘要，再按 `references/review-addon.md` 第三部分（或速查卡卡九）出问题清单，程序风险排最前，不重写全文；用户说"帮我改一版"再改。
- 严谨模式（党群岗、对外披露岗；ESG 报告和融合材料一律叠加）：提法只用用户提供的原文，附提法核对清单；对外数据逐项核对是否已披露；荣誉写授予机构和年份；有往年稿的标出雷同段落。

## 企业类型差异

按 `references/profile-detail.md` 第一部分（层级、出资关系、是否上市、央企或地方）和第六部分（其他单位）调整。最常漏的五处：
1. 二级及以下子企业：前置程序表加"上级企业审批或备案"；集团全资子企业不是国有独资公司，写"报集团公司决定（审批）"；数据写"本企业"口径，不与集团合并口径混用。
2. 国有独资公司：不设股东会，章程修改、合并分立、增减资、利润分配写"报履行出资人职责的机构决定"。
3. 国有控股、混合所有制、上市公司：关联交易写回避；对外材料核对是否已披露，决议公告由董事会办公室编制。
4. 地方国企：国资委规章多为参照，以本级国资委文件为准。
5. 国资监管机构（单位类型为党政机关）用审稿模式，不替企业补数据；高校、地方政府所属国有企业，出资人和审批链写学校、主管部门或本级政府，来自用户。
