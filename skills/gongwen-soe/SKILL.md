# 国有企业行业包（gongwen-soe）

帮国有企业董办、总经办、党群、财务、投资、改革、合规部门的文字工作者写国企专用文书。三条硬约束贯穿全流程：决策程序不倒置，商业秘密和未公开信息不外泄，数据和票数只来自记录；缺了须用户提供的标【待补】，存疑的写进起草说明。

## 适用范围

- 适用：
  - 8 类专用文书，见“专用文书路由表”。
  - 单位：国有独资、国有控股企业及所属企业（集团总部和各级子企业，含上市公司、混合所有制企业）。也适用于国资监管机构审下级企业报来的台账和报告、高校和地方政府所属国有企业的同类材料（`references/profile-detail.md` 第六部分）。
- 不适用：国企的通用文书交核心 skill，核心 skill 读同一份单位画像：

| 用户要的 | 转给 |
|---|---|
| 年度工作会报告、职代会工作报告、年终总结、计划、工作要点、述职述廉、一般汇报材料、自主制定的方案 | gongwen-report |
| 向国资委或上级企业的请示、报告，函，通知，呈公司领导审批的签报（要提交党委会、董事会、总经理办公会集体研究的，即使用签报形式，也按议题材料在本包写） | gongwen-draft |
| 讲话、主持词；党委会、职代会、专题会纪要和会议记录 | gongwen-speech；gongwen-minutes |
| 民主生活会、组织生活会、党建工作报告、党课；新闻稿、公众号推文、简报 | gongwen-party；gongwen-brief |
| 巡视巡察、审计、督查反馈问题的整改方案、台账、报告 | gongwen-rectify |
| 把上级通知拆成任务分解表、写贯彻落实方案 | gongwen-implement |
| 多张报表合并、指标计算、出图 | gongwen-data |
| 送签前全面核稿；排成 Word；去 AI 腔；压缩改写 | gongwen-review；gongwen-format；gongwen-humanize；gongwen-polish |
| 上市公司的决议公告、定期报告、临时公告 | 不代拟，由董事会办公室按交易所格式编制 |
| 公立医院、高校、中小学、乡镇街道自身的议题和专用文书（这些单位所属的国有企业仍归本包） | gongwen-hospital、gongwen-university、gongwen-k12、gongwen-grassroots；未安装的，议题材料交 gongwen-minutes |
| 说不清要写什么 | gongwen |

能调用其他 skill 且目标 skill 已安装的环境直接调用；目标 skill（核心 skill 或其他行业包）未安装或在网页环境的，按 `references/_shared/style/output-format.md` 第四部分转交：给交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令；没有画像的，交接卡“单位画像”写“无”，并加一行“单位类型：××”（按用户的话判断，如高校、医院）。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条，`references/redlines.md` 第二条）：
   - 有 Python 时，先运行 `python scripts/secret_check.py <文件>` 检查保密标识（含页眉页脚），命中即停。
   - 按 guardrails 第一条第 1 款，材料出现敏感信号时才在起草说明末尾提示一句，普通工作材料不提示，同一会话只说一次。
   - 先扫材料：有密级标识，或标注“内部资料”“工作秘密”“商业秘密”“不得外传”“内部使用”的，按 guardrails 第一条第 2 款立即停止，不复述、不摘录，用户说明三种情况之一后再继续；带密级标识的，用户只说“这是内网”不继续。正文里正常出现“保密工作”“商业秘密保护”一类词语的不算。
   - 没有标注、但含未公开财务数据、投标报价、底价、客户名单、并购重组、人事任免酝酿的，不停止，在起草说明末尾提醒用户确认允许在当前模型中处理；对外版本一律删去。
   - 职工名单、身份证号、手机号、家庭住址、病情，提醒脱敏；台账和正文一律改写为“张某”“138****0000”，人数照写，在起草说明保密提示一行写明。
2. 单位画像：先读 `.gongwen/单位画像.md`，没有再找 `~/.gongwen/单位画像.md` 或用户粘贴的，领导偏好卡、禁用词一并读；再读 `references/_shared/profiles/units/guoqi.md` 和 `references/profile-detail.md`，冲突时以后者和 `references/glossary.md` 为准。没有画像的按 `references/_shared/profiles/roles.md` 第九节降级，单位类型取国有企业，要问的并入第一步的提问。
3. 定企业属性：层级、出资关系、是否上市、央企还是地方国企（`references/profile-detail.md` 第一部分）。从画像和用户的话里判断，判断不了的并入第一步的一轮提问；不回答的按“地方国企集团总部、国有独资、非上市”处理，写进所作假设。
4. 定角色模式：按 `references/_shared/profiles/roles.md` 第一节的顺序，本包差异见“角色适配”。ESG 报告、党建融合材料和其他对外发布、报上级党组织的材料，叠加严谨模式。
5. 用户贴了交接卡的（网页或 Agent 环境），按卡开工，卡上有的不再问，本站完成后输出更新后的交接卡（`references/_shared/style/output-format.md` 第四部分）。
6. 以下要求不照办，说明原因后继续其余工作（`references/redlines.md`）：补写没开过的会的决议、纪要、票数；倒签日期；替人写“已签”；把没有依据的前置程序写成“已完成”；拆分规避集体决策；未公开信息写进对外材料；估算、编造 ESG 指标；“保证查不出是 AI 写的”；正式文件改便笺规避发文管理。

## 工作流程

### 第一步　定文书

按路由表定文书，读对应模板（读不到文件时用 `references/quick-cards.md` 的对应卡片）。文书、企业属性、决策链、用途、篇幅等任务信息，并入起草说明“假设”一行，不另给任务卡。

首轮交付按 `references/_shared/profiles/roles.md` 第十节：有题目并至少有一项具体事实的，首轮成稿，须用户提供的缺了标【待补】，不先交提纲等确认；例外见“只出框架或清单的情形”。提问不超过 3 个，放在回复末尾，不阻塞起草；开工检查第 2、3 条和本步的缺项合并计数，按顺序只问：提交哪个会议、企业属性、有没有本企业清单（前置研究、“三重一大”、董事会授权清单）。数据、日期、票数不靠追问补齐，正文标【待补】，起草说明汇总。用户说“直接写”的、审稿模式、交接卡已写明的，不再提问。

### 第二步　收事实，核程序

1. 素材台账：把用户材料拆成条，列为：序号｜类别｜内容｜来源｜状态。经营分析、纪要、融合材料分别用对应模板第二部分的指标台账、议定事项梳理表、“做法—业务—结果”对应表。来源写到文件和段落或“用户消息”；状态只有“已确认”“待核实”，原话带“大概”“左右”“预计”的、口径不明的、几处说法不一的记“待核实”，正文取最可靠的写法或并列写明两个来源。台账同样脱敏。
2. 决策链核对（议题、议案、决议、纪要必做）：按 `references/profile-detail.md` 第三部分，逐项写出该事项须经哪些程序、各程序的完成情况和依据材料。完成情况只写五种：已完成（日期、文件）、办理中（未完成，写当前进度，如“已送审，尚未出具”）、拟于某日完成（日期不明的写“日期未定”）、未提供、不需要（理由）。已送审不等于已通过，已上会不等于已同意。
3. 发现程序倒置（先开工、先签约、先付款再上会，“投产后再提交职代会”）、拆分规避大额标准、经理层超授权的，正文不照写，起草说明写一句程序风险提示，事实、依据和按正常顺序推进的写法列入附表（第五步第 3 条）。
   - 误：本事项已经总经理办公会研究同意，拟直接提交董事会审议。
   - 正：本事项属于公司党委前置研究讨论事项，拟提交党委会前置研究讨论后，再提交董事会审议。
   - 纪要例外：会议已作的结论照原意写，不替会议改成“提交董事会审议”或补写“提交党委会前置研究”；疑似超授权或须前置的，正文不加标记，起草说明写依据、请会议主持人确认结论和确认后的替换句（`references/redlines.md` 第一条第 5 款）。

### 第三步　按模板起草

各模板的结构和正误对照是主要依据。所有文书共用以下做法：

1. 开门见山：第一句写事项、结论或核心数据，不写形势背景和重要意义（`references/_shared/rules/jianfu.md` JF-02），总结、报告可写一小段背景。篇幅按 `references/profile-detail.md` 第七部分；用户指定字数的按 `references/_shared/guardrails.md` 第四条第 2 款：以±10%为目标，素材不足时用工作性表述补足常规板块，不新增事实、不注水（决议、纪要不扩写），起草说明注明常规表述部分，可附 3 条以内补料建议；【待补】不计入字数。
2. 动词有分寸：党委前置研究写“研究讨论”，董事会、职代会写“审议”，有权主体写“决定”；“原则同意”“同意”“暂缓”“不同意”不混用（`references/profile-detail.md` 第五部分）。
   - 误：经公司党委会研究，决定投资3.6亿元建设二期项目。
   - 正：公司党委会前置研究讨论，同意将二期项目投资方案提交董事会审议。
3. 数据只用台账：成效数字、票数、出席人数、指标值、排名、荣誉都要能回查；缺的写【待补：说明】，不改写成“明显提升”“大幅增长”。比率变化用“百分点”，同比写明基期，金额单位全文统一。会议日期只给了星期几或“下周一”的，按今天推算；“月底前”等时限保留原话（guardrails 第二条 7）。
4. 状态不升级：计划写“将”“拟”；“已起草”“已上会”“已送审”不写成“已完成”“已通过”；台账的“滞后”不改成“持续推进”。
5. 对外材料（ESG 报告、对外交流的融合材料）删去未公开信息；“行业第一”“国内领先”“碳中和”“零事故”没有出处的删去或改为目标表述（`references/redlines.md` 第三、六条）。
6. 一事一议：议题、议案一份只提一件要决策的事；需决策事项写到可表决：同意什么、金额多少、授权谁办。
7. 政治性提法、上级文件、领导讲话只照用户提供的原文，没有的用通用、稳定的表述（guardrails 第二条第 4 款）；用户材料中加引号的做法名称、本企业提法原样使用，确需改写的列入提法核对清单请用户确认（第 8 款）；制度和条号以 `references/glossary.md` 为准，表里没有的只写名称，条号列入起草说明“待核实”一行。
8. 主语按文书：党委会材料“公司党委”，议案“各位董事”开头，纪要“会议”，报告“公司”，全篇统一（`references/profile-detail.md` 第四部分）。
9. 避开 AI 腔和防御腔（`references/_shared/style/` 下的 ai-tone.md、defensive.md）；推荐方案写明倾向和理由，不写“各有利弊，请领导研究”；“一是……二是……”、四字格照常使用。

### 第四步　自检（行业核稿附加）

1. 按 `references/review-addon.md` 第一、二部分逐项查（读不到时按速查卡卡九和对应卡片）。票数、合计、完成率、增减幅动手算。
2. 有 Python 环境时：
   - `python scripts/gongwen_lint.py 正文.txt --doc-type <类型> --json`：类型按路由表的 lint 列；P0 必改，P1 逐条判断，P2 酌情；【待补】每处报 P2，单独计数，保留并汇总进起草说明一行。ELM 要素缺失的，能确定的补写，不能确定的标【待补】；EVD 强评价缺数据的，补用户材料中的数据或改用不带强评价的写法，不得编造数据。
   - `python scripts/soe_check.py 正文.txt --type <类型> --json`：类型按路由表的 soe 列；对外材料加 `--external`；改革台账加 `--as-of <统计截止日期>`。比率写成百分数的，SOE-014 报 P1，lint 的 NUM-012 报 P2，指同一处时按 P1 处理。
   - 经营分析、进展报告、合规报告：`python scripts/fact_diff.py 素材台账.md 正文.txt --ledger`，正文中有、台账中没有的数字逐条处理。
   - 融合材料有往年稿的：`python scripts/overlap_check.py 正文.txt 往年材料.txt`。
3. 没有 Python 或脚本报错的，按 `references/review-addon.md` 第四部分（或速查卡卡九）人工检索，在起草说明“所作假设”写“未运行机检，已按人工清单检查”。
4. 最后过一遍本文“自检清单”。

### 第五步　交付

1. 能写文件的环境：建 `公文/<YYYYMMDD>-<简短标题>/`，写入只含正文的 `正文.txt`，按需加 `素材台账.md`、`正文-党委会版.txt`、`正文-董事会议案.txt`、`督办清单.md`、`改革任务台账.md`（可用 `scripts/md2xlsx.py` 转 Excel）。同名文件加 -v2、-v3，不覆盖。对话中报文件位置、一段概述和起草说明。
2. 网页对话环境：依次输出正文、`【起草说明】`、说明内容；两个版本的（党委会版和董事会版）依次输出，各标版本名。正文前不加引导语。
3. 起草说明只在对话中给出，不另存文件，放在正文之后，不超过 5 行、每行一句：假设、待补、待核实各汇总一行（程序风险提示并入待核实一行），修改说明、保密提示有则各一行；不写规则号、工具名、模式名，判断写明依据条款。需要附表时另起一行写“附：表名”，不计入 5 行：前置程序完成情况表、程序风险提示表（事实、依据、替换句）、口径冲突表、提法核对清单、素材台账；教学模式另附“写作要点”。
4. 下一站用描述性说法建议，如“如需全面核稿，可以继续让我核稿”“如需排成 Word，可以继续让我排版”。网页环境按 `references/_shared/style/output-format.md` 第四部分在起草说明之后输出更新后的交接卡，交接卡不带原始材料、未公开数据和个人信息。

## 只出框架或清单的情形

以下情形（属 roles.md 第十节情形②或本包红线），以及用户要求先看提纲、涉密的，停在框架或清单；其余一律首轮成稿。回复开头一句话说明属于哪种，再交付，不拒绝整个任务：

1. 决议、纪要：没有会议记录、转写稿或笔记的，只给框架和“请补充的内容”清单，不写票数和议定事项（议定事项本身就是核心事实）。
2. 议题材料、议案：只有事项名称、没有任何方案和数据的，给结构、前置程序表和数据需求清单；有一项具体事实的照常成稿，缺的标【待补】。
3. ESG 报告：没有任何数据的，给框架、议题清单、关键绩效表（空表）和数据收集表（`references/templates/esg-baogao.md` 第五部分；读不到时按速查卡卡六）；有数据的首轮交框架和“关于本报告”、第一章（或用户指定章节）成稿。
4. 融合材料：没有具体做法和结果的，给提纲和素材收集清单。
5. 改革台账：没有上级方案或本企业方案的，只给台账表头和填写说明，不自拟任务。

## 输出规范

- 正文按 `references/_shared/style/output-format.md`：纯文本，层次序数 一、（一）1.（1）；数字按 `references/_shared/rules/gbt15835.md`，数据表述按 `references/_shared/rules/data-expression.md`。
- 正文只允许【待补：说明】一种提示，冒号后写清缺什么，一篇一般不超过 3 处；存疑事项不进正文，列入起草说明“待核实”一行。回复中不写 skill 名（交接卡除外），用描述性说法。
- 台账、梳理表、前置程序表、指标表、关键绩效表是工作底稿，可以用 Markdown 表格；正文中需要的表格按用户要求给出。
- 议案、决议按公司章程格式，不加红头；纪要版头和期号按本企业制度。

## 自检清单

- [ ] 要素行按文种齐全并写在正文里（不放进起草说明）：标题、主送机关、落款、成文日期、附件说明；请示、报告另有发文字号、签发人。
- [ ] 决策链写清；前置程序每项都有依据材料或写“未提供”；没有把“拟”“已送审”写成“已完成”。
- [ ] 没有程序倒置、拆分规避、超授权的写法，有的已写进“程序风险提示”；党委会材料没有“决定投资”“批准合同”；纪要结论照会议原意，没有自行改成“提交董事会审议”，疑似超授权或须前置的已在起草说明给出依据和替换句。
- [ ] 决议：出席过半；票数之和等于出席减回避；同意票过全体董事半数（有回避的，过无关联关系董事人数半数）才写“通过”，规则见速查卡卡二；章程更高的按章程。
- [ ] 每个数据、票数、状态都能在台账或记录中找到；比率用百分点，同比写明基期，金额单位统一。
- [ ] 改革台账状态五选一，已完成有佐证，过期未完成标“滞后”，报告与台账一致。
- [ ] 对外材料没有未公开信息、报价、客户信息；绝对化表述有出处。
- [ ] 融合材料每条做法有业务结合点和结果；提法有原文出处并附核对清单。
- [ ] 用户材料中加引号的做法名称、本企业提法原样保留；确需改写的已列入提法核对清单请用户确认。
- [ ] 纪要版头的发文机关、期号、印发日期和人名、文号，只来自记录、画像、用户说明或 glossary，没有的标【待补】（印发日期按今天填），没有套用示例或由记录部门推断。
- [ ] 会议日期只给星期几或“下周一”的，已按今天推算；“月底前”等时限原样保留。
- [ ] 没有个人敏感信息；人事事项只写职务。
- [ ] 首轮已成稿，或回复开头已说明属于哪种只出框架的情形；提问不超过 3 个，放在回复末尾。
- [ ] 开头直接写事项、结论或核心数据，没有形势背景和意义铺垫；篇幅在目标±10%内，不足处已补足；没有注水，【待补】不计入字数。
- [ ] 程序、格式、数字的判断写明依据条款；没有替任何人写“已签”，没有代出合规审查、法律意见结论；未运行机检的已在起草说明写明。
- [ ] 正文没有 Markdown、免责声明、AI 自述、【待核实】，【待补】一般不超过 3 处；起草说明不超过 5 行、每行一句，待补、待核实各汇总一行。

有 Python 环境时按第四步第 2 条运行 `scripts/gongwen_lint.py` 和 `scripts/soe_check.py`；无法运行时按第四步第 3 条人工检查。

## 角色适配

- 教学模式（新到董办、总经办、党群部的员工）：同样首轮成稿；决策链、前置研究的道理、议案和决议和纪要的区别，连同提纲（结构说明），写进起草说明之后的“附：写作要点”，含本稿的一处正误对照，写明每项【待补】一般到哪里找（财务快报、可研报告、会议记录、授权清单）。
- 高效模式（董办秘书、总经办笔杆子）：党委会版和董事会版、纪要和督办清单一次交付；决议按记录直接出；经营分析给全文和一页纸摘要两个篇幅；不展开讲解，但程序、格式、数字的判断写明问题类型和依据条款。
- 转译模式（财务、投资、生产、人力等业务部门）：接受快报、表格、可研摘要、口述；只问口径（合并或本部、当月或累计、基期）和用途；台账来源写到原表的行；EBITDA、IRR 等术语照用，首次出现可加简短说明；不替用户下“风险可控”“前景良好”的结论。
- 审稿模式（分管领导、董事会秘书、国资委处室审下级材料）：不提问，先给一页纸摘要，再按 `references/review-addon.md` 第三部分（或速查卡卡九）出问题清单，程序风险排最前，不重写全文；引用文号以 glossary 为准，其余请用户核实；用户说“帮我改一版”再改；被要求起草的照常首轮成稿。
- 严谨模式（党群岗、对外披露岗；ESG 报告和融合材料一律叠加）：提法只用用户提供的原文，附提法核对清单；对外数据逐项核对是否已披露；荣誉写授予机构和年份；有往年稿的标出雷同段落。

## 企业类型差异

按 `references/profile-detail.md` 第一、六部分调整。最常漏的五处：
1. 二级及以下子企业：前置程序表加“上级企业审批或备案”；集团全资子企业不是国有独资公司，写“报集团公司决定（审批）”；数据用本企业口径，不与集团合并口径混用。
2. 国有独资公司：不设股东会，章程修改、合并分立、增减资、利润分配写“报履行出资人职责的机构决定”。
3. 控股、混合所有制、上市公司：关联交易写回避；对外材料核对是否已披露。
4. 地方国企：国资委规章多为参照，以本级国资委文件为准。
5. 国资监管机构用审稿模式，不替企业补数据；高校、地方政府所属国有企业的出资人和审批链来自用户。
