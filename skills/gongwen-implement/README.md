# 上级文件转化（gongwen-implement）

> 版本 1.0.0　成熟度：Beta（测试版）

上级发来通知、意见、行动方案，本单位要限期拿出实施方案，事后还要报落实情况。这个 skill 帮你把上级文件逐条拆开，做成任务分解表，再写成本单位的方案。上级文件的每一条都有着落，任务写的是你们单位自己的措施；你没给的措施和数据标【待补】，不替你编。写完会检查有没有照抄上级原文、时限是不是早于上级、有没有层层加码。

## 能做什么

| 功能 | 说明 |
|---|---|
| 提取上级文件要点 | 按原文条款编号，列出目标、任务、时限、责任分工、报送要求，标明哪些归本单位 |
| 任务分解表 | 任务、牵头单位、配合单位、完成时限、成果形式、对应上级条款；有 Python 时可转成 Excel |
| 实施方案、贯彻落实方案 | 开门见山，任务写本单位的对象、数量和部门，篇幅按减负规定控制 |
| 对标对表 | 上级文件每一条都核对有没有落实，漏项列出来；已写好的方案可以只挑问题，已写好的落实情况报告可以核对与任务表是否一致 |
| 照抄检测、照抄初稿改写 | 用 `scripts/overlap_check.py` 比对方案和上级文件，列出重合率和高重合段落；照抄的初稿按你给的本地措施改写，前后各测一次；没有 Python 时按清单人工比对 |
| 时限倒排、加码提示 | 本单位时限早于上级，提前多少按实际需要；标准、频次、报材料、一票否决等超出上级要求的逐条提示 |
| 贯彻落实情况报告 | 按任务分解表逐项报进展，附对账表，状态与材料一致 |
| 学习传达要点 | 上级会议、文件精神的传达提纲，主要精神只取原文，附提法核对清单 |

## 可以这样说

1. “省里发了个专项整治的通知，区里要10天内出实施方案，帮我们局把任务拆一下。”
2. “市卫健委这个文件，帮我转化成我们医院的落实方案，科室分工我写在下面了。”
3. “领导说我们的方案跟上级文件太像了，基本是抄的，帮我改成我们自己的措施。”
4. “上级要报贯彻落实情况了，按之前的任务表把进展写成报告。”
5. “下周党委会要传达集团工作会议精神，帮我整理个传达要点。”

## 输入

- 必需：上级文件原文（粘贴文字，或 txt、docx 文件）。没有原文时只能给框架，不会凭印象写上级文件的内容。
- 最好提供：本单位职责分工（谁牵头）、现有基础和数据、准备怎么做、领导已定的意见、本单位时限。
- 可选：单位画像 `.gongwen/单位画像.md`。没有画像也能用，最多问 3 个问题。
- 写落实情况报告时：任务分解表和每项任务的进展。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `要点表.md` | 上级文件要点表 |
| `任务分解表.md`、`任务分解表.xlsx` | 任务分解表（xlsx 需要 openpyxl） |
| `正文.txt` | 方案或报告正文，纯文本，可直接粘进 Word 或交给 gongwen-format 排版 |
| `起草说明.md` | 所作假设、待补和待核实事项、对标对表核对表、时限倒排表、加码风险提示、重合检测结果 |
| `上级文件.txt` | 你提供的上级文件（删去联系人信息），供重合检测比对；多份文件分别存为 `上级文件-甲.txt`、`上级文件-乙.txt` |

在网页大模型里使用提示词版时，依次输出正文、起草说明和各张附表。

## 注意事项

1. **保密**：请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。上级文件标有密级或“内部资料”“工作秘密”“不得外传”等字样时会停止处理；只标“此件不公开”的照常处理，但会提醒你确认其中不含工作秘密。材料里有个人姓名、手机号、身份证号的，请先脱敏；产出中会改用“张某”“138****0000”。
2. **不编造**：上级文件的名称、文号、指标、时限只取原文；本单位措施、牵头部门、数据只用你提供的。缺的标【待补】，补齐后再定稿。你材料里加引号的做法名称和本单位提法原样保留；你只说“下周五”“月底”的，不会替你推算成具体日期。
3. **首轮直接出稿**：有上级文件原文，就一次交付要点表、任务分解表和方案，问题放在最后，最多3个。只有拿不到原文、你要求先看要点表、材料涉密时才停下。指定了字数而素材不够的，会在回复第一段说明差距并列出要补的材料，不注水。
4. **时限要你拍板**：没告诉它本单位时限的，它会给出倒排建议，正文先标【待补】；你说“时间你倒排”，它才直接写日期。落实情况报告里滞后任务的新完成时限也由你定，它不会自己填日期。
5. **不为降重而改写**：照抄的段落要换成本单位的具体措施。没有措施时它会标【待补】，不会用近义词把上级原文改头换面。
6. **重合率只是参考**：重合率反映的是文字相同的程度，是否照搬由人判断；指标数值、带引号的底线要求和提法原文可以保留。
7. **事实和判断由你负责**：方案是否印发、标准怎么定、时限怎么排，由你和你的单位决定。

## 与其他 skill 的分工

| 需求 | 用哪个 |
|---|---|
| 只转发上级文件、不拆任务；印发方案用的通知 | gongwen-draft |
| 没有上级文件依据、本单位自主制定的方案、计划、工作要点 | gongwen-report |
| 巡视巡察、审计、督查反馈问题的整改材料；按清单自查 | gongwen-rectify |
| 本人的学习心得、研讨发言、党课 | gongwen-party |
| 部署会、传达会上的领导讲话 | gongwen-speech |
| 会议议定事项的督办清单 | gongwen-minutes |
| 方案压缩篇幅 / 核稿 / 排成 Word | gongwen-polish / gongwen-review / gongwen-format |
| 装有行业包时：中小学课后服务方案（有上级通知的也算）、国企改革任务台账和改革进展报告等行业专用文书 | gongwen-k12、gongwen-soe 等对应行业包；没装的照常用本 skill 或上面各行的 skill |

能调用其他 skill 的工具里会直接转交；目标 skill 没装或在网页大模型里，会给你交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令（见 `references/_shared/style/output-format.md` 第四部分）。

一份实施方案的完整链路：gongwen-implement 拆文件、出任务表和方案 → gongwen-draft 写印发通知 → gongwen-review 核稿 → gongwen-format 出 docx。

## 成熟度

Beta。要点提取、任务分解、对标对表、照抄检测、时限倒排、加码提示和落实情况报告的流程已可用；评测用例见 `evals/`。已知局限：
- 照抄检测按连续相同的文字比对，查不出改了说法的照搬，任务段落是否真正落地仍靠人按清单判断；
- 任务分解表转 Excel 依赖共享脚本 `md2xlsx.py`，没有 openpyxl 或脚本未就绪时需要手工复制表格；
- 法定节假日无法自动识别，倒排时限遇到节假日需要人工调整。
