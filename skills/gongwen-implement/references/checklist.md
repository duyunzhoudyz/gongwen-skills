# 人工自检清单（无法运行脚本时）

网页版、内网没有 Python、脚本报错时，按本清单逐项检查，在起草说明写“未运行机检，已按人工清单检查”；照抄比对按 `references/localize.md` 第三部分，另写“未运行重合检测，已人工逐段比对”。

## 一、残留与格式

1. 正文没有 `#`、`**`、`-` 列表、`>` 引用、代码块；表格只出现在【起草说明】之后。
2. 正文前没有“以下是为您撰写的”，正文中没有“仅供参考”“请结合实际情况调整”、AI 自述、emoji。
3. 层次序数依次为 一、（一）1.（1），不跳级；“（一）”后不加标点，“1.”用下脚点。
4. 一级标题独占一行，末尾不加标点；“（一）检查住宅电梯。”这种与正文同段的标题，末尾用句号。
5. 正文中的提示只有【待补：说明】一种，全角方括号、全角冒号，冒号后写清缺什么；没有【待核实】，【待补】一般不超过 3 处。

## 二、标点与数字

1. 中文语境用全角标点；引号用“”。
2. 标题末尾不加标点；标题中除法规、规章、规范性文件名称外一般不用书名号。
3. 发文字号用六角括号，不加“第”字：某政办发〔2026〕37号。
4. 日期写全：2026年6月19日；本单位时限可写“6月19日前”。年份不简写。
5. 数值范围写全单位：15%～30%、9亿～16亿元。
6. 百分比与百分点不混用：比率之差用“百分点”。

## 三、事实与标记

1. 上级文件的名称、文号、成文日期、指标数值、时限，逐个回到原文核对，一字不差。
2. 正文中每个本地数字（电梯台数、户数、公里数、金额）都能在用户材料中找到；找不到的改为【待补】；措施按上级要求和常规写出的不在此列。
3. 牵头单位、配合单位、统筹单位都来自用户、画像或上级原文的分工；没有依据的牵头单位改为【待补：牵头单位】，配合单位删去。
4. 本单位时限：用户给的，或用户授权倒排的；其余为【待补：完成时限，须早于上级要求的×月×日】。
5. 起草说明不超过 5 行，待补、待核实各汇总一行，写明正文位置。
6. 用户说的“下周五”等相对日期已按今天推算为具体日期；“月底前”等期限原样保留。
7. 用户材料中加引号的做法名称、本单位提法原样保留；确需改写的已列入提法核对清单，请用户确认。

## 四、对标对表

1. 要点表覆盖了上级文件的正文和全部附件。
2. 每一条都有结论：已对应、不涉及（有理由）、漏项（已处理）。
3. 报送要求、工作要求、禁止性规定都有着落。
4. “本单位自定”的任务做了加码检查。

## 五、照抄、加码、时限

1. 任务和措施段落没有与上级原文连续15字以上相同的句子；照录的行动名称和事项名称、目标数值、引号内的底线要求和提法原文除外。没有把【待补】插在照抄句中间。
2. 没有只换主语或近义词的段落。
3. 标准、范围、频次没有超出上级；没有一票否决、责任状、按月排名、千分制、“纳入年度考核”；没有要求下级报送贯彻落实情况或再定配套方案（用户坚持的已列入加码提示）。
4. 每个本单位时限都早于上级对应时限，预留不超过汇总、审核、报送的需要。

## 六、篇幅与文风

1. 部署专项工作的方案正文一般不超过4000字（党政机关、基层、社区）；医院、学校、国企超过时已在起草说明提示。用户指定字数或时长的，在目标±10%内，不足的已用工作性表述补足；【待补】不计入字数，没有注水。
2. 首段一句话写依据和目的，没有空泛的形势背景、重要意义。
3. 部署用“要”“于×月×日前完成”，没有“建议”“可以考虑”“尽量”“适时”。
4. 没有“值得注意的是”“不是……而是……”、提示性冒号（“核心是：”）、拟人化比喻、“赋能”“闭环”堆砌。

## 七、按产品补查

- 落实情况报告：开头项数与对账表一致；状态都有用户材料依据；没给进展的标了【待补：进展情况】；下一步安排的时限取自任务表或用户材料，滞后任务的新时限标了【待补】；没有“请批准”“妥否”等请求性语句。
- 学习传达要点：主要精神每条都能在原文找到；引号内逐字一致；提法核对清单完整；没有凭记忆补的引语。
- 对标对表检查：问题清单每条有位置、原文、问题、依据、建议；没有输出改写后的全文（用户要求改的除外）；审核落实情况报告的，附任务进展对账表，任务表每一项都核对了报告中的说法。
