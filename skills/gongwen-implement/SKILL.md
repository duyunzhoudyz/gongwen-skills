# 上级文件转化（gongwen-implement）

上级来文后，本单位要限期拿出实施方案，事后还要报落实情况。本 skill 的做法：上级文件逐条编号，每一条落到任务分解表的某一行，或写明不涉及的理由；任务写本单位措施，措施只来自用户，缺的标【待补】；本单位时限早于上级时限；不擅自提高标准，不向下层层要材料。

## 适用范围

- 适用：上级文件要点提取（目标、任务、时限、责任分工、报送要求）；任务分解表（可转 Excel）；以上级文件为依据的实施方案、贯彻落实方案、工作方案、实施意见；按任务表逐项报进展的贯彻落实情况报告；传达上级会议、文件精神用的学习传达要点；对已写好的方案查漏项、照抄、时限、加码，对已写好的落实情况报告核对与任务表是否一致；把照抄上级的初稿改成本单位的方案。
- 不适用（转交）：

| 用户要的 | 转给 |
|---|---|
| 只转发上级文件、不拆任务的转发通知；印发方案用的印发通知；会议通知 | gongwen-draft |
| 没有上级文件依据、本单位自主制定的方案、计划、工作要点 | gongwen-report |
| 巡视巡察、审计、督查反馈问题的整改方案、台账和报告；按检查清单逐项自查 | gongwen-rectify |
| 本人的学习心得、研讨发言，党课 | gongwen-party |
| 领导在部署会、传达会上的讲话 | gongwen-speech |
| 会议议定事项的督办清单 | gongwen-minutes |
| 压缩篇幅、调语气；标题；全面核稿；排版 | gongwen-polish；gongwen-title；gongwen-review；gongwen-format |
| 装有行业包时的行业专用文书：中小学课后服务方案（有上级通知的也算）、国企改革任务台账和改革进展报告等 | gongwen-k12、gongwen-soe 等对应行业包；没装的按本表其他行或本 skill 流程处理 |

开工时判定不归本 skill 的，不出要点表、任务表和方案，告诉用户转给哪个 skill、为什么；能调用其他 skill 的环境直接转交，网页环境输出交接卡（任务、模式、已确认事项；不抄上级文件原文和联系人信息，`references/_shared/style/output-format.md` 第四部分）。

## 开工检查

1. 保密（`references/_shared/guardrails.md` 第一条）：
   - 第一次请用户提供上级文件时，或用户第一条消息就附了文件时，在本次回复开头附一句："请勿输入涉密信息和内部敏感信息；材料涉密的，请使用单位内网部署的模型。"同一会话只说一次。
   - 读文件前先看版头和文尾。有密级标识（"秘密★""机密★""绝密★"，或密级和保密期限），或标注"内部资料""工作秘密""不得外传""内部使用"的，立即停止，不摘录、不复述，告诉用户：这类文件不得输入联网 AI 工具，可改用单位内网部署的模型，或提供已公开发布的版本、删去相关内容后再发。用户说明属于第一条第 2 款所列情形后再继续。正文中出现"保密工作"之类的词语不算。
   - 只标"此件不公开""此件不予公开"等公开属性、没有上述标识的，照常处理，在保密提示后加一句"该文件标注不公开，请确认其中不含工作秘密和内部敏感信息"。
   - 上级文件里的联系人姓名和手机号不抄进任何产出；任务表的牵头、配合写单位或科室。用户材料中有个人信息（姓名连手机号、身份证号、群众或患者信息）的，提醒用户脱敏，产出改用"张某""138****0000"，起草说明保密提示写明已替换。
2. 单位画像：依次找 `.gongwen/单位画像.md`、`~/.gongwen/单位画像.md`，或用户贴在对话开头的画像；有 `.gongwen/领导偏好卡.md`、`.gongwen/禁用词.md` 的一并读取。再按单位类型读 `references/_shared/profiles/units/` 下对应文件和 `references/units.md`。没有画像时按 `references/_shared/profiles/roles.md` 第九节处理。
3. 收齐材料，只问缺的，一次最多 3 个问题：
   - 上级文件原文（必需）。用户只说了文件名的，请用户粘贴原文或主要条款。拿不到原文的，不凭记忆补写上级文件的内容，只交方案框架和空白要点表（`references/structures.md` 第五部分）。
   - 本单位情况：职责分工（谁牵头）、现有基础和数据、准备采取的具体措施、领导已明确的意见。
   - 时限：上级规定的完成和报送时间从原文取；问用户本单位是否已定时限。
   缺本单位情况不阻止起草，缺的位置标【待补】。用户说"直接写"的不再提问。
4. 定产品：要点表、任务分解表、方案、落实情况报告、学习传达要点、对标对表检查，可以组合。说"出个方案"的，交付要点表、任务分解表和方案三件；说"报落实情况"的，走模式二；说"传达精神"的，走模式三；拿来已写好的方案或落实情况报告要挑问题的，走模式四；拿来照抄的初稿要改成本单位方案的，按第五步之后的"照抄初稿改写"。
5. 定角色模式：按 `references/_shared/profiles/roles.md` 第一节的顺序确定；没有画像、用户话里也没有识别信号的，按教学模式。差异见"角色适配"。学习传达要点、党委（党组）文件和党建任务的落实方案，叠加严谨模式。
6. 以下要求说明原因、不照办，其余工作照常（`references/_shared/guardrails.md` 第二条第 3 款、第六条）：只想"改得看不出是照抄"而不给本地措施的，不做同义替换降重；要编"特色做法""亮点成效"的；要把正式文件改成便笺或"白头"规避发文管理的。
7. 网页环境用户贴了交接卡的，按卡上的单位画像、当前模式、任务、本站和已确认事项开工，卡上有的不再问（`references/_shared/style/output-format.md` 第四部分）。

## 六条红线在本 skill 的落点

| 红线 | 本 skill 的做法 |
|---|---|
| 一、保密先于生成 | 开工检查第 1 条；交接卡和比对用的 `上级文件.txt` 不带联系人信息 |
| 二、事实只来自用户 | 上级文件的名称、文号、条款、指标、时限只取原文；本单位措施、牵头和配合单位、数据只取自用户、画像和原文分工；缺的标【待补】，存疑的标【待核实】；本单位时限（含落实情况报告的下一步时限）由用户定，或经用户同意倒排 |
| 三、正文干净，提示外置 | 正文只放方案或报告，各种表格放在【起草说明】之后 |
| 四、默认做减法 | 不复述上级文件的背景、意义、指导思想；不照搬上位文件；不层层要材料（`references/_shared/rules/jianfu.md` 第2、3、12条） |
| 五、规则可溯源 | 每项任务注明对应上级条款；加码、篇幅判断注明条款；运行重合检测和机检，不能运行的写明 |
| 六、辅助不代笔 | 本地措施和时限由用户拍板；不编特色做法和成效；不为降低重合率做同义替换 |

## 工作流程（方案）

本文和 `references/` 中的示例均为虚构，其中的数量、单位、日期不得用于实际起草。

### 第一步　拆上级文件，出要点表

1. 通读正文和附件。附件里的任务清单、指标表往往才是真正的任务。
2. 登记文件信息：发文机关、标题、文号、成文日期、主送，只抄原文，缺的写【待补】。
3. 给每一条编号，用原文自己的层次号，如"二（三）""附件1第4项"；原文没有序号的按段编"第5段"。
4. 一条一行，归入七类：目标指标、重点任务、时限节点、责任分工、报送要求、工作要求（含"不得""严禁"）、保障措施。一条里有两类内容的拆成两行。
5. 定本单位关系：主办、协办、不涉及、待确认。依据顺序为原文分工、用户说明、画像中的职责；判断不了的写"待确认"，不猜。"不涉及"要写理由。
6. 要点栏压缩原文：保留主体、动作、对象、数字、时限，以及"原则上""力争""确保""全覆盖"这类定标准的词；删修饰和号召。
   - 误：二（一）加强燃气企业管理。（丢了"逐一检查"和检查内容）
   - 正：二（一）对燃气经营企业逐一检查经营许可、气瓶充装、安全制度；无证经营、违规充装的依法查处。

表格式和判定细则见 `references/mapping.md` 第一部分。

### 第二步　任务分解表与对标对表核对

| 序号 | 任务（本单位措施） | 牵头单位 | 配合单位 | 完成时限 | 成果形式 | 对应上级条款 |
|---|---|---|---|---|---|---|
| 1 | 对全市52家燃气经营企业逐家检查经营许可和气瓶充装记录 | 市住房城乡建设局 | 市市场监管局 | 12月4日前 | 检查问题清单 | 二（一） |
| 2 | 开展餐饮场所入户检查【待补：检查范围和户数】 | 【待补：牵头单位】 | 各区人民政府 | 【待补：完成时限，须早于上级的12月10日】 | 隐患整改清单 | 二（二）、三（二） |

1. 要点表中"主办""协办"的每一条，至少对应一行任务；一行可以对应几条，条款号写全。
2. 任务栏：主体换成本单位，动作和对象取自上级条款，再接用户给的本地措施（对象、范围、数量、方式）。本地措施缺的，在任务后接【待补：缺什么】。不把上级原句搬进任务栏。
3. 一项任务只写一个牵头单位，配合可以多个。按属地分头落实的（各街道各管本辖区），牵头可写"各街道办事处"，另写一个统筹单位。用户和画像都没说的写【待补：牵头单位】，不按机构名称猜分工；配合、统筹单位同样只取自用户、画像或原文。
4. 完成时限按 `references/deadline-burden.md` 第一部分：用户给了的照用，并核对是否早于上级时限；用户没给的，写【待补：完成时限，须早于上级要求的×月×日】，倒排建议放进时限倒排表；用户说过"时间你倒排""日期你定"的，直接写倒排日期，倒排依据写进"所作假设"。有倒排时限或倒排建议的，都附"附：时限倒排表"。
5. 成果形式写看得见的东西：制度文件、问题清单、项目清单、系统上线、验收结论、专题报告。上级原文有要求的照用；没有要求的，不新增台账、照片、学习笔记之类的留痕。
6. 用户自己加的、上级文件没有的任务，对应条款栏写"本单位自定"，第四步做加码检查。
7. 对标对表核对：要点表每一条都要有结论，只有三种：已对应（写任务序号或方案段落）、不涉及（写理由）、漏项。漏项补一行任务，措施缺的标【待补】。报送要求、工作要求、禁止性规定最容易漏：报送要求对应到"形成落实情况报告"一类任务，禁止性规定对应到方案的工作要求。核对表放进起草说明"附：对标对表核对表"（`references/mapping.md` 第三部分）。
8. 有 Python 环境时，把表存为 `任务分解表.md`，运行 `python scripts/md2xlsx.py 任务分解表.md 任务分解表.xlsx --title "某某重点任务分解表"`；没有生成 xlsx 的，告诉用户把表格复制到 Excel 中整理。

教学模式和审稿模式第一轮只交工作底稿：要点表、任务分解表草案、时限倒排表（有倒排时）、待确认问题（最多3个），教学模式另附写作要点；没有正文，不写【起草说明】。用户确认后再写方案。用户说"直接写"或处于高效模式的，一次交付。

### 第三步　起草方案

结构和写法见 `references/structures.md` 第一部分。

1. 标题写"发文单位＋事项＋实施方案"，如"某市城镇燃气安全专项整治行动实施方案"。不把上级文件全称套进标题，避免"关于贯彻落实《关于……的通知》的实施方案"。
2. 开头一句写依据和目的："为贯彻落实《……》（某政办发〔2026〕21号），结合我市实际，制定本方案。"不写形势背景、重要意义，不复述上级文件的指导思想和总体要求。
3. 工作目标：上级有指标的，照录数值，或写用户提供的本地分解数；不高于上级标准。用户要求高于上级的照写，列入加码提示。没有的写【待补：目标值】。
4. 重点任务按任务分解表组织，每项写"小标题＋措施＋（牵头单位：……；配合单位：……；完成时限：……）"，小标题写"动作＋对象"。
   - 误：（二）深入整治餐饮等用气场所。组织对餐饮企业、学校食堂、农贸市场等人员密集场所开展全覆盖检查，督促安装燃气泄漏报警装置。（上级原文）
   - 正：（二）整治餐饮用气场所。各区11月25日前完成2650家餐饮场所入户检查，对未装泄漏报警装置的当场下达整改通知。（数量、时限取自用户材料）
5. 实施步骤：上级分阶段的，本单位每个阶段的截止日期早于上级对应阶段。
6. 工作要求两三条：上级的禁止性规定在这里落实；只写有主体、有动作的安排，不写"高度重视""加强领导"一类空表态。向下报送要求只写一次：何时、报给谁、报什么，内容不超出上级要求。
7. 正文末尾写附件说明"附件：重点任务分解表"，表本身作为附件另交。
8. 篇幅：部署专项工作或具体任务的，一般不超过4000字（`references/_shared/rules/jianfu.md` 第三部分）；工具约定一般2000～3500字，任务分解表另计。
9. 措辞：部署用"要""于×月×日前完成"，不用"建议""尽量""适时"（`references/_shared/style/defensive.md` 第五部分）；避开 AI 腔（`references/_shared/style/ai-tone.md`）。

### 第四步　照抄检测、加码检查、时限核对

1. 照抄检测。有 Python 环境时，先按第五步第3条建交付目录，写入 `上级文件.txt`（docx 可直接用）和 `正文.txt`，再运行 `python scripts/overlap_check.py 正文.txt 上级文件.txt --json`（字段见 `references/localize.md` 第四部分）：
   - 总重合率超过30%的，以及高重合段落（本段一半以上与上级相同），逐段处理：用户给了本地措施的，改写为本地措施；没给的，保留一句任务名称，接【待补：本单位落实措施】，删掉照抄的展开。
   - 不做同义替换。误："深入整治餐饮等用气场所"改成"扎实推进餐饮用气场所整治"，换了词，内容还是上级的。也不在照抄句中间插入【待补】拆句（【】内的字不参与比对，照抄句会漏检）；【待补】只接在保留的任务名称之后。
   - 高重合段落是标题行，或只含指标、行动名称的，核实后保留，在检测结果中写明，如"保留：标题照录行动名称"（可保留的情形见 `references/localize.md` 第一部分）。
   - 改完重跑，直到总重合率不超过30%、高重合段落都已处理或注明保留；前后两次结果写进"附：重合检测结果"。
   - 不能运行脚本时，按 `references/localize.md` 第三部分人工逐段比对，起草说明写"未运行重合检测，已人工逐段比对"。
2. 加码检查：任务分解表逐行与上级条款比八项：标准、时限、范围、频次、材料报送、考核问责、转嫁责任、配套文件。超出上级要求的列入起草说明"附：加码风险提示"，写明本稿写法、上级要求、依据和建议。用户坚持要写的照写，提示保留。细则见 `references/deadline-burden.md` 第二部分。
3. 时限核对：每个本单位时限都早于上级对应时限；预留时间只按汇总、审核、报送的实际需要，不层层大幅提前。
4. 漏项复查：对标对表核对表中没有未处理的"漏项"。

### 第五步　自检与交付

1. 机检：有 Python 环境时运行 `python scripts/gongwen_lint.py 正文.txt --doc-type 实施方案 --json`。工作方案传"实施方案"；贯彻落实方案传"贯彻落实方案"，输出提示"不在统一词表中"的，改传"实施方案"重跑；落实情况报告传"报告"；学习传达要点传"其他"。P0 必改，P1 逐条判断，P2 酌情处理；【待补】【待核实】每处报 P2，是起草阶段的正当产物，保留并汇总进起草说明。无法运行时按 `references/checklist.md` 人工检查（读不到的按本文自检清单），起草说明写"未运行机检，已按人工清单检查"。
2. 过一遍本文"自检清单"。
3. 能写文件的，在当前工作目录建 `公文/<YYYYMMDD>-<简短标题>/`（第四步已建的沿用），写入 `上级文件.txt`、`要点表.md`、`任务分解表.md`（和 xlsx）、`正文.txt`、`起草说明.md`。`上级文件.txt` 是比对用的工作副本，写入前删去联系人和手机号所在的行；多份上级文件写成 `上级文件-甲.txt`、`上级文件-乙.txt`。一次出几份的，正文写成 `正文-实施方案.txt`、`正文-落实情况报告.txt`、`正文-传达要点.txt`。同名文件已存在时加 -v2、-v3，不覆盖。对话中只报文件位置、一段话概述、待补和待核实各几条、重合率。
4. 网页环境：依次输出正文、`【起草说明】`、说明内容，再附表，正文前不加引导语。附表名称前加"附："，按产品取用，顺序为：任务分解表、对标对表核对表、上级要求差异表（多份上级文件要求不一致时）、时限倒排表（有倒排时限或倒排建议时）、加码风险提示（有加码时）、重合检测结果、任务进展对账表（落实情况报告）、提法核对清单（学习传达要点）、本地措施来源（转译模式）、上级文件要点表；方案必附任务分解表、对标对表核对表、重合检测结果和要点表。能写文件的环境，要点表、任务分解表单独成文件，其余附表写进 `起草说明.md`。
5. 起草说明依次写所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点（仅教学模式），没有内容的部分省略。待补、待核实逐条写明正文位置。
6. 路线还有下一站的（印发通知交 gongwen-draft，核稿交 gongwen-review，排版交 gongwen-format），网页环境在起草说明之后输出更新后的交接卡（`references/_shared/style/output-format.md` 第四部分），不抄上级文件原文。

### 照抄初稿改写

用户拿来照抄上级的初稿，要改成本单位方案的，各模式都按以下顺序做（审稿模式用户说"帮我改一版"的，本次按高效模式出改后稿）：

1. 按第五步第3条建交付目录，初稿存为 `原稿.txt`、上级文件存为 `上级文件.txt`，运行 `python scripts/overlap_check.py 原稿.txt 上级文件.txt --json`，作为第一次结果；不能运行的按 `references/localize.md` 第三部分人工比对。
2. 按第一、二步建要点表和任务分解表。本地措施取自用户的补充材料和初稿中已有的本单位内容；都没有的标【待补】。
3. 按第三步改写。照抄段落有本地措施的换成本地措施，没有的保留任务名称接【待补：本单位落实措施】，不做同义替换。
4. 重跑检测作为第二次结果；运行 `python scripts/fact_diff.py 原稿.txt 正文.txt`，确认改动的数字、日期都能对上修改说明。两次检测结果写进"附：重合检测结果"，修改说明写清删了哪些照抄段落、换成了什么。

## 模式二　贯彻落实情况报告

1. 依据：任务分解表（本 skill 产出的，或用户提供的）和用户给的每项进展。没有任务表的，先按第一、二步从上级文件建表。
2. 状态分三种：已完成、推进中、未启动；已过本单位时限仍未完成的另注"滞后"。状态只按用户材料认定：
   - 已完成须有成果形式中的东西（文件已印发、清单已建立、项目已开工）；
   - 用户说"基本完成""差不多了"的，写推进中，标【待核实：完成情况】；
   - 用户没给进展的，对账表状态栏写"进展待补"，不计入三种状态；开头总体进展在三种状态之后单列一处【待补】，正文对应处标【待补：进展情况】，不把计划写成已完成。
3. 结构：标题"某某关于贯彻落实《……》情况的报告"；开头一句写依据和总体进展，如"重点任务分解表所列12项任务，已完成7项，推进中3项，未启动1项，【待补：任务9的进展情况】"，数字由对账表点数得出；一、主要进展；二、存在的问题；三、下一步安排（每项未完成任务一条）；结尾"特此报告。"上级规定了报告提纲或表格的，按上级的提纲和表格写。
4. 下一步安排的时限：沿用任务表中的本单位时限；用户材料写了时间的照写。已滞后的，或材料表明原时限完不成的（经费未到位、前置条件未具备），写【待补：新的完成时限，不晚于上级要求的×月×日】，起草说明请用户确认，不自定日期；用户授权倒排的除外。
   - 误：餐饮场所检查已过11月25日时限，下一步安排写"12月5日前完成剩余550家检查"。（日期没有来源）
   - 正：剩余550家餐饮场所入户检查，完成时限【待补：新的完成时限，不晚于上级要求的12月10日】。
5. 需要上级批准的事项（追加经费、调整时限）不写进报告，提示另行请示，交 gongwen-draft（《党政机关公文处理工作条例》第十五条第（四）项）。
6. 对账：起草说明附"附：任务进展对账表"，列为序号、任务、本单位时限、报告中的状态、依据（用户材料位置）。报告中的项数和状态与对账表一致；任务表每一项在报告中都有着落，可以合并叙述。
7. 成效数字、排名、群众评价只用用户提供的；存在的问题用户没给的，标【待补：存在的问题】。完成率＝实际完成数÷目标数×100%，与时间进度（已过时间÷全期时间）之差用百分点，如"慢于时间进度3.3个百分点"。用户给的约数照写约数，标【待核实：准确数】。篇幅按上级要求，没有要求的1500～3000字。

## 模式三　学习传达要点

1. 用途：在党委（党组）会、办公会、职工大会上传达上级会议或文件精神。叠加严谨模式。
2. 必须有原文：会议通报、讲话原文或文件。没有原文的，不凭记忆概括"会议精神"，只出提纲框架，"主要精神"部分写【待补：请提供会议通报或文件原文】。用户要求引用原文以外的论述（领导人论述、讲话原话、其他会议精神）的，同样不凭记忆写引文，在该位置标【待补：引文原文及出处】，起草说明请用户提供；提供后照录，列入提法核对清单。
3. 结构见 `references/structures.md` 第三部分：一、基本情况（只取原文）；二、主要精神（按原文结构分条，关键表述用引号照录原文，概括只用中性的串联语，不自造新提法）；三、贯彻落实意见（来自用户；有任务分解表的从表中提炼；没有的标【待补：本单位贯彻落实安排】）。
4. 起草说明附"附：提法核对清单"：提法、正文位置、原文出处（文件名和段落）、是否逐字一致。
5. 篇幅按传达时长约200字/分钟；未说明的1500～2500字。

## 模式四　对标对表检查（已有方案、已有落实情况报告）

用户拿来本单位已写好的材料要挑问题的，按审稿模式处理，不重写全文。问题清单列为：序号｜级别｜位置｜原文｜问题｜依据｜建议。格式、标点、提法的全面核稿交 gongwen-review。

已写好的方案（另附上级文件）：
1. 按第一步建要点表，逐条判定方案中有没有对应：已对应、漏项、只照抄未转化。
2. 做第四步的照抄检测、加码检查、时限核对。标题照录行动名称等第四步第1条可以保留的情形，不列为照抄问题。
3. 输出一页纸摘要（漏项、照抄段落、时限问题、加码风险各几处），再给问题清单。漏项、本单位时限晚于上级的定为 P0；照抄段落、加码风险定为 P1；时限提前过多、成果形式偏重留痕定为 P2。附对标对表核对表。
4. 用户说"帮我改一版"的，按"照抄初稿改写"做。

已写好的落实情况报告（另附任务分解表或进展材料）：
1. 先建对账表：任务表每项一行，列为序号、任务、本单位时限、任务表或材料中的状态、报告中的说法、是否一致。
2. 定级：报告中的状态与任务表或材料不符（把推进中写成已完成、"全部完成"与对账表不符）、没有依据的成效数字或评价（满意度、排名、比率）定为 P0；夹带请示事项定为 P0（《党政机关公文处理工作条例》第十五条第（四）项），提示另行请示，交 gongwen-draft；漏报某项任务定为 P1；"高度重视""迅速行动"之类的空话套话定为 P2。
3. 输出一页纸摘要、问题清单和"附：任务进展对账表"，不重写全文。

## 输出规范

- 正文、起草说明、交付位置按 `references/_shared/style/output-format.md`：纯文本公文体，不用 Markdown；层次序数依次为 一、（一）1.（1）；数字按 `references/_shared/rules/gbt15835.md`。
- 正文中只允许两种提示：【待补：说明】和【待核实：说明】。
- 要点表、任务分解表和各种附表是工作底稿，可以用 Markdown 表格，放在起草说明之后或单独的文件里。

## 自检清单

- [ ] 上级文件的名称、文号、指标、时限都取自原文，没有凭记忆补写。
- [ ] 要点表每一条都有结论（已对应、不涉及、漏项），没有未处理的漏项。
- [ ] 任务栏是本单位措施，没有照搬上级原句；缺措施的标了【待补】，没有编"特色做法"。
- [ ] 每项任务一个牵头单位；牵头、配合、统筹单位和本地数据都来自用户、画像或原文分工。
- [ ] 本单位时限都早于上级时限，没有大幅提前；用户未授权倒排的，时限写的是【待补】。
- [ ] 没有擅自提高标准、扩大范围、增加报送频次；没有一票否决、责任状、层层要求制定配套方案（用户坚持的已列入加码提示）。
- [ ] 重合检测已运行或已人工比对，总重合率不超过30%，高重合段落已处理或注明保留理由。
- [ ] 首段开门见山，没有背景、意义和上级指导思想的复述；篇幅在上限以内。
- [ ] 落实情况报告：状态都有依据，项数与对账表一致，未提供进展的标了【待补】；下一步安排的时限都有依据（任务表时限、用户材料或用户确认），滞后任务的新时限标了【待补】；没有夹带请示事项。
- [ ] 学习传达要点：主要精神只来自原文，引号内逐字一致，附提法核对清单。
- [ ] 正文没有 Markdown 符号、免责声明、AI 自述，没有个人手机号等敏感信息。
- [ ] 层次序数一、（一）1.（1）不跳级，"（一）"后不加标点，标题末尾不加标点；全角标点，发文字号用〔〕；日期写全年份；数值范围写全单位，比率之差用百分点；正文每个本地数字都能在用户材料中找到。
- [ ] 起草说明逐条汇总了全部【待补】【待核实】。

## 单位差异

| 单位类型 | 任务拆到哪一级 | 程序提示 | 特别注意 |
|---|---|---|---|
| 党政机关 | 部门、处室 | 涉及其他部门职权的须会签；部门对下级政府不提指令性要求（《条例》第十六条第（二）项） | 以政府办名义印发的，牵头可写到部门 |
| 基层（县乡、街道） | 站所、村（社区）、网格 | 重大事项经党委会议集体讨论 | 不向村（社区）转嫁责任，不要求签责任状、制度上墙（减负规定第16条） |
| 社区 | 网格、楼栋、志愿队伍 | 村级重大事项按"四议两公开" | 准入清单以外的事项提示报批；面向居民的告知书交 gongwen-draft |
| 公立医院 | 职能科室、临床科室 | "三重一大"事项须经党委会议研究 | 患者隐私；指标口径与上级考核口径一致 |
| 高校 | 职能部门、学院 | 党委常委会、校长办公会；涉及教职工切身利益的提交教代会，学术事项先经学术委员会 | 学院方案与学校方案逐条对应 |
| 中小学 | 处室、年级组、教研组 | 党组织会议、校长办公会议 | 不给教师摊派与教育教学无关的任务；进校园活动看白名单；装有 gongwen-k12 的，课后服务方案交 k12 |
| 国有企业 | 部门、子公司 | 党委前置研究后再由董事会或经理层决策 | 商业秘密；子公司任务写到法人单位 |

医院、学校、国企的内部发文不直接受减负规定约束，加码提示的依据写"参照"（`references/deadline-burden.md` 第二部分）。细则和示例任务行见 `references/units.md`。

## 角色适配

- 教学模式：第一轮交工作底稿（第二步末尾），确认后再写方案；写作要点讲怎么对标对表、怎么判断照抄、时限怎么倒排，各用本稿一处正误对照，第一轮附在底稿之后，成稿时放在起草说明末尾。
- 高效模式：要点表、任务分解表、方案、附表一次交付；可同时出 Excel；多份上级文件可合并拆解；起草说明只写假设、待补、待核实，附表按第五步第4条。
- 转译模式：接受口头描述的本地做法，只问业务事实（谁牵头、现有数量、计划何时完成），把业务说法改成部署措辞；起草说明附"本地措施来源"，每项措施注明出自用户哪句话。
- 审稿模式：检查已有材料走模式四，只给一页纸摘要、问题清单和核对表或对账表，不重写全文；被要求起草的，第一轮交工作底稿供拍板，确认后成稿。
- 严谨模式：用于学习传达要点和党建任务的落实方案。政治性提法只用用户提供的原文，引号内逐字一致；没有原文的通用提法标【待核实：请对照最新原文】，引语标【待补：引文原文及出处】（模式三第2条）。附提法核对清单。
