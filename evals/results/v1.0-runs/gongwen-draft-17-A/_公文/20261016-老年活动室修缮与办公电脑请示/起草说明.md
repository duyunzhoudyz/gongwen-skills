【起草说明】

一、所作假设

1. 任务卡：

```text
任务卡
发文名义：某社区居民委员会
写给谁：某街道办事处（对社区工作有指导职责的上级）
要办的事：（1）请求拨付老年活动室屋顶修缮经费3.5万元；（2）请求为社区配备办公电脑1台
文种：请示（社区平时说的“申请”，属请示性质）；两件事，分写两份
行文方向：上行文
单位类型：社区　角色模式：转译模式（推断）　篇幅：未指定，两份都按事实多少写短
```

2. 文种判断及依据：两件事都是请街道批准（批钱、批设备），属于请求批准，用请示（《党政机关公文处理工作条例》第八条第（十一）项）；不用报告，因为报告只汇报情况、不要求上级批复（第八条第（十）项）。社区居委会是基层群众性自治组织，向街道报送材料以街道规定为准，条例对机关的要求只作参照（第四十条）。社区平时说的“申请”属请示性质，所以标题写“关于……的请示”，不写“关于申请……的请示”（“申请”与“请示”意思重复，实务）。街道要求用“申请”作文种名的，把标题末尾的“请示”改为“申请”，结语不变。

3. 拆成两份的理由：修缮经费和办公电脑是互不相干的两件事，街道要分别审批，请示应当一文一事（《党政机关公文处理工作条例》第十五条第（四）项；社区报送街道的材料，一文一事同样适用，实务）。合写的话，一件被退回或要补材料，会拖慢另一件。街道明确要求合并报送的，按街道要求办，两件事在正文里分条写即可。

4. 没有提供单位画像：单位类型按您自述的“社区居委会”定为社区，沿用“某社区”“某街道”的说法；主送写“某街道办事处”，落款写“某社区居民委员会”；行文方向按请示推断为上行；社区一般不用红头，正文不写发文字号和版头要素。

5. 当前模式：转译模式（推断）。依据：您用口语说明了要办的事，没有“第一次写”之类的新手信号。说明尽量不用术语，另附“业务说法→公文表述”对照和素材台账。

6. 您说“直接写”，所以没有向您提问。正文只用了您提供的事实：老年活动室屋顶漏水，请求拨付3.5万元，配备办公电脑1台。其余缺项都标了【待补】，没有推断或编写。

7. 正文没有写“经社区党组织研究”“经居民会议讨论”“批准后再施工”之类的程序和承诺，因为这类程序事实只来自您。社区的重要事项一般先经社区党组织研究；如果已经研究过，请在第2段事项前补一句，如“经社区‘两委’会议研究”。

8. 可以用总入口 gongwen（帮您理清要写什么文、再转给合适的工具）建一份 3 个字段的简版画像，以后不必再回答这些问题。

二、待补事项

正文共10处【待补】（屋顶修缮请示6处，办公电脑请示4处）。已运行机检，两份均无P0、P1问题，P2提示只有这些【待补】标记，是起草阶段的正常产物，已逐条列在下面，补齐后才能报送。

（一）屋顶修缮请示（正文-屋顶修缮请示.txt）

1. 第1段：漏水的部位、面积、开始时间，以及对老年人活动的影响。一般到社区巡查记录、现场照片、老人反映中找。
2. 第2段：修缮内容和3.5万元的测算依据。一般到施工单位报价单、预算表中找。
3. 第2段：计划施工时间。一般到与施工单位商定的工期里找。
4. 附件说明：屋顶修缮预算或施工报价单。有的话附在后面，没有的话删去“附件”这一行。
5. 成文日期：送街道前的签发日期。
6. 附注：联系人及电话（经办人）。

（二）办公电脑请示（正文-办公电脑请示.txt）

1. 第1段：现有办公电脑的数量、使用年限和使用情况，以及需要新配的原因。一般到社区设备台账、资产清单中找。
2. 第2段：配置要求或预算金额。由街道统一购置、配发的，写配置要求；需要街道拨钱、社区自己购买的，写预算金额，并把“配备办公电脑1台”改为“拨付购置经费”，标题随之调整。
3. 成文日期：送街道前的签发日期。
4. 附注：联系人及电话（经办人）。

（三）两份通用

1. 单位全称：标题、主送、落款中的“某社区”“某街道”，换成实际全称，不自造简称。

（四）版头和落款要素（列在最后）

1. 发文字号、签发人：社区一般不用红头，是否编号、是否标注签发人，以街道规定为准（上行文一般标注签发人，条例第九条第（六）项）；街道有要求的，排版时填入。
2. 公章和签字：落款处加盖社区居民委员会公章；街道有要求的，经社区党组织书记签字后报送。
