# 评分任务

你是中文公文写作评测的评分员。下面有 {n} 个用例，每个用例有两份待评输出（甲、乙），由两个不同的写作助手各自独立完成。请对每份输出逐条判定期望（expectations）是否满足，并核查编造情况。除了写评分结果文件和必要的临时脚本外，不要修改任何文件。只读取本说明中列出的工作目录、机检摘要和输入材料文件，不要读取评测目录中的其他文件（如 index.json、blind.json、tasks、machine 目录），也不要读取 D:\公文写作skill 仓库。

## 每份输出包含

- 工作目录：`_回复.md` 是助手给用户的完整回复；`_正文/` 下是交付的文书全文（可能没有）；`_过程.md` 是助手自述的操作过程（读取的文件、运行的命令）；其他文件是助手生成的交付物（如 .md、.docx、.json）。工作目录中与"用户提供的文件"同名的是输入材料。
- 机检摘要：gongwen_lint 结果、fact_diff 列出的"输出中出现而输入材料中没有的数字"、Word 文件的格式检查结果（check_docx）、输入文件是否被改动。

## 判定规则

1. 每条期望判 pass 或 fail。只看这份输出本身，不要拿两份输出互相比较，两份各自独立判定。不要因为输出提到了某个工具名或方法名而放宽或收紧标准。
2. 期望写"或同等写法""或同义写法""之类"时按语义判定；没有这类说明的具体要求（标题措辞、结语、数字、格式、栏目）按字面判定。
3. 期望要求"标【待补】""标【待核实】"时看实质：输出在该处明确标出信息缺失或需核实、请用户补充或核对、没有编造，即为满足；占位写法不必与【待补】字面一致（如【待补充】、（待补）、"××（请补充）"均可）。
4. 期望涉及"运行了某脚本""输出某文件""原文件未被修改"时，以工作目录中的实际文件、机检摘要和 `_过程.md` 为准，脚本名必须一致。
5. 期望涉及 Word 文件版式（字体、颜色、线条、页码、版记、对齐等）时，用 python-docx 打开 docx 实际检查（可以写临时脚本，临时文件只放在 {scratch} 下）；"检查结果 P0 为 0"以机检摘要中 check_docx 的结果为准。
6. 期望涉及篇幅时，以机检摘要中"正文（标题后、起草说明前）约 N 字"为准；没有 `_正文` 时自行估算正文部分字数。
7. 期望说"回复中""起草说明中""修改说明中""交付说明中"时，`_回复.md` 和工作目录中的交付文件都算。
8. 期望涉及"没有提问"时，向用户提出需要对方回答的问题即算提问；结尾"如需调整请告诉我"之类的客套不算。
9. 期望由多个分句组成时，全部分句都满足才判 pass。
10. 输出停止处理或只提问时，凡是需要交付内容才能满足的期望一律判 fail，除非期望本身就是要求停止或提问。期望写"如输出了正文……"而实际没有输出正文时，判 pass。
11. 每条判定给一句证据：引用输出中的原文片段（不超过 40 字），或说明缺少什么。

## 编造核查

对机检摘要中 fact_diff 列出的每个"新增数字"，对照输入材料全文判定：

- "编造"：输入材料和用户消息中都没有依据的事实性数字，如统计数据、金额、人数、比例、日期、时限、排名、文号序号；
- "派生"：由输入中的数据正确换算、计算或改写单位得到（如 1256000 元写成 125.6 万元、两数相加），或把输入里的汉字数字写成阿拉伯数字；计算有误的算"编造"；
- "非事实"：序号、条款号、标准号、页码、年份、字数或时长估算、引用用户消息中的数字、明显是说明性举例的数字等。

另外，把 fact_diff 覆盖不到的非数字编造（输入中没有的人名、单位名、引语、具体事例、会议精神、上级文件名称和内容、未经材料支持的成效评价如"广受好评"）列入 other_fabrications。只看交付内容（正文、提纲、标题、改稿等）；给用户的说明中明确作为假设或示例的内容不算。

## 输出

每个用例写一个 JSON 文件到 `{grades_dir}\<skill>-<id>.json`（skill 和 id 见各用例标题），UTF-8 编码，格式：

```json
{
  "skill": "gongwen-report",
  "id": 1,
  "outputs": {
    "甲": {
      "expectations": [{"idx": 0, "pass": true, "evidence": "……"}],
      "fabrications": [{"value": "48652人次", "verdict": "编造", "note": "材料中没有门诊人次"}],
      "other_fabrications": [{"content": "……", "note": "……"}],
      "notes": "不超过 80 字的总体观察"
    },
    "乙": {}
  }
}
```

"乙"的结构与"甲"相同。expectations 必须按 idx 覆盖该用例的全部期望；fabrications 覆盖机检摘要列出的全部新增数字（没有则为空数组）。写完后用 Python 校验 JSON 合法、条数正确。

全部完成后，最终回复只写一行："已评 {n} 个用例"。
