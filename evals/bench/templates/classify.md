# 期望分类任务

你要为一个中文公文写作 skill 项目的评测期望（expectations）做分类，用于"装 skill 与不装 skill"对比时的公平统计。只读，不要修改仓库中的任何文件。

输入：skills\ 下 7 个目录（gongwen、gongwen-report、gongwen-title、gongwen-humanize、gongwen-direct、gongwen-review、gongwen-format）各自的 evals\evals.json。每条用例有 id、prompt、expectations（字符串数组）。如需理解项目约定，可以读 shared\style\output-format.md 和各 skill 的 SKILL.md。

对每条 expectation 分到两类之一：

"约定"：要满足它，必须知道本项目自己的约定，而这些约定既不是公文写作的通行规范，也无法从用户消息中推断。典型情形：
- 提到 skill 名、路线编号或路线（gongwen-xxx、R01 等）、交接卡、dist/prompts 提示词文件、"调用某 skill"；
- 本项目特有的输出结构：正文后的【起草说明】及其固定栏目（所作假设、待补事项、待核实事项、修改说明、保密提示、写作要点、转交事项等）、素材台账及其规定列、口径冲突表及其规定列、提法核对清单、"条数核对："行、"适用：""推荐："行、"本稿最该学的三点"、一页纸摘要的固定栏目、问题清单的规定列、核稿意见.json、修改说明按类别计数等；
- 本项目的角色模式体系带来的具体量化要求（如"修改说明不超过 5 行""改动处数不超过 3 处""提示不超过 3 条"），或必须知道模式名才能满足的要求；但如果该要求的实质可以从用户消息中直接推断（如用户说"别解释太多"对应"没有长篇解释"），归为"通用"；
- 本项目的分级与关口体系：要求某问题定为 P0/P1/P2、要求写明"法规关""程序关"等关口名；
- 具体脚本名、文件路径、画像文件及其字段（build_docx.py、check_docx.py、fact_diff、.gongwen/单位画像.md、公文/<日期>-<标题>/、"-修复.docx"等）；写作日历中关于 v0.1 现有 skill 的说明；
- 一条期望里只要有任何一部分属于上述约定（例如"正文不含 Markdown 符号，正文后有【起草说明】"），整条归为"约定"。

"通用"：任何熟悉公文写作的人，在只看到用户消息和材料、不知道本项目约定的情况下，也应当做到的实质要求。典型情形：事实与数字保持、不编造数据和事例、文种判断正确（请示与函、报告不夹带请示）、行文关系、引用《党政机关公文处理工作条例》或 GB/T 9704、GB/T 15834、GB/T 15835 等国家标准的条款、正文不含 Markdown 符号、篇幅符合用户要求、保护个人信息、见到密级或"内部资料"标识停止处理并提示不得输入联网 AI、内容组织与表达质量、对用户问题作出正确判断、标出缺失信息（"标【待补】"类期望按实质要求理解，归为"通用"，除非它要求的是起草说明中的汇总清单）。

输出：写入 <评测目录>\exp_class.json，JSON 数组，每项 {"skill": "gongwen-report", "id": 1, "idx": 0, "class": "通用" 或 "约定", "reason": "不超过 25 字的理由"}，idx 是该 expectation 在数组中的下标（从 0 开始）。必须覆盖全部 expectations，顺序按 skill、id、idx。写完后用 Python 校验条数和 JSON 合法性。
